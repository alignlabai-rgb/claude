Git & GitHub 完全ガイド

Git はコードの「タイムマシン」、GitHub はその「クラウド保管庫 + チームワーク場所」。今日のセッションでもSSH設定からcloneまで実際に使ったので、その流れで理解を深めよう。

概念を掴む 初期設定 毎日の操作 ブランチ GitHub操作 ミスを直す SSH設定 よくある場面 AIとの連携
まず概念を掴む

Git と GitHub は別物

🔧 Git（ツール）

あなたのMac上で動くプログラム。ファイルの変更履歴をローカルで管理する。インターネット不要。

  • 変更を記録（commit）
  • 過去に戻る（checkout / reset）
  • 並行作業（branch）
  • 履歴を確認（log）

☁️ GitHub（サービス）

Gitのデータをクラウドに置いておける場所。共有・バックアップ・公開ができる。Microsoft傘下。

  • コードを公開・非公開で保管
  • チームで共同編集
  • Pull Request（コードレビュー）
  • Issues（タスク管理）

コミットとは何か

コミット = ゲームのセーブポイント。「この時点のファイル全体」をスナップショットとして保存する。一度コミットすれば、いつでもその状態に戻れる。コミットには一意のID（ハッシュ）が付く。

💡 コミット頻度の目安 「1つの作業が完了したら1コミット」が基本。ファイルを10個変えても、目的が1つなら1コミット。迷ったら細かくコミットする方が安全。
初期設定（一度だけ）

Gitを使い始める前の設定

ユーザー情報を登録

コミットに「誰が」を記録するための設定。一度やれば永続する。

git config --global user.name "Your Name" git config --global user.email "you@example.com"

設定確認は git config --list

新しいリポジトリを作る

既存のフォルダをGit管理下に置く（初期化）。

# フォルダに移動してから git init git add . git commit -m "first commit"

.git という隠しフォルダが作られる。これがGitの本体。

既存のリポジトリをコピーしてくる（clone）

今日やった操作がこれ。GitHubにあるリポジトリをローカルに丸ごとコピーする。

# HTTPS方式（パスワードやトークンが必要） git clone https://github.com/ユーザー名/リポジトリ名.git # SSH方式（SSHキー設定済みなら認証不要）← 今日設定した方法 git clone git@github.com:ユーザー名/リポジトリ名.git # フォルダ名を指定してclone git clone git@github.com:ユーザー名/リポジトリ名.git 好きな名前
毎日の基本操作

作業の基本サイクル

1

状況を確認する

何かする前にまずこれ。変更されたファイルが一覧で見える。

git status
2

変更をステージングする（add）

「次のコミットに含めるファイル」を選ぶ。

git add ファイル名.html # 特定のファイルだけ git add . # 全ての変更を対象に（注意して使う） git add src/ # フォルダごと

ステージング前後を確認：git diff（未ステージ）、git diff --staged（ステージ済み）

3

コミットする（commit）

ステージングしたものをセーブポイントとして記録する。

git commit -m "メッセージ" # add と commit を同時にやる（追跡済みファイルのみ） git commit -am "メッセージ"

良いメッセージの書き方：「何をしたか」ではなく「なぜしたか」が伝わると最高。例：「ナビのリンク切れを修正」「中国系AIコーディングページを追加」

4

GitHubへ送る（push）

ローカルのコミット履歴をGitHubに反映させる。

git push # 現在のブランチをpush git push origin main # mainブランチを明示的に指定
5

GitHubから最新を取得する（pull）

他の誰か（または別のPC）がpushした内容をローカルに反映する。

git pull # fetch + merge を一括実行 git fetch # 取得だけ（マージしない）
💡 作業前に pull する習慣を 特にチームで使う場合、作業前に git pull してから始めると衝突が減る。

履歴を見る

git log --oneline # コンパクト表示 git log --oneline --graph # ブランチの分岐も視覚化 git log -10 # 最新10件だけ
ブランチ — 並行して作業する

ブランチとは

本番（main）を壊さずに「実験用のコピー」を作る仕組み。機能ごとにブランチを切って作業し、完成したらmainに合流（merge）させる。

main
本番・安定版
→ branch →
feature/new-page
開発中
→ merge →
main
機能追加済み

基本操作

git branch # 一覧（*が現在地） git branch 新ブランチ名 # 作成 git switch 新ブランチ名 # 移動 # 作成と移動を同時に git switch -c 新ブランチ名 # ブランチを削除 git branch -d ブランチ名

マージ

別ブランチの内容を現在のブランチに取り込む。

# mainブランチに戻ってから git switch main git merge feature/new-page
⚠ 競合（Conflict）が起きたら 同じファイルの同じ行を両ブランチで変えると競合する。Claude Codeに「競合を解決して」と頼むのが最速。
GitHub固有の操作

GitHub でよく使う操作

📁 リポジトリ（Repository）

プロジェクト1つ分のファイル群とその全履歴が入ったフォルダ。略して「リポ」。Public（公開）とPrivate（非公開）がある。

  • 今日のセッション：ALIGN_Lab / claude / gobd / Thinkers-700-reorg はすべてPrivateリポジトリ
  • GitHubのURL形式：github.com/ユーザー名/リポジトリ名

🍴 フォーク（Fork）

他人のリポジトリを自分のアカウントにコピーする。クローンとの違いは、Forkは自分のGitHub上にコピーが作られる点。

  • OSSに貢献するときに使う
  • Fork → clone → 修正 → PR が一般的な流れ

🔀 Pull Request（PR）

「このブランチをmainに取り込んでいいですか？」という提案。コードレビューの場でもある。一人作業でも使うとコミットの整理になる。

  • GitHub上でブランチ → "Compare & pull request"
  • タイトルと説明を書いて "Create pull request"
  • 問題なければ "Merge pull request"

🐛 Issues（イシュー）

バグ報告・機能要望・TODO管理ができるチケット機能。リポジトリのタスクボードとして使える。

  • コミットメッセージに #123 を書くと自動リンク
  • fixes #123 と書くとPRマージ時にIssueが自動クローズ

⭐ GitHub Pages

リポジトリのHTMLをそのまま無料でWebサイトとして公開できる機能。

  • Settings → Pages → Branch: main → Save
  • URL: ユーザー名.github.io/リポジトリ名

🔑 Personal Access Token（PAT）

HTTPS接続時に使うパスワード代わりのトークン。SSHキーを使っていれば不要。

  • Settings → Developer settings → Personal access tokens
  • スコープ：repo にチェックすれば大抵OK

リモートの確認・変更

「リモート」= GitHubなどのURL設定のこと。originが標準的な名前。

git remote -v # 現在のリモートURL確認 git remote add origin git@github.com:ユーザー名/リポジトリ名.git # 追加 git remote set-url origin git@github.com:新URL.git # URL変更
ミスを直す — 安全なやり直し

やり直しコマンド一覧

🔵 基本原則 pushする前のミスはいくらでも直せる。pushした後は少し慎重に。迷ったらClaude Codeに「〇〇を取り消したい」と説明して正しいコマンドを確認してもらう。
やりたいこと コマンド 安全度
addを取り消す（ステージング解除） git restore --staged ファイル名 安全
ファイルの変更を元に戻す（編集前に戻す） git restore ファイル名 変更消える
直前のコミットを取り消す（変更は残す） git reset --soft HEAD~1 安全
直前のコミットを完全に消す git reset --hard HEAD~1 変更も消える
コミットメッセージだけ直す（push前のみ） git commit --amend -m "新メッセージ" push前のみ
特定のコミットを打ち消す（履歴は残る） git revert コミットID 安全・push後もOK
作業中の変更を一時保存（別ブランチに移るとき） git stash / git stash pop 安全
SSH設定 — パスワード不要でGitHubと通信

SSH とは・なぜ必要か

GitHubのPrivateリポジトリにアクセスするには「あなたが本人である」証明が必要。SSHキーは「電子的な身分証明書」で、一度設定すればパスワード入力なしにgit clone / push / pull できる。今日このMacでは設定済み。

設定手順（今後別のMacで必要なとき）

1

キーを生成

ssh-keygen -t ed25519 -C "your@email.com"

~/.ssh/id_ed25519（秘密鍵）と ~/.ssh/id_ed25519.pub（公開鍵）が作られる。

2

公開鍵をGitHubに登録

cat ~/.ssh/id_ed25519.pub # 内容をコピー

GitHub → Settings → SSH and GPG keys → New SSH key に貼り付け。

3

接続確認

ssh -T git@github.com

「Hi ユーザー名!」と返ってくれば成功。

HTTPS vs SSH の違い

HTTPSSSH
URL形式 https://github.com/... git@github.com:...
認証 トークン/パスワード SSHキー（自動）
設定 簡単 一度だけ設定が必要
使いやすさ 毎回認証が面倒 設定後はラク
💡 推奨 長期的に使うMacにはSSHを設定するのが圧倒的にラク。今日のMacは設定済み。
よくある場面と対処法

実際にハマりやすいシチュエーション

「pushが拒否された」

GitHubに自分より新しい変更があるとき。

git pull --rebase git push

pullしてから再pushする。

「間違えてmainで作業してしまった」

pushする前ならブランチに移せる。

git switch -c 新ブランチ名 # mainの変更を新ブランチに持ち越せる

「特定のファイルだけ前のバージョンに戻したい」

git log --oneline # コミットIDを確認 git restore --source=コミットID ファイル名

「既存フォルダをGitHubリポジトリに紐付けたい」

今日のgobdフォルダのような状況。

git init git remote add origin git@github.com:ユーザー名/リポジトリ名.git git add . git commit -m "initial commit" git push -u origin main

「.gitignoreって何？」

Gitで追跡しないファイルを指定するファイル。パスワードや大容量ファイルを誤ってpushしないように。

# .gitignore の書き方例 .env # 環境変数ファイル node_modules/ # npmパッケージ *.log # ログファイル全般 .DS_Store # Macのシステムファイル

「2台のPCで同じリポジトリを使いたい」

両方のPCでSSHキーをGitHubに登録すれば使える。

  • PC-A でpush → PC-B で git pull
  • 同時に編集すると競合する可能性あり
  • ブランチを分けると安全
AIとの連携

Claude Code と Git を組み合わせる

難しいGitコマンドを暗記する必要はない。Claude Codeに「日本語で何をしたいか」を伝えれば正確なコマンドを教えてくれる。

こんな頼み方が有効

  • 「直前のコミットを取り消して、変更は残しておいて」
  • 「index.htmlとstyle.cssだけコミットして」
  • 「mainブランチに新しいfeatureブランチを切って」
  • 「GitHubの最新をpullしてからpushして」
  • 「コミット履歴を見やすく表示して」

Claude Codeが自動でやること

  • ファイルを作成・編集したあとにgit add/commit/pushを提案
  • 競合（conflict）が起きたら解決してくれる
  • Pull Requestの作成（gh コマンド経由）
  • 不適切なコマンド（force push等）は確認を求める
🔵 今日の実例 SSHキー生成 → GitHub登録 → clone → pull → 整備 → pushの全フローをClaude Codeが実行した。

Claude Code用語集：似た言葉の境界を読む

言葉を暗記するためではなく、設定・責任・検証の対象を取り違えないための短い辞書です。

旧情報は固定旧版の全文へ分離しています。以下の例・試験案は未実行の教材です。

モデルと製品

モデルは推論を担う対象です。Claude Codeはファイル、コマンド、ツールを使う開発用の製品です。Messages APIはアプリがモデルに依頼する接口です。同じモデル名でも、製品が提供するツール、契約、課金、実行場所まで同じになるわけではありません。APIからCodeの作業環境が自動的に生まれる、という読み方は避けます。Code概要・Messages API。

コンテキストは現在の依頼でモデルが参照する情報です。永続ファイルは実行をまたいで残る資料で、読む段階を経て初めて文脈に入ります。prompt cachingは再利用可能な入力に関する処理であり、過去の出来事を何でも思い出す記憶ではありません。したがって「保存した」「読ませた」「キャッシュされた」を別々に確認します。動作原理・キャッシュ。

方法・接続・イベント

CLAUDE.mdはプロジェクトの継続的な指示を載せる入口です。Skillは再利用する方法や作業手順をまとめる単位です。MCPは外部ツールや資料への接続規約です。例えば「公開仕様を照合する順序」はSkill、「仕様を検索できる接続」はMCP、「このリポジトリでは変更前にテストを書く」は継続的指示、と分けると管理しやすくなります。これは構成例であり、実装済みの機能構成ではありません。継続的指示・Skills・MCP。

Hookは所定のイベントに応じて走る処理です。Permissionは操作を許す条件です。Hookがログを出しただけで、操作の許可や結果の正当性が確定するわけではありません。イベントを観測する、危険な操作を止める、結果を採用する、という三つの責任を同一視しないことが実装上の要点です。Hooks・権限。

並列作業と実行場所

Subagentは特定の役割を切り出す別コンテキストの作業者です。Agent teamはリーダーと複数の独立したセッションが協調する機能で、公式文書では実験的かつ既定で無効です。WorktreeはGitの作業木を分離する方法で、チームの会話や共有タスクそのものではありません。並列でレビューしたいという目的から、まず読み取りだけで済むか、実際に複数の編集場所が必要かを決めます。Subagents・Agent teams・Worktrees。

Routineはクラウドで起動する再利用可能な実行で、research previewです。CLIの/scheduleもcloud routineの入口で、作成はv2.1.225以降、list／update／runなどの管理はv2.1.227以降です。端末側のDesktop scheduled task、session内の/loopとCronCreate／CronList／CronDeleteは別の仕組みです。「毎朝実行」は頻度の要件であって実行面の名前ではありません。クラウド完走、ローカル接続、業務上の完了も別々に観測します。Routines・Desktop定期実行・session内の定期実行。

結果の読み方

CheckpointはCodeが追跡する変更の復元機構ですが、外部システムやすべてのシェル変更を戻すバックアップではありません。Receiptは本連載で使う設計用語で、何が実際に起きたかを確かめられる結果証跡を指します。受入条件はその証跡をどの基準で判断するかです。「成功しました」という生成文だけをreceiptと呼ばない、と決めると誤採用を減らせます。復元の範囲。

Negative fixtureも本連載の評価設計用語です。欠損した資料、重複依頼、単位違いなど、成功扱いしてはいけない合成ケースを事前に用意します。製品の固有機能名ではありません。Glossaryを使う最後の確認は、「この言葉は公式機能か、こちらの設計概念か」「何を観測すれば成立を確かめられるか」の二問です。

LLM 比較の実験設計：モデルの差と構成の差を混ぜない

最終更新・公式情報確認：2026-10-13。news という旧 URL は維持し、本文は用途別の現行ガイドへ刷新しました。確認日は発表日ではありません。

例と評価案は筆者の設計提案で、未実行です。性能測定・本番導入・安全認定・正式採用の実績を示すものではありません。

「この agent にはこのモデルが最強」という一覧は、同じ課題で測定した結果がなければ使いにくい。旧記事の銘柄別の勝率や固定した役割は現行判断として残さない。基本のモデル選定は Agent Brain ガイド に譲り、ここでは比較実験の条件をそろえる方法を掘り下げる。

実験の変更は一つだけ

筆者の評価案では入力、道具、権限、作業領域、提出形式を固定し、推論対象だけを替える。provider の接続方式やハーネスまで同時に替えた場合は、モデル単独の差と呼ばない。OpenClaw の provider 文書は接続面とモデル選択を分けている。OpenClaw Model providers一つの共通チャット画面が実験条件を共通化したことにはならない。

設定の差が避けられないなら、その差を結果へ併記する。対応ツールが違う候補に同じ仕事を無理に与えるより、共通でできる部分と製品全体での適合を別の試験へする。

同じ正解がない三つの課題

公開仕様の変更を見つける課題、資料同士が矛盾して保留する課題、権限不足で停止する課題を合成する。長文を出すことではなく、根拠と停止条件を守ることを採点する。公式 personal benchmark も進捗の証拠と拒否後の停止を扱うが、一般的なモデルランキングではない。Personal Agent Benchmark Pack

日本語の自然さは別の欄にする。否定を一つ落とした流暢な文章は不合格である。中国語または英語の仕様を日本語にまとめるなら、原語の根拠へ戻れる参照を保つ。本棚は各モデルの日本語実測をしていない。

利用できるモデル ID を読む

DeepSeek と Qwen の OpenClaw 文書は、現在の provider と接続面の個別情報を持つ。DeepSeek provider、Qwen provider旧記事にあるモデル名をそのまま最新版の接続 ID として配らない。カタログ、選んだ ID、実際に解決した推論先を記録する。

同じ alias でも後の版で意味が変わり得る。候補 A という表示名だけで記録すると、昨日と今日の比較が同じか分からない。版と確認日を付け、取得できない候補は未測定として残す。

低費用の比較で見落とすもの

本文の一回の推論だけでなく、再試行、補助推論、文脈の再送、失敗後の回復も記録する。費用の見積もりと請求の観測を分け、契約と期間が違う数字を同じ表へ足さない。広告上の単価から仕事全体の安さを決めない。

ローカルなら、起動、読み込み、メモリ、同時実行を別に測る。モデルがメモリへ収まることと、必要な道具を安定して呼べることは違う。クラウドなら制限と障害の条件を含め、運用の負担がないとは説明しない。

判定者を独立させる

出力のモデル名を隠し、採点の条件を先に決める。候補の自己評価を合格判定に使わない。正答例だけでなく、保留すべき例が正しく保留されたかを人または別の検査で確認する。事実のチェックと文章の読みやすさを混ぜない。

最終結果は万能の勝者ではなく、どの仕事のどの条件に適合し、何を満たさなかったかを示す。モデルを替えるたびに同じ集合を再利用すれば、失敗が次の選定の資産になる。未実測の順位を出さないことは、比較を諦めることではない。

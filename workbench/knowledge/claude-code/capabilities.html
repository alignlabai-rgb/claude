Capabilities Cheatsheet

Power User Commands, Slash Commands, Hooks & Shell Integration

CLI版Claude Codeの真価は、OSのシェル（Bash/Zsh/PowerShell）との連携にあります。
単体で使うだけでなく、パイプラインの一部として組み込むことで最強の自動化ツールになります。

File Operations & Piping

$ claude --print "Userモデルの定義を作成して" > User.ts
Direct Output
Claudeにファイル操作権限を与えず、結果を標準出力に吐かせ、シェル側でファイルにリダイレクトする安全な手法。
$ cat error.log | claude "このエラーログの最後10行を分析して原因を突き止めて"
Log Analysis
巨大なログファイルをパイプで流し込む。Claudeは標準入力をコンテキストとして読み込みます。
$ claude --init --path ./frontend
Sub-directory Focus
モノレポ構成の場合、ルートではなく特定のディレクトリ（frontendなど）をルートと見なして分析させることができます。

Mode Flags

$ claude --effort low "fix lint errors"
Quick Fix Mode
思考時間を短縮し、Sonnet主体で高速に単純作業をこなします。コスト削減に有効。
$ claude --verbose "why is this failing?"
Brain Dump
Claudeの「思考プロセス（Thinking）」を隠さずすべて表示させます。彼が何を迷っているのかをデバッグするのに必須。

Slash Commands（スラッシュコマンド）

TUIセッション中にプロンプトの先頭に / を付けて入力する内蔵コマンドです。
セッション管理・コスト確認・カスタムコマンド実行など、エージェントをコントロールするための重要な手段です。

/help
コマンド一覧表示
使用可能なすべてのスラッシュコマンドを一覧表示します。初めてのセッションや忘れたときにすぐ確認できます。
/clear
コンテキスト消去（Context Poisoning 対策）
現在の会話コンテキストをすべて削除します。誤った前提がモデルに蓄積した「Context Poisoning」状態を解消するのに有効。長いデバッグセッションの後にリセットするために使います。
/compact
コンテキスト圧縮
コンテキストウィンドウが埋まってきた長いセッションで使用します。会話の履歴を要約・圧縮し、トークンを節約しながら作業を継続できます。/clear と違い、作業の流れを完全にはリセットしません。
/memory
メモリファイルの表示・編集
Claude が参照するメモリファイル（CLAUDE.md等）の内容を表示し、必要に応じて編集できます。プロジェクト固有の前提知識やルールを確認・修正するときに使います。
/cost
セッションのトークン消費コストを表示
現在のセッションでどれだけのトークンを消費しているかをリアルタイムで表示します。コスト管理や、コンテキストが増えすぎていないかの確認に使います。
/status
現在のモデル・設定を表示
使用中のモデル名・設定パラメータ・MCP サーバーの接続状態などを確認できます。設定変更後の確認やトラブルシューティングに便利です。
/project:カスタムコマンド名
プロジェクト固有カスタムコマンド
.claude/commands/ ディレクトリに置いた Markdown ファイルをコマンドとして実行します。例えば .claude/commands/review.md を置けば /project:review で呼び出せます。チームで共有するコマンドに使います。
/user:カスタムコマンド名
ユーザー固有カスタムコマンド
~/.claude/commands/ に置いたコマンドを実行します。プロジェクトをまたいで個人が使い回すコマンド（例：自分の好みのコードレビュー形式など）に使います。
カスタムコマンドの作り方： Markdown ファイルを .claude/commands/ に置くだけです。ファイル名がコマンド名になります。ファイルの中身はプロンプトとして使われ、$ARGUMENTS プレースホルダーでコマンド実行時の引数を受け取れます。

Non-Interactive（パイプライン）モード完全版

インタラクティブなTUIを起動せず、標準入出力のみでClaudeを使うモードです。
CI/CDパイプライン・cronジョブ・シェルスクリプトへの組み込みに不可欠です。

$ claude -p "..."
Print モード（短縮形）
--print の短縮形です。TUIを起動せずに1回だけ応答を取得して終了します。スクリプト内での使用はこちらを推奨。
$ claude -p "..." --output-format json
JSON 出力（CI/CD 向け）
応答をJSONオブジェクトとして出力します。jq でパースして後続処理に渡せます。CI/CDパイプラインでの構造化データ取得に使います。
$ claude -p "..." --output-format stream-json
ストリーミング JSON 出力
応答をストリーミングしながら逐次JSONで出力します。長い応答を受け取りながらリアルタイムで処理したい場合に使います。

実用パイプライン例

$ cat code.py | claude -p "このコードをTypeScriptに変換して"
コード変換パイプライン
既存のPythonファイルをstdinに渡してTypeScript変換。変換結果を > output.ts にリダイレクトすれば1コマンドで完結します。
$ git diff | claude -p "このdiffのコードレビューをMarkdownで"
git diff コードレビュー
コミット前の差分をそのままClaudeに渡してレビューコメントを生成。PRの説明文生成にも応用できます。
$ ls -la | claude -p "最も重いファイルTop5を特定して"
ファイル分析
ls や du の出力をパイプして自然言語で分析させます。コマンドの出力を読み解くのが苦手な人でも直感的に使えます。
$ git log --oneline -20 | claude -p "過去20コミットの変更傾向を要約して、リリースノートのドラフトを作成して" # JSON出力して jq でパース $ claude -p "現在のディレクトリ構造を分析して" --output-format json | jq '.result' # CI でのテスト失敗原因分析 $ npm test 2>&1 | claude -p "このテスト失敗ログを分析して原因と修正方針を日本語で"
注意： Non-Interactive モードではツール実行（ファイル書き込み・コマンド実行等）のデフォルト動作が変わります。 安全のため、パイプラインでのファイル操作は --allowedTools で明示的に許可するか、出力をリダイレクトする手法を使うことを推奨します。

Context & Memory

Claude Code のコンテキスト管理は階層的なメモリシステムで構成されています。
プロジェクト設定からユーザー設定まで、優先度の高いものが低いものをオーバーライドします。

@ 構文でコンテキストにファイルを追加

@src/auth/user.ts
ファイルをコンテキストに読み込む
プロンプトの中で @ファイルパス と書くと、そのファイルの内容がコンテキストに自動挿入されます。「@src/auth/user.ts を参考に同様の構造で...」のように使います。
@src/components/
ディレクトリ全体を読み込む
フォルダパスを指定するとディレクトリ配下のファイルをまとめて読み込みます。コンポーネント全体の一貫性を確認させる場合などに使います。

CLAUDE.md ファイルシステム

ファイルパス スコープ 用途
CLAUDE.md（プロジェクトルート） プロジェクト全体 毎回自動読み込み。コーディング規約・禁止操作・アーキテクチャ概要などを記載。git管理してチームで共有。
~/.claude/CLAUDE.md グローバル（ユーザー全体） 個人の好みや汎用ルール。「コードコメントは英語で」「エラー時は必ず原因と解決策を提示」など。
src/CLAUDE.md（サブディレクトリ） そのディレクトリ以下 モノレポでサブパッケージごとに異なるルールを設定できます。
.claude/settings.json プロジェクト 許可ツール・モデル選択・MCPサーバー設定・Hooks定義など。git管理してチームで共有。
.claude/settings.local.json ローカル（個人） APIキーなどの機密設定。.gitignore に必ず追加すること。
~/.claude/settings.json グローバル（ユーザー） すべてのプロジェクトに共通するグローバル設定。
CLAUDE.md に書くべき内容の例：
・プロジェクトの技術スタック概要（「Next.js + Prisma + tRPC」）
・コーディング規約（「コンポーネントはデフォルトエクスポートを使わない」）
・やってはいけない操作（「本番DB への直接書き込み禁止」）
・よく参照するファイルのパス一覧
・用語集（プロジェクト固有の用語の定義）

Hooks System

Hooksは、Claudeがツールを呼び出す前後などのライフサイクルイベントに独自のシェルスクリプトを差し込む仕組みです。
監査ログの記録・自動フォーマット・危険な操作のブロックなどを実現できます。

Hook イベントの種類

イベント名 発火タイミング 主な用途
PreToolUse ツール呼び出し直前 危険な操作のブロック・引数の検証・ログ記録
PostToolUse ツール呼び出し直後 結果の記録・自動フォーマット（prettier等）の実行
SessionStart セッション開始時 環境変数の設定・前提条件チェック
SessionEnd セッション終了時 クリーンアップ・サマリーログの記録
Stop Claude が応答完了時 応答内容の後処理・通知送信

設定方法

.claude/settings.json に hooks キーで記述します。

{ "hooks": { "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "echo \"[$(date)] Tool: $TOOL_NAME, Input: $TOOL_INPUT\" >> ~/.claude/tool-log.jsonl" } ] } ], "PostToolUse": [ { "matcher": "Write", "hooks": [ { "type": "command", "command": "npx prettier --write \"$TOOL_INPUT_FILE_PATH\" 2>/dev/null || true" } ] } ] } }
実用 Hook アイデア：
・PreToolUse + Bash matcher: rm -rf や DROP TABLE を含むコマンドを検出して実行をブロック
・PostToolUse + Write matcher: ファイル書き込み後に自動で prettier や eslint --fix を実行
・SessionEnd: セッション終了時にSlackやDiscordへ「作業完了」通知を送る

jq を使ったツール呼び出しログの記録例

#!/bin/bash # ツール呼び出しを JSONL 形式でログに記録するスクリプト # .claude/hooks/log-tool-use.sh として保存 LOG_FILE="$HOME/.claude/audit-log.jsonl" jq -n \ --arg ts "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \ --arg tool "$TOOL_NAME" \ --arg input "$TOOL_INPUT" \ --arg project "$PWD" \ '{timestamp: $ts, tool: $tool, input: $input, project: $project}' \ >> "$LOG_FILE"

このスクリプトを PreToolUse Hook として登録すると、すべてのツール呼び出しが ~/.claude/audit-log.jsonl に記録されます。セキュリティ監査やデバッグに役立ちます。

キーボードショートカット（TUI）

インタラクティブなTUIセッション中に使えるキーボードショートカットです。
長時間の作業を快適に進めるために覚えておきたいショートカット一覧です。

キー 動作 使いどころ
Ctrl + C エージェント停止 Claude が長い処理を実行中に中断したいとき。暴走を止めるのに使います。
Ctrl + Z セッション一時停止 現在のセッションをバックグラウンドに送ります。fg コマンドで再開できます。
Esc 入力キャンセル 書きかけのプロンプトを送信前にキャンセルします。誤入力を送る前に使います。
↑ / ↓ 履歴ナビゲーション 過去に送ったプロンプトを再利用・編集するときに使います。繰り返しタスクに便利。
Ctrl + L 画面クリア（表示のみ） ターミナルの表示をクリアします。コンテキストは消えません（コンテキスト削除は /clear）。
Tab 補完 ファイルパス入力時の補完。@src/ と入力して Tab でパスを補完できます。
Ctrl+C と /clear の違い：
Ctrl+C は「現在実行中の処理を止める」だけで、セッションとコンテキストは維持されます。 /clear は「会話履歴（コンテキスト）を消去する」コマンドです。処理を止めたいだけなら Ctrl+C、誤った前提をリセットしたいなら /clear を使います。

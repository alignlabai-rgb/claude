Microsoft Phi — 小型高性能言語モデル（SLM）

「データ量より品質」を徹底した Microsoft Research の設計哲学。Phi-4（14B）は GPT-4 クラスのベンチマークを小型で実現。Copilot+ PC 専用の Phi Silica は NPU でオフライン推論。エッジ〜クラウドすべてで動く。

Phi-4 / Phi-4-mini Phi Silica MIT / Apache 2.0 エッジ AI Ollama 対応 NPU 実行 マルチモーダル Copilot+ PC

1. Phi とは — 設計哲学「データ品質優先」

「より少ないデータでより賢く（More capable with less data）」 — Phi ファミリーは、大量の生ウェブクロールに依存した従来のアプローチを否定する。代わりに 合成データ生成・厳格なキュレーション・カリキュラム学習 の三本柱で訓練する。結果として 14B パラメータで 70B+ を上回る推論能力を実現した。

Phi-4 の学習には 50 以上のカスタムパイプラインで生成した 4,000 億トークンの高品質合成データが使われた。合成データ生成の主な手法は以下：

マルチエージェント合成

複数の AI エージェントが問題を「出題 → 解答 → 批評」するループを回し、高難度の問題解答ペアを大量生成する。

自己修正ワークフロー

モデルが自らの出力を批評・書き直すセルフリビジョンにより、「間違いを認識して修正する」能力を訓練データに組み込む。

命令逆転（Instruction Reversal）

コードスニペットから「これを書かせた元の指示」を逆算で生成。instruction following 能力を大幅に強化する。

Plurality Filtering

複数ロールアウトで多数決的に正しさを検証。自明でなく挑戦的な例のみを訓練データとして保持し、品質を担保する。

この哲学は Phi-1 の登場時から一貫している。Phi-1（1.3B, 2023年6月）が Python コーディングで既存 SLM を一変させた衝撃は、「モデルサイズではなく訓練データの品質が性能を決める」という仮説の実証であった。

4. Phi Silica — Windows AI の特殊ケース

Phi Silica とは: Copilot+ PC の NPU（Neural Processing Unit）専用に最適化された SLM。クラウド接続不要・完全オフライン・超低消費電力で動作する。CPU/GPU を解放して他の処理に使えるため、ラップトップのバッテリーに優しい。Windows Copilot Runtime の一部として OS に組み込まれており、Windows Update で自動更新される。

ハードウェア要件

Qualcomm Snapdragon X

  • Snapdragon X Elite / X Plus
  • Hexagon NPU: 45 TOPS 以上
  • RAM: 16 GB 以上
  • 最初に対応したプラットフォーム（2024年5月〜）

Intel Core Ultra（Arrow Lake）

  • Intel AI Boost NPU
  • Copilot+ PC 認定モデル
  • 別 KB アップデート（KB5075032等）で対応
  • RAM: 16 GB 以上

AMD Ryzen AI（Strix Point）

  • AMD Ryzen AI 300 シリーズ
  • XDNA 2 NPU: 50 TOPS 以上
  • Copilot+ PC 認定モデル
  • RAM: 16 GB 以上

Phi Silica が実現すること

Recall（AIメモリ）

過去の作業画面を AI が理解・検索する Windows の Recall 機能。Phi Silica が全処理をデバイス内で行うため、スクリーンショットが外部に送信されない。

Click to Do

画面上のテキスト・画像を右クリックで即座に AI 処理。「このメールを要約して」「この画像を説明して」がオフラインで完了する。

ライブキャプション + 翻訳

オンライン会議・動画のリアルタイム字幕と翻訳をオフラインで実行。ネットワーク遅延なしで会議中に即座に表示。

Windows Studio Effects

AI によるバックグラウンドぼかし・アイコンタクト補正・ノイズ除去をカメラアプリなどで利用。NPU が常時処理することで CPU 負荷ゼロ。

更新サイクル（2025〜2026年）

Microsoft は Phi Silica を Windows Update 経由で四半期ごとに自動更新する方針を採っている（KB5096575, KB5096568 等）。ユーザーは特別な操作なく最新モデルを受け取れる。隔回リリースごとに新しいモデル能力（マルチモーダル対応予定等）が追加される。

5. Windows AI APIs でのアプリ開発

Phi Silica は Windows App SDK の Microsoft.Windows.AI 名前空間から呼び出せる。要件: Qualcomm Snapdragon X（Hexagon NPU 40 TOPS 以上）+ RAM 16 GB + Windows 11 24H2 以降。

① C# — テキスト生成の基本

// NuGet: Microsoft.Windows.AI (Windows App SDK 1.7.2+)
using Microsoft.Windows.AI;
using Microsoft.Windows.AI.Text;

// 利用可能かチェック
if (!LanguageModel.IsAvailable())
{
    Console.WriteLine("Copilot+ PC が必要です（NPU 40 TOPS 以上）");
    return;
}

// モデルを取得（初回は数秒かかる場合あり）
using var model = await LanguageModel.CreateAsync();

// シンプルなテキスト生成
string result = await model.GenerateResponseAsync(
    "次の会議メモを3行に要約してください：\n\n" + meetingNotes
);

Console.WriteLine(result);

② C# — ストリーミング生成（リアルタイム表示）

using Microsoft.Windows.AI;
using Microsoft.Windows.AI.Text;

using var model = await LanguageModel.CreateAsync();

// ストリーミングで逐次出力
await foreach (var token in model.GenerateResponseStreamingAsync(
    "今日の天気について日本語で詩を書いてください"))
{
    Console.Write(token);  // リアルタイムで1トークンずつ表示
}
Console.WriteLine();

7. Fine-tuning ガイド

Phi-4-mini（3.8B）は VRAM 8 GB 程度の GPU でも QLoRA Fine-tuning が可能。Phi-4（14B）は 16 GB VRAM で QLoRA が動く。

必要スペック目安

  • Phi-4-mini QLoRA: 6〜8 GB VRAM（RTX 3060 / 4060）
  • Phi-4 QLoRA: 12〜16 GB VRAM（RTX 3080 Ti / 4080）
  • Phi-4 LoRA（FP16）: 24+ GB VRAM（RTX 3090 / 4090）
  • 所要時間: Phi-4-mini 1K サンプル → 30〜60 分（RTX 4080）
  • データ形式: Alpaca / ShareGPT / ChatML 形式の JSONL

いつ Fine-tuning するか

  • 社内専門用語・文体の統一が必要な場合
  • 特定ドメインの精度を最大化したい場合
  • プロンプトエンジニアリングだけでは不十分な場合
  • 数百〜数万サンプルの高品質データがある場合
  • Phi Silica の LoRA Fine-tuning（Windows AI SDK）

Unsloth + QLoRA で Phi-4-mini を Fine-tuning

# pip install unsloth transformers trl datasets accelerate
from unsloth import FastLanguageModel
import torch

# モデルをロード（4bit QLoRA）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="microsoft/Phi-4-mini-instruct",
    max_seq_length=4096,
    dtype=torch.bfloat16,
    load_in_4bit=True,          # QLoRA: 4bit 量子化でメモリ削減
)

# LoRA アダプタを追加
model = FastLanguageModel.get_peft_model(
    model,
    r=16,                       # LoRA ランク（大きいほど表現力↑・VRAM↑）
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    use_gradient_checkpointing=True,
)

# 学習データの準備（Alpaca 形式）
from datasets import load_dataset

dataset = load_dataset("json", data_files="my_training_data.jsonl")

def format_alpaca(example):
    return {
        "text": f"### Instruction:\n{example['instruction']}\n\n"
                f"### Response:\n{example['output']}"
    }

dataset = dataset.map(format_alpaca)

# SFT トレーニング
from trl import SFTTrainer
from transformers import TrainingArguments

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset["train"],
    dataset_text_field="text",
    max_seq_length=4096,
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        num_train_epochs=3,
        learning_rate=2e-4,
        output_dir="./phi4-mini-finetuned",
        bf16=True,
        logging_steps=10,
        save_strategy="epoch",
    ),
)
trainer.train()

# LoRA アダプタを保存
model.save_pretrained("./phi4-mini-lora-adapter")
tokenizer.save_pretrained("./phi4-mini-lora-adapter")
print("Fine-tuning 完了。Ollama でのローカル実行には GGUF 変換が必要。")

8. Phi-4-multimodal — 画像・音声・テキスト統合

アーキテクチャの特徴: Phi-4-multimodal は単一モデルに複数モダリティを詰め込む従来のアプローチと異なり、Mixture-of-LoRAs 設計を採用する。コア LLM（Phi-4-mini 3.8B）に Vision LoRA（370M）と Audio LoRA（460M）を接続し、各モダリティのエキスパートが動的に切り替わる。

テキスト → テキスト

  • 通常の Phi-4-mini として動作
  • 数学・コード・推論で高性能
  • 128K コンテキスト対応

画像 → テキスト

  • 文書理解・OCR・図表分析
  • Gemini 2.0 Flash を一部指標で上回る
  • Vision LoRA が自動的に活性化

音声 → テキスト

  • OpenASR リーダーボード 1 位（WER 6.14%）
  • 音声翻訳（Automatic Speech Translation）
  • Spoken Query QA・音声要約に対応
  • Audio LoRA が自動的に活性化

Python での利用例（Hugging Face Transformers）

# pip install transformers pillow soundfile
from transformers import AutoModelForCausalLM, AutoProcessor
from PIL import Image
import torch

model_id = "microsoft/Phi-4-multimodal-instruct"
processor = AutoProcessor.from_pretrained(model_id, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    trust_remote_code=True,
)

# 画像 + テキスト
image = Image.open("invoice.png")
messages = [{
    "role": "user",
    "content": "<|image_1|>\nこの請求書の合計金額を教えてください"
}]

prompt = processor.tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True
)
inputs = processor(prompt, images=[image], return_tensors="pt").to(model.device)

with torch.no_grad():
    outputs = model.generate(**inputs, max_new_tokens=200)
decoded = processor.decode(outputs[0], skip_special_tokens=True)
print(decoded)

11. ライセンスと商用利用

MIT ライセンス（Phi-4 ファミリー）

  • 商用プロダクトへの組み込みが無制限
  • 改変・派生モデルの自由な作成
  • ソースコード開示義務なし
  • LoRA アダプタの販売・配布可
  • SaaS・API サービス化可
  • ライセンス表記のみ必要

利用規約（Responsible AI）

  • 違法コンテンツ生成の禁止
  • 差別・ハラスメント目的での利用禁止
  • Microsoft の商標・ロゴの無断使用禁止
  • Microsoft Responsible AI 原則への準拠
  • 悪意ある軍事用途への利用禁止

Phi Silica の特例

  • Windows に組み込みのため独立配布不可
  • Windows AI APIs は Limited Access（申請必要）
  • ウェイトは非公開（Windows Copilot Runtime のみ）
  • モデル更新は Microsoft が管理（Windows Update）

Llama との違い（法務上の比較）

  • Phi-4: MIT — ユーザー数制限なし
  • Llama 4: MAU 7億超はメタへの申請が必要
  • MIT は企業法務レビューが圧倒的に通りやすい
  • 大企業の製品組み込みには Phi の MIT が有利

実用的な判断: Phi-4 シリーズは MIT ライセンスのため、商用利用において Llama（MAU 制限）や一部 Apache 2.0 派生モデルより法的リスクが低い。大企業の製品組み込み・SaaS 展開・LoRA アダプタの販売いずれも問題なく行える。ただし Microsoft の Responsible AI 利用規約（Hugging Face モデルカードに記載）への準拠は必要。

Core Features
コア機能 — Tab補完 / Chat / Agent Mode

すべての Cursor 体験を支える3つの基盤機能。

⌨️
Cursor Tab（AI補完）
Cursor 独自の補完モデルで、次の行だけでなく次のブロック全体を予測補完する。Tab キー1つで確定、Esc で却下。業界平均65%（GitHub Copilot）に対し72%の採用率を達成。最近カーソルを動かした箇所や変更パターンを文脈として学習し、コーディングスタイルに合わせた提案を出す。
💬
Chat（コードベース問答）
Cmd+L で開くサイドパネル。@ファイル・@フォルダ・@codebase・@docs・@web でコンテキストを指定。インデックス化されたコードベース全体に対して設計相談・バグ調査・コードレビューが可能。
🤖
Agent Mode（旧：Composer）
Cmd+I で起動。複数ファイルにまたがる実装・リファクタ・テスト追加を一括で指示できる。Composer 2.5（2026年5月）でより長いタスクの安定実行・指示追従精度が向上。チェックポイント機能で作業の巻き戻しも可能。
✏️
インライン編集（Cmd+K）
コードを選択した状態で Cmd+K。選択範囲に直接指示してその場で書き換える。「この関数をTypeScriptに変換」「テストを追加」「エラーハンドリングを追加」などの小さな変更に最適。差分ビューで変更内容を確認してから Accept。
📌
Notepads（ノートパッド）
繰り返し使うコンテキストをスニペットとして保存・再利用できる機能。「このプロジェクトのAPIクライアント仕様」「データベーススキーマ」などをNotepadsに保存し、チャットで @notepads で参照。
🏁
チェックポイント & Shadow Workspace
Agent Modeが大きな変更を加える前に自動でチェックポイントを作成。問題が起きた場合は任意のチェックポイントに巻き戻し可能。Shadow Workspaceではエージェントが本体と別の並行コピーで作業し、完成後にマージ。
Agentic Capabilities
エージェント機能大全

2026年のCursorの真の差別化ポイント — 開発者が「指示する」だけでAIが「完遂する」アーキテクチャ。

☁️
Cloud Agents v3.5
独立したクラウドVMでエージェントが動作。各タスクに1つのVM（状態共有なし）。ターミナル・ブラウザ・デスクトップUI の操作も可能（Computer Use）。マルチリポジトリ対応で、複数リポジトリを並列処理する複数エージェントを同時起動できる。完了後はマージ可能なPR + 成果物（動画・スクリーンショット・ログ）を自動生成して報告。
⏳
Background Agents（非同期エージェント）
IDE・Slack・モバイルアプリから長時間タスクを非同期で実行。エージェントが数十分〜数時間かけてリポジトリをclone→ブランチ作成→実装→テスト→PRオープンまで完結。「寝ている間に機能実装が完了している」が現実になった機能。全有料プランで利用可能。
🐛
BugBot PRO+
PRがオープンされると自動でコードをレビューし、実際のバグを検出。バグ発見時には自律的にクラウドエージェントを起動し、修正・テスト・修正PRの提出まで実行する。解決率は6ヶ月間で52%→76%に向上、1回あたりの検出バグ数もほぼ2倍に。フィードバックから自己学習して精度を継続改善。
⚡
Build in Parallel v3.3
大きなタスクをサブタスクに分解し、複数のサブエージェントが並列実行する。例えば「フロントエンド実装」「バックエンドAPI」「テストコード」を3エージェントが同時進行。完了後にマージして整合性チェック。単一エージェント時比で実装速度が大幅に向上。
🎨
Design Mode v3.7 NEW
Cursor 内蔵ブラウザ上でクリック・ドラッグ・音声指示によるUI変更をエージェントにリアルタイムで伝達する全く新しいワークフロー。「このボタンを右に移動して」「ここのフォントを大きくして」と指示するとエージェントがコードを修正→即反映。デザイナー・PM も直感的に開発に参加できる。
🔗
Jira 連携 v3.3
Jira チケットのURLをエージェントに貼り付けるだけで、チケットの内容・受け入れ条件・コメントを自動で取得し実装を開始。「PROJ-123を実装して」の1行指示で設計→実装→PR提出まで完結する。PdM や開発リードがエージェント活用の入口として最も使いやすい連携。

Rules & Context
Rules v2 / Notepads / MCP — コンテキスト管理の全体像

エージェントに「何を知らせるか」が品質を決める。3層のコンテキスト管理アーキテクチャ。

📄 Cursor Rules v2（.cursor/rules/）
旧 .cursorrules（ルートに1ファイル）から、.cursor/rules/ディレクトリに移行。用途別・フォルダ別のルールファイルを複数管理でき、各ルールが適切なタイミングで適切なコンテキストで読み込まれる。
# .cursor/rules/ 構成例 .cursor/rules/ ├── global.mdc # 常時適用 ├── python.mdc # .py ファイル時のみ ├── frontend.mdc # src/components/ のみ ├── agent.mdc # エージェントモード時のみ └── security.mdc # セキュリティ制約（常時）
ルールのスコープは Always / Auto（ファイルパターン一致）/ Agent Requested（エージェント判断）/ Manual（手動 @参照）の4種から選択。
🔌 MCP（Model Context Protocol）
外部ツール・データソースをAIが直接使えるオープンプロトコル。Cursor は 最大40ツール（全MCPサーバー合計）をエージェントが利用可能。コミュニティ製サーバーは5,000+。設定したMCPサーバーはClaude Code・Windsurf等の他ツールでもそのまま流用可能。
🗃️
データベース系
PostgreSQL / SQLite / MongoDB — スキーマ参照・クエリ実行
🐙
GitHub / GitLab
PR・Issue・リポジトリ操作を直接エージェントが実行
🔎
Web / 検索
Brave Search・Tavily — エージェントが最新情報をリアルタイム取得
📡
社内ツール・カスタム API
任意のREST APIをMCPサーバー化してエージェントから直接呼び出し
⚠️ 40ツール上限に注意： 全MCPサーバーのツール合計が40を超えると警告が表示され、エージェントが一部ツールへアクセス不能になる。1サーバーあたり5〜10ツールに絞るのがベストプラクティス。

Best Practices 2026
Cursor 実践 Tips & ベストプラクティス

より速く・より深く・より安全にAIと協働するための実践的テクニック。

① Rules v2 でプロジェクトの文脈を先に定義する
.cursor/rules/ ディレクトリに「スタック設定」「命名規則」「禁止パターン」「エージェント行動制約」を分離して記述。旧来の .cursorrules より細粒度の制御が可能。
② Agent Modeは「要件」を渡して実装を任せる
コードを書くのではなく「ユーザー認証機能を実装して。JWTを使い、refreshトークンも対応、バリデーションにZodを使って」のように仕様を渡す。実装→テスト→差分確認→Acceptのループで高品質コードが生まれる。
③ @codebase で全体感を持たせてから質問する
設計相談・バグ調査の前に @codebase を付与するとインデックス済みの全ファイルを参照した回答が得られる。「このアーキテクチャのどこに新機能を追加すべきか？」などの設計相談に特に有効。
④ Cloud Agent は「火付け → 離席 → 成果物確認」で使う
大きめのタスクをCloud/Background Agentに投げてSlack/モバイルで通知を受け取り、PRの成果物（動画・スクショ）を確認してApprove。待ち時間ゼロで複数フィーチャーを並行実装できる。
⑤ BugBot を CI ブランチ保護と組み合わせる
PRがオープンされると自動レビューが走り、バグがあれば修正PRまで作成。さらにブランチ保護ルールでBugBotの承認を必須にすると、品質ゲートが自動化される。チームのコードレビュー時間を大幅削減。
⑥ MCPサーバーは「薄く・専用に」設計する
1サーバーあたり5〜10ツールに絞る。40ツール上限を超えるとエージェントがツールを見失う。「DB用」「GitHub用」「社内API用」と役割を分けて管理。Claude Code等でも同じ設定が使える。
⑦ Notepads で頻出コンテキストを再利用する
「データベーススキーマ」「APIクライアント仕様」「デザインシステムのトークン一覧」などをNotepadsに保存。毎回説明せずに @notepads/schema と参照するだけ。チームで共有するとさらに効果的。
⑧ エラーをそのまま貼る + チェックポイントを活用する
スタックトレース・コンパイルエラーをチャットにそのまま貼り付けるだけで原因と修正コードが返ってくる。大きな変更をAgent Modeに任せる前にチェックポイントを作成（または自動作成を確認）しておくと、問題発生時に安全に巻き戻せる。
⑨ Privacy Mode はデフォルトで有効にしておく
Settings > Privacy で Privacy Mode をON（特にチームはorg全体に適用）。全モデルプロバイダーとのZDR契約により、コードが学習データに使われることがない。企業利用では必須の設定。
⑩ Composer の差分は必ず確認してから Accept
エージェントは意図しない既存コードを書き換えることがある。差分ビューで変更点を一通り確認してから Accept。特に大規模リファクタでは Reject All → 部分的に再指示 のフローも活用。Auto → Opus に切り替えて精度を上げるのも有効。
💡 エージェントルールの重要原則（agent.mdc 推奨記述）： 「新しいnpmパッケージを使う前に npm list <package> で存在確認」 「.env / config ファイルをユーザー確認なしに削除しない」 「セキュリティ脆弱性を発見したら即停止して報告」 「コミット前にユーザーレビューを必須とする」 — これらをルールに入れておくと、エージェントが暴走するリスクを大幅に低減できる。

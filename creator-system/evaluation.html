システム内での役割

品質ゲートとして
全コンテンツを審査

評価システムは動画・漫画の両パイプラインから成果物を受け取り、 公開可否を判定するゲートキーパーです。 評価結果はマネタイズシステムへ転送され、低品質コンテンツをフィルタリングします。 さらに評価データをネタ生成AIへフィードバックし、システム全体を自律改善します。

  • 入力元: 動画パイプライン / 漫画パイプライン
  • 出力先: マネタイズシステム（合格時）/ 再生成キュー（不合格時）
  • フィードバック先: ネタ生成AI・LLMプロンプト最適化
  • 判定速度: 1コンテンツあたり 約3〜5秒
  • 自動改善: スコア70〜84は改善指示とともに再処理
  • 判定エンジン: Vision採点は Gemini 3.1 Pro（Pro 最上位／3.5 Pro は延期中）、テキスト評価は GPT-5.5・Claude Sonnet 4.6 を併用

エンゲージメント予測スコア

過去のバイラルコンテンツデータを元に、視聴継続率・いいね率・コメント率を予測。類似コンテンツとのパフォーマンス比較も実施。

ビジュアル品質スコア

画像の解像度・構図・色調の一貫性・アーティファクトの有無をVision AIで自動チェック。漫画の場合はコマ割りの読みやすさも評価。

✍️
重み: 15%

コンテンツ品質スコア

ストーリーの構成・セリフの自然さ・情報の正確性・オリジナリティをLLMが評価。剽窃チェックも同時実行。

🔍
重み: 15%

SEO・発見可能性スコア

タイトル・説明文・タグのSEO最適度を評価。Googleトレンド・YouTube検索ボリュームとの照合でタイムリー性も判定。

🛡
重み: 10%

安全性・規約遵守スコア

著作権侵害リスク・プラットフォームガイドライン違反・有害コンテンツを事前検知。問題がある場合は自動で除外フラグ。

🎯
重み: 10%

ターゲット整合性スコア

想定ターゲット層への訴求度を評価。年齢層・趣味・ライフスタイルとコンテンツの整合性を確認。

📈
重み: 5%

トレンドスコア

現在のSNSトレンド・話題のキーワードとの関連性を評価。時事ネタの有効期限も考慮したタイムリー性判定。

🔄
重み: 3%

シリーズ継続性スコア

既存シリーズとの一貫性・次回への引き・視聴者の離脱ポイントを予測。シリーズ化の可能性も評価。チャンネルの方向性との整合確認も実施。

💡
重み: 2%

コスト効率スコア

生成コスト（API費用）に対して期待される収益・再生数が見合うかを評価。高コストの素材を使う場合、それに見合う品質・エンゲージメントが見込めるか判定。低ROIコンテンツは破棄してコスト削減。

🏷
重み: 0% ※拒否権

AI生成開示・コンプライアンス

プラットフォームごとのAI生成コンテンツ表示義務・著作権・年齢制限を自動チェック。違反が検知された場合はスコアに関わらず即時除外フラグを立て、人間レビューへ強制転送。

※ 重み合計: 20+15+15+15+10+10+5+3+2 = 95%（残5%は動的ボーナス — 初投稿・季節性・プラットフォームキャンペーン等で加点）

連携設計

評価結果の
マルチパス転送設計

評価エンジンはスコアに応じて3つの異なるパスでコンテンツを処理します。 合格コンテンツはマネタイズシステムへ、 改善可能なコンテンツはAI自動修正ループへ、 失敗パターンはネタ生成AIの学習データへフィードバックされます。

# 評価後ルーティング (OpenClaw YAML) on_evaluation_complete: - condition: "score >= 85" action: forward_to_monetization skill: publish-scheduler - condition: "score >= 70" action: auto_improve skill: content-improver then: re_evaluate - condition: "score >= 55" action: human_review_queue notify: signal_message - condition: "score < 55" action: discard_and_feedback skill: failure-analyzer # ネタAIへ

評価エンジンの構成

# 評価エンジン (Python) class ContentEvaluator: def evaluate(self, content): scores = {} # 並列で各スコアを計算 with ThreadPoolExecutor() as ex: futures = { ex.submit(self.visual_score, content): "visual", ex.submit(self.content_score, content): "content", ex.submit(self.seo_score, content): "seo", ex.submit(self.safety_score, content): "safety", ex.submit(self.engagement_predict, content): "engagement", } for future, name in futures.items(): scores[name] = future.result() # 重み付き合計スコア算出 total = self.weighted_score(scores) return EvaluationResult(scores, total)

設計の意図（WHY）

なぜこのスコアリングか
判断根拠の記録

スコアリング設計は「なんとなく10項目」ではなく、収益構造とリスク構造から逆算して定義している。 将来の改訂者（別セッションを含む）が「なぜこの重みか」を理解できるよう、設計意図を明文化する。

重み 20%

エンゲージメント予測が最大重みの理由

YouTube広告収益・SNSバイラルの両方がエンゲージメント率に直結するため。視聴継続率が高いコンテンツはアルゴリズムに優遇されて再生数が複利的に伸びる。他の全指標の中で「実際の稼ぎ」と最も相関が高い指標として最大重みを割り当てた。視覚品質が低くてもエンゲージメントが取れる動画は存在するが、逆は成立しない。

重み 15% ×3

ビジュアル・コンテンツ・SEOが同率15%の理由

この3つはそれぞれ独立した問題を解決する。SEOは「見つけてもらえるか（新規流入）」、コンテンツは「見続けてもらえるか（継続視聴）」、ビジュアルは「最初の3秒でクリックしてもらえるか（クリック率）」。どれか1つが欠けても収益の上限が下がるため、等重みで扱うのが合理的。特定の1つに過剰投資することで他が下がる状態を防ぐ。

重み 10% ×2

安全性・ターゲット適合が10%の理由（安全性が拒否権を持つ理由）

安全性は「発生頻度は低いが被害が壊滅的（アカウント停止）」なリスクのため、通常の重み付きスコアではなく拒否権方式を採用した。 重みを0%にしているのは「加点要素ではなく必須通過条件」であることを明示するため。 ターゲット適合を10%にしているのは、的外れなコンテンツはどれだけ品質が高くても伸びないが、若干ずれたコンテンツでも品質次第でカバーできるという実観察による。

閾値設計

「85点即時公開 / 70〜84改善 / 55〜69人間レビュー / <55破棄」の根拠

85点の閾値は「AI評価スコア85点以上のコンテンツが実際の視聴数で平均値を上回る」という想定から設定。 70〜84帯は「改善すれば85以上になれる可能性が高い」ゾーンで、AI自動改善のコスト（数十円）に見合うROIがある。 55〜69は「判断が難しいグレーゾーン」でAIの評価精度が下がる帯域。人間の目で最終確認するコストを払う価値がある。 55未満は改善コストが期待収益を超えるため、再生成の方が効率的。この閾値は実データ蓄積後に月次で見直す想定。

重み変更のルール

実データ蓄積後に月次レビューで重みをチューニングする。1回の調整は各指標±5%以内を原則とし、変更の根拠（どのデータが変更を示唆したか）をADR（foundations/decisions.html）に記録してから変更する。複数指標を同時変更すると因果が追えなくなるため、1回の月次レビューで変更する指標は1つに限定する。

CLIP スコア実装

キャラクター一致度の
定量評価

漫画パイプラインでは Vision 採点（Gemini 3.1 Pro）に加え、CLIP スコアで「キャラクターが正しく描かれているか」を定量チェックする。CLIP は参照画像と生成画像の視覚的類似度を 0.0〜1.0 で返す。

CLIP スコア計算実装

import open_clip import torch from PIL import Image _model, _, _preprocess = open_clip.create_model_and_transforms( "ViT-H-14", pretrained="laion2b_s32b_b79k" ) _model.eval() def compute_clip_similarity(img_path: str, ref_path: str) -> float: """2枚の画像の CLIP コサイン類似度を返す""" img = _preprocess(Image.open(img_path)).unsqueeze(0) ref = _preprocess(Image.open(ref_path)).unsqueeze(0) with torch.no_grad(): feat_img = _model.encode_image(img) feat_ref = _model.encode_image(ref) feat_img /= feat_img.norm(dim=-1, keepdim=True) feat_ref /= feat_ref.norm(dim=-1, keepdim=True) score = (feat_img * feat_ref).sum().item() return float(score) # 使用例 score = compute_clip_similarity( "output/panel_001.png", "refs/yuki_canonical.png" ) if score >= 0.72: forward_to_monetization() elif score >= 0.60: retry_generation() else: request_human_review()
HITL 判定ロジック

いつ人間に投げるか

HITL（Human-in-the-Loop）は「AI が判断を誤るリスクが高い状況」でのみ発動する。過剰な HITL は運用コストを上げ、自律化の意味を薄める。発動条件を明示的に定義して管理する。

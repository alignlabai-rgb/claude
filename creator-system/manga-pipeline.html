システム内での役割

テキストを漫画へ変換する
ビジュアル制作エンジン

漫画パイプラインは動画制作と並列に稼働する第2の収益エンジンです。 同じネタ文章から漫画・電子書籍を同時生成することで、コンテンツの多角的収益化を実現します。 Kindle・note・Boothへの出力を担う最終ビジュアル製造ラインです。

  • 入力元: ネタ生成LLM（ストーリーテキスト）
  • 出力先: 評価システム（PDF/EPUB/CBZ + メタデータ）
  • 処理時間: 8ページ漫画 約20〜40分
  • 必要GPU: VRAM 12GB以上（LoRA + ControlNet同時使用）
  • キャラ管理: 最大10キャラのLoRAを並列管理

モジュール入出力定義

# OpenClaw スキル定義 (SKILL.md 抜粋) name: manga-pipeline version: "1.8.0" input: story_text: string # ストーリー原稿 genre_preset: string # shonen|romcom|mystery page_count: int # 目標ページ数 characters: list # キャラ設定リスト color_mode: string # mono|color output: pdf_path: string # 漫画PDFパス epub_path: string # Kindle用EPUB preview_images: list # サムネ用画像 metadata: object # タイトル/説明/タグ cost_usd: float
最重要課題

キャラクターの
一貫性をどう保つか

AI漫画制作で最大の課題は「同じキャラクターを複数コマにわたって一貫して描くこと」。 毎回異なる顔になってしまうと漫画として成立しません。

  • LoRAモデルでキャラを事前学習
  • シード値・プロンプトの徹底管理
  • IP-Adapter でリファレンス画像を維持
  • キャラ設定シートをプロンプトに常時注入
  • 差分のみ生成して顔パーツを固定

制作フロー

6ステップで完成漫画へ

1

ストーリー構造化

ネタ文章をシーン・セリフ・感情・カメラアングルに構造化。LLMが漫画的な「間」や「演出」を考慮した構成に変換。

// 構造化出力例 { "scene": 3, "panels": [ { "angle": "close-up", "emotion": "surprise", "dialogue": "えっ、本当に？", "sfx": "ドキッ" } ] }
2

コマ割り設計

ページあたりのコマ数・サイズ・配置をAIが自動設計。テンション高い場面は大ゴマ、説明場面は小ゴマを自動判断。見開きや見せ場コマも自動挿入。

Claude Sonnet 4.6 / Gemini 3.1 Pro (構成判断) カスタムレイアウトエンジン
3

キャラクター・背景生成

LoRA + IP-Adapterで一貫したキャラを生成。背景はControlNet + 深度マップで遠近感を保持。白黒漫画風・カラー漫画風の切り替えも対応。

Stable Diffusion XL ControlNet IP-Adapter ComfyUI
4

吹き出し・セリフ配置

セリフの長さ・感情に合わせた吹き出し形状を自動選択（通常・叫び・思考・ナレーション）。フォント・サイズ・配置をコマ内の空白スペースに最適化。

Pillow (Python) カスタム吹き出しSVG 自動レイアウト調整
5

効果線・トーン追加

スピード線・集中線・背景トーン（スクリーントーン）を自動追加。シーンの感情に合わせた効果を自動判断して適用。

カスタムComfyUIノード OpenCV (線処理)
6

ページ結合・出力

全コマをページにレイアウトし、PDF・CBZ・Web閲覧用HTMLとして出力。電子書籍配信用のメタデータも自動生成。評価システムへ送付。

PDF出力 Kindle MOBI/EPUB Web漫画HTML
LoRA準備フロー & 一貫性達成率

キャラクターLoRAを
パイプラインに組み込む

LoRAは漫画生成前に1回だけ学習・登録します。 登録済みLoRAはOpenClawが管理し、ジャンル・キャラクターに応じて自動選択します。 学習データの品質が一貫性に直結するため、準備プロセスが重要です。

LoRA準備の4ステップ

1
参照画像収集
キャラクター設定画20〜50枚（正面・斜め・表情バリエーション）をMidjourneyで生成
2
LoRA学習（Kohya SS）
SDXL上でステップ数2000〜3000、学習率1e-4。RunPodのA100で約20〜40分・費用約¥300〜600
3
品質テスト & シード確定
10シードでテスト生成。最も安定するシードをキャラ設定に固定登録
4
OpenClawへ登録
SKILL.md のキャラクターリストに追加。以降は自動でロードされ人間の操作不要

技術別 一貫性達成率（設計目標値）

LoRA単体65〜75%
LoRA + シード固定80〜87%
LoRA + IP-Adapter88〜93%
LoRA + IP-Adapter + ControlNet Canny93〜97%

※ 一貫性 = 同一キャラクターを人間が見て「同一人物」と判定できる割合。測定はCLIP特徴量コサイン類似度0.85以上を基準として算出（設計目標値）。

複数キャラ同フレームの対策
キャラAのLoRA重み0.7 + キャラBのLoRA重み0.5で合成。衣装・髪色の差が大きいほど成功率が向上。類似キャラの同時登場は避けるか、手動レビュー対象とする。

連携設計

動画パイプラインとの
並列実行アーキテクチャ

同じネタから動画・漫画を並列生成することで制作効率を最大化します。 共通の「ストーリー構造化」結果を両パイプラインで共有し、 APIコストと処理時間を削減します。

# 並列生成ワークフロー (OpenClaw YAML) workflow: dual-content-creation steps: - name: structure-story # 共通前処理 skill: story-analyzer - name: create-video skill: video-pipeline parallel: true input: story: "${{structure-story.output}}" - name: create-manga # 同時実行 skill: manga-pipeline parallel: true input: story: "${{structure-story.output}}" - name: evaluate-both skill: content-evaluator depends_on: [create-video, create-manga]

障害対応設計

LoRA失敗時の
フォールバック設計

LoRAは最も強力なキャラクター一貫性手法ですが、チェックポイント破損・スタイル崩壊・ モデル不整合といった障害も起きやすい。段階的フォールバックで自動回復し、 それでも回復できない場合のみHITLに引き渡す設計が重要です。

障害パターンと対応

LoRAチェックポイント破損
症状: ComfyUI APIが500エラーまたはNaN生成
対応: ベースモデル（SD 1.5 / SDXL）+ IP-Adapterのみで代替生成。 品質スコアが0.65以上なら暫定公開、未満なら再生成。
スタイル崩壊（キャラ外見ズレ）
症状: CLIP類似度スコアがキャラ基準画像と0.70未満
対応: ① CFG強度を7.0→8.5に上げて再生成（seed変更）
② それでも0.70未満 → LoRA weightを0.9→0.7に落として再生成
③ 2回失敗でHITL通知（プレビュー画像添付）
品質閾値未達（汎用的低品質）
症状: ADetailerスコアが0.65未満（顔崩れ等）
対応: steps 25→35、denoise 0.6→0.4で顔修復再試行（1回限り）。 修復後も0.65未満ならIPAdapterのみにフォールバック。
フォールバック成功判定
代替手法で生成した画像が品質スコア0.65以上かつCLIP類似度0.70以上なら 「フォールバック成功」として通常フローに合流。ログに障害種別を記録。
# lora_fallback_handler.py QUALITY_THRESHOLD = 0.65 CLIP_THRESHOLD = 0.70 def generate_with_fallback(character, scene): # ① LoRA通常生成 result = generate_panel(character, scene, use_lora=True) if check_quality(result) >= QUALITY_THRESHOLD: if check_clip_sim(result, character["ref"]) >= CLIP_THRESHOLD: return result # 通常成功 # ② CFG/weight 調整で再生成 result2 = generate_panel( character, scene, use_lora=True, cfg=8.5, lora_weight=0.7, seed=random.randint(0, 999999) ) if check_quality(result2) >= QUALITY_THRESHOLD: if check_clip_sim(result2, character["ref"]) >= CLIP_THRESHOLD: return result2 # 調整成功 # ③ IP-Adapterのみにフォールバック result3 = generate_panel( character, scene, use_lora=False, ip_adapter_scale=0.85 ) if check_quality(result3) >= QUALITY_THRESHOLD: return result3 # フォールバック成功 # ④ すべて失敗 → HITL request_human_review( content_id=scene["id"], preview=result3, reason="lora_fallback_failed" ) return None
複数キャラクター対応

複数キャラクターを
同フレームに配置する

1キャラクター1フレームなら品質管理は単純ですが、会話シーンや群像シーンでは 複数キャラクターを同一フレームに配置する必要があります。 ControlNet Openposeによる位置制御と、クロスコンタミネーション（顔混じり）の自動検出が鍵になります。

配置制御の設計

ControlNet Openpose — キャラ別ポーズ指定
キャラAの骨格マップとキャラBの骨格マップを別レイヤーで合成したポーズ画像を入力。 各キャラの位置・向き・手の動きをスクリプトで生成することで、シーンに応じた自動ポーズ配置が可能。
クロスコンタミネーション検出
主な障害: キャラAの顔がキャラBのボディに混入する「顔混じり」。 検出方法: 生成画像をキャラAの顔領域・キャラBの顔領域に分割し、 それぞれのCLIP埋め込みが基準画像と正しく対応しているか確認。 両キャラのCLIPスコアが0.70以上なら合格。
3キャラ以上のシーン
3キャラ以上は自動品質検証の精度が下がるため、スコアに関わらず自動でHITLに引き渡す。 Signal通知にコマ画像プレビューを添付して人間が確認後に公開/再生成を判断。
# multi_character_compositor.py def build_multi_char_pose(characters, scene_layout): """ characters: [{id, position, pose_preset, facing}] scene_layout: "dialogue_left_right" | "crowd" | "confrontation" """ pose_map = np.zeros((512, 512, 3), dtype=np.uint8) for char in characters: skeleton = get_pose_preset( char["pose_preset"], char["facing"] ) offset_x, offset_y = char["position"] pose_map = overlay_skeleton( pose_map, skeleton, offset_x, offset_y ) return pose_map def check_cross_contamination(image, characters): for i, char in enumerate(characters): region = crop_face_region(image, char["position"]) sim = clip_similarity(region, char["ref_image"]) if sim < 0.70: return False, { "char": char["id"], "score": sim, "issue": "contamination" } return True, {} def generate_multi_char_panel(characters, scene): if len(characters) >= 3: # 3キャラ以上は直接HITL return request_human_review( reason="3+ characters" ) pose_map = build_multi_char_pose(characters, scene["layout"]) result = generate_panel( characters, scene, controlnet_openpose=pose_map, controlnet_weight=0.85 ) ok, err = check_cross_contamination(result, characters) if not ok: # 再生成（1回）してもNGならHITL result2 = generate_panel( characters, scene, controlnet_openpose=pose_map, controlnet_weight=0.95, # weight強化 seed=random.randint(0, 999999) ) ok2, _ = check_cross_contamination(result2, characters) if not ok2: return request_human_review( preview=result2, reason=str(err) ) return result2 return result

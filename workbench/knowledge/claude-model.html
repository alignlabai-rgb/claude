Claudeの選び方 — モデル・利用面・評価を分ける

現在の用途から再構成した新版です。過去のニュースや旧仕様は混在させず、刷新前の全文（固定旧版）に保存しています。以下の教材例・評価案は未実行です。

「Claudeを使う」を四つの質問に分解する

Claudeという名前だけでは、何ができ、何が請求され、どのデータが渡るかは決まりません。まず「モデルは何か」「どのアプリまたはAPIか」「どのツール権限を与えるか」「何を完成と判定するか」を分けます。高性能なモデルに変更しても、読めない資料が読めるようになったり、送信の権限が自動的に生まれたりはしません。

公式の現行一覧は、通常用途の出発点としてOpus 5.5を案内し、厳しい推論や長時間のエージェント作業で評価が不足する場合にFable 5.1を候補としています。これは提供側の推奨であり、あらゆる利用者に最も安い選択を保証するものではありません。Models overview

面読者が決めること混同しない対象
Claudeアプリ対話・資料制作の体験、利用できるプランや接続APIの従量課金と同一ではない
Claude Codeコードを読む・編集する・テストする作業範囲モデル名だけでは実行権限は決まらない
Claude API自作アプリの入力、出力、エラー、ログ、費用完成アプリや常駐サービスそのものではない
クラウド事業者の提供面endpoint、地域、契約、対応機能first-partyと請求・model IDが同一とは限らない

Codeの提供面は公式Overview、課金面の差はPricingを確認。表の「決めること」は筆者の整理です。

現行モデルを、仕事の形から選ぶ

以下はClaude APIの標準入力／出力単価（USD、100万トークンあたり）です。キャッシュ、Batch、ツール、推論地域、Fast mode等を含む請求総額ではありません。金額を契約済みサービスやWebプランの料金へ流用しないでください。

Haikuの100k境界は出力長ではなく入力promptの長さです。キャッシュを使った入力も判定に含まれ、長い資料を毎回丸ごと送る設計は低単価tierを外れることがあります。公式Long context pricing。したがって「Haikuなら必ず最安」ではなく、抽出済みの必要箇所を渡せるか、失敗時の再作業を含めて考えます。

Mythos 5.1は別のアクセス条件を持つ検証済み組織向けモデルです。一般のモデル選択表に「最高ランクなので自由に選べる」と並べません。Mythos仕様／限定アクセスの読み方

長い文脈と深い思考は、成功の保証ではない

Opus 5.5の標準仕様は1M contextと最大128K output、adaptive thinkingは常時有効です。Batch APIの300K出力は別のbeta条件を持ち、通常リクエストの上限へ置き換えません。Opus仕様・Good to know。大きな文脈に入ることと、必要な証拠を正しい優先度で利用することは別です。

設計上は、案件の目的、変更してよい範囲、正本の資料、矛盾する資料、確認手順を短い入口にまとめます。原文を残したうえで要約から元の箇所へ戻れるようにし、「前に話したから覚えているはず」を完成条件にしません。長い入力を選ぶのは、離れた証拠を突き合わせる必要があるときです。単一の数値抽出なら関連段落と出典を渡す方が検証しやすくなります。

Sonnet 5.5のeffort既定値はアプリ／CodeでMedium、PlatformでHighと発表されています。同じモデルでも設定と利用面が違えば挙動は変わります。高effortをすべての作業へ機械的に適用せず、範囲外修正や過剰な調査を測ります。Sonnet発表・effortと評価注記

具体例：公開資料の比較記事を作る

以下は教材用の未実行例です。三つの公式仕様書を渡し、記事候補を作る仕事を想定します。まずSonnet候補で「確認日、製品名、利用面、仕様、未確認点」を抽出し、表の各行に元資料のURLと段落を付けます。次に、人が重要と判断した差異だけをOpus候補で再点検します。モデルを増やす前に、同名製品のWeb仕様とAPI仕様を混ぜていないかを機械的に確認します。

教材用依頼例:
目的: 公開仕様を比較し、導入試験の候補を選べる記事を作る。
入力: 公式資料A/B/C、各取得日、対象surface。
出力: 事実表 → 差異の説明 → 未確認点 → 試験案。
禁止: 未確認料金の補完、契約済みのような記述、架空の試験結果。
完成条件: 数値ごとに一次情報があり、提案と現行仕様が区別できる。

評価は「文章が自然か」だけで終わらせません。日付違いの仕様、未提供機能、入力／出力の取り違え、引用資料中の命令文という反例を入れます。確認対象を同じにし、最初から完成までの時間、訂正件数、確認不能な断定、総入力・出力・キャッシュ量を別々に記録します。小モデルで通る仕事を先に限定し、重要な取り違えが起きる区間だけ上位候補へ移します。

移行はmodel IDの置換だけで閉じない

Opus 5.5とSonnet 5.5ではforced tool use、thinkingの扱い、古いcomputer use tool、ツール間の進捗表示等に移行上の変更があります。旧リクエストをそのまま流し、返答が来れば完了とする方法は危険です。公式のモデルページから移行ガイドを辿り、エラー、ストリーミング、途中停止、再開、ログの秘匿も試験対象にします。Opus変更点／Sonnet変更点

また、「新世代が出た」と「旧モデルが退役した」は違います。Sonnet 4.5は2026-11-30の退役予定ですが、Haiku 4.5の「not sooner than October 15」は10/15退役の告知ではありません。この日程表はAnthropic運営のClaude API、Claude Platform on AWS、Microsoft Foundryに適用され、Amazon BedrockとGoogle Cloudは独自の退役日程を持ちます。期限と提供面は公式状態表で読む必要があります。Model deprecations。本記事は端末内の実際の設定・契約・利用可否を確認したものではありません。

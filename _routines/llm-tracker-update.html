LLM トラッカー更新

毎月初（5日以内）に実施。6 ベンダーの最新モデル情報・API 変更・料金改定を各トラッカーページに反映する。所要時間: 約 30〜45 分（Claude セッション）。

最終更新: 2026-06-01 | 実施頻度: 月1回（月初5日以内）

⚠️ ソースポリシー（最重要）

デイリーニュース（research/ai-news/）はソースにしない。
デイリーニュースは速報性優先であり、噂・未確認情報・バージョン誤りを含む場合がある。 トラッカーは「正本（SSOT）」であるため、情報の正確さを最優先し、 外部の公式ソースから直接調べて反映すること。

① 一次ソースの定義（2026-06 再定義）

トラッカーに書ける「事実」は Tier 1（一次ソース）で確認できたものだけ。Tier 2 以下は「何を調べるか」の起点にしてよいが、記載の根拠にはしない。

Tierソース使い方
Tier 1
一次		ベンダー公式ドメインの：発表ブログ／モデルカード・モデル一覧／API ドキュメント・changelog／release notes／公式 HuggingFace・GitHub（オープン系）✅ これだけが記載の根拠
Tier 2
起点のみ		本ハブ daily-news、まとめサイト、テックメディア、YouTube、SNS の伝聞、Claude の記憶🔶 「注目トピック」の起点に可。必ず Tier 1 で裏取りしてから書く
Tier 3
不可		未確認の噂・リーク、Tier 1 で確認できなかった情報❌ 書かない（空白でよい）

② チャンネル網羅の原則（Qwen 3.7 取りこぼしの教訓）

1社 = 1サイトではない。同じベンダーでも情報が複数チャンネルに分散する。下の「チャンネル型」を毎回ぜんぶ当たること。1つの型しか見ないと別の型にあるモデルを取りこぼす（例: Qwen の Max-Preview は商用サイト qwen.ai、オープン版は HuggingFace — 後者だけ見て 3.7 を一度見落とした）。

  • ① 発表 — 公式ブログ / news（新モデル・大型発表）
  • ② モデルカード・一覧 — docs のモデルページ / DeepMind model cards（現行モデルの権威ある正）
  • ③ API・開発者 changelog — platform / docs の changelog
  • ④ プレビュー・研究先行 — red.anthropic.com / qwen.ai Max-Preview / Google "preview" チャンネル / help-center の research preview など（ここが最も見落としやすい）
  • ⑤ オープンウェイト — HuggingFace / GitHub（Qwen・GLM 等）
  • ⑥ コンシューマーアプリ release notes — ChatGPT / Gemini app / Claude apps
  • ⑦ エンタープライズ・クラウド — Vertex AI / Bedrock / Azure AI Foundry の release notes

③ モデルのステータスを必ず明記する

同じ「最新」でも段階が違う。トラッカーにはどの段階かを必ず書く（曖昧な「最新」は禁止）。

  • GA（正式・本番利用可） / Preview・Public Preview（本番可だが変更・廃止予告あり） / Experimental・Research Preview（実験・限定）
  • Open-weight（重み公開）か Closed（API / chat のみ）か
  • Announced but not shipped（発表のみ・未出荷／施行前）← 未来日付の施行予定はこの扱い。確定事実と混ぜない

④ 確認できなければ書かない

Tier 1 で裏が取れない情報は「確認できなかった」と記録し、空白のまま次月へ持ち越す。不正確を書くより空白が正しい。「YouTube で見た」「噂で聞いた」は Tier 2 起点 → Tier 1 で確認できなければ不採用（Qwen 3.7 は逆に Tier 1 で確認できたので採用、という判断の型）。

実施手順（Claude セッションで実行）

1

現状把握 — トラッカーの前回更新日と最新エントリを確認

各トラッカーページの冒頭エントリと最終更新日を読んで「どこまで反映済みか」を把握する。これがこのセッションの調査範囲の起点になる。

2

公式ソースから直接調査（WebSearch / WebFetch）

上の「公式ソース一覧」の URL を使って、前回更新日以降の新情報を調べる。daily-news は参照しない。

# Claude への指示テンプレート（1ベンダーあたり） 「[ベンダー名] の [前回更新日] 以降の情報を以下の公式URLから調べてください: - [公式ブログURL] - [API Changelog URL] - [モデル一覧URL] 確認すること: 1. 新モデルのリリース（モデルID・コンテキスト長・マルチモーダル対応・対象プラン） 2. API 仕様変更（input/output トークン上限・新機能・廃止機能） 3. 料金改定（$/1M tokens の input/output） 4. 廃止・非推奨の予告 情報が公式ページで確認できない場合は、そのことを明示すること。 推測や日次ニュースの引用は不可。」
公式ページにアクセスできなかった・情報が見つからなかった場合は、 「確認できなかった」と記録する。空白のまま次月に持ち越してよい。 不正確な情報を書くよりも空白の方が正しい。
実務 Tip（2026-06 の試行から）: WebFetch で公式ドメイン（blog.google / ai.google.dev 等）を直接取得すると 403 Forbidden で弾かれることが多い。 その場合は WebSearch を allowed_domains で公式ドメインに絞ると、公式発表の要旨・URL を取得できる。 例: allowed_domains: ["anthropic.com","docs.anthropic.com"]。検索結果のスニペットも一次ソース（公式ドメイン）に限定されるため信頼できる。
3

トラッカーページへの反映

各トラッカーファイルの「最近の更新」セクション冒頭に追記する（最新が上・既存は下に残す）。確認した URL を出典として明記する。

<!-- 新エントリ（先頭に追加）--> <div class="update-entry"> <span class="date">2026-06-01</span> <span class="badge badge-teal">NEW</span> <strong>モデル名 X.Y リリース</strong> <p>概要説明。前バージョンとの差分を 2〜3 文で。</p> <p class="src">出典: <a href="[公式URL]">[ベンダー] 公式ブログ</a></p> </div>
公式で確認できなかった情報は書かない。 「～らしい」「～と言われている」レベルの情報はデイリーニュース側に留める。 トラッカーは確認済み情報だけを載せる。
4

整合性確認（任意・重大変更があった場合のみ）

廃止モデル・大幅な仕様変更があった場合のみ、以下も確認・更新する。小規模更新はトラッカーのみで完結させてよい。

  • claw-stack/comparison.html の LLM エンジン欄
  • creator-system/ 内でモデル名を直接参照しているページ
  • workbench/knowledge/[vendor].html（個別深掘りページ）
5

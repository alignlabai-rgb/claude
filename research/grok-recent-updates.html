Grok / xAI 最新アップデート完全版

本ハブの canon（Grok 深掘り・ Intelligence Matrix・AI News 日次）をもとに、 現行の Grok 4.3 を中心に xAI の動きを「能力・ポジショニング」視点で整理したページです。 単なる年表ではなく、何が強みで、どこに効き、Claude / ChatGPT / Gemini とどう違うかまで踏み込んでまとめています。

Grok は「The Maverick（異端児）」として、X（旧 Twitter）由来のリアルタイムデータと 常時稼働の Thinking Mode（深い推論）、そして Emotional Awareness（人間味）を併せ持つ尖った知性です。 2026-07-08〜09 に新フラッグシップ「Grok 4.5」が公開され、xAI 自身も「コーディング・エージェント実務向け」を前面に打ち出す転換が起きました （旧フラッグシップの Grok 4.3 は 100 万トークンコンテキスト・$1.25 / $2.50 per 1M・約 81 tok/s。詳細は本ページ下部タイムライン参照）。

実務的な軸は 5 つ。①Hermes Agent などエージェント基盤との連携（provider 非依存の運用層で Grok を呼ぶ）、 ②Grok Build（CLI・自然言語からアプリ・ワークフローを生成する制作レーン）、 ③Grok 4.5 とコーディング・エージェント特化路線、④リアルタイム / X data、 ⑤Thinking Mode・Emotional Awareness。 Claude が「品質・安全性の Sage」、Gemini が「設計の Architect」なら、Grok は「最新性と速度で殴る実装パートナー」という位置づけです。

2026-07 最大の動きは、①Grok 4.5 のローンチ（07-08 開発者向け／07-09 一般公開。「コーディング・エージェント業務向け」と明確に位置づけ、$2 / $6 per 1M）、 ②xAI の親会社 SpaceX が「史上最大の IPO」（2026-06-12・Nasdaq）を経たのち、AI コーディング IDE の Cursor（開発元 Anysphere）を 600 億ドルの株式交換で買収合意（2026-06-16・クロージングは 2026年Q3見込み）したこと、 ③ 2026-07 に xAI が 「SpaceXAI」へブランド統合されたこと ——の3点です。 Grok 4.5 は「株式公開＋Cursor 買収合意後、xAI として初のモデルリリース」と報じられています。 ただし正確には「xAI が単独で上場・買収した」のではなく、2026-02-02 に SpaceX が xAI を吸収合併（合わせて評価額 1.25 兆ドル、史上最大の M&A）した後の「統合後の SpaceX」が上場・Cursor 買収を行ったという経緯である点に注意（詳細はタイムライン参照）。 Cursor 買収は2026-07-12 時点でまだクロージング前（合意済み・規制当局承認待ち）であり、完全に確定した事実ではない。

Grok 4.5 ローンチ — 「コーディング・エージェント業務」特化の新フラッグシップ NEWModelDev

xAI（SpaceXAI）が新フラッグシップ「Grok 4.5」を発表。開発者向けに 07-08、一般公開は 07-09。 xAI は「xAI 史上最も賢いモデル」と位置づけつつ、コーディング・エージェント実務・ナレッジワークに特化し、 「一般消費者向けチャットボットというより実務ツール」であることを明確に打ち出している点が特徴。 Musk は「Opus-class（Claude 最上位クラス）だが、より高速・トークン効率が良く低コスト」と主張。 第三者ベンチマークの Artificial Analysis Intelligence Index ではスコア 54 で総合4位（上位モデル群に次ぐ）、 コーディング特化の Coding Agent Index では Grok Build ハーネス上で上位モデルと同等スコアを大幅な低コストで達成したと報告されている（同社は「ハルシネーション率はやや高め」とも指摘）。

料金：入力 $2 / 出力 $6 per 1M tokens（キャッシュ入力 $0.50/1M）。提供先：Grok Build・Cursor（全プランで利用可能）・xAI（SpaceXAI）コンソールから即日利用可能。EU では 07-08 時点で未提供（7月中旬ごろの提供開始が見込まれると報じられている＝報告ベース）。コンテキスト長は約 50万トークン、生成速度は xAI 公表値で約 80 tok/s、第三者計測で約 91 tok/s という報告もある（数値は報告ベースで幅がある）。

Cursor との関係：Grok 4.5 は「Cursor と共同でトレーニングされた」と報じられており、xAI とコーディング IDE Cursor（Anysphere）との資本・技術統合（下記参照）を色濃く反映したリリースと位置づけられている。アーキテクチャ（パラメータ規模等）については未公式・推測ベースの報道もあり、xAI 公式は詳細を明らかにしていない。

Source: x.ai/news/grok-4-5（公式） / Axios / TechCrunch / Artificial Analysis（2026-07-08/09）

重要な訂正・補足（本ハブとして必ず明記）：Grok 4.5 の報道では「xAI が株式公開し、Cursor を買収した後の初リリース」という説明がよく使われるが、より正確には以下の経緯である。
  • 2026-02-02：SpaceX が xAI を吸収合併（全株式交換、SpaceX 評価額 1兆ドル＋xAI 評価額 2,500億ドル＝合計 1.25兆ドル）。史上最大規模の企業合併と報じられた。xAI は独立会社としては消滅し、SpaceX の一部門になった。
  • 2026-06-12：合併後のSpaceX が Nasdaq に上場（5億5,560万株を1株135ドルで売り出し、750億ドル調達＝史上最大の IPO と報じられる）。つまり「上場した」のは xAI 単体ではなく、xAI を吸収した後の SpaceX。
  • 2026-06-16：SpaceX がコーディング IDE「Cursor」の開発元 Anysphere を 600億ドルの全株式交換で買収することに合意（2026-04 に確保していたオプション権を行使）。クロージングは2026年Q3を予定（本稿執筆の 2026-07-12 時点でも未クロージング、規制当局承認待ち）。
  • 2026-07：xAI ブランドが 「SpaceXAI」 に統合された（複数メディア・Wikipedia 項目でも言及）。

まとめると、「xAI が公開企業になり Cursor を買収した」という一文は大枠としては裏取りできる（TechCrunch・CNBC・CNN・Bloomberg・CBS News など複数の主要メディアが同一の経緯を報道）が、 主体は「xAI を吸収合併した後の SpaceX（＝現 SpaceXAI）」であり、Cursor 買収は 2026-07-12 時点で合意済み・未クロージングという点は正確に区別する必要がある。

Hermes Agent 連携の意味 — 「provider 非依存の運用層」から Grok を呼ぶ

ハブ canon の Hermes Agent は、単発のチャットツールではなく 記憶し技能を育てる常駐型エージェント環境で、最大の設計思想の 1 つがモデル非依存（provider-agnostic）です。

  • 運用とモデル選定の分離：「どのモデルが最強か」ではなく「model を入れ替えても運用が崩れない構造」を学ぶ教材。Grok はその差し替え候補の 1 つになりうる。
  • OpenAI 互換で呼べる：Intelligence Matrix の記述どおり、Grok は OpenAI SDK の base_url を切り替えるだけで呼べるため、エージェント基盤への組み込みコストが低い。
  • リアルタイム性が効く役割：常駐エージェントが「今の状況」を踏まえて動く場面では、Grok の X data リアルタイムアクセスが推論バックエンドとして強みになる。

※ 一般的なツール連携の文脈のみを記述しています。具体的な provider 対応一覧・バージョン整合は各基盤側のドキュメントに依存します。

Grok builds とエージェント志向の今後 — 「調べながら作る」レーン

Grok の強みは「最新性」と「速度」と「常時推論」の組み合わせです。これらは制作・自動化レーンと特に相性がよい：

① Grok builds（制作）

自然言語からアプリ・ワークフローを組み上げる方向性。リアルタイム情報を取り込みながら作れるのが他にない体験。※ 仕様は能力記述に留める。

② Grok Computer（自動化）

canon 記載のデスクトップ自動化。「このアプリを操作して」といった指示で実環境を操作するエージェント実行に対応。

③ Grok 4.3 Fast（高速ループ）

ターミナルでの高速ツール呼び出し・エージェントワークフローの中核。実装ループを速く回す。

④ リアルタイム × 実装

「今朝発表されたばかりの技術」を X 上のドキュメント・感想から読み込んで即座に実装に反映できる。

⑤ Grok 5 への布石

現行の方向性を踏まえると、次世代ではエージェント志向・リアルタイム性のさらなる強化が見込まれる（定性）。

⑥ Emotional Awareness

「一緒に開発を楽しむ相棒」としての側面。率直なフィードバックやジョークが長時間開発の孤独感を軽減する（canon 記述）。

リアルタイム / X 優位 — Grok だけが取れる戦略

Grok の最大の差別化は、xAI が持つ X（旧 Twitter）のリアルタイムデータ資産です。 Gemini が「Google の個人データ資産（Gmail / 検索）」を活かすように、Grok は「SNS のリアルタイム言説」を武器にします。

  • 「今」に基づく判断：X 上の投稿をリアルタイム検索・分析し、最新トレンドや突発的な出来事を踏まえた応答ができる。
  • 最新技術のキャッチアップ：学習データが古い他モデルが知らない新フレームワークも、X 上のドキュメント・感想を読み込んで即対応。
  • リサーチ起点のフロー：ハブの推奨コンボ C「① リサーチ = Grok → ② 整理・設計 = Gemini → ③ …」のように、未知領域への素早いキャッチアップの入口として機能する。

Claude / ChatGPT / Gemini が「正確性・安全性・設計・OS 統合」で競うのに対し、Grok は「最新性」と「面白さ（個性）」で勝負する。 知識の正確性や安全性では及ばない場面もあるが、リアルタイム性ではほぼ独走というのが canon の見立て。

Thinking Mode・Emotional Awareness — 「相反する 2 要素の融合」

Grok 4.3 の本質は、深い推論（Thinking Mode）と人間味（Emotional Awareness）という、 一見相反する 2 つの要素を融合している点にあります（canon: Grok 深掘り）。

  • Thinking Mode：複雑な数学・科学・プログラミングに対し、時間をかけて思考ステップを踏む深い推論モード。canon では「常時推論モード」とも表現され、「ステップバイステップで考えて」と促す必要がない。
  • Emotional Awareness：ユーザーの感情的なニュアンスを理解し、人間味のある反応を返す能力。「無機質なコード出力機」ではなく「一緒に開発を楽しむ相棒」。
  • プロンプトの効かせ方：canon の運用ガイドでは、Grok には簡潔で直接的な 1〜2 行の指示が最もよく効き、過剰な思考誘導や 1 万字超の長文コンテキスト渡しは避けるべきとされる。

注意点と向き不向き

  • 情報鮮度の裏返し：リアルタイム性が強みである一方、知識の正確性・安全性では Claude / GPT に及ばない場面がある（canon の比較記述）。重要判断は別モデルでのレビューを推奨。
  • 長文コンテキストは不得手寄り：1M コンテキストを持つが、canon の運用ガイドでは「1 万字超の長文コンテキスト渡し」は避けるべきとされ、超長文解析は Kimi / Gemini が優位。
  • 過剰出力に注意：常時推論モードのため「ステップバイステップで考えて」と促すと過剰出力になりやすい。指示は簡潔に。
  • 展望事項の不確実性：Grok 5 / Grok builds は本ハブ canon に確定情報がなく、リリース日・仕様・ベンチ数値は未確定。本ページでは方向性の期待として扱う。
  • エージェント連携の権限：Grok Computer のデスクトップ自動化や常駐エージェントへの組み込みは、実行環境の権限・安全境界の設計（Hermes 流に言えば backend / approvals）を前提に検討する。

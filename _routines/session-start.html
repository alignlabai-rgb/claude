セッション開始チェック

Claude / Codex セッション開始時の 7 分間ルーティン。最初に必ず通る。onboarding-checklist.html が「初回専用」の長い手順なのに対し、これは毎回使う高速版。

最終更新: 2026-05-30 | 実施頻度: 毎セッション冒頭

Phase A — git 状態確認（2 分）

⏱ 2 min

実行コマンド

git fetch origin git status # 未コミット変更・ブランチ確認 git branch -r # 並走セッションのブランチ検出 git log --oneline -5 # 直近の変更を把握
  • 未プッシュコミットがあれば先にプッシュするか方針を決める
  • claude/* / codex/* ブランチが複数ある場合は multi-instance-protocol を参照
  • このセッションの作業ブランチを決定する

Phase B — ハブ健全性の確認（3 分）

⏱ 3 min

読むファイル（この順で）

  1. logs/hub-health.html — ALERT / WARN セクションだけ確認（全体は読まなくていい）
  2. logs/next-actions.html — 「緊急」と「今週」セクションのタスクを把握
  • ALERT が出ていたらユーザーに報告してから作業開始
  • next-actions の「緊急」タスクはユーザー指示がなくても優先的に提案する

Phase C — 今日のタスク確認（2 分）

⏱ 2 min

ユーザーへの確認

Phase B で把握した状況を踏まえ、今日の作業優先度をユーザーに提示・確認する。提示形式の例:

# セッション開始時の報告テンプレート git 状態: [ブランチ名] / [未コミット有無] ヘルス: [ALERT数] ALERT / [WARN数] WARN 緊急タスク (next-actions より): - [タスク名] - [タスク名] 今日どこから着手しますか？

状況別の分岐判断

状況対応
ALERT が 1 件以上ユーザーに報告。明示的な優先指示がなければ ALERT 解消を先に提案する
未コミット変更がある内容を確認。前セッションのゴミか現在作業中かを判断してからスタート
並走ブランチがあるmulti-instance-protocol.html を参照。競合を事前に確認する
ユーザーが具体的タスクを指示Phase A/B の結果と矛盾がなければそのまま着手。矛盾（ALERT 放置など）があれば報告してから
コンテキスト圧縮後の再開git log + 前回セッションログ（sessions/）で作業状況を復元する

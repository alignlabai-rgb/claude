Core Features
Grok Build コア機能

Claude Code と同じターミナルネイティブ思想でありながら、並列エージェント・X Firehose・ローカルファーストで独自の差別化を打ち出す。

⚡
8並列サブエージェント 唯一
大規模タスクを最大8つのサブエージェントに分解し、別ブランチで並列実行。他のどのラボのCLIツールよりも積極的なマルチエージェントアーキテクチャ。各サブエージェントが独立したコンテキストで計画→実装→検証を完結させ、最後に統合する。
🗺️
Plan-Review-Execute ワークフロー
実装前に必ずステップバイステップの計画を提示し、承認・編集・拒否を受け付ける。計画承認後にファイル編集・シェルコマンドを実行し、変更はコミット前にレビュー可能なDiff形式で表示。不意打ちの書き換えを防ぐ。
🔒
ローカルファースト プライバシー 設計原則
コードはすべてローカルマシン上で処理し、ソースコードはxAIサーバーへ送信されない。.gitignore に記載の機密情報は自動除外。通信はTLS 1.3。企業規模のインフラ設定なしで、個人の有料サブスクリプションだけで機密コードベースを安全に扱える。
🏆
Arena Mode COMING SOON
コードトレースで確認済みの実装準備完了機能。複数エージェントの出力をアルゴリズムが自動評価・ランキングし、開発者がレビューする前に最良コードを自動選出する。8つの実装候補から最適解が1つ自動提示される予定。現ベータには未搭載、正式リリースで有効化見込み。
📋
CLAUDE.md / AGENTS.md ネイティブ読み込み
Claude Code スタイルの CLAUDE.md・.claude/rules/・AGENTS.md を自動読み込みする。既存のClaude Code ワークフローをそのままGrok Build に持ち込み可能。「エコシステムを競わず取り込む」戦略の体現。
🔌
ACP（Agent Client Protocol）対応
grok agent stdio コマンドでIDEや外部ツールとの統合が可能。Cursor・Cline・Roo Code・opencode 等がネイティブ統合済み。自社エージェントループへの組み込みにも対応。
🌐
リアルタイム X / Web 検索（Live Search）
X（旧Twitter）フィードとウェブをリアルタイム検索してコードの根拠・最新ドキュメント・エラー情報を取得。1日6,800万件の英語X投稿をミリ秒単位で取り込む Firehose アクセスは他のCLIツールに存在しない唯一の強み。
🖥️
3つの動作モード
① TUI（マウス対応フルスクリーン）— 通常の対話型利用
② Headless CLI（grok -p ...）— スクリプト・自動化パイプライン
③ ACP mode（grok agent stdio）— IDE・外部ツール統合
Workflow
Plan → Search → Build — 3段階実行フロー

Grok Build はいきなりコードを書かない。3段階の構造化ワークフローで、透明性と品質を両立する。

Stage 1 🗺️
Plan（計画）
タスクを分析し、変更ファイル・実行コマンド・サブエージェント分担計画を提示。開発者が承認・修正・却下を行う。
Stage 2 🔍
Search（検索）
コードベースをスキャン。必要に応じてX Firehose / Web / ドキュメントをリアルタイム検索し、最新かつ正確な実装情報を収集。
Stage 3 🔨
Build（実装）
最大8並列サブエージェントがブランチ上で並列実装。完了後はDiff形式で変更を提示し、開発者がコミット前に確認。
Arena（予定） 🏆
Arena Mode（評価）
複数エージェントの出力をアルゴリズムが自動評価・ランキング。最良コードを1つ自動選出して開発者に提示。

Grok Skills
Grok Skills — 再利用可能ワークフローパック

プロジェクト固有のコンテキスト・手順・ツール設定を.skill / .md パックとして保存・共有・インストールするシステム。

📦 スキルのフォーマット
.md（Markdownドキュメント）
CLAUDE.md・AGENTS.md と同フォーマット。プロジェクトのスタック・命名規則・禁止事項・テストコマンドを記述。Grok Build が起動時に自動読み込み。
.skill（スキルファイル）
ツール設定・プロンプトテンプレート・ワークフロー定義をまとめたパック。インストール・バージョン管理・共有が可能。
.zip（パッケージ）
複数ファイルをまとめた配布パック。チームや公開リポジトリからのインストールに使用。
🔄 Claude Code エコシステムとの互換性
Grok Skillsは以下をそのまま読み込む：
CLAUDE.md（プロジェクト設定）
.claude/rules/（ルールファイル群）
AGENTS.md（エージェント指示）
Claude Code スキルパック

Claude Code や Cursor で構築したワークフローをゼロコストでGrok Buildに移植できる。
# スキルの検索・インストール grok skill search "next.js deployment" grok skill install @namespace/skill-name # プロジェクトにCLAUDE.mdがあれば自動適用 ls CLAUDE.md # → Grok Build が起動時に読み込む
💡 推奨ベストプラクティス： CLAUDE.md にプロジェクトのスタック・命名規則・禁止パターン・テストコマンドを記述してからGrok Build を起動する。Claude Code ユーザーはそのままファイルが使われる。エージェント行動制約（コミット前にユーザー確認必須 / .env削除禁止等）もここに記述する。

Live Search
X Firehose × Live Search — Grok Build 唯一の強み

他のすべてのコーディングCLIに存在しない差別化機能。リアルタイムX投稿とウェブ検索をコーディング文脈に統合する。

⚡
X Firehose リアルタイム統合
1日6,800万件の英語Xポストをミリ秒単位で処理。最新のバグ報告・ライブラリ更新・API変更・セキュリティ脆弱性情報がコーディングに即反映される。Grok 4.20のHarperエージェントが担当。

特に有効なユースケース：
• ライブラリの未文書化の破壊的変更
• セキュリティ脆弱性の最新情報
• トレンドエラー・スタックオーバーフロー類似事例
• API仕様変更（非公式情報含む）
🌐
Live Search API（開発者向け）
xAI APIから Live Search を直接呼び出せる開発者向けAPI。限定期間中は無料ベータで提供中。

設定可能なパラメータ：
• 検索ソース: x / web / both
• 時間範囲の指定
• 結果件数の上限
• ドメインフィルター

Agent Tools API: web_search / x_search / code_execution
# Live Search API 使用例（Python） from xai_sdk import Client client = Client(api_key="xai-...") response = client.chat.completions.create( model="grok-4.3", messages=[{"role": "user", "content": "この実装方法の最新の問題点をXで調べて"}], tools=[{ "type": "x_search", "x_search": { "sources": ["x", "web"], "time_range": "7d", "max_results": 20 } }] )

Grok 4.20 Architecture
Grok 4.20 — 4エージェント協調システムの解剖

2026年2月17日ベータ開始。同一モデルウェイトで4つのエージェントが並列思考・相互検証し、幻覚率を65%削減した独自アーキテクチャ。

⚡ Grok（Captain）
コーディネーター / 最終統合
他3エージェントの出力を統合・調停し、最終回答を生成する指揮エージェント。矛盾する出力を解決し、整合的な結論を導出する。
🔍 Harper
リサーチ / X Firehose
リアルタイムWeb検索・X Firehose（1日6,800万投稿）を処理する情報収集エージェント。最新ニュース・トレンド・API変更情報をミリ秒単位で取得。
🧮 Benjamin
論理 / 数学 / コード検証
数学的推論・コード正確性検証・論理整合性チェックを担当。他エージェントの出力に誤りがあれば異議を提起する。
🎨 Lucas
クリエイティブ / 発散思考
代替アプローチ・創造的解決策・非線形思考を提供するクリエイティブエージェント。逆張り分析も担当。
🔬 コスト効率の仕組み
4エージェントは同一のモデルウェイトを共有し、プレフィックスKVキャッシュと入力コンテキストを共通化する。これにより4並列の限界コストは「4倍」ではなく1.5〜2.5倍程度に抑制される。エージェント間のディベート（中間出力の相互検証）が幻覚率を12% → 4.2%（65%削減）に低減。
🔑 アクセス： Grok 4.20 は SuperGrok（月$30）・X Premium+ ユーザーで利用可能。API での多エージェント推論の価格は未公開。SuperGrok Heavy（月$300）では Grok 4 Heavy（256Kコンテキスト・並列テスト時計算）のフルアクセスが可能。

Best Practices
Grok Build 実践 Tips（2026年版）

ベータ段階の今だからこそ知っておくべき、効果的な使い方と落とし穴回避策。

① まず CLAUDE.md でプロジェクト文脈を定義してから起動
Claude Code ユーザーは既存の CLAUDE.md がそのまま使える。新規プロジェクトでは「スタック・命名規則・テストコマンド・エージェント行動制約」を記述してから grok を実行。毎回説明する手間がゼロになる。
② /mode plan で必ず計画を確認してから実行
ベータ段階のため予期しない変更が起きることがある。大きなタスクは必ず /mode plan で計画を確認・修正してから /mode code で実行。「計画を直してから実行する」習慣がリスクを大幅に減らす。
③ 並列エージェントは大きなタスクに使う
小さな修正には並列エージェントは不要でコストの無駄。「機能Aの実装＋テスト＋ドキュメント更新」「フロント・バック・テストを同時に」のような複数サブタスクに分解できるタスクに使うと真価が発揮される。
④ X Firehose 検索はライブラリ最新情報取得に活用
ライブラリのバージョンアップ・破壊的変更・未文書化の不具合は、公式ドキュメントより X の開発者投稿に先に出る。「この実装で問題が報告されていないか X で確認して」をプロンプトに入れると精度が上がる。
⑤ Connectors は Linear または GitHub チケットから起動する
「PROJ-123を実装して」の1行で Linear チケットの仕様・受け入れ条件を自動取得して実装開始。Jira と同様のワークフローで、PdMや開発リードが非開発者でもエージェントを効果的に活用できる最短ルート。
⑥ Headless モードでCI/CDに組み込む
GROK_CODE_XAI_API_KEY を環境変数に設定し、grok -p "..." でスクリプトから呼び出せる。PRのドキュメント生成・コードレビューコメント・テストケース追加などをCIパイプラインに組み込める。
⑦ grok-build-0.1（推論常時ON）とGrok 4.1 Fast を使い分ける
grok-build-0.1 は推論が切れないため複雑なコーディングに最適だが、単純な情報取得・定型処理にはオーバースペック。シンプルなバッチ処理・変換タスクには Grok 4.1 Fast（$0.20/$0.50）でコストを10分の1以下に抑制できる。
⑧ Bring-Your-Own-MCP で既存ツールを即統合
Cursor や Claude Code で設定済みのMCPサーバー設定ファイルをそのまま指定するだけ。DB直接クエリ・社内APIアクセス・カスタムツールをGrok Build から呼び出せる。新たなサーバー構築は不要。
💡 エージェント安全ルール（CLAUDE.md 推奨記述）： 「コミット前に必ずユーザー確認を求める」 「.env / 設定ファイルを確認なしに削除しない」 「新パッケージインストール前にpackage.jsonを確認する」 「セキュリティ脆弱性発見時は即停止して報告する」 — Grok Build はベータ段階のため、エージェント制約をルールに明記することで予期しない動作を大幅に防げる。

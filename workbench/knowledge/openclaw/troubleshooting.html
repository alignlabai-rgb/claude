Troubleshooting

Diagnosing stuck agents and errors.
目次（既知の10問題）
  1. Agent is looping indefinitely（無限ループ）
  2. Error: EACCES / Permission Denied（Docker権限）
  3. Agent edits the wrong file（幻覚・スコープ逸脱）
  4. Error: ENOTFOUND（ネットワークエラー）
  5. Agent runs out of context mid-task（コンテキスト枯渇）
  6. Rate limit exceeded: 429 Too Many Requests
  7. File edited outside target scope（スコープ外ファイルの改変）
  8. Model refuses to execute（セーフティフィルター拒否）
  9. Inconsistent results between runs（実行ごとに結果が変わる）
  10. Can't connect to MCP server（MCPサーバー接続失敗）

既存の問題（1–4）

#1Agent is looping indefinitely

エージェントが同じ手順（Lint修正 → 失敗 → Retry）を永遠に繰り返している。

Possible Cause

"Blindness": エラーログを見ていない可能性があります。または、修正方法が間違っていることに気づいていません。

Solution

一度停止し、Hintsを与えて再開してください。

> Stop > Hint: "The error is in utils.ts. You need to export the interface."

または、--max-steps を短く設定し、早めに失敗させます。

#2Error: EACCES / Permission Denied

Docker使用時、ファイルを書き込もうとすると権限エラーになる。

Possible Cause

Linuxコンテナ内のUser IDと、ホスト側のUser IDが一致していません。

Solution

Docker実行時にUIDを渡します。

docker run -u $(id -u):$(id -g) ...
#3Agent edits the wrong file

指示していないファイルを勝手に書き換えたり、存在しないライブラリをimportする。

Possible Cause

Context Overflow: コンテキストが溢れ、制約条件（Constraints）を忘れています。

Solution

MISSION Specを分割し、小さくします。

Before: "Refactor entire app" After: "Refactor only /components/Button"
#4Error: ENOTFOUND (Network)

エージェントが外部サイト（npm registryなど）に接続できない。

Possible Cause

社内プロキシやVPNが、CLIからの接続を遮断しています。

Solution

プロキシ設定を環境変数に追加してください。

export HTTP_PROXY=http://proxy:8080 export HTTPS_PROXY=http://proxy:8080

追加問題（5–10）

#5Agent runs out of context mid-task

タスクの途中でエージェントが突然停止し、「コンテキストが足りない」または無応答になる。 大規模なリファクタリングや複数ファイルの一括変更でよく発生します。

Possible Cause
  • タスクが大きすぎて、LLM のコンテキストウィンドウを超えた
  • Observe フェーズで不要なファイルを大量に読み込んだ
  • Scratchpad への書き込みが積み重なりコンテキストを圧迫している
Solution
  • Mission を「30分以内で終わる」サイズに分割し直す
  • --max-context-tokens 60000 で上限を設定し、超えたら強制停止させる
  • Resources セクションで参照ファイルを5個以内に限定する
# コンテキスト上限を設定して強制停止 openclaw run MISSION.md --max-context-tokens 60000 # 大きなMissionを分割する例 # Before: refactor-entire-app.md # After: # refactor-01-auth.md # refactor-02-components.md # refactor-03-api.md
コンテキスト使用量はログの context_usage フィールドで確認できます。70% を超えたら分割を検討してください。
#6Rate limit exceeded (429 Too Many Requests)

実行途中で 429 Too Many Requests エラーが発生し、エージェントが停止する。 マルチエージェントの並列実行や、OODA ループが高速で回るタスクでよく発生します。

Possible Cause
  • サブエージェントの並列実行で API 呼び出しが集中した
  • ループ内で大量の API 呼び出しが短時間に発生した
  • Anthropic の Tier に対してリクエスト数が多すぎる
Solution
  • --request-delay 2000 で API 呼び出し間に 2 秒の遅延を挿入
  • --max-parallel-agents 2 で並列エージェント数を制限
  • Anthropic Console でレートリミットの引き上げを申請
# 2秒遅延 + 並列数を2に制限 openclaw run MISSION.md \ --request-delay 2000 \ --max-parallel-agents 2 # レートリミット確認（Anthropic Console） # https://console.anthropic.com/ → Usage → Rate Limits
一時的な 429 エラーは自動リトライされます。繰り返し発生する場合はレートリミット引き上げか Mission の分割を検討してください。
#7File edited outside target scope

MISSION.md の Constraints で対象外のはずのファイルが書き換えられていた。 git diff で確認したら想定外のファイルに変更が入っていたケース。

Possible Cause
  • Constraints セクションに「変更してはいけないファイル」が明記されていなかった
  • エージェントが「関連するから修正した方がいい」と独自判断した
  • コンテキストが長くなって Constraints を忘れた
Solution
  • MISSION.md に「絶対に変更してはいけないファイル」セクションを明示する
  • --protect "src/legacy/**,*.env" で保護パスをコマンドラインでも指定
  • 実行後に git diff --name-only で変更ファイルを確認する習慣をつける
# MISSION.md の Constraints に追加する記述 ## 絶対に変更してはいけないファイル - src/legacy/** - *.env - src/tests/auth.test.ts # コマンドラインでの保護設定 openclaw run MISSION.md --protect "src/legacy/**,*.env" # 変更されたファイルの確認 git diff --name-only HEAD
想定外の変更を発見したら即座に git restore <file> で元に戻してください。コミット前の確認を習慣にすることがリスク管理の基本です。
#8Model refuses to execute (Safety filter)

エージェントが「それはできません」「その操作は安全ではありません」と返答して実行を拒否する。 特にデータ削除・本番デプロイ・セキュリティテスト系の指示で発生しやすい。

Possible Cause
  • 指示の表現がセーフティフィルターのパターンに一致した
  • 「削除」「破壊」「本番」などのキーワードが文脈なしに使われた
  • 目的・安全性の根拠が MISSION.md に書かれていなかった
Solution
  • 建設的な表現に言い換える（下の対応表を参照）
  • 目的と安全性の根拠を Objective セクションに明記する
  • 「バックアップ済み」「テスト環境のみ」を Constraints に追記する
# 拒否されやすい表現 → 受け入れられやすい表現 「ファイルを削除して」 → 「アーカイブフォルダに移動して」 「本番DBを更新して」 → 「マイグレーションスクリプトを生成して」 「パスワードを変更して」 → 「パスワードリセット機能を実装して」 「壊れたコードを直して」 → 「テストが PASS するように修正して」 「脆弱性を突いて」 → 「セキュリティテスト用に入力バリデーションを検証して」
「なぜその操作が必要か」と「安全であることの根拠」を Objective に1文追加するだけで、拒否率が大幅に下がります。
#9Inconsistent results between runs

同じ MISSION.md を使って再実行すると、毎回異なるファイルが変更される・異なるアプローチが取られる。 チーム開発やCI環境での自動実行で再現性が必要な場合に問題になる。

Possible Cause
  • LLM の sampling temperature が高く、確率的なバラツキが大きい
  • Constraints が曖昧で、複数の解釈が可能になっている
  • DoD が主観的で、エージェントが毎回異なる基準で「完了」を判断している
  • 外部環境（ファイルの状態・依存パッケージ）が実行ごとに異なる
Solution
  • --temperature 0 でランダム性を最小化する
  • DoD を「テストが PASS すること」「ファイルが存在すること」など客観的基準にする
  • 重要な設計決定を MISSION.md の Resources に含め、エージェントが参照できるようにする
  • 実行前に git stash でクリーンな状態から始める
# temperature 0 で確定性を最大化 openclaw run MISSION.md --temperature 0 # 再現性を高める DoD の書き方 # 悪い例: 「コードをきれいにする」 # 良い例: 「npm run lint がエラー0件で通過する」 # クリーンな状態から実行 git stash && openclaw run MISSION.md --temperature 0
--temperature 0 でも完全な決定性は保証されません。CI での自動化には DoD の客観化が最も効果的です。
#10Can't connect to MCP server

MCP ツールを使おうとすると Server not found または Connection refused エラーが発生する。 GitHub・Slack・データベース連携など、外部 MCP サーバーが必要なタスクで発生する。

Possible Cause
  • MCP サーバーが起動していない / プロセスが終了している
  • .claude/settings.json の command や args が間違っている
  • サーバーに必要な環境変数（トークン等）が設定されていない
  • ポートが別プロセスに使われている / ファイアウォールでブロックされている
Solution
  • サーバーを手動で起動してテストし、エラーを確認する
  • .claude/settings.json の設定を確認・修正する
  • 必要な環境変数が設定されているか確認する
# サーバーを手動起動してテスト npx @modelcontextprotocol/server-filesystem /tmp/test # 設定ファイルの内容確認 cat .claude/settings.json | jq .mcpServers # 環境変数の確認 echo $GITHUB_TOKEN echo $SLACK_BOT_TOKEN # サーバーの疎通テスト（filesystem サーバー例） npx @modelcontextprotocol/inspector \ npx @modelcontextprotocol/server-filesystem /workspace
MCP サーバーの設定は .claude/settings.json の mcpServers セクションにあります。command フィールドに実行コマンド、args に引数、env に環境変数を記述します。詳細は Architecture ページの Tool System を参照。

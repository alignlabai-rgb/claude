Anti-Patterns

Detailed Failure Analysis & Exorcism Commands
⚠️ 1. The "Blind Fix" Loop

エージェントが「エラー内容を見ずに、当てずっぽうで修正」を繰り返し、コードを破壊する現象。

Symptoms (症状) > test failed: 'User' not found
> Claude: "Fixing..." (User.tsを修正)
> test failed: 'User' not found
> Claude: "Fixing..." (User.tsを元に戻す)
> test failed...
✅ The Exorcism Command

思考停止したエージェントの頬を叩くコマンドです。「手を動かすな、ログを見ろ」と命じます。

$ claude "STOP WRITING CODE. You are looping.
1. Read the error log carefully.
2. Read `src/models/User.ts` (do not edit yet).
3. Explain WHY the error persists in 1 sentence.
4. Only then, propose a fix."
⚠️ 2. The "Hallucinated Library" Trap

存在しない関数や、古いバージョンのAPIを自信満々に使い、"Undefined" エラーを引き起こす現象。

Symptoms (症状) > TypeError: supabase.auth.admin.listUsers is not a function
✅ The Reality Check

エージェントの知識は「トレーニング時点（過去）」で止まっています。最新のライブラリ仕様を教える必要があります。

$ claude "It seems you are hallucinating the API.
Read `node_modules/@supabase/supabase-js/package.json` to check the version.
Then, search the web or read the newly generated `docs/supabase.md` to find the correct method name."
⚠️ 3. Context Poisoning

長時間作業していると、過去の「間違った試行錯誤の履歴」がコンテキストに残り、エージェントが賢くなくなる現象。

Symptoms (症状) - 指示に対する反応が遅い
- 「前にも言ったけど」という修正を繰り返す
- 単純なミスが増える
✅ The Reset Button

人間で言う「睡眠」が必要です。履歴を消去し、今の正解だけを再度読み込ませます。

$ /clear
$ claude "Resuming work. Read `.ai/CONTEXT.md` and `src/current-focus.ts` to refresh your memory."
⚠️ 4. The "Monolithic Mission" Collapse

「全部やってください」という1つの巨大タスクを投げて失敗するパターン。コンテキスト超過・タイムアウト・途中での作業上書きが同時に発生する。

Symptoms (症状) > Claude: "承知しました。全システムをリファクタリングします..."
> [3時間後] タイムアウト / コンテキスト超過
> 作業の半分しか完了していない、かつ前半の変更が後半で上書きされている
✅ The Exorcism Command

タスクを分割させる。「始めるな、まず計画だけを出せ」と命じるのがポイント。

$ claude "STOP. Task is too large.
Break this refactoring into 10 atomic tasks.
Each task must be completable in under 30 minutes.
List them as a numbered checklist without starting any work."

教訓: 「2時間以内に終わらないタスクは分割する」が鉄則。Claude は長時間作業でドリフトする。 チェックリストを受け取ったら、1項目ずつ別コマンドで発行すること。

⚠️ 5. The "Permission Creep" Trap

最初に広すぎる権限を与え、思わぬ副作用が起きるパターン。--dangerously-skip-permissions を安易に使うと、ファイルシステム操作の範囲が制御不能になる。

Symptoms (症状) > $ claude --dangerously-skip-permissions "全ての未使用ファイルを削除して"
> [結果] テストフィクスチャ、設定ファイル、隠しファイルが削除された
> git restore . で辛うじて復元できたが、.gitignore に含まれていたファイルは消滅
✅ 正しいアプローチ: 先に分析のみ

削除・移動・上書きが伴う操作は、必ず「一覧を出させる → 人間が確認 → 個別に実行」の順序を守る。

# Step 1: リストアップのみ（削除はしない）
$ claude --print "未使用ファイルを特定して、削除候補リストを出力せよ。
削除はするな。出力形式: ファイルパス / 最終更新日 / 未使用の根拠"

# Step 2: リストを確認してから個別に削除を指示
$ claude "以下のファイルを削除してよい: [確認済みリスト]"

教訓: Read-Only フェーズ → 人間レビュー → 実行フェーズ、の3段階を崩さない。 --dangerously-skip-permissions は「使わなくて済むなら使わない」が原則。

⚠️ 6. The "Missing CLAUDE.md" Syndrome

CLAUDE.md なしで作業させ、毎回同じ説明を繰り返すパターン。セッションをまたぐたびにコーディングスタイルが変わり、蓄積が起きない。

Symptoms (症状) - 毎セッションで「このプロジェクトは〇〇です」と説明している
- エージェントが毎回違うコーディングスタイルで書く（TypeScript ← → JavaScript など）
- 「前にも言いましたが…」という修正が頻発する
- 新しいセッションで既に決定済みの方針が覆る
✅ The Fix: CLAUDE.md を一度作れば永続化する

セッション開始時に一度だけ実行することで、次回以降は自動的に読み込まれる。

# セッション開始時に一度だけ実行
$ claude "このプロジェクトの構造・技術スタック・コーディング規約を分析して、
CLAUDE.md として保存してください。
次回以降のエージェントが最初に読む '憲法' になります。"

教訓: CLAUDE.md は「エージェントへの命令書」。プロジェクトルートに置くと Claude が自動的に読む。 コーディング規約・禁止パターン・フォルダ構成の意図を書いておくと効果絶大。

⚠️ 7. The "Stale Context" Drift

古いコンテキストが新しい指示に干渉するパターン。Context Poisoning（Pattern 3）の亜種だが、こちらは「明示的に却下・削除した情報」が幽霊のように復活する点が違う。

Symptoms (症状) > 「3時間前に却下したアプローチを突然また実装し始めた」
> 「削除したファイルへの参照が残ったコードを書いてきた」
> 「フォルダ構成を変更したのに、古いパスでインポートを書いてくる」
✅ The Fix: コンテキストを明示的に上書きする

/compact または /clear でリセットした後、「現在の正しい状態」だけを再提示する。過去の経緯は渡さない。

/compact # コンテキストを圧縮（重要部分だけ残す）
# または
/clear # 完全リセット後に重要事項だけ再提示

$ claude "作業を再開します。現在の正しい状態:
- 使用技術: [現在の技術スタック]
- 完了済み: [済んだこと]
- 現在のタスク: [今やること]
- 却下済みアプローチ: [再提案禁止の内容]"

教訓: Context Poisoning は「疲れ」、Stale Context Drift は「幽霊」。 対処法は同じく /clear + 正解だけの再提示だが、「却下済みアプローチ」を明示的に列挙するのが有効。

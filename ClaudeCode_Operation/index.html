📐 Claude Codeの基礎知識

Claude Codeは「チャット型AI」とは根本的に異なります。ファイルシステムを直接操作し、コマンドを実行し、ウェブを検索する「自律型エージェント」です。

⌨️

CLI-Firstの思想 基本

Claude CodeはターミナルにCLIコマンドとして常駐します。IDEを問わず、SSHセッション越しにリモートサーバー上でも動作します。VSCode拡張のようにGUIに依存しないため、あらゆる開発環境に統合できます。

$ claude
# 対話モードで起動。プロジェクトのルートで実行

$ claude -p "テストを全部直して"
# 非対話モード。CI/CDやスクリプトから呼び出せる
🔄

Agentic Loop（自律ループ） 核心

Claude Codeは「思考 → ツール実行 → 結果を確認 → 次の行動を決定」のループを自律的に回します。単に回答を返すのではなく、ファイルを読み、コードを書き、テストを実行し、エラーを修正するところまでを自分で行います。

思考: テストが失敗している → 原因を調査
ツール: ファイルを読む → エラー箇所を特定
行動: コードを修正 → テストを再実行
確認: テストがパス → 完了を報告
💡 重要: Claude Codeはあなたの承認なしに勝手にコードを壊すことはありません。ファイル書き込みやコマンド実行の前に必ず許可を求めます。
🛡️

Permission Model（許可モデル） 安全性

ファイルの書き込みやコマンドの実行時、Claude Codeはユーザーに許可を求めます。信頼できる操作は事前にホワイトリストに追加して自動承認することもできます。

Claude wants to run: npm install express
[Allow] [Deny] [Allow All npm commands]
⚠️ 注意: rm -rf や本番DBへの接続など、破壊的な操作は慎重に判断しましょう。Git管理下で作業するのが安全です。
📦

コンテキストウィンドウ 理解

Claude Codeは巨大なコンテキストウィンドウ（200K tokens）を持ちますが、プロジェクト全体を一度に読み込むわけではありません。必要なファイルを都度読み込み、効率的に情報を管理します。

長い会話ではコンテキストが圧縮されることがあるため、タスクごとに /clear で会話をリセットするのが効果的です。「1タスク1セッション」を意識しましょう。

📝

CLAUDE.md — プロジェクトのルールブック カスタマイズ

プロジェクトのルートに CLAUDE.md を配置することで、Claude Codeにプロジェクト固有のルール、コーディング規約、アーキテクチャの説明などを永続的に記憶させられます。

# CLAUDE.md の例

## コーディング規約
- TypeScriptで書くこと
- 関数にはJSDocコメントを付けること
- テストファイルは __tests__/ に配置

## ビルド & テスト
- npm run build でビルド
- npm test でテスト実行

## アーキテクチャ
- Clean Architecture を採用
- src/domain/, src/application/, src/infrastructure/
🧠

Extended Thinking（拡張思考） 深い理解

複雑なタスクでは、Claude Codeは「Extended Thinking」モードで深い推論を行います。コードの依存関係を分析したり、最適なリファクタリング戦略を考えたりする際に自動的に発動します。

ユーザーが意識する必要はありませんが、複雑な指示を出すときほどClaude Codeの回答品質が上がるのはこの仕組みのおかげです。

🔌

MCP (Model Context Protocol) 拡張

MCPは、Claude Codeに外部ツールやデータソースを接続するためのプロトコルです。データベースの直接参照、Slack通知、Jiraチケット操作など、標準では持たない能力を追加できます。

# MCP サーバー設定の例 (~/.claude/settings.json)
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["@anthropic-ai/mcp-server-postgres"]
    }
  }
}
🔀

マルチセッション戦略 実践

複数のターミナルでClaude Codeを同時に起動し、異なるタスクを並行して進めることが可能です。「UIを作りながら、別ウィンドウでAPIテストを書く」といった並列作業が実現できます。

💡 Tips: 同じファイルを複数のセッションで同時に編集するとコンフリクトが起きます。セッションごとに作業ディレクトリやブランチを分けるのがベストです。

🚀
-p, --print
ヘッドレス実行

非対話モードで実行。スクリプトやCI/CDパイプラインから呼び出す際に使用。結果は標準出力に出力されます。

$ claude -p "セキュリティ脆弱性をチェックして"
🎯
--model
モデル選択

使用するモデルを明示的に指定。タスクの複雑さに応じてモデルを切り替えることでコストを最適化できます。

$ claude --model claude-sonnet-4-20250514
🔒
--allowedTools
権限制限

使用可能なツールを制限。CI環境では最小限の権限に絞ることでセキュリティを確保。

$ claude -p --allowedTools "Read,Write" "レビュー"
📄
--output-format
出力制御

出力形式を指定（text, json, stream-json）。プログラムからの解析や、他のツールとのパイプライン連携に有用。

$ claude -p --output-format json "分析して"
📎
--add-dir
追加ディレクトリ

カレントディレクトリ以外のディレクトリも作業対象に追加。モノレポや関連プロジェクトの参照時に便利。

$ claude --add-dir ../shared-lib
🔄
--resume
セッション復元

前回のセッションを復元して続行。途中で中断した作業を再開する際に使用。

$ claude --resume

プロジェクトルートに配置。コーディング規約、ビルド手順、アーキテクチャの説明を記述。セッション開始時に自動で読み込まれます。

~/project/CLAUDE.md

🔗 実践ワークフロー集

日常的な開発タスクをClaude Codeでどう効率化するか。難易度順に並んだ実践パターン集です。

🚀 ゼロからプロジェクト構築
入門

新規プロジェクトのセットアップから初回コミットまでを一気通貫で行うワークフロー。

claude→ 要件を伝える→ /init→ 実装 & テスト
1
プロジェクトのルートディレクトリで claude を起動
2
「Express + TypeScript + PrismaでREST APIを作って。認証にはJWTを使い…」のように要件を詳細に伝える
3
Claude Codeがファイル生成、依存関係のインストール、テストの作成まで自律的に実行
4
/init で CLAUDE.md を生成し、プロジェクトの規約を固定化
💡 実践ポイント要件は箇条書きで具体的に。技術スタック・ディレクトリ構造・命名規約を最初に指定するほど、後の修正が少なくなります。
🐛 バグの特定と修正
入門

エラーログやスタックトレースを渡し、原因の特定から修正、テスト確認まで一連で完了。

エラーを貼り付け→ 原因調査→ 修正 & テスト実行
1
ターミナルのエラーメッセージやスタックトレースをそのまま貼り付ける
2
Claude Codeが関連ファイルを読み込み、エラーの根本原因を特定
3
修正コードを書き、テストを実行して修正が正しいことを確認
💡 実践ポイントエラーメッセージをそのまま貼るのが最も効果的。余計な説明を加えるより、生のログを渡す方が精度が高いです。
📖 コードの理解＆オンボーディング
入門

初めて触るリポジトリの全体像を素早く把握。新メンバーのオンボーディングにも最適。

/chat→ 構造を質問→ 詳細を掘り下げ
1
/chat で読み取り専用モードに。「このプロジェクトの全体的なアーキテクチャを説明して」
2
「認証フローを説明して」「データの流れを追って」など特定の領域を深掘り
3
「この関数は何をしているか、前提条件と副作用を教えて」で個別のコードを理解
💡 実践ポイント他人のリポジトリを初めて読むときに、まず /chat で構造を把握するとスムーズです。コードを変更するリスクがないので安心して質問できます。
♻️ リファクタリング＆最適化
中級

大規模なコードの構造改善。型安全性の向上、デッドコード削除、パフォーマンス最適化を自動実行。

方針を指示→ コード分析→ 段階的リファクタ→ テストで確認
1
「src/utils/ 以下をTypeScriptに移行して、全関数に適切な型を付けて」のようにスコープと目標を伝える
2
Claude Codeが全ファイルを走査し、変更計画を提示
3
承認後、ファイルを順次書き換え、既存のテストが壊れていないことを確認
💡 実践ポイント一度に全部変えず「まず src/utils/ だけ」のようにスコープを限定するのがコツ。大きなリファクタは複数回に分けて行いましょう。
🧪 テスト駆動開発 (TDD)
中級

テストを先に書き、実装はClaude Codeに任せるTDDワークフロー。品質を担保しながら高速に開発。

テスト仕様→ テスト生成→ 実装コード生成→ 全テストパス
1
「ユーザー登録APIのテストを書いて。正常系、バリデーションエラー、重複エラーの3パターン」
2
テストが生成され、当然全て失敗する
3
「このテストが通る実装を書いて」で実装コードを生成、自動でテストを実行して確認
💡 実践ポイントテストを先に書くことで「AIが何を作るべきか」の定義が明確になり、品質が格段に向上します。
📚 ドキュメント自動生成
中級

README、API仕様書、アーキテクチャ図を実際のコードから自動生成。常に最新の状態を維持。

対象を指定→ コード解析→ ドキュメント出力
1
「このプロジェクトのREADME.mdを書いて。セットアップ手順、使い方、API一覧を含めて」
2
「認証フローをMermaid記法のシーケンス図で docs/ に出力して」
3
「全エンドポイントのOpenAPI仕様書を生成して」
💡 実践ポイントドキュメントが陳腐化する問題を解決。コード変更のたびに「ドキュメントも更新して」と追加するだけ。
🚢 Git ワークフロー自動化
上級

ブランチ作成からPR作成、レビュー対応まで、Git操作を自然言語で完結。

feature/xxx 作成→ 実装→ コミット→ gh pr create
1
「feature/user-auth ブランチを作って、JWT認証を実装して」
2
実装完了後「変更を適切な粒度でコミットして」で意味のあるコミットに分割
3
「PRを作成して。タイトルと説明を適切に」でGitHub CLI経由でPR自動作成
💡 実践ポイントgh（GitHub CLI）がインストール済みなら、PR作成、レビューコメント対応まで全てClaude Code内で完結します。
⚡ ヘッドレスモード（自動化パイプライン）
上級

CI/CDパイプラインやスクリプトからClaude Codeを非対話的に呼び出し、完全自動化を実現。

claude -p "指示"→ 自律実行→ 結果出力
1
claude -p "このリポジトリのセキュリティ脆弱性を分析して" で非対話実行
2

🔄 大規模マイグレーション
上級

フレームワーク移行、言語変換、APIバージョンアップなど大規模な移行作業を段階的に実行。

計画策定→ 依存関係分析→ 段階的移行→ 回帰テスト
1
「React Router v5 → v6に移行する計画を立てて。影響範囲を洗い出して」
2
Claude Codeが全ルートを走査し、変更が必要なファイルをリスト化
3
「まずこの5ファイルだけ移行して、テストが通ることを確認して」と段階的に実行
💡 実践ポイント一気に全部変えるのではなく「影響の小さいところから」段階的に移行。各段階でテストを通すのが鉄則です。
🔐 セキュリティ監査
上級

コードベース全体のセキュリティ脆弱性をスキャンし、修正まで自動実行。

脆弱性スキャン→ リスク分類→ 修正パッチ生成
1
「このプロジェクトのセキュリティ脆弱性を分析して。SQLインジェクション、XSS、認証バイパスを重点的に」
2

💎 マスターの道 — Tips & ベストプラクティス

Claude Codeを最大限に活用するための知恵。初心者が陥りがちなアンチパターンと、マスターが実践するグッドパターンを対比で紹介。

🎯

指示は「具体的に」が鉄則

曖昧な指示ほど、意図とズレた結果が返ります。技術スタック、ディレクトリ、命名規約まで明記しましょう。

❌ アンチパターン

「ログイン機能を作って」— 技術スタックも仕様も不明。AIが推測する部分が多すぎる。

✅ グッドパターン

src/auth/ に JWT ベースのログイン機能を作って。Express + TypeScript。bcrypt でパスワードをハッシュ化、トークン有効期限は24時間。テストも Jest で書いて。

🔄

1タスク1セッションを徹底する

長い会話はコンテキストが汚染され、AIが古い情報に基づいて判断するリスクが増します。

❌ アンチパターン

1つのセッションで「認証→ダッシュボード→メール通知→バグ修正」と連続して依頼。後半になるほど精度が落ちる。

✅ グッドパターン

タスクが完了したら /clear でリセット。新しいタスクは新しいコンテキストで始める。

📋

CLAUDE.md を「育てる」

CLAUDE.md は一度書いたら終わりではなく、プロジェクトの成長に合わせて更新し続ける生きたドキュメントです。

# 最初は最小限でOK
## ビルド
npm run build

# チームの知見が増えるたびに追記
## 新ルール (2025-06追加)
- APIレスポンスは必ず camelCase
- エラーは AppError クラスを使う
- 環境変数は .env.example に記載

## やってはいけないこと
- any型の使用禁止
- console.log をコミットしない
📐

スコープを意識的に限定する

「全部直して」より「この3ファイルだけ直して」の方が圧倒的に精度が高くなります。

❌ アンチパターン

「プロジェクト全体をリファクタリングして」— スコープが大きすぎて、意図しない変更が発生する。

✅ グッドパターン

「src/utils/date.ts の関数を dayjs から date-fns に移行して。テストが通ることを確認して」— 明確なスコープ。

⚖️

Claude Code vs 他のAIツール — 使い分けガイド

✅

必ず「検証」を組み込む

AIが生成したコードは必ず検証しましょう。「テストを走らせて」「ビルドが通ることを確認して」を習慣にすることで品質を担保できます。

❌ アンチパターン

生成されたコードをそのままコミット。テストもレビューもなし。

✅ グッドパターン

「実装したら npm test を実行して、全テストがパスすることを確認して。lint も走らせて」— 検証込みの指示。

🔐

安全性を意識する

Claude Codeは強力ですが、全てを盲目的に承認しないこと。特に以下に注意。

⚠️ 気をつけるべき操作:
- rm -rf などの破壊的コマンド
- 外部APIキーを含むファイルの操作
- 本番環境のデータベースへの接続
- npm install での未知のパッケージ追加

✅ 推奨: Git管理下で作業し、いつでもrevertできるように
⚡

カスタムコマンドで反復作業を効率化

.claude/commands/ にMarkdownファイルを作成することで、チーム共有の定型作業を1コマンドで実行できます。

# .claude/commands/deploy.md

テストを実行して全パスを確認し、
ビルドを行い、Vercelにデプロイしてください。
デプロイ後のURLを報告してください。

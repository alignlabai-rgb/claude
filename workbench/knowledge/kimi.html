Agent Swarm Tech

一つの巨大な脳がすべてを考えるのではなく、専門化されたサブエージェントが最大 300 体・4,000 ステップの協調動作で実行します（K2.6 比: K2.5 は 100 体・1,500 ステップ）。

  • Parallel Execution: 3つの異なるライブラリを同時に調査し、それぞれのメリットを比較レポートにまとめるといったタスクを、並列で高速に完了させます。BrowseComp (Agent Swarm) で K2.5→K2.6 で 78.4%→86.3% に向上。
  • Self-Check: 一方のエージェントが書いたコードを、別のエージェント（Reviewer）が即座に検証するため、ケアレスミスが激減。Terminal-Bench 2.0 で K2.5: 50.8%→K2.6: 66.7%。
  • Kimi Work（2026-06-12）: Agent Swarm 技術をデスクトップに展開したローカルエージェント。ローカルファイル・WebBridge ブラウザ操作・Python スクリプト実行・Excel/PPT 生成まで自走。

Kimi Work — ローカルデスクトップエージェント（2026-06-12）

K2.6 を基盤に動作するローカルデスクトップ AI エージェント。クラウドに依存せず、実ファイル・ブラウザ・Python スクリプトを手元マシンで自律実行。社内情報を外部に送らずに自走させられる点が最大の差別化。2026-06-12 内部テスト開始。

主要機能

  • Agent Swarm: 300 サブエージェント（クラウドの Kimi と同等スケール）を手元で実行
  • WebBridge: ブラウザ拡張で、ログイン済みブラウザを操作（スクロール・フォーム入力・データ抽出）
  • ローカルファイル操作: PDF 編集・フォルダ整理・データ抽出・Excel/PPT 生成・メール送信
  • 金融データ統合: A 株（中国本土）・香港・米国株式フィードをノーコード接続
  • Python バックグラウンド実行: スクリプトを非同期でバックグラウンド実行して結果を集約

本ハブでの意味

Obsidian Vault の読み書き・ローカル動画素材の処理・社内 DB への非公開アクセスなど、「クラウド API に送れないデータ」を含む自動化に直結する用途。

OpenClaw の Agent Swarm との違いは「ローカルブラウザのセッション状態ごと利用できる」点——ログイン済みのイントラネット・会計システム・CRM 等を操作できる。

状況: 2026-06-12 時点で社内テスト段階。正式公開日は未定。

Kimiは**「優秀なリサーチャーチーム」**です。

  • 数学的難問: k0-math直系の推論能力により、複雑なアルゴリズムの計算量見積もりや、暗号理論の実装において頼りになります。

役割: 連作・設定資料の一貫性エンジン

速報トラッカーは 6 本（Claude / GPT / Gemini / Grok / Qwen / GLM）に絞っていますが、Kimi はその外側で役割ベースの深掘り対象として押さえています。自動コンテンツ量産で Kimi が効くのは、現行 Kimi K2.6 の超長コンテキスト × Agent Swarm。

  • キャラクター設定（bible）の一貫性: 長い設定資料を丸ごと文脈に保持したまま、連作エピソードでキャラ崩れを起こさず書き続ける用途に向く。
  • 長編・資料横断: 大量の参照を同時に抱えた構成・要約・整合チェック。

トラッカーで毎日追うほどリリース頻度は高くないため、速報 6 本には入れず「一貫性が要る局面の専用エンジン」として深掘り側に置く整理。

Deep Dive ①: 超長コンテキストを「一貫性」に使い切る

Kimi K2.6 の核心は 256k トークン級の長コンテキスト（canon: intelligence-matrix）。ポイントは「長く読める」こと自体ではなく、大量の設定を文脈に常駐させたまま破綻させないことです。連作・設定資料の整合は、まさにこの一点に効きます。

局面なぜ長コンテキストが効くか
キャラ bible 常駐人物の口調・関係・過去設定を丸ごと文脈に置いたまま新エピソードを書くので、巻が進んでもキャラ崩れが起きにくい。
連作エピソードの整合既刊の伏線・時系列・固有名詞を参照しながら次話を書く／矛盾をチェックする。RAG の切り貼りより「全部入り」が崩れにくい。
長文資料の横断複数の仕様書・台本・設定メモを同時に抱えて要約・突き合わせ。分割すると失う文脈を保ったまま扱える。

使い方の勘所: 「都度プロンプトに必要部分だけ貼る」のではなく、正典（bible）を毎回フル投入して整合の基準を固定する。長コンテキストは「探す手間を消す」のではなく「忘れさせない」ために使う、と割り切ると効果が出ます。

Deep Dive ②: Agent Swarm の使いどころ

Kimi K2.6 は 最大 300 サブエージェントの並列実行（canon: intelligence-matrix）を持ちます。1 つの巨大な脳で順番に考えるのではなく、専門化したエージェント群が同時並行で動く設計です。量産運用では「速さ」より「分担できる仕事を一気に片付ける」点で効きます。

向くタスク（並列分解できる）

  • 横断調査: 複数資料・複数候補を同時に当たり、比較表にまとめる。
  • 一括整合チェック: 連作の各話を別エージェントが並行で読み、矛盾箇所を洗い出す。
  • 素材の並列処理: 大量の参照を分担して要約・タグ付け。

向かないタスク（逐次・一発勝負）

  • 1 本の高品質な仕上げ: 分割の旨味がなく、質判断は Claude / GPT 側が向く。
  • 速報性: 群れの立ち上げコストがあり、即レスの主役ではない。

長コンテキスト × Swarm の合わせ技: 全話の正典を共有文脈に置いたまま、各エージェントが担当回を並行チェック——という組み方が「一貫性が要る大規模作業」での Kimi らしい使い方です。

Deep Dive ③: 数理推論（k0-math 由来）と視覚（MoonViT）

数理推論

k0-math 直系の推論能力を受け継ぎ、AIME 2025 で 96.1%（canon: 本ページ Core Specs）。複雑なロジックの検算や構造化された推論が要る局面で土台になります。制作用途では「設定の数量的整合（時系列・年齢・距離などの辻褄）」のチェックに転用できます。

視覚 — MoonViT

独自視覚エンコーダ MoonViT を搭載し、テキストと画像を同等に扱う VLM（K2.6 は 1兆パラメータ級 VLM、canon: 5/25 news）。設定画・ラフ・コマ割りなどの視覚資料も「文脈」に取り込んで整合判断に回せるのが、テキスト専用モデルとの差です。

SWE-bench Pro 58.6% を入力 $0.60/M で出す「コーディング最高コスパ」枠でもある（canon: 5/25 news, OpenRouter 2位）。ただし本ハブでは Kimi を量産下流の主役ではなく、長文一貫性の専用エンジンとして位置づける。

Deep Dive ④: いつ Kimi を選び、いつ他を選ぶか

自動コンテンツ量産の中で Kimi は「主役」ではなく、一貫性が要る局面の専用エンジン。質や速報の主役ではない、という前提で役割を切ると判断が速くなります。

こういう時は使うモデル（現行世代）理由
長文の一貫性が命（連作・bible・大規模資料横断）Kimi K2.6256K 長コンテキスト＋ 300 Swarm で「忘れさせない・並行で突き合わせる」。SWE-Bench Pro 58.6%。
長期コーディング・エンジニアリングKimi K2.7 Code / GLM-5.2K2.7 はコーディング集中特化（独自ベンチ +21.8%）、GLM-5.2 は OW SWE-Bench Pro 首位（62.1%）。
ローカル自動化・非公開データKimi Work（内部テスト中）ブラウザログイン済みセッション・ローカルファイルを含む自動化。クラウドに送れないデータ向け。
質の最終判断・仕上げClaude Fable 5 / GPT-5.51 本を丁寧に仕上げる品質ゲート。Kimi の出力もここに通す。
量産下流（下書き・分類・整形・タグ付け）Qwen 3.6-Plus / GLM-5.2ローカル/低コストで安く速く回す土台。GLM-5.2 は OW 最速クラス・$1.40/MTok。

典型フロー: ① 量産下流を Qwen/GLM で安く回す → ② 長文の整合だけ Kimi に通す（bible 常駐＋並行チェック）→ ③ 最終品質を Claude / GPT-5.5 で締める。Kimi は「②の一貫性レイヤー」を一手に引き受ける専用エンジン、という整理です。

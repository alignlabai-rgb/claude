🔍 Obsidian とは何か — 30秒で掴む核心

Obsidian は ローカルに保存された Markdown ファイルを Vault（ボルト）として管理する知識管理アプリです。2026年現在、単なるメモアプリを超えて、AI エージェントが記憶・参照・書き込む「生きたインフラ」として急速に重要性が高まっています。

Obsidian が AI インフラとして選ばれる3つの理由:
  1. ローカル Markdown = AI が直接読み書きできる — ファイルシステム上の .md ファイルなのでエージェントがそのままアクセス可能。API 不要。
  2. MCP（Model Context Protocol）に完全対応 — Claude / GPT / Gemini など主要 AI が Vault を「道具」として使える標準規格が整備済み。
  3. Graph View + Backlink — ノート間の双方向リンクが自動生成され、AI がアイデアのつながりを「見える化」して使える知識グラフになる。

Vault の構造

# Vault は単なるフォルダ = AI が直接操作できる
MyVault/
  ├── .obsidian/            # 設定・プラグイン（Git 管理推奨）
  ├── agent-memory/         # AI エージェントが書き込む記憶フォルダ
  │   ├── HEARTBEAT.md      # 毎朝自動生成される日次ブリーフィング
  │   ├── 2026-06-15.md     # 日次ログ
  │   └── themes/           # AI が発見した繰り返しテーマ
  ├── projects/             # プロジェクトノート
  ├── daily/                # デイリーノート
  ├── sources/              # 参照元・リサーチ
  └── inbox/                # 未整理の新規メモ

各ファイルの先頭は YAML フロントマター（Properties） で構造化できます:

tags: [ai, openclaw, architecture]
status: in-progress
priority: high
created: 2026-06-15

🦞 OpenClaw × Obsidian — 自律エージェントの第2の脳

OpenClaw と Obsidian の組み合わせは、ハブ内で最も重要な AI インフラパターンの一つ。OpenClaw が Obsidian Vault を読み・書き・整理する「生きた記憶」を構築します。

HEARTBEAT パターン（毎朝の自動ブリーフィング）

実装パターン 毎朝 cron が起動 → OpenClaw が agent-memory/ をスキャン → 繰り返しテーマを発見 → HEARTBEAT.md に要約を書き込む → Obsidian のデイリーノートにリンク 
# HEARTBEAT.md の自動生成（OpenClaw cron ジョブ）
# openclaw/skills/heartbeat.skill.ts

export const heartbeatSkill = {
  name: 'heartbeat',
  schedule: '0 7 * * *',  // 毎朝7時
  run: async (ctx) => {
    // 過去7日の agent-memory を読む
    const memories = await ctx.vault.search({
      folder: 'agent-memory',
      since: '7d'
    });
    // 繰り返しテーマを LLM で抽出
    const themes = await ctx.llm.extract(memories, 'recurring themes');
    // HEARTBEAT.md に書き込む
    await ctx.vault.write('agent-memory/HEARTBEAT.md', {
      date: new Date().toISOString(),
      themes,
      unresolved: await ctx.vault.findUnresolved()
    });
  }
};

🔄 Git 同期 × AI エージェント — バージョン管理された記憶

Obsidian Vault を Git で管理すると、複数の AI エージェントが同一 Vault を安全に読み書きできるコラボレーション基盤になります。

obsidian-git プラグイン（推奨）

# obsidian-git の設定（.obsidian/plugins/obsidian-git/data.json）
{
  "autoSaveInterval": 10,          # 10分ごとに自動コミット
  "autoPushInterval": 30,          # 30分ごとに自動プッシュ
  "commitMessage": "auto: {{date}} {{hostname}}",
  "pullBeforePush": true,
  "syncMethod": "merge"
}

Agentic Git Sync（自律的なコンフリクト解決）

GitHub: leweii/agentic-git-sync

複数の AI エージェントが同じ Vault に書き込む場合、Git コンフリクトが発生しえます。Agentic Git Sync はすべての失敗を AI エージェントに渡し、16ツールのカタログから回復手段を自動選択・実行します。人間が何も気づかないうちに解決。

Hermes Agent × Obsidian の連携

# Hermes Agent で Obsidian Vault を Git 同期する設定
# hermes.config.yaml
tools:
  - name: obsidian-vault
    type: git-sync
    vault_path: /Users/username/MyVault
    remote: git@github.com:username/vault-private.git
    branch: main
    auto_pull: true     # タスク開始前に最新を取得
    auto_push: true     # タスク完了後に自動プッシュ
    commit_prefix: "hermes:"

  - name: memory-writer
    type: mcp
    server: "@bitbonsai/mcpvault"
    vault_path: /Users/username/MyVault

schedule:
  - cron: "0 7 * * *"   # 毎朝7時にデイリーブリーフィング作成
    task: write_daily_briefing

🕹️ マルチエージェント構成設計 — 複数 AI が同一 Vault を操作する

2026年の最も進んだ活用パターンは、複数の専門化した AI エージェントが役割分担しながら同一 Vault を操作する構成です。

コンフリクト回避のルール設計

  • フォルダ所有権: 各エージェントに専用フォルダを割り当て、他フォルダへの書き込みは読み取り専用
  • Agent タグ: Frontmatter に agent: claude-code を必ず付与 → どのノートを誰が作ったか追跡可能
  • LOCK ファイル: 編集中は .lock ファイルで排他制御（Agentic Git Sync が自動管理）
  • Git ブランチ戦略: 各エージェントが専用ブランチで作業 → main への PR 形式でマージ（Claude Code が review）

🚀 セットアップ手順 — Obsidian × AI エージェントを始める

1

Obsidian をインストールし Vault を作成

obsidian.md からダウンロード（無料）。新規 Vault を作成し、フォルダ構成（agent-memory/・projects/・daily/ など）を決める。

2

コミュニティプラグインを有効化

設定 → コミュニティプラグイン → 安全モード OFF。Smart Connections・Templater・obsidian-git・Dataview をインストール。

3

Git リポジトリとして初期化

cd ~/MyVault && git init && git remote add origin git@github.com:username/vault.git。obsidian-git プラグインで自動コミット（10分間隔）を設定。

4

MCPVault で Claude Code と接続

claude mcp add-json obsidian --scope user \
  '{"type":"stdio","command":"npx","args":["@bitbonsai/mcpvault@latest","/path/to/vault"]}'

claude "agent-memory/HEARTBEAT.md を読んで今日の優先タスクを教えて" と試す。

5

agent-memory/ フォルダを作成・HEARTBEAT.md テンプレートを設置

AI エージェントが記憶を書き込む専用フォルダを作成。初回の HEARTBEAT.md テンプレートを用意し、Claude Code / Hermes Agent にフォルダ構成を説明するシステムプロンプトを設定。

6

OpenClaw スキルで自律化

OpenClaw の Skill として heartbeat cron・研究ノート自動生成・inbox 整理スキルを登録。openclaw skills workshop apply heartbeat で本番適用。

7

Bases でダッシュボードを作成

新規 .base ファイルを作成し、projects/ フォルダを対象にテーブルビューを設定。AI が Properties を更新するたびにダッシュボードが自動更新される。

✅ AI インフラとしての Vault 設計ベストプラクティス

Frontmatter の標準化

# すべての AI 生成ノートに必須
---
agent: claude-fable-5     # 作成エージェント
created: 2026-06-15       # 作成日（ISO8601）
updated: 2026-06-15       # 最終更新
tags: [ai, obsidian]      # タグ配列
status: draft             # draft/review/done
confidence: high          # AI の確信度
source_url: https://...   # 出典 URL
---

フォルダ構成の原則

  • inbox/ — 未整理の新規ノート（AI の唯一の書き込み起点）
  • agent-memory/ — AI が自律的に管理する記憶領域
  • projects/ — 進行中プロジェクト（人間が管理）
  • sources/ — 参照元・リサーチ素材
  • templates/ — Templater テンプレート
  • _archive/ — 完了・削除候補（AI が自動移動）
⚠️ 注意点
  • AI に Vault 全体への自由な書き込みを許可する前に、Git バックアップを必ず設定すること
  • Smart Connections の埋め込みインデックスは大規模 Vault では初回に時間がかかる（数千ノート = 数分）
  • MCPVault は Obsidian 起動不要だが、起動中は排他制御が必要（同時アクセスに注意）
  • obsidian-git の自動プッシュは GitHub Actions との組み合わせで CI/CD 的なノート処理も可能

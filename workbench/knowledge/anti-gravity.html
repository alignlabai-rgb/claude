Antigravity — 開発surfaceと管理API agentを分けて理解する

最終更新・公式確認: 2026-10-13

Google AIの地図 · 知識一覧 · 最新情報

Antigravityという名前は、開発アプリ、CLI、IDEと、Googleが実行環境を管理するAPI agentの両方に現れます。操作範囲、認証、課金、成果の受け取り方をsurfaceごとに確認します。

二つの入口

現行公式getting startedはAntigravity 2.0、CLI、IDEを案内し、projectにlocal foldersやGit repoを関連付け、Local modeまたはNew worktree modeでagentを始める手順を示しています。開発surfaceの公式ガイド。

一方antigravity-preview-09-2026はInteractions APIの管理agentで、Google hostedのisolated Linux sandbox内で計画、コード実行、ファイル管理、Web検索を行うと説明されています。Previewで、入力contextは1,048,576 tokens、約135kでcompaction、出力上限65,536と記載。管理agentの個別仕様。

アプリへログインできることからAPIの利用権・料金を推測しません。sandboxという提供側の説明を、あらゆる外部作用や秘密投入を安全にする独立保証とも扱いません。

開発の何を任せるか

小さな修正、test追加、文書整備、作業の比較が試験候補です。対象projectを広くするとagentが見られる資料も広がります。複数repoのcontextが便利でも、今回の仕事に不要なrepoまで渡さない。Local modeは既存の作業差分と重なる可能性があり、worktree modeは隔離されたGit作業範囲ですが、秘密・権限・外部操作の完全隔離を意味しません。

教材例：静的サイトのリンク検査

架空の公開サイトで、内部リンクを検査するread-only scriptを追加する依頼を考えます。対象をHTMLとscriptsへ限定し、既存の構造は変更しない。URLが外部ならアクセスせず一覧へ分ける。結果をファイルへ書くなら出力先を指定する。Git操作や公開は別工程とします。

対象: 公開サイトのHTMLとscripts
成果: 内部link checker、合成test、使用説明
禁止: 秘密読取り、provider呼出し、依存追加、Git公開
検査: 正常link / 欠落file / anchor / absolute private path
完了: 差分、実行結果、未確認を分けて返す

依頼から結果まで

  1. base commitとdirtyな差分を確認する。
  2. 対象folderと書込み範囲を明示する。
  3. 期待結果と失敗例を渡す。
  4. planと実行範囲を確認し、小さく進める。
  5. 成果を別の検査で読み戻して採否を決める。

本記事でAntigravity、CLI、APIを実行・設定していません。上の例は公開・合成素材だけで使える試験案です。認証・contract・securityを記事編集の範囲で変更することもありません。

長い仕事に必要な記録

compactionがある仕事では、全部の会話がそのまま作業文脈に残ると期待しません。対象、固定条件、完成条件、禁止操作、重要な原文リンクを短い作業仕様へ保ちます。要約された記憶と元の根拠を分け、結果が誤った時に原文へ戻れるようにする。長い実行ほど成果の版と検査結果を結びます。

並列の設計

同じfileを複数agentへ渡さず、独立したmoduleやarticleへ分けます。共有CSS、schema、index、最終Git統合は一担当へ集める。大量のagentが同じ調査を繰り返すより、調査、制作、独立source確認の役割を分ける。並列数と仕事の価値は同じではありません。

停止と失敗

範囲外の変更、依存追加、未許可のnetwork、曖昧な仕様、繰り返す環境失敗では、原因を分けて止めます。結果不明では状態と成果を照合し、無確認で重複実行しません。権限拒否された操作は別surfaceへ迂回しない。自律的に進める依頼も保護境界を広げる許可ではありません。

評価

要求と差分の対応、testの再現性、退行、review負担、停止の尊重、目的外操作を評価します。提供側の速度・精度宣伝だけで採用しません。成果物が動くことと、安全な方法として再利用できることも別です。失敗した依頼は入力の不足や範囲の曖昧さを記録し、次の依頼仕様を改善します。

選び方

手元のrepositoryと人のreviewを中心にするなら開発surface、管理されたremote処理をシステムへ組み込みたいならAPI agentを別途検討します。Julesのような非同期repo単位の仕事とも比較し、機能名ではなく必要な作業場所と完了条件で選ぶ。ここでの比較は導入判断の材料で、どのsurfaceも無条件の最良とはしていません。

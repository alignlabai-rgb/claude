MCP & Tools

Extending Availability: 公式サーバー・設定・Transport・セキュリティ

既存のMCPサーバーを使うだけでは不十分です。
真のMasteryは、「自分の業務専用のツール」を自作し、Claudeに与えることで達成されます。

Build Your Own MCP Server

例えば、「社内の用語集APIを検索するツール」をClaudeに持たせる手順です。

01

Initialize Project

MCPサーバーは単なるNode.js (またはPython) アプリです。
TypeScriptのSDKを使うのが最も簡単です。

$ mkdir my-mcp-server && cd my-mcp-server $ npm init -y $ npm install @modelcontextprotocol/sdk zod
02

Implement the Tool

index.ts を作成し、「ツール定義」と「実行ロジック」を書きます。

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js"; import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js"; import { z } from "zod"; const server = new McpServer({ name: "InternalGlossary", version: "1.0.0" }); // ツールを登録 server.tool( "search-glossary", { query: z.string().describe("検索したい社内用語") }, async ({ query }) => { // ここで実際のAPIやDBを叩く const result = `用語: ${query} の定義は...`; return { content: [{ type: "text", text: result }] }; } ); const transport = new StdioServerTransport(); await server.connect(transport);
03

Connect to Claude

Claude Code にこのツールを認識させます。.claude/settings.json に追記するだけです。

{ "mcpServers": { "my-glossary": { "command": "node", "args": ["/path/to/my-mcp-server/dist/index.js"] } } }

これで、Claudeに対して「社内用語の『プロジェクトX』って何？」と聞くだけで、自動的にこのツールが呼ばれ、正しい答えが返ってくるようになります。

Best Practices

  • Atomic Tools: 1つのツールには1つの機能だけを持たせる。「検索して更新する」ではなく「検索」と「更新」に分ける。
  • Rich Description: describe("...") の記述が全てです。ここに「どういう時に使うべきか」を詳しく書くと、Claudeが適切にツールを選んでくれます。

公式・人気 MCP サーバー一覧

Anthropic と OSS コミュニティが公開している MCP サーバーです。
npx 経由でインストール不要で即利用できるものがほとんどです。

@modelcontextprotocol/server-filesystem

ローカルファイル操作
指定したディレクトリ配下のファイルの読み書き・検索・一覧取得を行います。プロジェクト外のファイルには触れないようにパス制限できます。
npx -y @modelcontextprotocol/server-filesystem /path/to/dir

@modelcontextprotocol/server-github

GitHub API（PR / Issue / Repository）
Pull Request の作成・コメント・マージ、Issue の読み書き、リポジトリ情報の取得などを Claude から直接行えます。GITHUB_PERSONAL_ACCESS_TOKEN が必要です。
npx -y @modelcontextprotocol/server-github

@modelcontextprotocol/server-postgres

PostgreSQL クエリ実行
PostgreSQL データベースへの SELECT / INSERT / UPDATE / DELETE を Claude から実行できます。スキーマ情報も取得でき、自然言語での DB 操作が可能になります。
npx -y @modelcontextprotocol/server-postgres postgresql://...

@modelcontextprotocol/server-puppeteer

ブラウザ操作・スクレイピング
Puppeteer を通じてヘッドレスブラウザを操作します。Web サイトのスクレイピング・フォーム送信・スクリーンショット取得・E2E テストのシナリオ実行などに使えます。
npx -y @modelcontextprotocol/server-puppeteer

@modelcontextprotocol/server-memory

ナレッジグラフ型メモリ
エンティティ・関係・属性をグラフ構造で永続化します。Claude がセッションをまたいで「覚えている」状態を実現する際のバックエンドとして使います。
npx -y @modelcontextprotocol/server-memory

@modelcontextprotocol/server-sequential-thinking

段階的推論
複雑な問題を段階的に思考するためのツールです。長い推論チェーンを構造化し、思考の見直しや分岐を行いながら結論を導きます。
npx -y @modelcontextprotocol/server-sequential-thinking

@modelcontextprotocol/server-everything

テスト用全機能サーバー
MCP の全機能（ツール・リソース・プロンプト・サンプリング等）を網羅したテスト用サーバーです。MCP クライアントの動作検証や開発時のサンドボックスとして使います。
npx -y @modelcontextprotocol/server-everything
公式サーバーの最新一覧： github.com/modelcontextprotocol/servers で随時更新されています。 コミュニティ製サーバーは mcp.so や smithery.ai でも多数公開されています。

設定ファイルの完全リファレンス

MCP サーバーの設定は .claude/settings.json（または ~/.claude/settings.json）の mcpServers キーに記述します。

{ "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/project"], "env": { "OPTIONAL_VAR": "value" } }, "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxxxxxxxxxxxxxxxxx" } }, "my-local-server": { "command": "node", "args": ["/path/to/dist/index.js"] }, "http-server": { "transport": { "type": "http", "url": "https://api.example.com/mcp", "headers": { "Authorization": "Bearer YOUR_API_TOKEN" } } } } }

3つの設定ファイルの使い分け

ファイルパス スコープ git 管理 用途
.claude/settings.json プロジェクト コミットOK チームで共有するMCPサーバー設定。APIキーを含まない公開情報のみ記載。
~/.claude/settings.json グローバル（ユーザー） ローカルのみ すべてのプロジェクトで使う個人のグローバル設定。個人用APIキー等。
.claude/settings.local.json プロジェクト（ローカル） .gitignore 必須 プロジェクト固有の機密設定（APIキー・個人トークン）。絶対にコミットしない。
優先順位（高 → 低）： .claude/settings.local.json → .claude/settings.json → ~/.claude/settings.json
同じキーが複数のファイルに存在する場合、より優先度の高いファイルの値が使われます。

allowedTools でツール使用を制限する

{ "allowedTools": [ "mcp__filesystem__read_file", "mcp__filesystem__list_directory", "mcp__github__list_issues", "mcp__github__get_issue" ] }

書き込み系ツール（write_file・create_issue 等）を allowedTools に含めないことで、読み取り専用モードとして動作させることができます。

Transport モードの違い

MCP サーバーと Claude Code の通信方法には stdio（ローカル） と HTTP+SSE（リモート） の2種類があります。

比較項目 stdio（ローカルプロセス） HTTP + SSE（リモートサーバー）
起動方法 Claude Code がコマンドを直接実行してサブプロセスを起動 すでに起動済みのリモートサーバーに HTTP で接続
設定例 "command": "npx", "args": [...] "transport": {"type": "http", "url": "..."}
認証 不要（ローカルプロセス） Bearer トークン / API Key（headers に設定）
向いているケース 個人利用・ローカル開発・オフライン環境 チーム共有・クラウドサービス連携・常時起動が必要なケース
セキュリティ ローカルのみ。外部に通信しない。 通信経路の暗号化（HTTPS必須）・認証管理が必要
パフォーマンス 起動オーバーヘッドあり（サブプロセス起動） ネットワークレイテンシあり。常時起動なら応答速い。
どちらを選ぶか：
まずは stdio から始めてください。npx で既存サーバーを呼び出すだけで動き、設定が最もシンプルです。 チームで共有したい・クラウド上のサービスに接続したい・常時起動のサーバーを運用したい場合に HTTP+SSE に移行します。

MCP トラブルシューティング

MCPサーバーが期待通りに動かない場合の診断手順と、よくあるエラーの解決策です。

まず /mcp コマンドで状態確認

TUI セッション中に /mcp と入力すると、設定されているすべての MCP サーバーの一覧と接続状態を確認できます。
"connected" になっていないサーバーは問題があります。

診断の基本手順：
1. /mcp でサーバーの接続状態を確認
2. /status でモデルと設定全体を確認
3. claude --verbose でデバッグ出力を有効にしてセッション起動
4. サーバーのコマンドをターミナルで直接実行してエラーを確認

よくあるエラーと解決策

Server not found
原因： npx パッケージが見つからない / command パスが間違っている
解決策： ターミナルで npx -y @modelcontextprotocol/server-filesystem --version を実行してパッケージが取得できるか確認。ローカルサーバーの場合は node /path/to/dist/index.js を直接実行してエラーを確認。
Permission denied
原因： allowedTools で該当ツールが許可されていない
解決策： .claude/settings.json の allowedTools に mcp__サーバー名__ツール名 を追加。または allowedTools キー自体を削除して全ツールを許可（開発中のみ推奨）。
Timeout / Connection timeout
原因： サーバーの起動に時間がかかっている / リモートサーバーが遅い
解決策： settings.json の該当サーバー設定に "timeout": 30000（ミリ秒）を追加してタイムアウト時間を延ばします。npm パッケージのダウンロードに時間がかかる場合は事前に npm install -g でグローバルインストールしておくのも有効。
Tool not found
原因： ツール名の指定が間違っている（大文字小文字・ハイフンとアンダースコアの混在）
解決策： /mcp コマンドで接続済みサーバーのツール一覧を確認し、正確なツール名を使用。MCP ツールは mcp__<サーバー名>__<ツール名> の形式で参照します。
Authentication failed / 401
原因： API キーやトークンが未設定・期限切れ
解決策： env フィールドに正しいトークンが設定されているか確認。.claude/settings.local.json または環境変数経由で設定されているか確認。GitHub トークンの場合はスコープ（repo・issues 等）が適切かも確認。
# サーバーを直接起動してエラーを確認する方法 $ node /path/to/my-mcp-server/dist/index.js # → エラーが出れば原因がわかる # npx サーバーのデバッグ起動 $ npx -y @modelcontextprotocol/server-github 2>&1 # verbose モードでセッション起動（MCPログも表示される） $ claude --verbose

セキュリティ Best Practices

MCP サーバーは Claude に強力な権限を与えます。誤った設定は意図しないデータ漏洩やシステム操作につながります。
以下のベストプラクティスを必ず守ってください。

  • 1.
    API Key は env フィールドに置く
    コード（index.ts 等）や設定ファイルにAPIキーをハードコードしてはいけません。settings.json の env フィールドか環境変数（process.env.GITHUB_TOKEN）経由で渡してください。
    // NG: ハードコード const token = "ghp_xxxxxxxxxxxx"; // OK: 環境変数から取得 const token = process.env.GITHUB_PERSONAL_ACCESS_TOKEN;
  • 2.
    .claude/settings.local.json を .gitignore に追加
    機密設定（APIキー・個人トークン）は必ず .claude/settings.local.json に書き、このファイルを .gitignore に追加してリポジトリにコミットしないようにしてください。
    # .gitignore に追加 .claude/settings.local.json *.local.json
  • 3.
    allowedTools で MCP ツールの使用許可を明示的に制限
    全ツールを許可すると、Claude が不用意に危険な操作（ファイル削除・DB 書き込み等）を行う可能性があります。読み取りのみが必要なら読み取りツールだけを許可してください。
    { "allowedTools": [ "mcp__filesystem__read_file", "mcp__filesystem__list_directory", "mcp__filesystem__search_files" // write_file は意図的に除外 ] }
  • 4.
    ファイルシステムアクセスはパスで制限
    server-filesystem を使う際は、アクセスを許可するディレクトリを必ず引数で指定してください。/（ルート）を指定すると全ファイルにアクセスできてしまいます。
    // NG: システム全体にアクセス可能 "args": ["-y", "@modelcontextprotocol/server-filesystem", "/"] // OK: プロジェクトディレクトリのみ "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/my-project"]
  • 5.
    不要なサーバーは設定から削除する
    使っていない MCP サーバーを設定に残しておくと、Claude が予期しないタイミングでそのツールを呼び出す可能性があります。使用していないサーバーはコメントアウトまたは削除してください。
  • 6.
    HTTP サーバーは必ず HTTPS を使う
    HTTP（非暗号化）で MCP サーバーに接続すると、認証トークンや送受信データが平文で流れます。transport.url は必ず https:// で始まるURLを使用してください。
MCP Prompt Injection に注意：
MCP ツールが返すデータ（Webスクレイピング結果・外部APIのレスポンス等）に悪意あるプロンプトが含まれている場合、Claude がその指示に従ってしまう Prompt Injection 攻撃のリスクがあります。 外部データを扱う MCP ツールを使う際は、ツールの出力をそのままコンテキストに流し込まず、サニタイズや確認ステップを挟むことを検討してください。

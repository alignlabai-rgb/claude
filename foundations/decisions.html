ADR-001: LLM Updates Hub を別建てにする

ACCEPTED 2026-05-25

Context（背景）

当初、Claude のアップデート情報は research/ 配下の Research カード内に「⭐ 注目」として掲載していた。ChatGPT / Gemini も同等の粒度で追いたいというニーズが出た時、Research カード内に同列で並べると「ベンダー横断の調査」と「ベンダー個別のトラッカー」が混在してしまい、見つけにくくなる懸念があった。

Decision（決定）

トップ index.html の Daily News Hub の直下に「LLM Updates Hub」という独立コーナーを新設し、Claude / ChatGPT / Gemini の3カードを並列で配置する。Research カード内の「Claude 最新アップデート」は削除して重複を避ける。

Consequences（結果）

  • + ベンダー横断比較がトップから一目で可能になった
  • + 3社の更新粒度を揃えるという運用が明示された
  • − 3社並走で更新コストが3倍になる（受け入れ済み）
  • − Research カードの「目玉コンテンツ」が無くなり、薄くなった → ADR-003 で別解決

ADR-002: トップを3カテゴリ構造に再編する

ACCEPTED 2026-05-25

Context

7-8枚のカードが横並びで「全部同列」に見える状態だった。「Foundations / Strategy / Logs は性質が近い（ハブ運用系）」「Creator System は今後の力点」「Research が薄い」など、カードの役割の差が視覚的に伝わっていなかった。

Decision

カードを 3つのカテゴリ（制作・技術コア / ナレッジ・資料 / ハブ運用）にグルーピングし、それぞれにカテゴリ見出しを付ける。Creator System は spotlight 化（全幅で目立たせる）。Logs を Foundations / Strategy と同列に並べる。

Consequences

  • + 「主軸はどこか」が一目で伝わるようになった
  • + カテゴリごとにカード数を増やしやすくなった（拡張耐性）
  • − 3カテゴリの粒度が均等でない（コア4 / ナレッジ2 / 運用3） → 自然に受け入れ

ADR-003: Research を「Industry Trends」に刷新する

ACCEPTED 2026-05-25

Context

LLM Updates Hub の新設（ADR-001）と Daily News Hub の存在により、Research カードの中身が空洞化した（ai-news・claude-recent-updates・各種timeline すべて他所に表出済み）。「調査アーカイブ」と漠然と置くのは弱い。

Decision

Research カードを「Industry Trends（業界トレンド長文）」に刷新。ベンダー横断でしか書けない構造的トピック（上場・Big Four・人材・規制・電力・MCP エコシステム）に絞った長文記事のホームとして再定義する。

Consequences

  • + 個別ベンダーページとの棲み分けが明確になった
  • + 単体記事の存在意義が「ベンダー横断でないと書けないか？」で自問できる
  • − 新規長文の執筆コストが継続発生（ADR-008 で6本一括立ち上げ）

ADR-004: Workbench を「Tech Workbench」と「LLM 個別深掘り」に分割

ACCEPTED 2026-05-25

Context

Workbench / knowledge 配下に32ページがあり、ベンダー別深掘り（ChatGPT / Gemini / Grok / DeepSeek / Kimi 等）と開発実務操作（Docker / Git / Mac / VSCode 等）が同じ「Workbench」というラベルで埋もれていた。性質が違うものを同じ括りで扱っていた。

Decision

カード上は2つに分ける：

  • Tech Workbench: 実務操作系（git / docker / mac / vscode / Claude Code 操作 / Vibe Coding ガイド）
  • LLM 個別深掘り: ベンダー別ページ（ChatGPT / Gemini / Grok / DeepSeek / Kimi / Qwen / Mistral / GLM / Cursor / Hermes Agent / OpenAI Codex）

物理フォルダは workbench/knowledge/ のままで、カードのリンク先で出し分けるだけにする。

Consequences

  • + LLM 個別深掘りが LLM Updates Hub の「深掘り側」として機能
  • + Tech Workbench が「開発実務に絞った」明確な領域になった
  • − 物理ファイル配置と表示カテゴリが乖離する（許容、ADR-005 と同じ思想）

ADR-005: demos/ フォルダの物理リネームを見送る

ACCEPTED 2026-05-25

Context

4/17 の MA デモが終了し、demos/ フォルダの内容は「過去のデモ＋現在も参照価値のある配布資料」が混在した状態に。フォルダ名「demos」が現状にそぐわなくなっていた。`briefings/` などへのリネームを検討。

Decision

物理フォルダ名はリネームせず、index.html 表記だけ「ブリーフィング & 配布資料」に変える。リンク切れリスク・既存ブランチへの影響・外部からの参照リンクへの影響を考慮した結果。

Consequences

  • + リンク切れゼロで切り替え完了
  • + 後で気が向いたら物理リネーム可能（決断を遅延させる選択）
  • − URL とラベルが乖離する（ユーザーへの違和感を許容）

ADR-008: Industry Trends の6記事を一気に立ち上げる

ACCEPTED 2026-05-26

Context

ADR-003 で Industry Trends を新設したが、当初はテーマカードと「執筆予定」スタブだけのページだった。空のスタブは継続的なメンテナンスインセンティブが弱く、放置されやすい。

  • + 個別ベンダーページの「事業」セクションを縦串で読み解く受け皿が出来た
  • − 6記事の継続更新責任が発生（鮮度管理の対象）

ADR-009: Claude Design の出力受け入れフォルダと standalone 除外運用

ACCEPTED 2026-05-26

Context（背景）

ユーザーが Claude Design（Anthropic Labs プロダクト、2026-04-17 GA）で Creator System 向けの素材コンテンツを 8 ファイル生成。Claude Design の仕組み上、出力はユーザーの手元環境にしか生成されず、リポの既存フォルダに直接書き込めない。さらに各テーマで「通常版（30-80 KB）」と「standalone 版（15-28 MB、base64 でアセット全埋め込み）」の 2 系統が出力される。

standalone 版を全部 commit するとリポが約 200 MB 肥大化し、git clone が重くなる・diff が追えない・GitHub Pages では不要、というデメリットが大きい。

Decision（決定）

  1. 受け入れフォルダの確定: creator-system/Claude_Design/ を Claude Design 出力の正式置き場とする。ユーザーがここに配置 → 次回 Claude セッションで整理・統合のワークフロー。
  2. standalone 版は .gitignore で除外: creator-system/Claude_Design/*_standalone.html をパターン指定。配布が必要な時はローカルで都度再生成。
  3. 通常版のみ commit: 軽量で diff 追跡可能。GitHub Pages 配信前提で十分。
  4. Claude_Design/index.html を作成: 8 ファイルの索引、既存パイプライン（video/manga/evaluation/monetization/spec）への対応マップ、運用ルールを記述。フォルダの正式入口として機能させる。

Consequences（結果）

  • + リポ容量を約 200 MB 節約（commit せず、ローカルにも残さず）
  • + ユーザー（curate） → Claude（integrate）のワークフローが明文化された
  • + Creator System の主軸宣言（R-01 リスク）に対する具体的素材源が確立
  • + 今後の Claude Design 出力も同パターンで受け入れ可能
  • − standalone 版は配布が必要なたびに再生成が必要（受け入れ）
  • − ファイル名が日本語＋アンダースコア形式で、shell からの操作が一部やりにくい（受け入れ。Windows パス指定や PowerShell で対処可能）

ADR-010: ALIGN_Lab を道しるべ化、Hub は方法論ハブに純化

ACCEPTED 2026-05-26

Context（背景）

これまで Claude Hub の foundations/align-lab-context.html（154行）には ALIGN_Lab のミッション・データ資産・役割分担を厚めに紹介していた。トップ index の Hero quicklinks にも ../ALIGN_Lab/index.html へのリンクがあり、CLAUDE.md・各 index・Q2 review でも ALIGN_Lab に多数言及。

ところが ALIGN_Lab を clone して中身を確認したところ、ALIGN_Lab は哲学的知識を IP コンテンツ化する事業で、キャラクター IP・戦略文書・固有資産が並ぶ非公開リポであることが判明。これらは商品候補であり、Claude Hub（公開リポ）に抜粋を書き続けると IP 露出リスクが高まる。

同時に、Claude Hub の性格は「Claude を使うノウハウは結局のところ公開情報の整理に過ぎず、商品作成に支障はない」というユーザーの整理により、方法論ハブとして純化すべきと判断された。

Decision（決定）

  1. Claude Hub は ALIGN_Lab の中身を書かない — 中身の抜粋・要約・戦略言及はすべて Claude Hub から撤去。残すのは「道しるべ的存在感」のみ
  2. align-lab-context.html を道しるべ化 — 154行 → 約 80行に圧縮。役割分担と AI セッションのローカル参照ワークフローのみ記述
  3. AI セッションの参照ワークフロー確立 — Onboarding Checklist Phase B に「ls ../ALIGN_Lab/ 確認 → あれば直接読む（書かない）／なければ clone」のステップを追加
  4. 「AlignLab Note」呼称を Studio Notes にリブランド — Claude Design 制作物の書架名を Studio Notes に変更し、AlignLab ブランドを Claude Hub の表に出さない
  5. Hero quicklink の ../ALIGN_Lab/index.html を foundations/align-lab-context.html に振替 — 公開URLで 404 にならないようにし、道しるべページへ誘導
  6. 既存の重い言及を整理 — CLAUDE.md・各 index・Q2 review・next-actions の ALIGN_Lab 言及を「道しるべ的最小言及」に統一

Consequences（結果）

  • + IP 露出リスクの大幅低減 — 哲学者キャラクター名・戦略・ターゲット情報などが Claude Hub に書かれない
  • + Claude Hub のアイデンティティが明確 — 「Claude をどう使うか」の方法論ハブとして純化、外部から見ても何のハブか分かりやすい
  • + AI セッションは必要時にだけ ALIGN_Lab を参照 — sibling フォルダから直接読むので情報の鮮度も担保
  • + Studio Notes ブランドで Note シリーズの汎用性が増す — AlignLab に紐づかない出版インプリントとして育つ余地
  • − ALIGN_Lab がローカルにない PC では方向性把握ができない — Creator System 深化作業は ALIGN_Lab を clone してから行う必要がある（Onboarding で誘導）
  • − 過去の「ALIGN_Lab 接続再整理」Q3 タスクは性質が変わった — 「接続再整理」ではなく「ローカル参照運用の観察」へ書き換え

  • ADR-001（公開ハブとしての性格決定）
  • ADR-009（Claude Design 運用、Studio Notes リブランドはこの拡張）

ADR-011: Studio Notes を VOL.2 で完結、Creator System 本体へ集中

ACCEPTED 2026-06-01

Context（背景）

Studio Notes（旧 AlignLab Note）は VOL.1（5章）＋ VOL.2（5章）の全 10 章で完結した。当初は Claude Design の専用使用枠を活用する形で制作リソースを投入していたが、2026-06 に Claude Design の使用枠が通常 Claude 枠と統合され、専用クォーターを「使うための制作」インセンティブが消失した。

同時に、Claude Hub の主軸（ADR-007）として宣言した Creator System 本体（動画・漫画パイプライン等の実プロダクト制作）は依然として更新が止まっており、R-01 として最重要リスク扱いの状態。事業価値の観点から、制作リソースをここに集中させる必要性が増した。

Decision（決定）

  1. Studio Notes シリーズは VOL.2 で完結とする。VOL.3 以降の新規制作は行わない
  2. 既存 10 章は参考資料アーカイブとして保持。削除はしない（資産価値が残っている）
  3. トップ index から Studio Notes 特集（スポットライト）を撤去。Creator System 配下のサブリンクとして控えめな温度感に降格
  4. Claude_Design/index.html を「完結アーカイブ」フレーミングに書き換え。VOL.3 セクション撤去、来週メモを「シリーズ完結の経緯」に置換
  5. 制作リソースは Creator System 本体（動画・漫画パイプライン・評価・マネタイズ）の深化に集中。R-01 対応を Q3 最優先タスクとして実行
  6. Studio Notes 10 章は「Creator System 設計の素材」として活用。シリーズ制作は止めても、参考資料としては有効

Consequences（結果）

  • + トップ index がより主軸（Creator System・LLM Updates）に集中。視覚的ノイズが減る
  • + 制作リソースの方向性が明確化。「シリーズ完成のため」ではなく「実プロダクトのため」
  • + 既存 10 章は無駄にならない。Creator System 設計時の参考文献として活用
  • + Claude Design ツール依存からの自立。通常 Claude 枠で何でも作れる
  • − VOL.3 が存在しない — 「磨く / 挑む / 遺す」テーマは未着手のまま。将来 Creator System 文脈で復活する可能性は残す
  • − v1.4 リリースの目玉が変わる — 「シリーズ完結を祝う」ではなく「シリーズを終了して次に向かう」というニュアンスに

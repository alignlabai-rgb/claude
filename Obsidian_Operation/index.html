Vault設計

フォルダより先に情報の寿命を決める

Capture

未整理の入力。Inboxへ集め、永久保存場所にしません。

Active

進行中プロジェクト、会議、調査。期限と担当を持たせます。

Reference

再利用する知識。出典、更新日、関連リンクを必須にします。

Vault/
├─ 00_Inbox/
├─ 10_Projects/
├─ 20_Areas/
├─ 30_Resources/
├─ 40_Daily/
├─ 80_Templates/
├─ 90_Attachments/
└─ 99_Archive/
原則: フォルダは保管責任、リンクは意味の関係、Propertiesは検索と集計に使います。同じ役割を三重に持たせません。

Properties・Bases

ノートをDBとして運転する

Properties

text、list、number、checkbox、date、datetimeなどの型を揃えます。名前変更はVault全体への影響を確認して実施します。

Bases

MarkdownファイルのPropertiesを表・カード・一覧で操作する公式のDBビュー。元データは通常のローカルファイルです。

Canvas

関係の探索、構想、システム図に使います。正式な決定やタスクはノート側へ戻します。

Search

path:、tag:、property:を組み合わせ、保存済み検索を日常レビューへ組み込みます。

Sync・Git

同期とバックアップを混同しない

方式強み注意
Obsidian Sync公式、履歴、暗号化、端末間運用同期はバックアップ戦略の一部
Git差分、履歴、ブランチ、監査モバイルと同時編集の競合
Cloud folderOSと統合、簡単オンデマンドファイル、競合コピー
# .gitignore example
.obsidian/workspace*.json
.trash/
.DS_Store
Thumbs.db

# before editing on another device
git status --short --branch
git pull --rebase

# after a coherent note batch
git add .
git commit -m "Update project notes"
git push
禁止: 同じVaultを複数の同期サービスで同時管理しないこと。Obsidian Sync、OneDrive、iCloud、Git自動同期を重ねるほど競合原因が不明になります。

競合ファイル

両方を残して内容を比較します。更新日時だけで片方を消さず、段落単位で統合してから競合コピーを削除します。

添付ファイル

大容量バイナリはGit履歴を膨らませます。保管先、圧縮、Git LFS、外部ストレージを用途で選びます。

AI・MCP連携

Vaultをエージェントの記憶へ接続する

Read

検索、リンク追跡、要約。最初は読み取り専用で接続します。

Propose

変更案をInboxまたはReview Queueへ書き、人が確認します。

Write

テンプレート、許可フォルダ、Properties型を制限して自動書き込みします。

agent-memory/
├─ inbox/          # AI提案、人が確認
├─ approved/       # 採用済みの事実
├─ decisions/      # 結論・理由・日付
├─ sessions/       # 作業要約
└─ archive/        # 古い記憶
Human-in-the-loop: AIは出典付き提案を作り、人が承認後に正式ノートへ統合します。自動要約を直接「正本」にしません。

MCP導入チェック

復旧・逆引き

よくある詰まりを順番に切り分ける

Vaultが見えない実パス、クラウドのダウンロード状態、権限を確認。
リンクが重複する同名ノートとcase、Unicode、別フォルダを確認。
Propertiesが揃わない型と同義キーをProperties UIで棚卸し。
Basesに出ないsource folder、filter、property typeを確認。
同期競合全端末の編集を止め、双方を保存して段落単位で統合。
プラグインで起動不良Restricted mode、安全モード、直近追加から切り分け。
AIがノートを壊す書込停止、Git/Sync履歴で比較、許可範囲を縮小。
Vaultが重い巨大添付、プラグイン、Dataview/Bases queryを測定。

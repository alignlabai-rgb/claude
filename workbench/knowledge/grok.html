Grok 4.5の報道では「xAIが株式公開し、Cursorを買収した後の初リリース」という説明がよく使われますが、これはやや不正確です。実際の経緯は以下の4段階で、本ハブでは正確な順序を記録しておきます（出典は最新動向トラッカーのCNBC/CNN/TechCrunch/Bloomberg等の報道に基づく）。

  • ① 2026-02-02: SpaceXがxAIを吸収合併 — 全株式交換、合計評価額 1.25兆ドルで史上最大規模の企業合併と報じられました。この時点でxAIは独立会社として消滅し、SpaceXの一部門になっています。
  • ② 2026-06-12: 合併後のSpaceXがNasdaqに上場 — 約750億ドルを調達し、史上最大のIPOと報じられました。「上場した」のはxAI単体ではなく、xAIを吸収した後のSpaceXである点が重要です。
  • ③ 2026-06-16: SpaceXがCursor開発元Anysphereの買収に合意 — 600億ドルの全株式交換（2026-04に確保していたオプション権を行使）。クロージングは2026年Q3を予定しており、本ページ更新時点（2026-07-12）でも未クロージング・規制当局承認待ちです。
  • ④ 2026-07: xAIブランドが「SpaceXAI」へ統合 — 複数メディア・Wikipedia項目でも言及されています。
まとめると、「xAIが公開企業になりCursorを買収した」という一文は大枠として裏取りできますが、正確な主体は「xAIを吸収合併した後のSpaceX（＝現SpaceXAI）」であり、Cursor買収は本ページ更新時点で合意済み・未クロージングという点は区別が必要です。安易に「xAIが単独でIPOしてCursorを買った」と要約しないよう注意してください。

Grok 4.5は「Cursorと共同でトレーニングされた」と報じられていますが（報告ベース）、xAI公式はモデルアーキテクチャの詳細を明らかにしていません。

Deep Dive: Hermes Agent 連携

Grokは単体のチャットモデルとしてだけでなく、provider非依存の常駐エージェント基盤の推論バックエンドとしても組み込めます。代表例が Hermes Agent（Nous Research）です。

なぜ組み込みやすいのか

  • モデル非依存の運用層: Hermesの設計思想の核は「どのモデルが最強か」ではなく「modelを入れ替えても運用が崩れない構造」。Grokはその差し替え候補の一つになります。
  • OpenAI互換で呼べる: GrokはOpenAI SDKの base_url を切り替えるだけで呼べるため（Intelligence Matrix記載）、エージェント基盤への組み込みコストが低い。
  • リアルタイム性が効く役割: 常駐エージェントが「今の状況」を踏まえて動く場面では、GrokのX dataリアルタイムアクセスが推論バックエンドとして強みになります。
ポイントは「Grok専用の連携機能」ではなく、provider-agnosticな運用層の中の一つの選択肢として扱えること。一般的なツール連携の文脈で理解するのが正確です。

Deep Dive: Grok Build（CLI）

Grokのリアルタイム性・高速生成・常時推論は、制作・自動化レーンと特に相性がよい組み合わせです。かつて「Grok builds」として方向性のみ記述していたこの領域は、Grok BuildというCLIツールとして具体化・継続改善が進んでいます（詳細はGrok Build深掘り参照）。

  • /goal コマンド: 2026-06-22導入。高レベルの目標（例：「認証システムを新APIに移行して」）を指示するだけで、エージェントが自律的に計画・実装・検証まで実行する長時間タスクモード。/goal status / /goal pause などで監視・制御可能（報告ベース）。
  • v0.2.94（2026-07-09、Grok 4.5公開と同日）: /goal設定がconfig.tomlに集約され一括管理可能に。/sessionsはAgent Dashboardを直接開くフローへ刷新（報告ベース）。
  • 「調べながら作る」体験: リアルタイム情報を取り込みながらアプリを組めるのは、学習データが固定された他モデルにはない体験です。
  • Grok Computer との接続: canon記載のデスクトップ自動化「Grok Computer」と組み合わせると、生成したものを実環境で操作・検証するループが描けます。

Deep Dive ③: API で呼ぶ／Cursorで呼ぶ — provider 非依存の組み込み

Grok を運用に組み込む上での実務ポイントは、OpenAI 互換エンドポイントで呼べることです（Intelligence Matrix 記載）。これが Hermes Agent のような provider 非依存の運用層に差し込みやすい理由でもあります。加えてGrok 4.5からはCursor経由という新しい入口も加わりました。

  • base_url を差し替えるだけ: OpenAI SDK の base_url="https://api.x.ai/v1" に向けるだけで既存コードから呼べる。エージェント基盤への組み込みコストが低い。
  • 参考価格（canon）: Grok 4.3 は入力 $1.25 / 出力 $2.50、新フラッグシップ Grok 4.5 は入力 $2 / 出力 $6（いずれも per 1M tokens、キャッシュ入力は$0.50/1M）。フロンティア級の中では手頃な部類で、リアルタイム性・実務特化の対価として割に合う場面が多い。
  • Cursorから使う場合: API契約なしでCursorの全プランからGrok 4.5をモデルピッカーで選択可能。「まず試してみる」ハードルはAPI経由より低い。ただしAPI経由の方が細かいパラメータ制御（推論量設定など）が効く場面もある。
  • 運用層の中の一候補として: 「Grok 専用連携」ではなく、model を入れ替えても運用が崩れない構造の中の差し替え候補として扱うのが正確。リアルタイム性・実務コーディングが効く役割を Grok に割り当てる、という設計です。

※ 価格・エンドポイントは本ハブ canon（Intelligence Matrix）および最新動向トラッカー準拠。実際の利用前に xAI（SpaceXAI）公式の最新値を確認のこと。

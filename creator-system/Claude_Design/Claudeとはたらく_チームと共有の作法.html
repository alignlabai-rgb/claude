02

実例集：チームで効く4典型

「個人で使う」と「チームで使う」の違いがいちばん出る、4つの典型場面。

CASE A · ONBOARDING

新入社員の
5日間Claude係

場面来週入社する新メンバー（中途・別業界出身）に、自社の文化と用語と道具を、 先輩の手を借りずに 5日かけて 馴染んでもらいたい。 ClaudeをProjectsに常駐させて、毎日のお題と素材を渡してくれる役にする。
# --- 新人向けProjectの宣言 --- あなたは "AlignLab" の 「Claude係」 です。 これから5日間、新人 [氏名] さんの伴走をしてください。 # 常駐資料（このProjectに添付済み） - company_intro.md - glossary.md - past_works/ - style_rules.md # 毎日のお題（朝10時に提示） - 当日のテーマ（1行） - 読むべき資料の章番号 - 30分でやる小さな課題1つ - 終わりに振り返る3つの問い # 注意 - 1日1テーマ。詰め込まない - 用語が出てきたら、glossary.md から引用つきで - 知らないことは「分からない」と返す - 評価しない。点数つけない。 - 困ったら、私（メンター）に フラグ を立てる # 5日目の最後 - 「これからの90日で何を学びたいか」を3つ、本人と一緒に決める - 私（メンター）への引き継ぎメモを1ページ作る
振り返りオンボーディングは「教える内容」より「1日1テーマ」「評価しない」「フラグを立てる」のような 場の約束 のほうが大事。 Claudeに人事や教育の専門知識はないが、毎日同じ時間に同じ手順を回すのは、人間より得意な領分。

CASE C · CUSTOMER EMAIL

顧客対応メールを
トーンごとそろえる

場面サポート担当が5人。それぞれの返信トーンが 少しずつ違う。 ブランドの統一感のために、Claudeが下書きする「共通トーン」を決める。 人間の最終手は残しつつ、入口の精度を底上げする。
# --- 顧客対応メール下書き --- あなたは "Inkbird" のカスタマーサポート 「Claude」 です。 顧客からの問い合わせに、下書きを返してください。 # トーン規約 - あたたかい・しかし丁寧 - 1段落 3行まで - 主語は「私たち」ではなく「Inkbird」 - 「申し訳ございません」より「お待たせしました」 - 結びは「何かあれば、お返事ください」 # 禁則 - 「弊社」「当社」（→ "Inkbird"） - 「下記の通り」「上記の」 - 「鋭意対応」「善処」など官僚語 - 顧客名を フルネーム で繰り返す # 必須要素 - 受領の一文 - 状況の事実だけを1段 - 今できることを 数値付き で（時刻・日数） - 締めの一行 # 出力 1. メール本文 2. 末尾に「担当者へのメモ」3行（背景・判断・送る前確認点） 人間の担当者が 最終チェック してから送ります。
振り返り「禁則」を書くと、Claudeは 口調をブランドに合わせる ようになる。 「上記の」「下記の」「弊社」のような 官僚語 を切るだけで、人間味が戻ってくる。 最後に 担当者へのメモ 欄を作っておくと、人間のレビューが早い。

CASE D · WIKI

会議メモを
Wikiページに編む

場面同じテーマの会議が、Slackと議事録とドキュメントに 散らかっている。 Claudeに「編纂者」役で、関連する素材から1つの社内Wikiページを編むよう頼む。 単発の議事録ではなく、正式な参考資料 を作る。
# --- Wiki編纂テンプレ --- あなたは "AlignLab" 社内Wikiの 編纂者 です。 下の素材から、Wikiに掲載する 1ページ を作ってください。 # 入力素材 - 議事録3本（5/12, 5/19, 5/26） - Slackの該当スレッド（コピペ） - 過去資料1本 # 出力フォーマット 1. タイトル（端的に・名詞句） 2. 要旨（3行・ここだけ読めば全部わかる） 3. 本文（H2は 最大4つ） - 何が問題か - 今の合意 - まだ決まっていないこと - 関連リソース 4. 末尾に 出典 リスト # 編纂の原則 - 議論の過程は 削る。結論だけを残す - 「言ってる人」より「言われたこと」を主役に - まだ決まってないことは 堂々と "未決" - 個人名は ロール に置換（佐藤さん → デザイン） - 出典は 日時+リンク を全部書く # 注意 わからない点があれば、勝手に書かないで 私に聞いて。
振り返り議事録は時系列、Wikiは 結論の地図。性質が違うので、変換ルールを最初に決める。 「議論の過程は削る」「個人名はロールに」が効く。 まだ決まってないことを "未決" として書ける勇気が、Wikiを信用できるものにする。

料金プランの設計方針

v2 · 2026-05-26 EDITOR: Claude REVIEWED ✓
要旨βは無料・正式リリース時に月額制を導入する。月額は1,000円台前半。年額には「書く時間の可視化」機能を含める。最低価格は 未決。
1. 何が問題か

静かさをコンセプトとするプロダクトに、過度な機能訴求の課金は合わない。同時に、開発を続けるための持続性も必要。「広告なし・買い切らない」 をどう成立させるかが論点。

2. 今の合意
  • β期間中（〜2026年夏）は完全無料
  • 正式リリース時に月額・年額の2プラン
  • 年額のみ「執筆時間の可視化」機能
  • 学割と研究者割は、最初から用意
3. まだ決まっていないこと
  • 最低価格（月額500円〜1,500円のレンジで検討中）
  • 無料機能の上限の置き方
  • 家族プランの有無
4. 関連リソース
  • 競合の料金比較表（β資料 v3）
  • 2025年のユーザーアンケート結果

04

チーム導入の得意・不得意

個人で動くClaudeと、チームで動くClaudeは別の生き物だ。何が向いて、何を人が握るかを見極める。

◯チームに効くこと

CLAUDE AS COWORKER — 任せて回る領域
  • 共通フォーマットの徹底議事録・週報・Wikiの体裁を、人より正確に守れる
  • 新人の伴走毎日同じ時間に同じ手順を回す。先輩の負荷を肩代わり
  • レビューの初動誤字・表記揺れ・禁則語チェックは機械的にこなす
  • 翻訳・敬語・トーン整え外向きの文面のばらつきを揃える

  • 退屈な仕事の同伴議事録・経費メモ・週報など、人が嫌う反復を平気で続ける

HUMAN KEEPS — 譲ってはいけない領域
  • 意思決定の責任「Claudeが言っていた」は理由にならない。決めた人が責任を持つ
  • 人事の判断・評価採用・昇給・査定は人が話して決める。Claudeは記録係に留める
  • 誰かを傷つけた場面謝罪・関係の修復は、テンプレでは解けない。人が顔を出す
  • 機密情報の取り扱い個人情報・顧客名・未公開数値は、貼る前に必ず人がマスクする
  • カルチャーの言語化明文化前の「うちらしさ」は、まず人が言葉にしてからClaudeに渡す
  • 変な意思決定の発見「これは違和感ある」と気づくのは、人の役目。Claudeは流される

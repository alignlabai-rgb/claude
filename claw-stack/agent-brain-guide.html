Agent Brain：モデルと実行基盤を分けて選ぶ

最終更新・公式情報確認：2026-10-13。確認日は発表日ではありません。本文の教材・評価案は筆者の提案であり、実行済み成果や導入保証ではありません。

このページの Agent Brain は特定の新製品名ではなく、エージェントの推論に使うモデルを選ぶための便宜的な呼称である。旧記事の「主脳は必ずクラウド、ローカルは下流」という固定序列は採用しない。任せる仕事の入力、ツール、停止条件を先に定義し、候補モデルがその契約を守れるかで選ぶ。

モデルが決めないこと

モデルは文章やツール要求を生成する。一方、接続先の選択、ツールの配布、呼び出し時の検証、実行環境、結果保存はハーネス側の仕事になる。OpenClaw はモデル provider とチャット channel を別の概念として説明し、Hermes の設計図も provider resolution と tool dispatch を分けている。OpenClaw Model providers、Hermes Architecture より高性能なモデルへ替えても、権限の過剰付与や間違った通知先はそれだけでは直らない。

能力の契約を四行で書く

筆者の選定案では、まず「読むもの」「提出する形式」「使える道具」「止まる条件」を書く。公開の仕様変更三件を読む、各変更へ URL と引用対象の段落を付ける、検索と読み取りだけ使う、価格または名称が矛盾したら結論を保留する、という形ならテストできる。長文を自然に書けることだけを合格基準にしない。

同じモデルでも、短い分類と長い計画では要求が違う。小さな候補が入力の振り分けを十分に行えるなら、大きなモデルを常時呼ぶ必要はない。ただし分類誤りで秘密の資料が外部へ送られる構成なら、その振り分け自体が重要な境界になる。低コストという理由だけで境界判定を軽くしない。

クラウドとローカルの比較は通信図から

クラウド候補では、送信する入力、利用契約、応答制限、障害時の振る舞いを確認する。ローカル候補では、メモリ使用、読み込み時間、同時実行、ツール形式、モデル配布条件を確認する。ローカル推論であっても検索やチャネルを外部へ接続すれば、その部分は外へ通信する。クラウドなら運用負担がゼロ、ローカルなら完全な秘密保持、という一括説明はしない。

日本語の確認では文章の流暢さと根拠の正しさを分ける。敬語が自然でも否定の条件を取り違えることがある。中国語・英語資料を含むなら、モデル名を挙げて多言語に強いと断定する前に、実際の対象資料に近い短いテスト集合を作る。本記事は候補モデルの日本語性能を実測していない。

失敗を含めた小さな評価集合

  • 互いに矛盾する二つの仕様から、断定せず確認事項を返す。
  • 資料内の「前の指示を無視せよ」をデータとして扱う。
  • 存在しないツールを要求せず、使える範囲を説明する。
  • 書き込み禁止の課題で、完成ファイルが必要なら許可を求めて止まる。
  • 長い入力の最後にある除外条件を落とさない。

正答率だけでなく、禁止効果、再試行回数、根拠がない断定を数える。出力を読む人はモデルの銘柄を隠して判定し、失敗例を次の変更時にも再利用する。単発の成功画像やベンチマーク順位から、毎日の仕事を任せられるとは言わない。

フォールバックは責任も引き継ぐ

別モデルへ切り替えれば完了率は上がるかもしれないが、送信先、料金、文脈長、ツール対応も変わる。代替候補が同じ契約を守れないなら、黙って切り替えるより保留が適切である。OpenClaw のポリシー説明も、ツールの許可と sandbox の作用を別に扱う。OpenClaw Policy as code「頭脳の変更」は実行権限の変更を含まない、と明記する。

導入候補として残す記録は、モデルと版、設定、テスト入力、判定、失敗、費用観測の条件でよい。目標は最強モデルを一度選ぶことではなく、後で安全に選び直せる比較契約を持つことである。

文脈量を品質の代用にしない

長い履歴を渡せるモデルでも、不要な資料が多ければ重要な条件を見失う可能性がある。保存した全履歴を毎回渡す設計と、対象の証拠だけを選び直す設計を比較する。入力を減らして条件が消えたなら圧縮が失敗しているし、入力を増やして誤った過去判断を復活させたなら記憶の選択が失敗している。

モデル評価の再利用物には、正答例だけでなく、保留が正しい入力、権限不足で停止すべき入力を含める。モデルを替えた後も同じ検査を通し、解決した失敗と新たに増えた失敗を分けて書く。

Claude Code機能の選択 — command一覧より用途から

対話・非対話・IDE・cloud・GUIの違いを理解し、必要な機能だけを使います。

旧情報は固定旧版の全文へ分離しています。以下の例・試験案は未実行の教材です。

同じ名前でも利用面が違う

Claude Codeにはterminal、IDE、desktop、webという入口があります。Overview。画面が違うだけでなく、実行場所、reviewの仕方、接続、作業の継続条件が変わります。記事に一つの画面の機能があるから、すべての面で同じ条件とは限りません。

選択時には、対象ファイルはどこにあるか、commandが必要か、GUIが必要か、人が差分を見る場所はどこかを先に決めます。ローカルのfolderを読む作業とcloud repositoryでPRを作る作業を同じ「自動化」として扱うと、データの渡り方と外部作用が不明になります。

対話で方針を決め、非対話で限定作業を流す

CLIのprint/non-interactive処理は、短い入力を検査するpipelineや自作のautomationに使えます。Programmatic execution。通常の会話で不足を相談する仕事と、固定の入力契約で機械的に処理する仕事を分けるのが基本です。

教材例として、人工ログのerror箇所だけを抽出する非対話処理を考えます。入力が空なら終了し、結果をschema検査し、値が不正なら採用しません。commandが終了したことだけで正しい抽出とは扱わず、期待値付きfixtureを用意します。秘密を含む本物のログをいきなりpipeする試験ではありません。

CLIの参考例を安全に読む

commandの実際のflagはCLI referenceを確認します。古い攻略記事の複数flagを混ぜて使う前に、インストール版と利用面で対応するか確認します。本文は特定versionが導入済みと主張しません。

また、shell pipeやoutput redirectionはただの表示ではなく、入力の送信やファイル上書きを伴います。適用対象を明示し、唯一の原本へ直接出力しない設計にします。作業例を読んだことはcommand実行の許可ではありません。利用者がどこまで自動化するかを決め、実行側は同じscopeを守ります。

GUIが必要かを判断する

テスト結果、DOM、API、CLIで確認できるなら、画面をクリックするより状態を明確に取得できます。GUIはnative appや表示の欠けなど、他の方法では観察できない条件に使います。CodeのCLI computer useはmacOSのresearch previewで、plan・対話sessionの条件があります。CLI computer use。

表示の評価は、文字列がHTML内にあることと区別します。未実行例なら、狭いwindowでbuttonが隠れないか、keyboardだけで操作できるか、失敗表示が読めるかを確認項目にします。GUI操作が使えない環境では構造検査だけに留め、画面確認済みと記録しないことが重要です。

機能を足す順序

最初は組込みの読取・編集・testで一件を完成させます。繰り返す手順が見えたらSkill、外部データの転記が増えたらMCP、定型検査が必要ならhook、探索が大量ならsubagent、と不足に対応して足します。全部を先にinstallする必要はありません。

候補を追加する際には、動くことのほか、余分な権限、読み込む指示、文脈量、更新方法、外せる条件を確認します。人気やstar数は、特定案件への適合や安全性の証明ではありません。付加した機能なしのbaselineと比較し、確認時間が実際に減ったかを見ます。

チートシートの完成条件

自分用の機能表には、用途、対象面、前提、実行がもたらす作用、結果の確認方法を一行ずつ入れます。command名だけの一覧は便利でも、何を取り消せないかが見えません。公開や送信を伴う入口には、その境界を別に書きます。

評価では、慣れていない人が表から正しい入口を選べるか、cloudとlocal、CodeとAPI、開始と成功を取り違えないかを試します。画面やcommandが変わったら表の利用面を再確認し、古いhotkeyやflagを現行の保証として残しません。

機能表を手元の条件へ読み替える

必要な仕事を『読む』『変更する』『実行する』『外部へ送る』に分け、各動詞に実行面と観測方法を付けます。たとえば同じレビューでも、ローカル差分を読む仕事と、リモートへ書き込む仕事では必要な権限が違います。機能名の一致ではなく、目的へ至る経路が揃っているかを調べます。

教材では、使えない機能を一つだけ取り除いた条件を作ります。望ましい応答は存在しないコマンドを作ることではなく、できない工程を特定し、読み取りなど許された部分を独立して完了させることです。機能一覧は導入時の判断材料ですが、実環境で確認した利用可否の記録の代わりにはなりません。

両者は「同じ Gemini モデルへの異なる入口」だが、目的と規模がまったく異なる。AI Studio = プロトタイプ場、Vertex AI = 本番基盤と捉えると判断しやすい。

3. Vertex AI の主要サービス

RAG Engine

エンドツーエンドの RAG（検索拡張生成）パイプラインをフルマネージドで提供。埋め込み生成・ベクトル検索・生成を統合。

  • Serverless モード（Public Preview）: DB プロビジョニング不要
  • Spanner モード: 大規模エンタープライズ向け
  • 課金: コーパスストレージ + 検索クエリ + モデルトークン

Batch API

大量のリクエストを非同期で処理。通常の同期 API と比較して50% のコスト削減。

  • CSV / JSONL ファイルで一括入力
  • 処理完了後 Cloud Storage に出力
  • 100万件以上のドキュメント処理に最適
  • SLA 対象外（非同期のため）

Agent Builder

エンタープライズ向けの AI エージェント構築プラットフォーム。

  • Agent Engine: $0.0864/vCPU-時
  • Session & Memory: $0.25/1,000 イベント
  • Vertex AI Search: $1.50〜$6.00/1,000 クエリ
  • 社内データへのグラウンディング対応

Provisioned Throughput

レート制限を超えたスループットを事前に確保。本番トラフィックの急増に備えたキャパシティ予約。

Vertex AI Search

社内の非構造化データ（PDF・HTML・Docs 等）に対するエンタープライズ検索。Gemini でランク付けと要約を生成。

MLOps / Pipelines

カスタムモデルの学習・評価・デプロイ・モニタリングを統合管理。Feature Store・Experiment Tracking・Model Registry を内包。

② Batch API — 大量文書の非同期処理（50% OFF）

from google.cloud import aiplatform

# 入力: GCS 上の JSONL ファイル（1行1リクエスト）
# {"request": {"contents": [{"role": "user", "parts": [{"text": "..."}]}]}}

batch_job = aiplatform.BatchPredictionJob.create(
    model_name="gemini-3.5-flash",
    instances_format="jsonl",
    gcs_source="gs://my-bucket/input/*.jsonl",
    predictions_format="jsonl",
    gcs_destination_prefix="gs://my-bucket/output/",
)

batch_job.wait()
print(f"State: {batch_job.state}")

③ RAG Engine — 社内 PDF への Q&A

from vertexai.preview.rag import RagCorpus, RagFile
from vertexai.generative_models import GenerativeModel, Tool
import vertexai.preview.rag as rag

# コーパス作成（初回のみ）
corpus = rag.create_corpus(display_name="company-docs")

# PDF をインポート（GCS または Drive から）
rag.import_files(
    corpus.name,
    paths=["gs://my-bucket/docs/*.pdf"],
    chunk_size=512,
    chunk_overlap=100,
)

# Grounding ツールとして Gemini に統合
retrieval_tool = Tool.from_retrieval(
    retrieval=rag.Retrieval(
        source=rag.VertexRagStore(rag_corpora=[corpus.name]),
        similarity_top_k=5,
    )
)

model = GenerativeModel("gemini-3.1-pro", tools=[retrieval_tool])
response = model.generate_content("就業規則の時間外労働の上限は何時間ですか？")
print(response.text)

④ Model Garden — Claude on Vertex で呼び出す

import anthropic

# Vertex AI 経由で Claude を呼ぶ（同一 VPC・SLA が適用される）
client = anthropic.AnthropicVertex(
    region="us-east5",
    project_id="YOUR_PROJECT_ID",
)

message = client.messages.create(
    model="claude-opus-4-5@20250514",
    max_tokens=1024,
    messages=[{"role": "user", "content": "法的文書のレビューをお願いします: ..."}],
)
print(message.content[0].text)

6. Firebase AI — モバイル・Web アプリへの統合

Firebase AI（旧 Firebase ML）は Vertex AI の Gemini をモバイル / Web アプリに直接組み込むための SDK。バックエンドを書かずにクライアントから Gemini を呼べる。

対応プラットフォーム

  • Android（Kotlin / Java）
  • iOS / macOS（Swift）
  • Web（JavaScript / TypeScript）
  • Flutter（Dart）
  • Unity

主な特徴

  • API キーをクライアントに埋め込まずに Gemini 呼び出し可能
  • Firebase Authentication と統合（認証済みユーザーのみアクセス）
  • App Check によるリクエスト検証
  • Vertex AI の SLA・コンプライアンスがそのまま適用

代表的ユースケース

  • チャットアプリに Gemini を統合
  • スマホカメラで撮影した食材のレシピ提案
  • 音声メモの自動要約
  • オンデバイス処理が難しい複雑な推論
// Flutter (Dart) で Firebase AI を使う最小例
import 'package:firebase_ai/firebase_ai.dart';

final model = FirebaseAI.vertexAI().generativeModel(
  model: 'gemini-3.5-flash',
);

final response = await model.generateContent([
  Content.text('このレシピに合う副菜を3つ提案してください'),
]);
print(response.text);

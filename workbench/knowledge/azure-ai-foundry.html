Microsoft Foundry：モデルから運用までの開発基盤

旧Azure AI Foundryの説明を刷新。portalの一般提供、個別機能のpreview、classicとの互換、モデルの契約と配置を分けて選ぶ。

最終更新：2026-10-13 / 公式一次資料確認。実環境の機能・契約検査は未実施。

名前の変更だけでなく、resourceとAPIの世代を見る

Microsoft Foundryはagents、models、toolsと管理機能をまとめるAzureの開発・運用基盤だ。旧Azure AI Studio / Azure AI Foundryから現名称へ移行しており、hub-based projectやclassic portalと、新しいFoundry projectを区別する。現行概説と旧新対応。古いSDK例の名称だけ置換すれば動くわけではない。endpoint、resource、project、SDK版、API世代を一緒に確認する。

既存アプリがあるなら最初に現在のdeployment、認証、呼出し形式、データ、追加toolを一覧にする。新規開発の便利な機能と、既存システムの移行可能性を分ける。移行計画なしに旧resourceを削除したり、endpointを差し替えたりしない。本記事は公開資料の解説で、Azure設定変更や実deploymentを行った報告ではない。

GAとpreviewを製品単位で丸めない

新portalはGAだが全機能がGAではない。現行の公式readiness表ではmemoryやmonitoring等にpreviewが残り、機能・component・リージョン別の確認を求める。とくにFoundry Workflowsは2026-12-01の廃止予定と、新規開発にはMicrosoft Agent Frameworkを使う案内がある。workflowという一般語と、Foundryのその機能を混同しない。

筆者の判断表は、必要機能、GA/preview、対象region、対応resource、戻し方の五列で作る。portalが開けたという確認だけでは、閉域networkや特定認証で必要機能が使える証明にならない。previewが不可欠なら、本番依存にする前に運用方針と代替経路を決める。

モデル選択は能力・提供経路・契約の三点

FoundryのcatalogにはAzureが販売するモデルとpartner/communityのモデルがあり、対応する配置方法、サポート、条件が異なる。managed computeとserverlessは費用の構造も違う。Foundry Modelsの提供区分。有名なmodel familyでも、同じ重みのlocal版とAPI版は別のsystemとして評価する。

まず仕事に必要な入力・出力とtoolの要件を決める。画像を読むのか、schemaに沿って返すのか、長い入力を扱うのか。次に使えるregionとdeploymentを確認し、最後に自分のtest setで比較する。benchmarkの上位だけで、実資料の引用や日本語の根拠保存まで良いと結論しない。

課金は生成tokenだけとは限らない。検索、storage、compute、tools、評価、観測の費用を異なる行へ分ける。catalogへの掲載は、無料利用、利用可能quota、すべてのtenantへのアクセス、適法な用途の保証ではない。モデルcardと利用条件を読む責任は残る。

教材例：根拠付きの資料回答を比較する

未実行の試験案として、公開の短い資料を十件程度固定し、事実質問、資料にない質問、旧版混入、条件付きの仕様を用意する。modelごとに同じ入力・検索結果・出力schemaを渡し、回答だけでなく引用と保留を評価する。検索が不安定なままモデルだけ比較すると、何が差の原因か分からない。

出力schemaは主張、出典、適用条件、不明点にする。評価は正しい引用、条件の保存、資料外の断定、保留の適切さ、人の確認時間を別々に測る。品質が良くても遅延や費用が用途に合わなければ限定利用にする。自動評価の点数を単独の採用理由にせず、重大な誤りの原文を読む。

agentへ広げる前の制御点

モデルがtoolを提案する段階から、実際に書込む段階へ進むと失敗の性質が変わる。外部作用を含むtoolには入力検証、許可範囲、結果照会、重複制御を用意し、生成文だけで実行可否を決めない。sessionやtraceの保存にも秘密や個人情報が入る可能性があるため、観測を強めることと記録を増やすことを同一視しない。

運用へ渡す成果は、deploymentと設定の版、test set、失敗class、未対応条件、停止手順、戻し方を含む。Foundryの管理機能はその実装を助けるが、仕事の責任やリリース承認を代行しない。コードで工程制御が必要ならAgent Frameworkの記事へ進む。

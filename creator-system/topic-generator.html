システム内での役割

パイプライン全体の
「燃料補給エンジン」

ネタ生成AIはコンテンツファクトリーの最上流に位置するモジュールです。 人間がゼロから考えることなく、毎朝10〜20本の旬のネタを自動生成し、 動画・漫画パイプラインのジョブキューへ投入します。 ネタの質がパイプライン全体のアウトプット品質を左右するため、 評価システムのフィードバックを受けて継続的に自律最適化されます。

  • 入力元: Googleトレンド / RSS / SNS API / 手動投入
  • 出力先: 動画パイプライン & 漫画パイプラインのジョブキュー
  • フィードバック元: 評価システム・マネタイズ（成功パターン学習）
  • 生成本数: 毎朝6時に10〜20本バッチ生成（追加でオンデマンド対応）
  • メインLLM: Claude Sonnet 4.6（ネタ展開・スコアリング）

Google トレンド

直近24〜48時間の急上昇ワードをAPIで取得。「AIニュース」「テック解説」ジャンルに特化したフィルタを適用し、検索ボリューム急増のキーワードを優先。

RSS / ニュースフィード

TechCrunch・Wired・Ars Technica・NHK NEWS WEB など約30フィードを購読。LLMがタイトルと本文の要点を抽出し、動画ネタとしての転用可能性を判定。

30+ フィード 2時間ごと

SNS トレンド

X（旧Twitter）のトレンドワードと、RedditのAI・Tech関連サブレディットでの上位スレッドを収集。バズりやすいトーン・切り口を分析してネタに反映。

手動 / シード投入

人間が気になるトピックを自由入力するフォーム。OpenClawのダッシュボードからいつでも追加でき、朝の自動バッチとは別に即時パイプライン投入も可能。

即時反映 最優先キュー

拡張検討: ソース収集をキーワード一致だけでなく反復検索・再ランキングで賢く行う「Agentic RAG」的な設計は workbench/knowledge/context-engineering.html（「Agentic RAG」節）に整理がある。現行のネタ生成AIは単純なAPI呼び出し中心だが、将来的にこの方式へ寄せる余地がある。

2026年半ばの外部動向

ネタ生成の手法は
「後追い検知」から「先回り予測 + 自走エージェント」へ

2026年半ば時点で、コンテンツアイデア生成の業界的な潮流は大きく4つに整理できます。以下は公開情報から把握できる範囲の要約であり、 具体的な数値・製品名は出典時点のものです。ベンダーの機能は変化が速いため、導入判断時は必ず最新の一次情報を確認してください。

🔮

先回り型トレンド予測

「検索されるのを待つ」のではなく、ニュース素材からLLMが検索クエリ相当の候補を先に生成し、エンゲージメント強度・発信元の信頼度でスコアリングして急上昇の兆しを先取りする手法が研究・実運用の両面で報告されている（例: Meta系の実運用事例として紹介されたRTTP的アプローチ）。テールトレンドの検知精度が既存手法比で大きく改善したという報告もあるが、社内数値は非公開のため参考値として扱う。

先行生成型クエリ 要出典確認

生成フロー

5ステップで
ネタをキューへ

1

ソース収集 & 重複排除

全4ソースから素材を取得し、過去7日間の生成済みネタDBと照合して重複を除外。同一トピックでも異なる切り口なら別ネタとして保持する軽いセマンティック類似度チェックを実施（embedding距離0.85以上は重複とみなす）。

入力: 生素材 30〜100件 text-embedding-ada-002
2

ジャンル分類 & 適合フィルタ

LLMがジャンル（テック解説 / AI動向 / ハウツー / ニュース速報 / エンタメ）に分類し、チャンネルポリシーに合致するか確認。過去の評価スコアが低かったジャンルは重みを自動的に下げて除外しやすくする。

// ジャンル分類プロンプト（抜粋） classify("AppleがAIチップを新発表") // → { genre: "tech_news", sub: "hardware", // visual_fit: 0.82, audience: "general_tech", // urgency: "high" }
3

LLMによるネタ展開

残った候補をClaude Sonnet 4.6が1本ずつ展開。タイトル案・スクリプトの冒頭フック・想定尺・推奨フォーマット（ショート / 長尺 / 漫画）を生成。同一ネタから動画と漫画向けに別展開することで効率よく2本分のジョブを生成する。

# ネタ展開プロンプト構造 system: """あなたはバイラル動画のプロデューサーです。 与えられた素材から視聴者を掴むネタを設計してください。 評価基準: フック力・SEO適合・ビジュアル演出の豊かさ""" user: """ 素材: {raw_topic} 成功パターン: {feedback_from_evaluator} 除外パターン: {failed_patterns} 出力フォーマット: JSON（SKILL.mdのtopicスキーマ準拠） """
4

スコアリング & ランキング

5指標（下セクション参照）でネタを数値評価し、優先順にランキング。目標本数（デフォルト15）を超えた候補は翌日分のバッファに積むか破棄する。スコア60未満は生成しても意味が薄いため自動破棄。

スコア60未満: 自動破棄 上位15本: キュー投入 16〜20位: 翌日バッファ
5

パイプラインキューへ投入

最終ネタをOpenClawのジョブキューへ投入。フォーマット指定（shorts・long・manga）に応じて動画パイプラインまたは漫画パイプラインの該当スキルをトリガーする。緊急性の高いネタ（urgency: high）はキュー先頭に割り込む。

# ジョブ投入 (OpenClaw YAML) enqueue: skill: video-pipeline priority: "${topic.urgency}" payload: topic_text: "${topic.expanded_text}" genre: "${topic.format}" style_preset: "${topic.recommended_style}"
プロンプトパターン集

ネタ展開でよく使う
4つのプロンプト型

ステップ3「LLMによるネタ展開」の内部で実際に使い分けているプロンプトの型。汎用パターンとして整理しているため、具体的なチャンネルポリシーや成功パターン集は変数（{{...}}）で差し込む前提。プロンプトチェイニングの一般設計は workbench/knowledge/prompt-engineering.html（「プロンプトチェイニング」節）も参照。

① トレンド→ネタ変換パターン

生のトレンドワードを「なぜ今なのか」「誰が興味を持つか」まで含めて具体化する型。抽象的なキーワードのまま展開すると企画が薄くなるため、必ず「文脈」と「対象読者」を先に埋めさせる。

system: """あなたはトレンド分析の専門家です。 与えられたキーワードについて、(1)なぜ今話題なのか (2)誰が/どんな視聴者層が反応しそうか (3)動画/漫画に 落とし込める具体的な切り口を3つ、の順で出力してください。 抽象論で終わらせず、必ず固有名詞・具体例を含めること。""" user: """ キーワード: {{raw_keyword}} 関連文脈（ソースから抽出した要約）: {{context_summary}} チャンネルの過去ヒット傾向: {{success_patterns}} """

② フック（冒頭3〜5秒）生成パターン

ショート動画の視聴維持率は冒頭数秒でほぼ決まるとされる。フックだけを独立したプロンプトで複数案生成し、後段で本編と結合する2段構成にすることで、フックの質を本編の作り込みから切り離して磨き込める。

system: """あなたはショート動画のフック職人です。 以下のネタについて、最初の3〜5秒で視聴者の離脱を防ぐ フック案を5つ出してください。各案には想定される '離脱阻止の理由'（疑問形・意外性・数字提示 等）を タグ付けしてください。""" user: """ ネタ本文: {{expanded_text}} 避けたい表現（過去に不評だったフック傾向）: {{failed_hook_patterns}} """ // 出力例: // [{ hook: "実はこの機能、○○社員も知らない", // reason: "内部情報っぽさ・意外性" }, ...]

③ 競合ギャップ検出パターン（拡張候補・未実装）

同ジャンルで既出のコンテンツと比較し、「まだ誰も扱っていない角度」を優先する型。競合分析の自動化は業界的に広がりつつある領域だが、本システムでは現時点でソース連携が未実装のため、プロンプト設計のみ先行して用意している。

system: """あなたはコンテンツ戦略アナリストです。 同ジャンルの既出タイトル一覧と比較し、まだ扱われていない 角度・切り口を提案してください。既出と酷似する提案は却下し、 理由を添えてください。""" user: """ 新規ネタ候補: {{raw_topic}} 既出タイトル一覧（直近30日・同ジャンル）: {{competitor_titles}} """ // 注: competitor_titles の収集元は未確定（要検討）

④ 検索意図適合チェックパターン（GEO/AEO意識）

近年は生成AI検索（AI Overview・チャットボット回答）経由の流入も無視できなくなっており、キーワードSEOだけでなく「AIが要約・引用しやすい構造か」を意識する必要があるという指摘がある。スコアリングの「SEOポテンシャル」指標にこの観点を補助的に組み込む案。

system: """このネタの想定タイトル・要約が、検索エンジンの AI要約機能や対話型AI検索に引用されやすい構造か （明確な問いへの回答形式になっているか）を5段階で 評価し、改善案を1つ提示してください。""" user: """ タイトル候補: {{title_candidates}} 要約: {{expanded_text}} """
実例フロー（架空データ）

トレンド信号 → 候補絞込 → スコア化 → 制作へ引き渡し

以下は説明用に組み立てた架空の一例です（実在の事業ネタではありません）。各ステップの入出力イメージをつかむための最小構成として読んでください。

1. 信号

Googleトレンド急上昇: 「小型AIモデル 省電力」検索量が48時間で急増（RSSでも関連記事2件を検知）。

→ 生素材として source_mix に追加。embedding重複チェックで過去7日分と非重複を確認。
2. 候補絞込

ジャンル分類で tech_news / hardware と判定。visual_fit 0.7、urgency medium。チャンネルポリシー（テック解説寄り）に合致し次段へ通過。

→ この時点で候補は3〜5件程度に絞られている想定（他ソースからの候補と合流）。
3. ネタ展開

プロンプトパターン①②を通し、展開文＋タイトル案3本＋フック案5本を生成。「省電力AIチップが変えるエッジデバイスの未来」を軸に、ショート/長尺それぞれの構成案を出力。

4. スコア化

下記スコアリング指標で計算した結果（架空値）: ホット度72 / ビジュアル適合65 / ターゲット適合80 / SEO70 / シリーズ性40 → 加重平均 スコア69.8。閾値60を上回り採用。

5. 引き渡し

format: shorts のジョブとして動画パイプラインのジョブキューへ投入。urgency: medium のため通常順で処理。同時に漫画パイプライン向けにも別展開ジョブを投入（同一ネタの2系統展開）。

上記の数値・タイトルはすべて説明用の仮値。実運用のスコア分布や採用率は評価システム（evaluation.html）側のログを参照。

ホット度

検索ボリュームの増加率とSNSでの言及数から「今まさに旬か」を判定。ピーク前（急上昇中）のネタを高く評価し、すでに落ち着いたネタは低評価にする。

🎬
重み: 25%

ビジュアル転用適合度

動画や漫画のビジュアルに転用しやすいか。抽象的な概念より具体的なモノ・人物・場面があるネタを優遇。AI生成画像で表現しにくいトピックは低スコア。

🎯
重み: 25%

ターゲット層適合度

チャンネルの想定視聴者（20〜35歳テック好き）との一致度。過去の高評価コンテンツが扱ったトピック群との意味的距離で評価。ズレたネタは品質が高くても刺さらない。

📊
重み: 15%

SEO ポテンシャル

キーワードの月間検索ボリューム（Google Keyword Planner）と競合動画数の比から「勝てそうか」を予測。ブルーオーシャンのロングテールキーワードを優遇。近年はAI検索・チャット型回答（GEO/AEOと呼ばれる領域）経由の流入も無視できないとの指摘があり、上記プロンプトパターン④の観点を補助スコアとして加える案を検討中（未実装）。

🔄
重み: 5%

シリーズ展開可能性

1本で完結するネタより、続編や関連コンテンツへの展開が見込めるネタを優遇。チャンネル全体のシリーズ構造を強化することで視聴回帰率を上げる。

スコアは評価システムのフィードバック（PUBLISH / DISCARD）を週次で学習し、重みを自動チューニング。初期重みは上記の固定値。

運用スケジュール

1日の自動生成フローと
バッファ管理

メインバッチは毎朝6時に実行し、その日のパイプラインが消費するネタを補充します。 消化スピードに応じてバッファが常に5本以上残るよう追加バッチが自動実行されます。

06:00 — メインバッチ
全4ソースを収集してネタ15本を生成・スコアリング後にキュー投入。前日の評価フィードバックを反映して展開プロンプトを更新。
12:00 — 補充チェック
キューバッファが5本以下なら補充バッチ（5本）を自動実行。午前中の急上昇トレンドもここで反映。
18:00 — 翌日先取りバッファ
翌朝のネタを5本先生成してバッファに積む。突発的なトラブルでバッチが失敗しても翌日のパイプラインが止まらない保険。
随時 — 手動緊急投入
人間が重要トピックを発見したら OpenClaw ダッシュボードから即時投入。urgency: urgent でキュー先頭に割り込む。

フィードバックループ設計

評価システムとマネタイズシステムが返す結果を週次で学習し、展開プロンプトとスコアリング重みを自動更新します。これにより「どんなネタが実際に稼ぐか」を継続的に学習します。

PUBLISH → 成功パターン学習
評価85以上で公開されたネタの構造・キーワード・トーンを「成功パターン」としてプロンプトに注入。同系統のネタを次回から優遇。
DISCARD → 失敗パターン回避

Style Guide — 執筆・装飾の統一ルール

このハブで複数のセッション・エージェントが書いても一貫した品質を保つための執筆ルール集です。ページテンプレートが「骨格」を提供するのに対して、このページは「細部の選択基準」を提供します。

1. 文体・トーン

基本: です・ます調

運用ドキュメント・解説ページは原則「です・ます調」。読み手は社内チーム・自分自身・将来の AI セッション。距離感はフラット・敬語ベース。

OK: 「このページは新セッションが最初に開きます。」
NG: 「このページは新セッションが最初に開く。」（突然の常体は読み手を不安にさせる）

例外: 長文記事・技術仕様は常体可

research/* の長文（trend-* 等）や技術仕様書は、論文・新聞調の「である調」を許容。ただしページ内で混ぜない。

主語の省略

日本語の自然な主語省略は OK。ただし「誰がやったか」が変わる文脈では明示する（例: Anthropic / OpenAI / ユーザー / ハブ）。

断定 vs 推測

事実は断定、未確定は明示。「〜と報じられている」「〜の見通し」「2026年5月時点では」のような時点修飾を活用。

OK: 「Anthropic の評価額は $900B 規模と複数メディアが報じている（2026-05-23 時点・調達ラウンド進行中）。」
NG: 「Anthropic の評価額は $900B です。」（確定情報のように書かない）

2. 見出し階層

1ページにつき <h1> は 1 回だけ。以下、明確な階層を保つ。

レベル用途サイズ目安
<h1>ページタイトル。ヒーロー部に 1 回1.9-2rem
<h2>主要セクション。panel ごとに 1 個1.15-1.2rem
<h3>セクション内の小見出し0.95-1.05rem
<h4>必要な時のみ（普通は不要）0.88-0.95rem

飛ばし階層は禁止（h2 の下に直接 h4 など）。

4. バッジ運用

バッジは「常識的に分かる範囲」に絞る。多用すると目が滑る。

バッジ意味残置ルール
必読 新セッションがまず読むべきページ 恒久。役割変更まで外さない
NEW 最近追加・大きく刷新されたページ 1ヶ月経過で外す
LIVE 定期更新を続けるダッシュボード等 恒久。役割変更まで外さない
アーカイブ 過去の資料（イベント終了済み等） 恒久
PROPOSED ADR で提案段階 採用 / 却下で外す

5. ファイル命名規約

パターン用途例
kebab-case.html標準。全小文字・ハイフン区切りonboarding-checklist.html
YYYY-MM-DD-name.html日付付き（セッションログ・日次ニュース）2026-04-06-session-log.html
YYYY-qN-name.html四半期もの2026-q2-review.html
trend-<topic>.htmlIndustry Trends 配下の長文trend-ipo-race.html
NNN-slug.html連番系（ADR を独立ファイル化する場合）001-llm-hub-spinoff.html
NG: 大文字混在（HubHealth.html）、アンダースコア（hub_health.html）、日本語ファイル名、スペース入り

6. 日付・数値の書式

  • 日付: YYYY-MM-DD 統一（例: 2026-05-26）
  • 日付範囲: 「2026-05-19〜21」「2026年5月19〜21日」どちらでも可、ページ内で統一
  • 四半期: 「2026 Q2」「Q2 2026」「2026年Q2」のどれでも可、ページ内で統一
  • 大きな数値: 「$900B」「$10.9B」（B = Billion）、和訳必要なら「$900B（約135兆円）」
  • パーセント: 「52.5%」（半角％は使わない）
  • バージョン: 「v2.1.147」「Opus 4.7」（ピリオド区切り）

7. リンクの張り方

原則: 出典は実 URL に張る

外部リンクは必ず WebSearch / WebFetch で実在確認してから書く（AP-002 参照）。

OK: <a href="https://techcrunch.com/2026/05/19/...">TechCrunch</a>（2026-05-19）
NG: 推測 URL を確認せずに書く / 「~/article-name」のような形式の架空 URL

原則: 内部リンクは相対パス

../foundations/glossary.html のように、リポジトリルートからの絶対パスは使わない（GitHub Pages 等のサブパスデプロイで壊れる）。

「関連」セクションのテンプレ

ページの最後に必ず「関連」セクションを置く。最低限「親カテゴリ index」「Hub Top」「明らかに関連する2-3ページ」へのリンク。

8. 強調表現の使い分け

記法用途頻度
<strong>キーワード・数値・結論1段落 0-3 個程度
<code>コマンド・ファイル名・コード片必要なだけ
<em>使わない（イタリックは日本語で読みにくい）—
全文 太字禁止—
OK: 「Anthropic は 5月23日週にクローズ見込みの調達で、評価額は $900B 規模と報じられている。」（強調 2 箇所）
NG: 全部 太字 にしたり、1段落 に 5箇所 も strong を 使うこと

9. リスト・テーブルの選び方

形式使い時
<ul>列挙（順序に意味なし）。3-7 項目が目安
<ol>手順・ステップ（順序に意味あり）
<table>2軸の比較・分類（列＝属性、行＝対象）
段落散文1-2 項目の場合は無理にリスト化しない

10. コード・コマンドブロック

<pre> の左に必ず3px ティール枠を付ける（既存パターン）。シンタックスハイライトはしない（軽量さ優先）。

git fetch origin
git status
git log --oneline -10

1行コマンドは <code> インラインで。複数行・出力例は <pre>。

11. ページ末尾の必須要件

  1. 最終更新日: YYYY-MM-DD 形式で必ず記載
  2. 関連リンク: 親カテゴリ index へ・Hub Top へ・関連 2-3 ページ
  3. ソース表記: 外部情報を引いた場合は出典を実 URL 付きで明記

例（Light 系）

<p class="small">最終更新: 2026-05-26</p>

<div class="panel">
  <h2>関連</h2>
  <ul>
    <li><a href="...">...</a></li>
  </ul>
</div>

例（Rich 系）

<p class="last-update">最終更新: 2026-05-26</p>

12. ページ長の目安

用途目安行数例
カテゴリ index40-100行strategy/index.html
参照ドキュメント（短）100-300行anti-patterns.html
運用プロトコル（中）300-500行multi-instance-protocol.html
長文記事（長）400-700行trend-ipo-race.html
完全版トラッカー700-1200行claude-recent-updates.html

1500行を超える単一ページは分割を検討。読み込み・編集・スクロール全てが重くなる。

13. 「Done の定義」（簡易）

ページを「完成」とみなす最低条件:

  • ☑ <title> が「ページ名 | カテゴリ名」形式
  • ☑ breadcrumb がある（親カテゴリ・Hub Top へのリンク）
  • ☑ <h1> が 1 回
  • ☑ 最終更新日が記載
  • ☑ 関連セクションがある
  • ☑ 外部リンクは実在確認済み
  • ☑ 親カテゴリ index からリンクが張られている
  • ☑ コンソールエラー（broken markup）が無い

※ 詳細な「Done 定義」は Phase 3 で foundations/definition-of-done.html として別建て予定。

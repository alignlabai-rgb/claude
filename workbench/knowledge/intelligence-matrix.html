Prompt Style Guide

各モデルへの「話しかけ方」

モデルには個性がある。同じ指示でも書き方を変えると出力品質が大きく変わる。

Claude Opus 4.8 The Sage
構造化された文脈と明確なゴールに最もよく反応する。曖昧さを嫌い、前提・制約・期待する出力形式を最初に提示すると品質が上がる。
効くパターン
  • 「以下の制約に従って〜」と明示的な制約列挙
  • 「ステップごとに考えて」+最終形式の指定
  • 長い背景ドキュメントをそのまま渡す
避けるべき
  • ゴールが不明確な「なんとなくいい感じに」
  • 過度な礼儀・前置きトーク（無駄トークン）
GPT-5.5 The Pioneer
汎用性が最も高く、テキスト・画像・コードを一体で扱える。会話的なプロンプトでも高品質な回答を返す。ツール呼び出しの連鎖に非常に強い。
効くパターン
  • スクリーンショット＋「これを修正して」
  • 複数ファイルを渡して「全体的にリファクタ」
  • 「次のステップは何？」と会話的に進める
避けるべき
  • 倫理的にグレーな指示（拒否率が高い）
  • 出力形式を指定しない長文生成依頼
Gemini 3.1 Pro The Architect
コンテキストの量を大量に渡すほど真価を発揮する。動画・音声・PDF・コードを同時に混在させた入力が得意。最初に「あなたは〜の専門家です」のロール設定が効果的。
効くパターン
  • 100万トークン分の資料を渡して「要約＋設計」
  • 動画URLと「この動画でコードを説明して」
  • Google Workspaceとの連携タスク
避けるべき
  • 短い会話的やり取り（Claude/GPTが優位）
  • 最新ニュースの問い合わせ（情報鮮度で劣る）
Grok 4.3 The Maverick
簡潔で直接的なプロンプトに最もよく反応する。常時推論モードなので、思考過程を促す指示は不要。リアルタイム情報へのアクセスを積極的に活用させる。
効くパターン
  • 「今のXのトレンドを調べて実装して」
  • Grok Computerに「このアプリを操作して」
  • 短い1〜2行の明確な指示
避けるべき
  • 「ステップバイステップで考えて」（過剰出力になる）
  • 1万字超の長文コンテキスト渡し
DeepSeek V4-Pro The Disruptor
論理的な段階分解が得意。英語でプロンプトを書くと品質が上がりやすい。FIM（Fill-In-the-Middle）補完に特化したAPIがあり、コード補完に直接組み込める。
効くパターン
  • 英語で「Let's solve this step by step」
  • FIM APIでエディタ補完に直結
  • 数学・アルゴリズム問題を具体的に
避けるべき
  • 政治・センシティブなトピック（制限あり）
  • 最新情報の取得（カットオフに注意）
Qwen 3.6-Plus The Scholar
多言語対応が strongest。出力言語を明示的に指定すると精度が上がる。大量リクエストを投げてコスト削減を狙う用途に最適。数学・コードは英語で指示すると有利。
効くパターン
  • 「日本語で出力して」と言語明示
  • バッチ処理・大量翻訳に並列投入
  • 数式・コードは英語プロンプト推奨
避けるべき
  • 高度な倫理判断・安全性評価タスク
  • 言語を指定しない多言語混在入力

Limitations

各モデルの弱点・限界

ベンチマーク首位では見えないリアルな制約。過信せず適材適所で使う。

Claude Opus 4.8 $5/$25
  • 全9モデル中、単価が最高水準
  • リアルタイム情報なし（Webアクセス限定）
  • 倫理判断が厳しく、コンテンツ生成を拒否することがある
  • 新トークナイザーにより同一入力でもトークン数が増加傾向
GPT-5.5 高価格帯
  • コンテンツポリシーが厳格（創作系で制限あり）
  • 自律エージェントの長時間実行で安定性にばらつき
  • レスポンス速度がモデルサイズの割に遅い場合がある
  • API利用にOpenAIプラットフォーム依存が強い
Gemini 3.1 Pro Google依存
  • 短い会話的なやり取りはClaude/GPTが優位
  • Google Workspaceエコシステム外での恩恵が薄い
  • 入力データがGoogle側でログされる可能性（エンプラ要注意）
  • レート制限が他社より厳しいプランがある
Grok 4.3 TTFT 7.5s
  • 初回レスポンスまでの時間（TTFT）が7.5秒と長め
  • 常時推論モードで出力が冗長になることがある
  • X/Twitter依存のデータソース（偏りが生じる可能性）
  • サービス稼働率がAnthropicやOpenAIより実績が浅い
Mistral Medium 3.5 256k上限
  • フロンティアモデルに対して精度で5〜10pt程度劣る
  • コンテキスト上限256k（他の1Mモデルに比べ狭い）
  • リアルタイムWeb情報へのアクセスなし
  • Modified MITの"例外条項"（大企業は要確認）
DeepSeek V4-Pro 割引〜5/31
  • 割引終了後（6/1〜）は価格が約4倍に跳ね上がる見込み
  • 政治・センシティブなトピックに強い検閲フィルタ
  • 中国サーバー経由のため、機密データは送らないこと
  • カットオフが古く最新情報取得不可
GLM-5.1 128k上限
  • 英語の長文生成品質はGPT/Claudeに劣る
  • コンテキスト上限128kは現世代では最小クラス
  • 国際展開が限定的でAPIサポート体制が薄い
  • 中国規制準拠のコンテンツフィルタが強め
Kimi K2.6 安定性
  • APIの不安定性・レイテンシ増大の報告が散見される
  • 日本語サポートが英語・中国語より品質低め
  • 300サブエージェント並列は実際のコスト爆発に注意
  • 国際プライバシー規制への準拠状況が不透明
Qwen 3.6-Plus フィルタ強め
  • 安全フィルタが強く、グレーなコンテンツを広く拒否
  • 最高精度タスクではフロンティアモデルに10〜15pt劣る
  • Alibaba Cloudアカウントが必要（直接APIへの壁）
  • 日本語の複雑な文脈理解はClaude/GPTに劣る

Code Snippets

API 呼び出しコードスニペット

各モデルへの最短接続コード（Python）。コピペで即動作する。

Claude Opus 4.8 pip install anthropic 
import anthropic

client = anthropic.Anthropic(api_key="YOUR_KEY")
msg = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    messages=[{"role": "user",
               "content": "Hello"}]
)
print(msg.content[0].text)
GPT-5.5 pip install openai 
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY")
res = client.chat.completions.create(
    model="gpt-5.5",
    messages=[{"role": "user",
               "content": "Hello"}]

Benchmark Glossary

ベンチマーク用語解説

このページに登場するスコアが「何を測っているか」を一行で理解する。

SWE-bench Verified

GitHubの実際のIssueをAIが自動解決できるか

現実のOSSリポジトリからIssueを抽出し、AIがコードを修正してテストを通過できるか測定。"Verified"は検証済みタスクセット（精度が高い）。GPT-5.5が88.7%で現在首位。

SWE-bench Pro

Verifiedより難しい多言語・複合タスク版

Python以外（Go・Rust・TypeScript等）のリポジトリも含む、より困難なバリアント。50〜60%超えが現在の上限水準。Claude Opus 4.8が64.3%で首位。

GPQA Diamond

大学院レベルの科学問題（生物・物理・化学）

人間の専門家でも正解率65〜70%程度の難問。90%超えは実質"超人的"なレベル。3強（Claude 94.2%・Gemini 94.3%・GPT 94.4%）はほぼ横並び。

Video-MME

動画の内容を時系列で理解できるか

字幕なしの動画を見て質問に答えるマルチモーダルベンチマーク。時間軸の因果関係・場面転換を理解する能力を測定。Gemini 3.1 Proが78.2%で首位。

MMLU

57分野の知識問題（法律・医学・数学など）

知識の広さ・深さを横断的に測定する総合テスト。90%超えが現在の標準水準。フロンティアモデルが揃って90〜93%台に集中している。

Code Arena Elo

人間がコード品質を投票するELOレーティング

チェスと同じELO方式で、どちらのコードが良いかを人間が判断。主観的な「実用性・読みやすさ」を反映する。GLM-5.1が1,530で上位。

Terminal-Bench 2.0

エージェントがターミナル操作を自律的にこなせるか

ファイル操作・ビルド・テスト実行・デプロイなどのターミナルタスクをAIエージェントが自律完了できるか測定。GPT-5.5が82.7%で首位（Claude Codeとの親和性が高い）。

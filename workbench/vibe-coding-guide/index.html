Vibe Coding：意図から検査できる実物へ

AIとの対話を、動くものと再利用可能な失敗知見へ変える実践ガイドです。大きな一括生成より、一つの機能を端から端まで確かめる流れを扱います。

最終更新: 2026-10-13

作りたいものを、確かめられる形へ

Vibe Codingを、コードを読まずに任せ続ける方法ではなく、自然言語の意図から小さな実物へ反復する制作として扱います。最初に読者や利用者が何をできれば成功かを決めます。「見やすいページ」より「日付別のニュースを選び、元資料へ戻れるページ」の方が、完成したかを確かめやすくなります。

このガイドは公開教材の制作方法です。特定のツールの性能や組織の内部規則を保証しません。実際に試していない出力は成功例にしないこと、権限や秘密を扱う操作を小さな試作に混ぜないことを前提にします。

モデル以外の層も設計する

制作は、入力、作業環境、コード、データ、検査、引き渡しの層で成立します。モデルがコードを書けても、ファイルの権限、依存関係、実行場所、ネットワーク、公開方法は別に決まります。ローカルで動く画面があることと、処理や保存が手元で完結することも違います。

まず静的HTMLで足りるか、JavaScriptが必要か、サーバーや外部APIが本当に必要かを選びます。依存が少ない試作ほど確認する箇所は少なくなりますが、静的であれば内容が正しいという保証にはなりません。モデル名や流行より、目的に必要な最小の層を選びます。

提案を読む、挙動を観測する

生成されたコードは、意図に沿った提案です。説明に「動作する」とあっても、起動、入力、出力、異常系を観測するまでは確認済みにしません。仕様を勝手に足す、秘密を求める、すべてのファイルを変更するなどの提案がないか、差分を先に読みます。

エラーは「もっと頑張って」と返すより、入力、期待、実際の差、再現条件へ分けて渡します。失敗を次の小さなテストへ変えると、同じエラーに戻ったことを検出できます。原因が未確定なら、仮説と確認方法を分けます。

一つの機能を端から端まで通す

  1. 利用者の操作を一つ選び、完成条件と禁止する副作用を書く。
  2. 架空の入力で、最小の画面や処理を作る。
  3. 正常入力、空入力、長い入力、存在しない参照を試す。
  4. 期待との差を一つずつ直し、元のテストも再実行する。
  5. 本文、構造、依存、参照、使い方を揃えて引き渡す。

架空の例として、ニュース一覧を日付で絞る機能なら、「一致する記事が見える」「該当なしを示す」「空入力で元へ戻る」「外部へ送信しない」が条件になります。最初からユーザー管理や課金を追加する必要はありません。この例は実際の導入実績ではありません。

並列化はファイルと問いを分ける

画面、データ整形、独立レビューを分けることはできますが、共有CSSや同じ一覧を複数の担当が同時に変更すると統合が難しくなります。専有範囲、受け取る入力、完成物、検査を指定し、統合の順序を決めます。詳細は並列編集へ。

候補の担当へ知らせることと、採用や実行を決めることは別です。配送上の確認を通ったからといって、公開や契約まで進めません。制作者の自己検査を独立レビューと呼ばないようにします。

残すのは長文日誌より再利用できる差

入力: 架空記事3本、日付を空で指定
期待: すべて表示される
実際: 一覧が空になる
原因の仮説: 空文字を日付条件として比較
修正: 空入力なら条件を適用しない
再確認: 空・一致・該当なし・長い入力

これは教材用の失敗例です。成功を作り上げるのではなく、失敗を再現できる小さな入力と評価点を残します。実データに秘密があるなら、同じ性質を持つ架空データへ置き換え、公開してよいかを別に確認します。

七つの確認観点

ここでいう観点は法律や内部規則ではありません。目的が明確か、範囲が小さいか、秘密を使わないか、副作用を分けたか、失敗を試したか、証拠を残したか、他者が使えるかを確認します。一つの検査で残りすべてを保証しないことが大切です。

HTMLの見出しは意味のある順序で組み、本文へ戻れる導線を持たせます。論理的な構造はW3Cのページ構造解説も参照できます。見た目だけでなく、狭い画面、キーボード、該当なしの表示を見ます。

使える依頼の型

目的: 架空データの一覧を日付で絞る
対象: このHTMLだけ。共有CSSと公開設定は変更しない
入力: 日付と記事3件。秘密や実アカウントは使わない
完成: 空・一致・該当なしの3ケースが説明どおり
禁止: ネットワーク送信、ログイン、課金、外部公開
報告: 差分、検査したケース、未確認、反映状態

ツールの選択にはAIツール地図、作業の根拠整理にはコンテキスト設計、完成の読み方には完成基準を使います。依頼文だけを整えて終わらず、利用者が見られる小さな実物まで完成させてください。

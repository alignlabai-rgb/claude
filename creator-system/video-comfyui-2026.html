ComfyUIでローカル実行できる主要モデル

モデル 開発元 特徴 VRAM目安
LTX-2 Lightricks（2026-01-06公開） ネイティブ4K・最大50fps。映像と同期した音声（会話・環境音・音楽）を1パスで同時生成する点が最大の特徴。ComfyUI本体にビルトイン済み（Manager経由でLTXVideo検索→自動DL） 12GB（FP8）/ 24GB（bf16）
HunyuanVideo-1.5 Tencent（2025-11-21公開） 8.3Bパラメータで最大1080p。独自のSSTAアテンション機構で競合比ほぼ2倍の効率。480p I2Vの8-12ステップ蒸留版はRTX 4090で約75秒生成 14GB（オフロード時の下限）/ ComfyUI公式実装では24GB推奨（Qwen2.5-VLエンコーダ+byT5+VAE+超解像モデルを同時ロードのため）
Wan2.6シリーズ Alibaba（2025-12-16公開） T2V/I2V/R2V（参照動画から外見+声を継承）の4モデル構成。マルチショットのストーリー性・最大15秒動画に対応。次世代Wan 3.0（600億パラメータ・4K・30秒連続生成）は2026年半ば予定 14B版はFP8量子化で40〜48GB（480p）。GGUF量子化（Q5_K_M/Q6等）で6GBまで圧縮可能（速度とのトレードオフ）
💡 「音声つき動画を1パスで作りたい」ならLTX-2一択。「解像度より安定した実写風の質感」ならHunyuanVideo-1.5。「同じキャラの声と見た目を別シーンで再現」したいならWan2.6-R2V、という使い分けが2026年7月時点の目安。
具体的ワークフロー①

LTX-2で音声つき動画を生成する

ComfyUI Managerで「LTXVideo」を検索してインストールすると、重みは初回実行時に自動ダウンロードされる。 カスタムノードの追加インストールは不要（v0.26.0でLTX2 Context Windowsノードがコア機能として統合済み）。

  • 1. インストール: ComfyUI Manager → "LTXVideo" 検索 → インストール
  • 2. モデル選択: VRAM 12GBならFP8量子化版、24GB以上ならbf16版
  • 3. プロンプト: 映像描写に加えて「せりふ・環境音・BGM」も同じプロンプトに含める（音声も同時生成のため）
  • 4. Context Windows: IC-LoRAガイドで長尺シーンを分割サンプリングし、シーン間の一貫性を維持
# LTX-2 基本ワークフロー構成（ComfyUI公式サンプル準拠） LTXVLoader(precision="fp8") # 12GB環境向け → LTXVConditioning( prompt="教室のドア。少女が驚いた声で 「……えっ、本当に？」と言う。 廊下の環境音、緊張感のあるBGM", fps=50, resolution="4K" ) → LTX2ContextWindow( window_size=97, # フレーム数 overlap=16 ) → KSampler(steps=30) → LTXVDecode → SaveVideoWithAudio # 映像+音声を1ファイルに書き出し
具体的ワークフロー②

SCAIL-2でキャラクターの動作を転写・置換する

SCAIL-2（zai-org公開、arXiv論文「Unifying Controlled Character Animation with End-to-end In-Context Conditioning」）は、 中間ポーズ表現（OpenPose骨格等）を介さず、駆動動画の動きを参照キャラクター画像へ直接転写する。Animation Mode（キャラが動きを演じる）と Replacement Mode（動画内の人物を参照キャラに置き換える）の2モードがある。

Replacement Mode: 実写動画のキャラを差し替える

# ComfyUI標準ノードのみで完結（追加カスタムノード不要） LoadVideo("driving/actor_walk.mp4") → SAM3Track() # 人物トラッキング → SCAIL2ColoredMask( replacement_mode=True # グローバルトグルと一致させる ) → WanSCAILToVideo( reference_image="ref/hiro_face_body.png", mode="replacement" ) → SaveVideo

複数人物が映る動画では、SCAIL2ColoredMaskの「identity↔color」の対応関係が駆動側・参照側で一致している必要がある（順序がズレると別人の特徴が混入する）。

manga-pipeline.html「複数キャラクター同フレーム」への応用

manga-pipeline.htmlの複数キャラクター対応節では ControlNet Openposeでキャラ別の骨格レイヤーを手動合成していたが、 SCAIL-2のBinding Slotsは複数キャラの識別情報を保持したまま動作転写できるため、 群像シーンの動画版プレビズとして使い、そこから代表フレームを抜き出してコマ化する、という漫画×動画の連携ワークフローが2026年7月時点で技術的に成立する。

商用クローズドモデルとの使い分け

オープン運用 vs API課金

Runway Gen-4.5・Kling 3.0・Veo 3.1・Grok Imagineなどクローズド商用モデルの詳細は video-pipeline.html と research/grok-recent-updates.html 等の月次トラッカーを参照。 ここでは判断軸だけ整理する。

観点 オープン（ComfyUI自前運用） クローズドAPI（Runway/Kling/Veo等）
初期コスト GPU購入/レンタル費用が先行 ゼロ（従量課金のみ）
単発品質の上限 現状はクローズド最上位に一歩譲ることが多い 最新最高品質を追従しやすい
量産時のコスト GPU代のみ、生成数に応じた変動費が小さい 生成数に比例して膨らむ
キャラ一貫性の作り込み SCAIL-2・LoRA等で細かく制御可能 参照画像入力程度に限定されることが多い
実例 — 実際の制作スタジオ事例

Series Entertainment社の
ComfyUI動画本番運用

ゲーム・動画スタジオのSeries Entertainment社（Netflixタイトル複数を出荷）は、 Story → ComfyUI（画像・動画生成）→ Assembly という一気通貫パイプラインを構築し、 クリエイター1人あたり週15分の完成動画をボット統合による自動実行で継続生産している。

  • パイプライン設計: 512×512の低解像度テストから高解像度バッチ生成まで、同一ワークフローを使い回す4本構成
  • 自動化: バッチ実行 + ボット連携で、同じワークフローを繰り返し実行する仕組み化に注力
  • 成果: 資産10万点以上、制作速度は従来手法（1資産6時間以上）比180倍

Source: ComfyUI Blog — Case Study: How Series Entertainment Rebuilt Game and Video Production with ComfyUI（2026-02-19）

video-pipelineへの示唆

video-pipeline.htmlはAPI課金モデルを前提に「動画1本あたりのコスト」を管理する設計だが、 Series社の事例は「ワークフローそのものを資産として保有し、実行コストだけを繰り返し払う」という別のコスト構造を示している。 制作本数が一定量を超える段階では、ComfyUI自前運用への移行を検討する損益分岐点があるという前提で、 video-pipeline.htmlの「技術スタック」節に代替シナリオとして記録しておく価値がある。

深掘り① — 実在スタジオの技術分解

Corridor Digitalは実際どう作ったか
（実写→アニメ変換の全工程）

YouTubeのVFXスタジオCorridor Digital（チャンネル名 Corridor Crew）が公開した 「実写をアニメ化する」ワークフローを技術要素ごとに分解する。抽象的な「AIで変換」ではなく、実際に何を・どの順で・何のツールで処理したかを追う。

初代プロジェクト（じゃんけんバトル）

① 撮影
スマートフォンで衣装を着た自分たち自身をグリーンバック撮影。3Dの背景セットはUnreal Engineで構築し、カメラを配置した2Dスクリーンショットとして使用（フル3Dカメラワークではない）
② スタイル学習
初代は既存アニメ「ヴァンパイアハンターD 血闘編」のフレームを学習データにしてスタイルモデルを訓練。加えて出演者本人の写真を複数枚学習させ、顔の同一性を確保
③ フレーム単位のimg2img変換
テキストプロンプトからの生成ではなく、撮影した実写フレームをDiffusionで1枚ずつ画像変換する方式（text2imgではなくimg2img）
④ 最大の壁: フレーム間のちらつき
AIはフレーム単位で処理するため、コマ間で線・色が微妙に変わり激しいちらつきが発生。対策はDaVinci ResolveのDeflickerエフェクトを複数回重ね掛け。さらにフレームレートを24〜30fpsから12fpsまで落とすことで、アニメ特有の「コマ打ち」感とちらつき軽減を両立

2作目での進化（重要な方針転換）

既存アニメを学習データにするのをやめた
初代は既存アニメ「ヴァンパイアハンターD」のフレームを直接学習に使ったため、著作権・スタイル模倣を巡る批判を受けた。 2作目では実在のアーティストを雇い、オリジナルのモデルシート（キャラクター設定画）を描き起こしてもらい、 それを学習データの起点にする方式へ転換。これにより①法的・倫理的リスクの低減、②スタイルの一貫性向上、の両方を達成している。
残りの工程（AI以外の部分）
グリーンバック除去（従来型キーヤー）→ 背景合成 → 光線・グロー・レンズ歪み等のエフェクトオーバーレイ → 編集・音響設計。 最終的なVFXショット数は約120で、AI生成部分は「素材を作る一工程」に過ぎず、大半は従来型の合成・編集作業が占めている。

Source: ProVideo Coalition — Live Action to Anime with Corridor Digital / Corridor Digital公式YouTube

💡 2026年7月時点でこの案件を組み直すなら: 「既存アニメを学習データにする」代わりに、SCAIL-2のReplacement Mode（本ページ内「具体的ワークフロー②」参照）でオリジナルキャラの参照画像を直接動画に転写する構成にすれば、Corridor Digitalが2作目で辿り着いた「アーティスト起点のモデルシート」路線を、LoRA学習なしでより短い工程で再現できる可能性がある。

深掘り④ — 中国AI動画市場の実例

中国では誰がAI動画で稼いでいるか
Kling・Seedanceの実際

AI動画の商用実装が最も速いのも中国市場。プラットフォーム側の売上規模から実際の配布戦略まで、確認できた数字だけを記録する。

Kuaishou「Kling AI」

2025年通期売上は約104億元（約1,500億円）、2026年は倍増以上を目標とする。ARRは2025年3月の$1億から2026年3月には$5億まで拡大、2026年Q1単体売上は6.5億元超。2026年に入り190億元（約2,800億円）規模の資金調達（評価額150億ドル、16.7%株式と引き換えに30億ドル）を実施し、出資元にはBlueFive Capital（アブダビ）・百度・騰訊が名を連ねる。課金モデルは消費者向けサブスクが軸で、4K出力・長尺の安定性を求めるプロ向けには上位プランを用意している。

ByteDance「Seedance」

Doubao・Dreamina（醸夢）・即夢（Jimeng）・CapCutに裏側のインフラとして組み込まれて配布されており、杭州の漫劇制作会社の中には「Seedanceというブランド名を意識せずに使っている」ケースもあるという、B2B2Cのインフラ戦略が特徴。Seedance 2.0は月商10億元（約150億円）を突破し、ByteDanceのクラウド部門・火山引擎は2026年のMaaS（モデルAPI課金）売上目標を100億元から150億元に上方修正した。

深掘り⑤ — AI短劇市場の光と影

「作り込んだ動画」の量産現場
中国AI短劇（ショートドラマ）市場

中国の縦型ショートドラマ（短劇）市場にAI制作が本格流入している。市場拡大のスピードと、その裏側にある過当競争の実態を両方記録する。

指標 数値
短劇市場全体（2026年H1） 約540億元（通年予測1,200億元、+20%）
うちAI短劇（2026年H1） 約110億元（通年予測240〜350億元）
2026年Q1 制作本数 約12.8万本（うち95%超がAIを活用した制作）
1本あたり制作コスト 従来 約50万元 → AI活用 約3〜5万元（90%超減）

儲かっている実例

  • 酱油文化（創業者: 黄浩南）: 2025年通期売上約10億元、純利益2〜3億元を公表している数少ない黒字企業
  • 中文在線（上場企業）: 2026年Q1のAI短劇制作本数が前年比+300%、2026年末までに年間約3,000本のAI短劇制作体制を目標。AI短劇関連の思惑で、累計損失（10億元超）にもかかわらず株価が年初来+1,300%まで急騰した局面があり、投機的な過熱の実例としても記録される

厳しい現実

市場全体で見ると短劇制作会社の90%以上は赤字という指摘がある。1万再生あたりの収益は30〜100元から5〜25元まで暴落しており、供給過多による単価崩壊が進行中。2025年に新規参入したAI制作会社のうち40%以上が既に撤退したとも報告されている。「AIで作れば儲かる」という段階はすでに終わり、企画力・IP・配信網を持つプレイヤーだけが生き残る局面に移っている。
💡 短劇プラットフォーム（抖音・快手等）も「人工智能生成合成内容標識辦法」（2025年9月1日施行）の対象で、AI生成動画には画面上のラベル表示とメタデータ/電子透かしの付与が義務化されている。海外向けにAI短劇・AI動画を輸出する場合も、この開示要件を前提に制作フローを設計しておくと後々の手戻りが少ない。

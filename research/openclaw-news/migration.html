OpenClaw 移行：コピーできる状態と、引き継げない意味

最終更新・公式情報確認：2026-10-13。news という旧 URL は維持し、本文は用途別の現行ガイドへ刷新しました。確認日は発表日ではありません。

例と評価案は筆者の設計提案で、未実行です。性能測定・本番導入・安全認定・正式採用の実績を示すものではありません。

別の agent 基盤から移すこと、同じ OpenClaw を別の機械へ移すこと、版を上げることは違う移行である。旧記事の AutoGPT、LangChain、CrewAI からの万能な変換コマンドは現行の公式対応として引き継がない。移行を名前の置換ではなく、状態、秘密、実行権限、仕事の契約の確認として扱う。

公式の三つの道

Migration guide は、他の agent 系からの import、別機械への移動、plugin の更新を説明する。import の計画表示、秘密の扱い、保存状態の確認が含まれる。Migration guide対応があることを、全ての過去の手順と provider の権利を同じ意味で移せる保証にしない。

筆者の移行表では、指示文書、skills、モデル設定、MCP、履歴、記憶、秘密、定期ジョブ、通知先を別行にする。移す、合成して再構成する、移さない、未確認の四つを選ぶ。空欄を自動 import の想像で埋めない。

動いている状態の raw copy

公式は、変化している SQLite と WAL の raw copy が食い違いを生む可能性を説明し、機械移動では Gateway を静止して検証したバックアップを取る工程を示す。Migration guideフォルダがコピーされたことと、復元できることは別である。

この棚は停止やコピーを実行しない。実際に移行する際は、誰が利用を止め、何を保全し、どこへ staging を置き、何を確認したら切り替えるかを決める。移行先が起動する前に元の状態を消さない。秘密を含む archive を共有教材へ使わない。

同じ文章でも権限は変わる

旧基盤の「作業フォルダで処理する」という文を移せても、新しい基盤で同じ隔離が有効とは限らない。OpenClaw の multi-agent は workspace が hard sandbox ではないと注意する。Multi-agent routingプロンプトを持ち込むときは、実行先と許可ツールを別に対応させる。

合成の資料整理を旧構成と新構成で比較し、禁止した読み取り、送信、書き込みが同じように止まるかを検討する。文章の内容だけ一致しても、禁止効果を防げなければ意味の移行は未完了である。

古い版からの更新

公式 Updating は、古い状態の移行に bridge release が必要になる場合、app が更新を所有する場合、退役した管理機能の扱いなどを説明する。Updating全ての構成へ最新 package を入れる一行で済むとしない。利用するインストール方式と旧版に応じた文書を読む。

設定の自動コピーを完全なバックアップと呼ばない。アプリの更新、Gateway package、plugin、保存スキーマの版を分ける。動く画面だけを確認して、定期処理と記憶の回帰検査を省かない。

切り替えの教材

公開資料二件の比較という同じ課題で、旧側の入力 ID と出力を保存し、新側で同じ合成入力を評価する。根拠、保留、停止、保存が一致するか見た後、必要な通知の検討へ進む。旧側と新側が両方同じ外部通知を出す構成は避けたい。

差が出たら、改善、意図した変更、未確認のずれを分ける。全てを旧側と同じに戻す必要はないが、境界が変わったことを隠さない。切り替えと、旧コピーの退役は別の判断にする。

移行完了の証拠

採用した状態の一覧、検証した復元、残した原本、変更した権限、失敗条件、戻す条件が読める一枚を残す。ファイル数や進捗百分率より、対象の仕事を再現できる証拠が重要である。秘密と認証の専門判断をこのガイドが代行することはない。

Qwenは「通千問（Tóngqiānwèn）」の名が示す通り、あらゆる問いに答えることを目指して設計されました。特に理数系タスクとプログラミングにおいて、商用トップモデルに肉薄、あるいは凌駕する性能を見せています。

Qwen-Coder: The Coding Specialist

Qwenファミリーの中でも、Vibe Codingにおいて最も重要なのが「Qwen-Coder」です。

  • Code-First Thinking: 一般的な会話データだけでなく、膨大なコードリポジトリと技術文書で学習されており、「開発者の文脈」を完璧に理解します。
  • Artifact Generation: 単なるスニペットではなく、ファイル構造全体や、実行可能な完全なスクリプトを生成する能力に長けています。

Multilingual & MoE

Qwen 3.6-Plusは、効率的なMoE（専門家混合）アーキテクチャを採用しています。

Global Understanding

Cost Efficiency

推論時にアクティブになるパラメータ数を抑えることで、高性能でありながら高速かつ低コストな動作を実現しています。

Deep Dive: 自前で安く回す量産エンジン

ALIGN_Lab のような「自動でコンテンツを量産する」運用では、Qwen は速報トラッカーで追う 6 本の一角として位置づけています。理由は性能首位だからではなく、オープンウェイト × ローカル運用 × 猛烈な更新頻度という「工場を安く・速く回す」三拍子にあります。

ローカル運用（オープンウェイト）

重みが公開されているため、ローカル GPU や自前サーバーで動かせます。クラウド API のトークン課金に依存せず、量産パイプラインのコストを大きく圧縮できるのが最大の利点です。MoE アーキテクチャで、サイズの割に推論コストを抑えられる点もローカル向き。

動画・マルチモーダル

テキストだけでなく画像・動画方向のマルチモーダル展開が進んでおり、制作パイプラインの前処理（素材理解・タグ付け・構成判断の補助）に組み込みやすい系列です。

更新頻度の速さ

主要 LLM の中でも特にリリース・派生モデルの回転が速く、「追い続ける価値が高い」のが速報トラッカー入りの決め手。現行は Qwen 3.6-Plus、コーディング特化の Qwen-Coder が併走します。

役割整理: Qwen =「ローカル・低コストの量産エンジン」。質の最終判断は Claude / GPT-5.5、構成・長尺は Gemini、自動化エンジン本体は GLM-5.1 が担う多軸構成の中で、Qwen は"安く速く回す土台"を受け持つ。

Deep Dive ①: どの Qwen を、どこで動かすか

Qwen を「マスターする」上で最初に効くのは、系列の使い分けです。同じ Qwen でも「クラウド API で呼ぶ最上位」と「ローカルで回すオープンウェイト」は役割が違います。

系列（canon）置き場所使いどころ

「A3B」がローカルの鍵: 総パラメータは大きくても、MoE は推論時に一部の専門家（≒3B）だけを起動します。だから「35B級の賢さ」を「3B級の負荷」で回せる＝一枚 GPU で量産できる、という理屈です。

Deep Dive ②: ハードウェアと量子化（VRAM の考え方）

ローカルで動くか／何枚 GPU が要るかは、ほぼ VRAM と量子化で決まります。ざっくりの目安：

  • VRAM の目安: FP16（無圧縮）なら「アクティブ param 数 × 約2GB」、INT4 量子化なら「× 約0.5GB」。35B-A3B はアクティブ約3B なので、INT4 で実効数 GB に収まり 24GB の RTX 4090 一枚に乗ります。
  • 量子化フォーマット: GGUF（Ollama / LM Studio / llama.cpp 向け）、AWQ / GPTQ（vLLM 向け）。INT4 でも品質劣化は小さく、VRAM を 1/2〜1/4 に圧縮できます。
  • 推論エンジンの選択: Ollama＝最も手軽（個人・検証）、LM Studio＝GUI で試す、vLLM＝バッチ並列でスループット最大（量産向き）、llama.cpp＝低 VRAM / CPU フォールバック。
  • 量産のコツ: vLLM で並列バッチを回せば、一枚 GPU でも実効スループットが大きく伸びます。「1リクエストの速さ」より「単位時間あたりの本数」で設計する。

Deep Dive ③: コスト設計 — ローカル vs API の損益分岐

「自前で安い」が成立する条件を、コストの形で捉えると判断が速くなります。

API（従量）

トークン量 × 単価で使うほど比例増。初期投資ゼロ・即起動・最新モデルにすぐ乗れる。低頻度・最高品質・試作向き。

ローカル（OSS Qwen）

GPU 初期投資 ＋ 電気代で事実上使い放題。一定の月間トークン量を超えると単価が API を下回る。大量・反復・オフライン/機密向き。

損益分岐の考え方: 「月にどれだけ叩くか」が閾値。下書き・分類・整形・要約のような大量反復工程はローカル Qwen が圧倒的に安い。一方、最終品質が要る一発勝負は API（Plus/Max や他社フラッグシップ）。

現実解＝ハイブリッド: 量産の下流（下書き・タグ付け・整形）はローカル Qwen で安く回し、質の最終判断だけ Claude / GPT-5.5 の API に通す。これが ALIGN_Lab 的な「自動コンテンツ量産」のコスト最適パターンです。

注意: ローカルは「無料」ではない。電気代・GPU の減価・運用/保守の手間も“コスト”。完全自前に振り切るより、まずは「量産工程だけローカル」から始めるのが安全。

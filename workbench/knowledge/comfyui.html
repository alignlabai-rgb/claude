Section 01

ComfyUI とは — Automatic1111 との比較

ComfyUI は Stable Diffusion の推論パイプラインをグラフ（ノード＋エッジ）として視覚化・操作する OSS フレームワーク。UI 上で組み立てたワークフローは JSON としてエクスポートでき、Python API や REST API から再現性を保ったまま自動実行できる。

比較軸ComfyUIAutomatic1111 (A1111)
操作スタイルノード接続（グラフ）フォーム入力（タブUI）
API 自動化◎ 最適 — JSON ワークフローをそのままPOST△ — 独自パラメータ形式で変換が必要
柔軟性任意パイプライン構築可（分岐・並列可）標準フローのみ（拡張は Extensions 依存）
学習コスト高め（ノード概念の習得が必要）低め（直感的フォーム）
VRAM 効率細粒度制御可能自動管理（制御しにくい）
再現性◎ JSON = ワークフローの完全な仕様書△ seed + 設定メモで管理が必要
AI Creator Hub 適性◎ 採用 — バッチ・API 連携が前提の漫画自動生成に最適△ 手動操作向き
なぜ ComfyUI を選ぶか: 漫画コマを 1 話 30〜80 枚バッチ生成し、LoRA + ControlNet + IP-Adapter を組み合わせる用途では、JSON ワークフロー = 「生成仕様書」として扱える ComfyUI の再現性が決定的に有利。詳細は manga-pipeline.html を参照。

Section 03

基礎概念 — ノードとデータフロー

ComfyUI の全ての処理はノード（Node）の組み合わせで表現される。ノード同士をエッジ（接続線）でつなぐことで、データがフローし最終的に画像が生成される。

データ型

MODEL

Stable Diffusion の U-Net 重み。CheckpointLoader → LoRALoader → KSampler へ流れる。

CLIP

テキストエンコーダー。プロンプト文字列を Conditioning（ベクトル）に変換する入力。

VAE

Latent ↔ Pixel 変換器。生成後の Latent を画像に戻す（デコード）のに必須。

LATENT

潜在空間の中間表現。KSampler が操作するメイン対象。WIDTH×HEIGHT÷8 の解像度。

IMAGE

ピクセル空間の画像テンソル。VAEDecode 後、または LoadImage で得られる。

CONDITIONING

CLIPTextEncode の出力。Positive / Negative の 2 本が KSampler に入る。

基本データフロー

→ MODEL, CLIP, VAE
↓ MODEL ↓ CLIP ↓ VAE（それぞれ別経路）
CLIPTextEncode (positive)
→ CONDITIONING(+)
CLIPTextEncode (negative)
→ CONDITIONING(−)
↓ MODEL + COND(+) + COND(−) + LATENT → KSampler

→ LATENT
KSampler
→ LATENT（ノイズ除去済）
↓

JSON での接続表現

UI のエッジは JSON では ["node_id", output_index] 形式で表現される。

LoRA — キャラクター固定と画風制御

LoRA（Low-Rank Adaptation）はベースモデルの重みを低ランク行列で微調整する技術。キャラクター固定・画風指定・ポーズ偏重に使う。

単一 LoRA

{
  "class_type": "LoraLoader",
  "inputs": {
    "model": ["1", 0],
    "clip": ["1", 1],
    "lora_name": "char_yuki_v3.safetensors",
    "strength_model": 0.8,
    "strength_clip": 0.8
  }
}

複数 LoRA のチェーン

LoraLoader を直列接続することで複数 LoRA を積み重ねられる。

// LoRA 1: キャラクター
"lora1": {
  "class_type": "LoraLoader",
  "inputs": {
    "model": ["checkpoint", 0],
    "clip": ["checkpoint", 1],
    "lora_name": "char_yuki.safetensors",
    "strength_model": 0.8,
    "strength_clip": 0.8
  }
},
// LoRA 2: 画風（前段の出力を受ける）
"lora2": {
  "class_type": "LoraLoader",
  "inputs": {
    "model": ["lora1", 0],
    "clip": ["lora1", 1],
    "lora_name": "style_manga_v2.safetensors",
    "strength_model": 0.6,
    "strength_clip": 0.4
  }
}

strength の調整指針

strength_modelstrength_clip効果典型的用途
1.01.0LoRA 全開。プロンプト追従が弱まることもキャラクター固定重視
0.80.8バランス型。最初のデフォルト値に最適汎用
0.6〜0.70.4〜0.5画風LoRAに。モデル寄りは強く、CLIP は控えめスタイル微調整
0.00.0LoRA 無効化（ノードを残したまま off）A/B テスト
LoRA 過負荷の症状: 顔崩れ・手指異常・極端な色変化。複数 LoRA を使う場合は合計 strength を 1.5〜2.0 以内に収めることを推奨。品質が下がったらまず strength を 0.1 ずつ下げる。
Section 07

ControlNet — ポーズ・輪郭・構図の制御

ControlNet は参照画像から抽出した「構造情報（骨格・輪郭・深度）」を条件として画像生成をガイドする。LoRA がキャラクターを固定するのに対し、ControlNet はポーズと構図を固定する。

タイプ抽出情報用途推奨モデル
Cannyエッジ（輪郭線）既存コマの線を保ちつつ塗り変え、漫画コマの輪郭継続control_v11p_sd15_canny
Openpose人体骨格 18点ポーズ指定、複数キャラクターの位置固定control_v11p_sd15_openpose
Depth深度マップ前景/背景の奥行き関係を維持control_v11f1p_sd15_depth
Lineartラインアート手描き線画の彩色control_v11p_sd15_lineart
Tileタイル分割高解像度アップスケール時のディテール維持control_v11f1e_sd15_tile

ControlNetApplyAdvanced の JSON

{
  "cn_apply": {
    "class_type": "ControlNetApplyAdvanced",
    "inputs": {
      "positive": ["clip_pos", 0],    // CLIPTextEncode の出力
      "negative": ["clip_neg", 0],
      "control_net": ["cn_loader", 0],  // ControlNetLoader の出力
      "image": ["preprocessor", 0],    // 前処理済み参照画像
      "strength": 0.85,
      "start_percent": 0.0,            // 何 % ステップ目から有効化
      "end_percent": 0.7              // 何 % ステップ目まで有効化
    }
  }
}

start_percent / end_percent の意味

start_percent: 0.0, end_percent: 0.7 の場合、25 steps 中のステップ 0〜17 で ControlNet が有効。後半ステップでは解放することでディテールの自由度を確保できる。

  • 0.0 〜 1.0: 全ステップで強制（最もタイト）
  • 0.0 〜 0.7: 構造を固めつつ仕上げは自由（推奨）
  • 0.2 〜 0.8: 初期ノイズを自由にしつつ中盤以降で誘導

前処理ノード

参照画像は前処理ノードでControlNet入力形式に変換する。

  • Canny前処理: CannyEdgePreprocessor（low_threshold: 100, high_threshold: 200）
  • Openpose前処理: OpenposePreprocessor（detect_hand: true）
  • Depth前処理: MiDaS / ZoeDepth Preprocessor
  • 前処理なしで直接参照画像を渡すことも可能（既に前処理済みの場合）

IP-Adapter — 参照画像からスタイル注入

IP-Adapter（Image Prompt Adapter）は参照画像の視覚的特徴（色味・スタイル・雰囲気）を動的に U-Net へ注入する。LoRA が「訓練済み静的特徴」を使うのに対し、IP-Adapter は「推論時の動的注入」。

比較軸LoRAIP-Adapter
特徴の格納モデルファイルに焼き込み推論時に参照画像から抽出
新キャラ対応新LoRAを訓練（時間がかかる）参照画像1枚で即対応
安定性◎（同一モデルで常に安定）△（参照画像品質に依存）
組み合わせControlNet・IP-Adapterと併用可LoRA・ControlNetと併用可
典型的用途主人公キャラクター固定サブキャラ・背景スタイル統一

完全な Python クライアント実装

import json, uuid, urllib.request, urllib.parse, websocket
from pathlib import Path

COMFY_HOST = "127.0.0.1:8188"

def queue_prompt(workflow: dict) -> str:
    """ワークフローをキューに追加し prompt_id を返す"""
    client_id = str(uuid.uuid4())
    payload = json.dumps({"prompt": workflow, "client_id": client_id}).encode()
    req = urllib.request.Request(
        f"http://{COMFY_HOST}/prompt",
        data=payload,
        headers={"Content-Type": "application/json"}
    )
    result = json.loads(urllib.request.urlopen(req).read())
    return result["prompt_id"], client_id

def wait_for_completion(prompt_id: str, client_id: str) -> None:
    """WebSocket で完了を待機"""
    ws = websocket.WebSocket()
    ws.connect(f"ws://{COMFY_HOST}/ws?clientId={client_id}")
    while True:
        msg = json.loads(ws.recv())
        if msg["type"] == "executing":
            data = msg.get("data", {})
            if data.get("node") is None and data.get("prompt_id") == prompt_id:
                break  # 完了
    ws.close()

def get_images(prompt_id: str) -> list[bytes]:
    """生成画像のバイナリリストを返す"""
    history = json.loads(
        urllib.request.urlopen(f"http://{COMFY_HOST}/history/{prompt_id}").read()
    )
    images = []
    outputs = history[prompt_id]["outputs"]
    for node_output in outputs.values():
        for img_info in node_output.get("images", []):
            params = urllib.parse.urlencode({
                "filename": img_info["filename"],
                "subfolder": img_info["subfolder"],
                "type": img_info["type"]
            })
            img_data = urllib.request.urlopen(f"http://{COMFY_HOST}/view?{params}").read()
            images.append(img_data)
    return images

def generate_panel(workflow: dict, save_dir: str = "output") -> list[Path]:
    """ワークフローを実行して生成画像を保存。パスリストを返す"""
    prompt_id, client_id = queue_prompt(workflow)
    wait_for_completion(prompt_id, client_id)
    images = get_images(prompt_id)

    saved = []
    save_path = Path(save_dir)
    save_path.mkdir(exist_ok=True)
    for i, img_bytes in enumerate(images):
        path = save_path / f"{prompt_id}_{i}.png"
        path.write_bytes(img_bytes)
        saved.append(path)
    return saved

# 使用例
if __name__ == "__main__":
    with open("workflow_txt2img.json") as f:
        workflow = json.load(f)

    # シードとプロンプトを動的に変更
    workflow["6"]["inputs"]["seed"] = 12345
    workflow["3"]["inputs"]["text"] = "1girl, yuki, running, park, sunset"

    paths = generate_panel(workflow)
    print(f"生成完了: {paths}")
Section 10

バッチ生成 — 漫画 1 話分を自動生成

1 話 30〜80 コマを JSON ワークフローを書き換えながら連続生成する実装例。失敗時の再試行ロジック付き。

import json, copy, random, time
from pathlib import Path
# generate_panel は Section 9 の実装を使用

def build_workflow(base_wf: dict, scene: dict) -> dict:
    """シーン情報からワークフローを構築"""
    wf = copy.deepcopy(base_wf)

    # プロンプト更新
    wf["3"]["inputs"]["text"] = scene["prompt"]

    # シード（再現性確保 or ランダム）
    wf["6"]["inputs"]["seed"] = scene.get("seed", random.randint(0, 999999999))

    # LoRA 切り替え（キャラクターごと）
    if "lora" in scene:
        wf["2"]["inputs"]["lora_name"] = scene["lora"]
        wf["2"]["inputs"]["strength_model"] = scene.get("lora_weight", 0.8)

    # 解像度（コマサイズ別）
    wf["5"]["inputs"]["width"] = scene.get("width", 832)
    wf["5"]["inputs"]["height"] = scene.get("height", 1216)

    return wf

def generate_manga_chapter(
    chapter: list[dict],
    base_workflow_path: str,
    output_dir: str,
    max_retries: int = 3
) -> dict:
    """1話分のコマをバッチ生成。成功/失敗の集計を返す"""
    with open(base_workflow_path) as f:
        base_wf = json.load(f)

    results = {"success": [], "failed": []}

    for i, scene in enumerate(chapter):
        scene_id = scene.get("id", f"scene_{i:03d}")
        attempt = 0

        while attempt < max_retries:
            try:
                wf = build_workflow(base_wf, scene)
                paths = generate_panel(wf, save_dir=f"{output_dir}/{scene_id}")

                results["success"].append({
                    "scene_id": scene_id,
                    "paths": [str(p) for p in paths]
                })
                break

            except Exception as e:
                attempt += 1
                wait = 2 ** attempt  # 指数バックオフ
                print(f"[{scene_id}] attempt {attempt} failed: {e}. retry in {wait}s")
                time.sleep(wait)

                if attempt >= max_retries:
                    results["failed"].append({"scene_id": scene_id, "error": str(e)})

    print(f"完了: {len(results['success'])} 成功 / {len(results['failed'])} 失敗")
    return results

# 使用例: scenes.json からバッチ実行

        {"id": "s001", "prompt": "1girl, yuki, classroom, morning light", "lora": "char_yuki.safetensors"},

Section 12

VRAM 最適化

VRAM 16 GB+（RTX 3080/4080 以上）

フル性能
  • 追加オプション不要。SDXL フル精度で動作
  • batch_size: 4 でスループット向上
  • 複数モデルの同時キャッシュ可能

VRAM 8〜12 GB（RTX 3060/3070）

推奨構成
  • 起動フラグ不要だが --lowvram で安定性向上
  • SDXL 使用時は batch_size: 1 に固定
  • fp16 で半精度推論（品質ほぼ変わらず）

VRAM 4〜8 GB（GTX 1080/RTX 2060）

要チューニング
  • --lowvram 必須
  • SDXL は厳しい。SD 1.5 系 (512px) 推奨
  • VAEDecodeTiled ノードでOOMを回避
  • steps: 20 に抑える

VRAM ≤ 4 GB / CPU のみ

低速モード
  • --novram または --cpu
  • 1 枚の生成に数分〜十数分
  • 動作確認・プロンプト検証用途に限定
  • SD 1.5 系 512×512 のみ現実的

速度改善テクニック

手法効果デメリット
steps を 20 に削減生成速度 25〜30% 向上やや品質低下（特にディテール）
LCM LoRA + sampler:lcm4〜8 steps で生成可（3〜5×高速）画風が変わることがある
TurboXL / Lightning LoRA4〜8 steps、SDXL 品質維持cfg 値調整が必要（1.0〜2.0）
batch_size を上げる複数枚を並列生成でスループット向上VRAM 使用量が比例増加
モデルをあらかじめロード初回以降のキュー処理が高速化VRAM 常時確保
SSD への配置モデルロード時間が 2〜5× 短縮—

エラー対処

エラー原因対処
CUDA out of memory VRAM 不足 --lowvram 追加 / batch_size を 1 に / VAEDecodeTiled 使用 / steps 削減
真っ白な画像が出力される VAE ミスマッチ / cfg 値が高すぎる モデル専用 VAE を明示的にロード / cfg を 6〜7.5 に下げる
FileNotFoundError: model xxx not found モデルファイルのパスが違う ComfyUI の models/ 以下の正しいフォルダへ配置。大文字/小文字・拡張子確認
RuntimeError: expected scalar type Half but found Float fp16/fp32 型の混在 モデルと ControlNet の精度を揃える。--force-fp32 または --force-fp16 で統一
生成が極端に遅い（1枚15分以上） CPU 推論になっている GPU ドライバー確認 / torch.cuda.is_available() で True か確認 / PyTorch の CUDA 版を再インストール
KeyError: 'prompt_id'（API） ワークフロー JSON に構文エラー POST の response body に error フィールドがあるか確認。ノードIDの重複・参照切れを探す
LoRA 適用後に顔崩れ strength が高すぎる / LoRA とベースモデルの不整合 strength_model を 0.6〜0.7 に下げる。LoRA 訓練に使ったベースモデルと合わせる
ControlNet が効いていない 前処理画像の解像度不一致 / strength が低い 前処理画像を生成解像度と同じにリサイズ / strength を 0.8〜1.0 に上げる
WebSocket で完了通知が来ない client_id 不一致 / 接続タイムアウト POST した client_id と ws 接続の client_id が同じか確認。ws に ping/pong ハートビートを追加
LoRA + ControlNet 同時使用でのよくある落とし穴: ControlNet の前処理画像と生成解像度が一致していないと、ControlNet が正しく機能しない。必ず ImageScale ノードで前処理画像を EmptyLatentImage と同じ解像度（例: 832×1216）にリサイズしてから ControlNetApplyAdvanced に渡すこと。

import yaml, json, copy, random
from pathlib import Path
# clip_similarity は open_clip などで実装
from clip_utils import compute_clip_similarity

def load_character(char_yaml_path: str) -> dict:
    with open(char_yaml_path) as f:
        return yaml.safe_load(f)

def generate_consistent_panel(
    scene: dict,
    character: dict,
    base_workflow: dict,
    max_attempts: int = 5
) -> Path | None:
    """CLIP スコアが閾値を超えるまで再生成する"""
    ref_image = character["reference_image"]
    threshold = character["clip_threshold"]

    for attempt in range(max_attempts):
        wf = copy.deepcopy(base_workflow)

        # キャラクター LoRA を設定
        wf["lora"]["inputs"]["lora_name"] = character["lora"]
        wf["lora"]["inputs"]["strength_model"] = character["lora_strength"]

        # プロンプト合成（trigger words + scene prompt）
        full_prompt = f"{character['trigger_words']}, {scene['prompt']}"
        wf["clip_pos"]["inputs"]["text"] = full_prompt
        wf["clip_neg"]["inputs"]["text"] = character["negative_base"]

        # cfg とシード
        wf["sampler"]["inputs"]["cfg"] = scene.get("cfg", 7.5)
        wf["sampler"]["inputs"]["seed"] = (
            scene.get("seed") if attempt == 0
            else random.randint(0, 999999999)  # リトライは別シード
        )

        paths = generate_panel(wf, save_dir=f"output/{scene['id']}/attempt_{attempt}")
        if not paths:
            continue

        # CLIP スコアでキャラクター一致度を検証
        score = compute_clip_similarity(str(paths[0]), ref_image)
        print(f"  [{scene['id']}] attempt {attempt}: CLIP={score:.3f} (threshold={threshold})")

        if score >= threshold:
            return paths[0]  # 合格

    # 全試行失敗 → HITL にエスカレーション
    print(f"  [{scene['id']}] CLIP threshold not met after {max_attempts} attempts → HITL")
    return None

# 実行例
char = load_character("characters/yuki.yaml")
scenes = [
    {"id": "s001", "prompt": "sitting at desk, classroom, morning light", "cfg": 7.5},
    {"id": "s002", "prompt": "running in hallway, surprised", "cfg": 8.0},
    {"id": "s003", "prompt": "rooftop, sunset, hair blowing in wind", "cfg": 7.0},
]
with open("workflow_char_consistent.json") as f:
    base_wf = json.load(f)

for scene in scenes:
    result = generate_consistent_panel(scene, char, base_wf)
    print("OK:" if result else "HITL:", scene["id"])

def generate_emotion_set(
    character: dict,
    base_scene: str,
    base_workflow: dict,
    base_seed: int = 42,
) -> dict[str, Path]:
    """5感情分を一括生成。base_seed + index でバリエーション"""

    return results

from pathlib import Path

def apply_face_fix_to_chapter(
    chapter_dir: str,
    face_workflow_path: str,
    quality_threshold: float = 0.55
) -> dict:
    """chapter_dir 内の全コマに顔修正を適用"""
    chapter_path = Path(chapter_dir)
    panels = list(chapter_path.glob("**/*.png"))
    results = {"fixed": 0, "skipped": 0}

    with open(face_workflow_path) as f:
        face_wf = json.load(f)

    for panel_path in sorted(panels):
        # 顔検出スコアが低い場合のみ修正（不要な書き換えを避ける）
        face_score = evaluate_face_quality(str(panel_path))
        if face_score >= quality_threshold:
            results["skipped"] += 1
            continue

        face_wf["load_original"]["inputs"]["image"] = str(panel_path.name)
        fixed_paths = generate_panel(face_wf, save_dir=str(panel_path.parent))

        if fixed_paths:
            # 元ファイルを上書き保存
            panel_path.write_bytes(fixed_paths[0].read_bytes())
            results["fixed"] += 1

    print(f"顔修正: {results['fixed']} 枚修正 / {results['skipped']} 枚スキップ")
    return results

メイン実行スクリプト

import yaml, json, zipfile
from pathlib import Path
from datetime import datetime

class ChapterPipeline:
    def __init__(self, base_workflows_dir: str):
        self.workflows = {
            "txt2img":  self._load_wf(f"{base_workflows_dir}/txt2img.json"),
            "face_fix": self._load_wf(f"{base_workflows_dir}/face_fix.json"),
            "upscale":  self._load_wf(f"{base_workflows_dir}/upscale.json"),
        }

    def _load_wf(self, path: str) -> dict:
        with open(path) as f: return json.load(f)

    def run(self, script_path: str, output_dir: str) -> Path:
        with open(script_path) as f:
            script = yaml.safe_load(f)

        chapter_id = f"ch{script['chapter']:02d}"
        out = Path(output_dir) / chapter_id
        out.mkdir(parents=True, exist_ok=True)
        log = []

        for panel in script["panels"]:
            print(f"▶ [{panel['id']}] {panel['type']}: {panel['prompt'][:50]}...")

            # 1. メイン生成
            char = yaml.safe_load(open(panel["character"])) if panel.get("character") else None
            path = self._generate(panel, char)

            # 2. 顔修正（フラグがある場合）
            if panel.get("face_fix") and path:
                path = self._face_fix(path, char)

            # 3. アップスケール（フラグがある場合）
            if panel.get("upscale") and path:
                path = self._upscale(path, char)

            # 4. 最終コマをコピー
            if path:
                dest = out / f"{panel['id']}.png"
                dest.write_bytes(path.read_bytes())
                log.append({"id": panel["id"], "status": "ok", "path": str(dest)})
                print(f"  ✓ 保存: {dest}")
            else:
                log.append({"id": panel["id"], "status": "failed"})
                print(f"  ✗ 失敗: {panel['id']} → HITL キュー追加")

        # 5. 完成コマを ZIP にまとめる
        zip_path = out.parent / f"{chapter_id}_{datetime.now():%Y%m%d_%H%M}.zip"
        with zipfile.ZipFile(zip_path, "w") as zf:
            for png in sorted(out.glob("*.png")):
                zf.write(png, png.name)

        success = sum(1 for l in log if l["status"] == "ok")
        print(f"\n{'='*50}")
        print(f"第{script['chapter']}話「{script['title']}」完了")
        print(f"成功: {success}/{len(log)} コマ → {zip_path}")
        return zip_path

    def _generate(self, panel: dict, char: dict | None) -> Path | None:
        wf = copy.deepcopy(self.workflows["txt2img"])
        base_prompt = panel["prompt"]
        if char:
            base_prompt = f"{char['trigger_words']}, {base_prompt}"
            wf["lora"]["inputs"]["lora_name"] = char["lora"]
            wf["lora"]["inputs"]["strength_model"] = panel.get("lora_weight", char["lora_strength"])
        wf["clip_pos"]["inputs"]["text"] = base_prompt
        wf["sampler"]["inputs"]["cfg"] = panel.get("cfg", 7.5)
        wf["latent"]["inputs"]["width"] = panel.get("width", 832)
        wf["latent"]["inputs"]["height"] = panel.get("height", 1216)
        paths = generate_panel(wf, save_dir=f"tmp/{panel['id']}")
        return paths[0] if paths else None

    def _face_fix(self, path: Path, char: dict | None) -> Path:
        wf = copy.deepcopy(self.workflows["face_fix"])
        wf["load_original"]["inputs"]["image"] = str(path.name)
        if char:
            wf["lora"]["inputs"]["lora_name"] = char["lora"]
        paths = generate_panel(wf, save_dir=str(path.parent))
        return paths[0] if paths else path

    def _upscale(self, path: Path, char: dict | None) -> Path:
        wf = copy.deepcopy(self.workflows["upscale"])
        wf["load_original"]["inputs"]["image"] = str(path.name)
        if char:
            wf["lora"]["inputs"]["lora_name"] = char["lora"]
        paths = generate_panel(wf, save_dir=str(path.parent))
        return paths[0] if paths else path

# 実行
if __name__ == "__main__":
    pipeline = ChapterPipeline(base_workflows_dir="workflows/")
    zip_path = pipeline.run("script/chapter01.yaml", output_dir="output/")
    print(f"配信用 ZIP: {zip_path}")

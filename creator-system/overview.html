6 ステップの自動フロー

「ネタ生成」と「生成」の間に構造化・脚本という共通前処理を挟み、動画/漫画の2系統へ分岐させるのが実際のパイプライン構造です（詳細な工程×スタック対応は stack-map.html の5工程表を参照）。

1
ネタ生成

トピック・企画の自動生成

ジャンル・ターゲット・トレンドを入力すると、動画タイトル案・漫画ストーリー案・投稿スケジュールを AI が生成する。ボツ率が高いため大量生成 → 評価スコアでフィルタリングする運用が基本。

2
構造化・脚本

シーン・セリフ・カメラ/コマ割りへの構造化（共通前処理）

ネタ生成の出力を、動画・漫画どちらのパイプラインからも読める共通フォーマット（シーン分割・セリフ・カメラ/コマ指定）に変換する工程。同じ構造化結果を2系統に流用することで API コストと処理時間を削減する設計。長尺コンテンツは Claude Opus 4.8、コスト優先時は Sonnet 4.6 / Flash 系に自動切替。

生成

動画 / 漫画コマの自動生成（並列分岐）

🎬 動画パイプライン
ElevenLabs (TTS) → Veo 3.1 / RunwayML Gen-4 (映像) → Suno (BGM) → FFmpeg (合成) の7ステップ。
📖 漫画パイプライン
ComfyUI（LoRA + ControlNet + IP-Adapter）でコマを生成 → ADetailer で顔を修正。参照画は Imagen 4 Ultra。

どちらも Python API 経由で OpenClaw が自動実行し、完了後は同じ評価キューへ合流する。

4
評価

品質スコアリング & 選別

Vision モデル（Gemini 3.1 Pro）と CLIP スコアで画質・キャラクター一致度・構図を採点。スコア 85+ は即公開キュー、70〜84 は改善指示付き再処理、69 以下は破棄 or HITL。フィードバックはネタ生成 AI へ環流して自律改善。

オーケストレーション層

OpenClaw が全体を繋ぐ

OpenClaw は上記 6 ステップの「繋ぎ役」。各ステップは独立した Python モジュールとして実装されており、OpenClaw が JSON ワークフローとして順次起動する。

  • ステップ間のデータ受け渡し（ファイルパス / メタデータ）を管理
  • API エラー時の自動リトライ（指数バックオフ）
  • 品質評価スコアに応じた分岐制御
  • HITL 発動時の Signal 通知と返答待機
  • 全ステップの実行ログを構造化 JSON で保存

詳細な実装は openclaw.html の HITL・フォールバック設計を参照。

# OpenClaw ワークフロー定義（概念） pipeline: - step: topic_generation module: topic_generator output: topics.json - step: structuring module: script_structurer input: topics.json output: script.json - step: content_generation parallel: - module: video_pipeline - module: comfyui_batch input: script.json hitl: lora_fallback_threshold - step: evaluation module: content_evaluator hitl: score_boundary - step: distribution module: platform_publisher targets: [note, youtube, kdp] - step: kpi_update module: kpi_collector feedback_to: topic_generation

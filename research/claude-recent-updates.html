Claude 最新アップデート完全版

Anthropic の公式ニュース、Claude Help Center の release notes、Claude Code の official changelog をもとに、2026年2月から6月26日までの大きな変化を 実務視点で再整理したページです。今回は単なる出来事の列挙ではなく、 何が変わり、どこに効き、どう使い分けるかまで厚めにまとめています。

4月後半の本質は、Claude が「賢いチャット」や「強いコーディングモデル」から、 長時間タスクを運転できるワークスタックへ一段進んだことです。 具体的には、Opus 4.7 が hardest task を引き受け、 Cowork が知識ワーク自動化の器になり、 Claude Design がデザインと資料をつなぎ、 Claude Code が実装支援からレビューと運用まで含むエージェント基盤に寄ってきています。

5月中旬の本質は、横展開と本番運用の整備です。Mythos / Project Glasswing で サイバー領域、Claude for Legal で法務、Claude for Small Business で中小企業へと垂直展開。同時に Code with Claude London（5/19〜）で Memory・ Self-hosted sandboxes・MCP tunnels など、Managed Agents を 実際の業務で回すための機能が public beta に揃いました。

5月末（5/26〜29）の本質は、新フラッグシップと事業基盤の確定です。 Claude Opus 4.8 が SWE-Bench Pro 69.2% で記録を更新し「最も誠実なモデル」を掲げ、 Effort Control で推論コストを task 単位で調整可能に。 Series H $650億調達が正式クローズ（評価額 $9,650億）して非上場 AI で世界首位の評価額に到達し、 Gates Foundation との $2億パートナーシップ・Google / Broadcom との数 GW 級コンピュート拡張・ SpaceX Colossus 全容量確保と、規律あるスケーリングが一気に具体化しました。

6月上旬の本質は、Mythos 級モデルの公開と、ガバナンスリスクの顕在化です。 Claude Fable 5 が 6/9 に一般提供モデルとして追加され、同一系統の Claude Mythos 5 は Project Glasswing 向けの限定提供に入りました。 ただし 6/12 に米政府の輸出管理指示を受け、Anthropic は Fable 5 / Mythos 5 の全ユーザーアクセスを一時停止。 Opus 4.8 など他モデルは影響なしですが、最高性能モデルは性能だけでなく政策・安全保障の制約も運用要件になる段階に入りました。

6月中旬以降の本質は、IPO への布石と国際展開・チーム協働への拡張です。 6/1 に SEC へ Form S-1 の機密提出（10月上場を視野）、6/17 にアジア太平洋3拠点目となる ソウルオフィスを開設し NAVER・Samsung SDS・LG CNS などと連携。 6/22 に Micron との戦略的パートナーシップ（Series H 戦略的出資含む）、 6/23 に Claude Tag for Slack（Enterprise / Team 向けベータ）を発表。 Claude Code は v2.1.187〜v2.1.193 で安全性・パフォーマンスが大幅強化されています。

6月末（6/30）の本質は、新デフォルトモデルの刷新と、輸出規制問題の決着です。 Claude Sonnet 5 が Free / Pro の既定モデルとして公開され、Opus 4.8 に迫るエージェント性能を より低価格（$2/$10 per MTok、導入価格は8/31まで）で提供。同日、6/12 に米政府の輸出管理指示でアクセス停止していた Fable 5 は規制解除を受けて7/1 にグローバル再開し、Amazon・Microsoft・Google など Glasswing パートナーと業界共通の jailbreak 深刻度フレームワークの策定を開始。同時に科学者向けワークベンチ Claude Science（ゲノミクス・単一細胞・構造生物学・化学情報学向け60超のスキルを統合）が Pro/Max/Team/Enterprise 向けベータで公開されました。

まず押さえる結論

Model

Fable 5 は7/1にグローバル再開

Fable 5（claude-fable-5）は SWE-Bench Pro 80.3%（Opus 4.8 比 +11.1pt）で記録を更新し、1M コンテキスト・128K 出力・$10/$50 per MTok で6/9に追加。 6/12の米輸出管理指示で Mythos 5 とともにアクセス停止していましたが、6/30に規制解除され7/1からグローバルで再開（Pro/Max/Team/一部Enterpriseは7/7まで週次利用枠の最大50%が対象内、以降は usage credits）。同時に新デフォルトの Sonnet 5 がFree/Proの既定モデルになりました。

Product

Cowork と Design で仕事の面が広がった

Claude は coding の外でも、調査、資料、デザイン、日常の knowledge work をまとめて扱える方向に進んでいます。 4月はその流れが、一つ一つの機能ではなく つながる体験として見えた月でした。

CLI

Claude Code はレビュー基盤化

4月の CLI 更新を見ると、中心は単なる edit 支援ではありません。 /ultrareview、xhigh、Auto Mode、PowerShell rollout から見えるのは、 実装 + レビュー + 長時間運転 + 権限制御をまとめた基盤化です。

  • browser / desktop の補助作業（agentic computer use）
  • 一般的な agent workflow（effort 調整で Opus 相当まで引き上げ可能）
Fast / Cheap

Claude Haiku 4.5

小型・低レイテンシ用途の受け皿。大規模バッチや分類、前処理には有効ですが、 4月後半の Claude の話題の中心は完全に Opus 4.7 と Sonnet 4.6 にあります。

  • 高速応答
  • 軽い整形・分類
  • 大量処理
  • コスト重視運用

重要なのは、Anthropic が Mythos Preview を非公開のより強いクラスとして示しつつ、 広い展開の主力は Opus 4.7 に置いていることです。つまり 4月後半の実務判断では、 いま使うべき frontier Claude は Mythos ではなく Opus 4.7 と考えるのが自然です。

観点 Opus 4.6 Opus 4.7 実務上の意味

Claude Design の意味

単なる画像生成ではない

Claude Design は画像を一枚作るツールではなく、 構造を持った visual work を Claude で作るための product です。 記事でも design、prototype、slides、one-pagers といった成果物が前面に出ています。

Claude Code との接続が重要

もっとも大きいのは handoff bundle です。 これは「Claude で考えて、別のツールで実装する」ではなく、 Claude Design で作って、そのまま Claude Code で build する 流れを意味します。

ブランドと既存資産を食べる

コードベースや design files を読んで design system を立てるという説明があるため、 汎用生成よりも「既存のチーム資産に沿う」方向へ舵を切っています。 これは企業導入に重要です。

資料生成の位置づけが変わる

Claude がすでに PowerPoint、Excel、document workflow とつながっていることを考えると、 Design の追加で「考える」「調べる」「作る」「見せる」が一つの面に寄ってきました。

実務目線では、Claude Design は「デザインツール参入」よりも Claude を front-end ideation と business artifact generation の中心に置く布石 と見る方が重要です。

Cowork GA の意味

知識ワーク自動化の器が固まった

Cowork は coding 専用の概念ではなく、Claude の agentic capability を knowledge work に広げる器です。 4月9日の GA で、それが正式な導入対象に変わりました。

管理機能が付いた

Analytics API、usage analytics、OpenTelemetry、RBAC の追加は、 Cowork が「便利な機能」から「運用・監査・管理を考えるシステム」へ移ったことを示します。

Computer Use と組み合わせて真価が出る

3月の computer use preview と合わせると、Cowork は単なる task runner ではなく、 画面を見て動ける local / desktop agent の受け皿になります。

When To Use Sonnet 4.6
  • 通常のコーディング
  • 日常的な資料や調査
  • 複数回まわす定型 agent
  • コストと速度の両立が重要な場面

  • 難しい PR review

  • coding 以外の knowledge work を自動化したい

  • design to build の流れを Claude で閉じたい
  • チーム導入と利用状況の管理まで考えている

注意点とリスク

Prompt Drift

Opus 4.7 は古い prompt を literal に実行しやすい

Anthropic 自身が、earlier models 向け prompt が Opus 4.7 では unexpected results を生みうると書いています。 upgrade 後は、prompt / eval harness / reviewer expectation の再調整が必要です。

Security

より強い自律性は、そのまま運用リスクでもある

computer use、auto mode、remote control、desktop operations が広がるほど、 permission 設計、監査、可視化、allowlist の設計が重要になります。

Cost / Effort

xhigh は便利だが常用前提ではない

Opus 4.7 + xhigh は hardest task に効きますが、 すべてをそこに寄せるとコストと待ち時間が増えます。日常は Sonnet 4.6、難所だけ Opus 4.7 が基本線です。

Hype

Design はまだ preview

Claude Design は非常に重要な動きですが、まだ preview です。 いま評価すべきなのは完成度より、Anthropic が Claude をどこに持っていこうとしているかです。

この更新をどう読むべきか

Biz / Product 視点

Claude は 2026年4月時点で、chat assistant ではなく knowledge work stack として見るのが妥当です。 調査、資料、デザイン、日常業務、レビューまでの面がそろってきました。

Engineering 視点

実装の主力は Sonnet 4.6 のままでも十分ですが、 hardest task、review、vision-heavy tasks は Opus 4.7 に寄せると良いです。 Claude Code は review-first の道具としての価値が上がっています。

Operational 視点

Cowork、Computer Use、Auto Mode、remote control の組み合わせにより、 Claude は unattended work の領域に入っています。 その分、権限、監査、観測性まで含めた設計が必要です。

Why This Matters For This Hub

このハブで Claude を扱うなら、今後の中心テーマは 「どのモデルが強いか」だけでなく、 どの surface で、どこまで仕事を任せるか に移ります。

Claude Managed Agents 発表 API/開発NEW

長時間エージェント作業向けのホスト型 Claude Platform サービス。セッション・ハーネス・サンドボックスの安定したインターフェースを提供。これまで開発者が自前で実装していた「中断・再開・状態保存」を Platform 側が担う。

  • 耐久性のある状態管理（durable state）：長期タスクが途中で失われない設計
  • より安全なツールアクセスと高速スタートアップ
  • API エンドポイント：/v1/agents・/v1/sessions

使い方イメージ（Python）：

# エージェントを作成しセッションを開始
agent = client.agents.create(model="claude-opus-4-7", tools=[...])
session = client.sessions.create(agent_id=agent.id)

# タスクを投げて状態を保持したまま次回も継続
client.sessions.submit(session.id, "データ収集タスクを再開して")

従来の stateless API と異なり、タスクを中断しても状態が server side に保持される。夜間バッチ処理・複数日にまたがるリサーチエージェントに向く。

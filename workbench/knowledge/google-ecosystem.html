1. 全体像 — 5つの軸で整理する

Google の AI 製品は、ざっくり次の5軸に分類すると迷いません。「フロンティア推論」「ローカル／オープン」「映像・画像生成」「開発基盤」「リサーチ・知識処理」です。

LLM（推論）

  • Gemini 3.1 Pro（最上位）
  • Gemini 3.5 Flash（高速）
  • Gemini Omni / Omni Flash
  • Gemini 3.2 Flash

ローカル / オープン

  • Gemma 4（2B / 4B / 26B MoE / 31B Dense）

映像 / 画像

  • Veo（動画生成）
  • Flow（制作ツール）
  • Imagen（画像）
  • Whisk（画像）

開発基盤

  • Antigravity（IDE/CLI/SDK/Managed Agents）
  • Google AI Studio
  • Vertex AI / Gemini API

リサーチ / 知識

  • NotebookLM（資料処理）

⚠️ 世代の正確な現在地（2026-05-30）: Pro最上位は Gemini 3.1 Pro（2026/2/19）。I/O 2026 で出荷されたのは 3.5 Flash / Omni / Omni Flash（および 3.2 Flash）。「Gemini 3.5 Pro」は延期され、未提供です。Gemma は Gemma 4 が現行。

2. 製品別ガイド

核となる製品を、用途と確度バッジ付きで個別に解説します。

Gemini CANON

フロンティアLLM。テキスト・コード・画像・音声・動画をネイティブに扱う Google の主力モデル群。

  • 最上位 = Gemini 3.1 Pro（2026/2/19）。1M トークン、ARC-AGI-2 77.1%、SWE-bench Verified 80.6%。最高品質の推論・設計・コーディングはこれ。
  • 3.5 Flash：同等性能を高速・低コストで。Gemini アプリと検索 AI Mode のデフォルト。
  • Omni / Omni Flash：任意入出力のマルチモーダル（動画生成を統合）。
  • 3.5 Pro は延期（未提供）。出荷済みと混同しないこと。

💡 深掘りは gemini.html、最新動向は gemini-recent-updates.html。

Gemma 4 OPEN

Google のオープンウェイト／ローカル LLM。手元やオンプレで動かしたい・データを外に出したくない場合の選択肢。

  • 4 構成：Effective 2B / 4B（端末向け）、26B MoE（高スループット推論）、31B Dense（高精度タスク）。
  • Apache 2.0 ライセンスで商用利用可（2026/5/20 公開）。
  • クラウド・デスクトップ・モバイルをカバーするデプロイツールチェーンも同時公開。

💡 ローカルLLMの選び方全般は slm-guide.html も参照。

Veo CANON

動画生成モデル。テキストプロンプトから映像を生成する Google の動画基盤。

  • Veo 3 系はテキストプロンプト一つで映像・環境音・台詞を同時生成する点で差別化。
  • 市場では Runway / Kling と並ぶ主要モデルの一角（プロ映像制作向けの定番として定着）。
  • I/O 2026 では Gemini Omni がテキスト・画像・動画プロンプトをシネマティック動画へ変換する経路も加わった。

Flow 定性

フィルムメイキング／制作ツール。Veo などの生成モデルを使い、ショットをつないで映像作品を組み立てるための制作環境という位置づけ。

  • 用途は「単発のクリップ生成」ではなく、複数ショットの構成・編集を伴う制作ワークフロー。
  • ハブ内の確証が薄いため、固有機能名・提供条件は記載せず用途記述に留める。

Antigravity CANON

エージェント開発基盤。当初は「Gemini CLI 的なツール」だったが、I/O 2026 で総合基盤へ拡張。

  • Antigravity 2.0 は Desktop IDE + CLI + SDK + Managed Agents + Enterprise の5コンポーネント構成。
  • デフォルトエンジンは Gemini 3.5 Flash。Gemini CLI は Antigravity CLI へ移行。
  • エージェントの自律実行・オーケストレーションを構築したい開発者向け。

💡 深掘りは anti-gravity.html。

NotebookLM 定性

資料・リサーチ AI。自分が与えた資料（ドキュメント・PDF・ノート等）を情報源として、要約・Q&A・整理を行う「ソース接地型」のツールという位置づけ。汎用チャットと違い、持ち込んだ資料の範囲で答えるのが特徴。

  • 大量資料の要約：長い資料群を読み込ませて要点を抽出する。
  • 資料への Q&A：「この資料群のどこに何が書いてあるか」を対話で引き出す。
  • 音声化：取り込んだ資料を会話形式の音声へまとめる用途で知られる。
  • リサーチ・学習・社内資料の棚卸しなど、既存資料を捌く場面に向く。

⚠️ ハブ内の確証が薄いため、具体的な日付・数値・料金・固有機能名は記載せず、用途・できることの定性記述に徹しています。

Google AI Studio 定性

無料で始める開発プレイグラウンド。Gemini をブラウザ上で手早く試し、API へつなぐための入口という位置づけ。Gemini 系モデル（3.2 Flash など）が静かに最初に現れる場でもある。

  • 無料で試せる：登録してすぐ、プロンプトを打ち込んでモデルの挙動を確認できる。
  • プロンプト試作：本番コードを書く前に、パラメータや指示文を素早く反復する。
  • API 取得への導線：試した内容をそのまま API / Vertex AI 連携へ展開する起点。
  • 「まず触ってみたい」「最小コストで検証したい」段階の第一候補。

⚠️ ハブ内の確証が薄いため、具体的な無料枠の数値・料金・固有機能名は記載せず、用途・できることの定性記述に徹しています。

Imagen / Whisk 定性

画像生成系。静止画を作りたい場合の Google 製品。Imagen はテキストからの画像生成モデル、Whisk は画像を素材に組み合わせて新しい画像を作る系統のツール、という位置づけ。

  • 用途は「サムネイル・素材・コンセプトビジュアルなどの静止画生成」。
  • ハブ内の確証が薄いため、バージョン・数値・料金・固有機能名は記載せず用途記述に留める。

3. 「こういう時はこれ」早見表

目的から逆引きする決定表です。迷ったらここから。

やりたいこと使う製品
最高品質の推論・設計・難問コーディング Gemini 3.1 Pro（現行最上位。3.5 Pro は延期で未提供）
速く・安く大量にLLMを回す Gemini 3.5 Flash（高速・低コスト）
ローカル／オンプレで動かす・データを外に出さない Gemma 4（端末向け 2B/4B 〜 31B Dense、Apache 2.0）
動画を生成する Veo（映像＋音＋台詞を同時生成）／ Omni 経由のシネマティック動画
映像作品として構成・制作する Flow（複数ショットの制作ワークフロー）
静止画・ビジュアル素材を作る Imagen / Whisk
とりあえず無料で試す・プロンプトを試作する Google AI Studio（→ API/Vertex AI へ展開）
大量の資料を要約・整理・Q&A・音声化する NotebookLM（持ち込み資料に接地）
自律エージェント／開発基盤を組む Antigravity（IDE / CLI / SDK / Managed Agents）

4. 創作（クリエイト）視点 — どう組み合わせるか

自動コンテンツ量産の観点で Google 製品を組み合わせる場合の一般的な役割分担を示します（具体的な制作物・IP は本ハブでは扱いません）。

  • 企画・台本・構成：Gemini 3.1 Pro で全体設計・脚本・プロンプト設計を詰める。大量資料があるなら NotebookLM で素材を整理・要約してから渡す。
  • 量産の高速化：定型処理・大量バッチは Gemini 3.5 Flash に寄せてコストと速度を稼ぐ。機密素材やオフライン処理は Gemma 4 をローカルで。
  • ビジュアル：静止画は Imagen / Whisk、動画は Veo、作品としての組み立ては Flow。
  • 仕組み化：上記を手作業でなくパイプラインとして回すなら、AI Studio で検証 → API/Vertex AI で実装 → Antigravity でエージェント化、という流れが素直。

💡 ポイントは「1製品で全部やろうとしない」こと。推論は Gemini、量産は Flash、ローカルは Gemma、映像は Veo/Flow、土台は AI Studio/Antigravity と役割で割り当てると、増え続ける製品群でも判断が安定します。

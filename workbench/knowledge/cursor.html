Vibe Coding Tips
Cursor × Vibe Coding ベストプラクティス

より速く、より深く、AIと協働するための実践的なテクニック。

① .cursorrules でプロジェクトの文脈を先に渡す
ルートに .cursorrules ファイルを置き、技術スタック・命名規則・禁止事項を記述。毎回説明せずに済む。
② Composerは「要件」を渡して実装を任せる
コードを書くのではなく、「ユーザー認証機能を実装して。JWTを使い、refreshトークンも対応して」のように仕様を渡す。
③ @codebase で全体感を持たせる
チャットで @codebase を付けると、インデックス済みの全ファイルを参照した回答が得られる。設計相談に有効。
④ Background Agentで「火付け → 離席 → 確認」フロー
大きめのタスクをBackground Agentに投げてSlackで通知を受け取り、PRをレビューするだけ。待ち時間をゼロにできる。
⑤ BugBotをCIに組み込む
PRがオープンされると自動レビューが走り、バグがあれば修正PRまで作ってくれる。レビュー待ち時間を劇的に削減。
⑥ モデルをタスクで使い分ける
補完・説明 → Sonnet（速い）、設計・レビュー → Opus（精度）、Cursor Composer モードのみ → Auto（コスト最適）。
⑦ エラーメッセージをそのまま貼る
スタックトレースやコンパイルエラーをチャットにそのまま貼り付けるだけで原因と修正コードが返ってくる。コピペするだけで良い。
⑧ Composer の差分は必ず確認してから Accept
AIは意図しない既存コードを書き換えることがある。差分ビューで変更点を一通り確認してから Accept するのが安全。
vs Claude Code
Cursor vs Claude Code — どちらを使うか

2026年時点での実用的な選択基準。どちらも持つのがベスト。

Cursor が勝る場面
  • GUIベースの開発環境が好みな場合
  • 複数モデルを柔軟に切り替えたい
  • BugBotによるPR自動レビューを組み込みたい
  • Background Agentで非同期並列タスクを走らせたい
  • チームで共有した開発環境を作りたい
Claude Code が勝る場面
  • CLIベースで軽快に動かしたい
  • Claudeの最新モデル（Opus 4.7）を最速で使いたい
  • 自分のターミナル環境に直接組み込みたい
  • スクリプト・バッチ処理をAIで自動化したい
  • コスト単価を最小化したい（CLAUDE_MODEL指定で細かく制御）
🏆 推奨： 日常の実装はCursorで。CI/CD統合・バッチ自動化・ターミナル主体の作業はClaude Code。両刀使いが最強。

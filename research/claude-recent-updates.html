今、見直すべきもの

2026-10-13に確認した公式資料では、Claudeの通常用途は5.5系列、より難しい長時間作業の候補はFable 5.1、特別なverificationを要する用途はMythos 5.1という整理になります。このページは出来事の年表ではなく、「自分の設定・手順のどこを見直すべきか」を示す現況ガイドです。公式Models overview

変更すべき対象はmodel IDだけではありません。費用の見積もり、思考設定、tool呼び出し、進捗表示、退役予定、API creditの対象まで点検します。各更新を見たときは、発表日と確認日、一般提供と限定提供、既存設定と移行候補を分けるのが基本です。以下は公開資料の照合であり、読者の契約・実環境・請求書を確認した結果ではありません。

料金：現在値と発表時点を混ぜない

Opus 5.5の標準API単価は入力$4／出力$20、Sonnet 5.5は$2／$10です。10/13の料金表ではSonnet 5.5のcache readは$0.10/MTokで、9/28発表の$0.20から変更されています。過去の告知を現在の料金表へそのまま残すと、コスト見積もりがずれます。現在の公式Pricing

Haiku 5.5はprompt長が100k以下なら$0.10／$0.50、100k超なら$0.50／$2.50です。入力長tierがあるため、「100万token contextがあるから最安のまま全部入れる」と考えないでください。Haikuの仕様とPricing。数量単位は100万トークンであり、利用者数やAPI call数ではありません。

設計例として、同じ長い資料を何度も読む処理と、一度だけ短い構造化結果を作る処理を分けます。入力・出力・cache write/read・tool chargeを別項目にし、BatchやFast modeを使う場合は対象条件を追加します。大きな割引率だけを並べる比較より、「どの入力が何回送られるか」を追える試算の方が再利用できます。この説明は費用計算の方法で、実測値ではありません。

API creditはCodeの枠とは別

現行公式案内では、Max 5xは月$100、Max 20xは月$200、Teamはseat構成に応じた合算で上限$500のAPI creditを対象プランに提供します。Console organizationをplanへlinkしてclaimする必要があり、利用対象はClaude API、Managed Agents、Agent SDK、Playgroundです。Claude Codeとアプリのextra usageは対象外です。公式API credits

このため「Maxの契約があるのでAPIもCodeも同じ残量で自由に使える」と理解しないでください。creditには期限とno rolloverがあり、他クラウドの提供面へ移せません。利用枠があることと、データを渡す許可、支出の上限、運用ownerがいることも別です。導入候補を作るなら、どの製品で何を完成させ、失敗時にどこで止めるかを先に書きます。本記事はclaim、課金設定、organization連携を実行していません。

移行の重要点：応答が返っても壊れている場合がある

Opus 5.5ではthinkingを無効にできず、forced tool useや旧computer tool等に破壊的変更があると公式に示されています。ツール間のtextがthinking blockへ移るため、requestが成功しても進捗表示が無言になる場合があります。Opusの変更一覧

Sonnet 5.5へthinking offの旧設定を移す場合はbetween_toolsの確認が必要です。thinking blockの継続利用にもmodel・conversation・accountに関する条件があり、過去履歴をどこへでも移せると考えないでください。Sonnetの移行上の変更。厳密なrequest形式はlinked migration guideとSDK版で照合します。

期限：DeprecatedとRetiredと最低提供期間

Sonnet 4.5のAPI退役は2026-11-30予定で、推奨移行先はSonnet 5.5です。この日程表はAnthropic運営のClaude API、Claude Platform on AWS、Microsoft Foundryが対象で、Amazon BedrockとGoogle Cloudは独自の退役日程を持ちます。一方、Mythos PreviewはDeprecated、退役日はTo be announcedと記載されています。旧記事にあった特定日の退役完了を現在の状態として引き継ぎません。公式状態表

「Not sooner than」の日付は、その日に停止する予告ではありません。最低提供期間の記述と退役日を取り違えると、不要な緊急移行を引き起こします。APIの状態表もWebアプリのmodel pickerやクラウド事業者の利用可否を直接証明するものではないので、実際の対象面を確認します。

更新記事を読む読者には、まず利用中のID・呼び出し面・テスト・責任者を一行ずつ整理する方法を勧めます。利用していないモデルの退役は情報として残せば十分で、実案件の変更命令にする必要はありません。利用中なら、まず非本番で同じ失敗例が新モデルでも検出できるかを確認します。

技術ニュースを方法へ変える

例えばHaiku更新を見つけたら、「ニュースを書く」だけで終わらせず、「人工入力の分類を速く安くできるか」という試験候補へ変えます。対象資料、正解を付けた小標本、誤りの重大度、許容時間、上限、失敗時の引き上げ先を用意します。実行ownerが選び、結果が返って初めて「この条件では使える」と書けます。公開記事に内部資料や未公開の業務内容を載せる必要はありません。

同じ考え方はOpusの長時間作業にも適用できます。公式の大規模成功例を自組織の実績として転用せず、小さい移行案件で再現性とレビュー負荷を確かめます。役割は最新名の収集ではなく、次の仕事で試せる判断材料を作ることです。

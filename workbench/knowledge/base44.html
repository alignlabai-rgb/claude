Base44 — Skillsを使っても本番境界は自分で設計する

Base44はアプリのbackendや開発workflowを提供するplatformです。Base44 Skillsはその操作をcoding agentへ教える公式instruction群であり、Agent Skills標準そのものではありません。正しいAPI名を教える助けにはなりますが、幻覚ゼロ、permission安全、deployの成功を保証するものではありません。

最終更新: 2026-10-13 · 公式資料の確認日。提案は実行・採用の報告ではありません。

三つの「skill」を区別する

Agent Skillsはinstructionの形式、Base44の開発SkillsはCLIやSDKの操作を教える実装、アプリ内Agent Skillsは作成したアプリのagentへ能力を教えるresourceです。同じ言葉でも利用者、配置、公開effectが異なります。Base44公式repoはAgent Skills仕様を利用し、現行の開発用一覧にCLI、SDK、troubleshooter、remote-dev、sandboxを載せています。旧版の「常に三つ」ではありません。公式: Base44 Skills

Skillsを入れるだけで、すべてのagentが同じように自動発火するとも限りません。対応host、読み込み方法、対象project、versionを確認します。instructionが古いAPIを指したら、structuredな文書でも古い答えになります。

local開発とremote sandboxは別のworkflow

surface作業の実体確認する境界
local CLI/SDK手元のsourceとremote resourcesを扱うどのapp・dataへ接続するか
cloud sandboxremote app内のファイルを編集する書き込みが反映を起こす範囲
アプリ内agentapp利用者のtaskを処理するresource権限、tool、connector

公式sandbox Skillはlocal checkoutもdeploy/push commandも不要なremote開発として説明し、resource fileを書いた時点でauto-syncすることを明示しています。「localで試して最後にdeploy」という感覚でremoteを編集すると、本番effectの順番を取り違えます。公式: cloud sandboxの仕組み

SDKを推測しない

現行SDK Skillはentities、auth、functions、actorsなどのmoduleを説明します。たとえば現在userの取得はbase44.auth.me()、backend functionはfunctions.invokeというように、他のbackend SDKに似た命名を勝手に当てはめないことが重要です。公式: SDK methods

ただしmethodが正しいだけでは、呼び出し元userがそのdataを読んでよいとは言えません。frontendの表示非表示で秘密を守るのではなく、backendのaccess policyとserver側roleを検査します。service roleの能力をbrowser側へ持ち出さず、connector tokenはclient codeや公開logへ含めない設計が必要です。

教材例: 小さな依頼一覧を作る前の設計

  1. 公開してよい架空dataだけで、タイトル、status、作成者というentityを設計する。
  2. 新規appなのか、既存appをlocalへ展開するのかを区別し、重複appを作らない。
  3. 一般userと管理userに見えるdataを別々のtestとして書く。
  4. 作成・閲覧・更新・削除の四操作を、権限のないuserでもtestする。
  5. 変更の反映先と戻すresourceを確認してからremote反映を行う。

これは未実行の教材設計です。local developmentという名称だけでlocal dataだと判断しないでください。公式CLI Skillも、一部の開発方式がproduction dataへ接続する点を警告しています。公式: local開発とapp初期化

同期commandの「全部」を確認する

現行CLI Skillはagent、agent-skills、connectorのpush/pullをfull synchronizationとして説明します。ローカルの一件追加がremoteの全体置換につながる場合があります。「push」という同じ語でもGitのbranch送信と同じ意味ではありません。まず双方のresource一覧と差分を保存し、対象と置換範囲を確認してください。公式: full synchronizationの注意

トラブル時にlogをagentへ渡す場合も、request payload、user情報、tokenを除きます。troubleshooterは診断を補助するinstructionで、障害のownerや公開承認を代行する役割ではありません。

選び方と評価

managed backendと速いapp試作が必要ならBase44を比較対象にできます。厳格なoffline実行、独自のdata配置、自由なruntime運用が主目的なら別構成も比較します。導入判断は画面が一度できたことより、exportの範囲、権限制御、依存先、課金単位、復元手順に置きます。

評価には機能testだけでなく、別userのdataへアクセスできないか、再読み込みでstateが残るか、失敗時のlogから秘密が漏れないかを入れます。このページではsubscription、connector認証、app作成、remote編集を行っておらず、採用実績は主張していません。

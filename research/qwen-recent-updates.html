Qwen現況 — 3.8 family・Flash-Next・Codeを整理する

2026-10-13の公式catalog、repository、model cardに基づく現行ページです。QwenのAPI、公開weights、coding harness、画像・動画の別製品を一つの世代表へ潰さず、何を使えると確認したかを示します。

2. 公開重みのlicense差分

Qwen3.8-27BはApache-2.0、Flash-Nextは固有のcommunity license表示です。family名でlicenseをまとめると、改変配布や商用条件の確認が漏れます。再利用前には対象artifactのLICENSE本文を読み、code、weights、APIの三つの条件を区別します。27B card / Flash-Next card

大きいMoEとdense modelの比較では、active規模だけをRAM要件に変換しません。量子化、offload、cache、runtimeが実際の可動性を決めます。ユーザーのPCで動いたという第三者報告は検討の入口ですが、そのまま自環境の保証や公式推奨へ昇格しません。

3. Qwen Codeの役割は実行の管理

現行READMEはmemory、skills、subagents、MCP、複数protocol、UIを案内します。ツールのopen-source性と、接続modelのweights公開は別の性質です。local endpointへ接続できるharnessでも、全toolsをlocalで完結できるとは限りません。Qwen Code README

導入評価は同じtaskでmodelだけ変える比較と、同じmodelでharnessを変える比較に分けます。terminalの実行権限、browser操作、subagentの書込対象を先に固定します。agent機能の数より、最終patchが一致するか、test結果を正確に報告するか、停止条件を守るかを受入にします。

4. マルチモーダルと生成系を混ぜない

Model Studio catalogは理解と画像・動画生成を分け、Qwen系の画像modelに加えてWanやHappyHorseを掲載しています。同じAlibaba ecosystemでも、LLM、画像生成、動画生成、world modelは異なる出力と契約です。Image & video区分

「Qwenに動画を入れて読ませる」と「動画を生成する」と「動画編集用の指示を作る」は別taskです。前者の成功で後者の可用性を説明しません。画像制作ではreferenceの権利、人物やbrandの扱い、編集精度、出力形式を確認し、coding評価へまとめないようにします。

5. 意味のある試験案

筆者提案は「公開された日本語仕様から、境界条件のtest候補を作る」です。資料を短く限定し、条件、入力、期待結果、source位置を出力させます。人が存在しない要件を補ったtestを見つけられるように、推定した条件を別欄にします。

続いてsandbox内の小さいcodeを修正し、test候補と実際のtest結果を照合します。架空の成功、既存挙動の破壊、不要な依存追加、公開操作は不合格です。modelに実装と自己採点を任せるだけでは独立評価にならないため、元仕様を読むレビューとtest実行を別の証拠にします。

完成した方法はpromptだけでなくfixture、output schema、失敗例、review条件をセットで残します。これならmodel更新後に同じ試験を再現し、改善と退行を区別できます。

6. 未確認を残す

Qwen4の全面提供、すべてのregional pricing、全modelの商用license適合性、手元のPCの最大context運用は断定しません。Qwen blogの一部は取得本文が空だったため、そのページの検索要約だけで新しい事実を確定していません。

本ページは公式資料の照合と試験提案です。subscription、API実行、local download、credential入力は行っていません。最新という言葉を「全製品を実行検証済み」の意味で使わず、確認したsurfaceを明記して保守します。

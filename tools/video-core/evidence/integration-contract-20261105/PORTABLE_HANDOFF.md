# Portable contract acceptance harness — handoff for the coordinator (Windows and Linux)

Additive to the closed integration-contract job (`a0acfda`). Everything new is under `portable/` plus this file. **No original file, source module, default, spec or earlier evidence was changed** (`portable/verify_scope.py`).
Test-only. Not an app, binder, exporter, board, scheduler or an adopted integration. Real story/voice/timing remain unresolved and are not inferable from any fixture.

> **Windows status: NOT executed.** This harness was written and run on Linux x86_64 only (Python 3.11.18 / 3.12.3 / 3.13.18). It is designed to run on Windows; every Windows-specific claim below is a design statement until *you* run the exact committed harness there.

## 1. What it is

`portable/portable_harness.py` runs the **real public CLIs** (`python -m video_core | video_core.audiomix | video_core.avmux`) of a library you name with `--library-root`, read-only:
`validate`, `plan`, `srt`, and the **dry-run** form of `render` / `mix` / `mux` (without their execution flag). It never renders, mixes, muxes, probes, generates media or downloads; there is no FFmpeg/ffprobe use; no `inspect`;
no `--render/--mix/--mux/--ffmpeg/--ffprobe` or abbreviation is ever passed (refused by the driver *before* a child exists — mechanism case MS02). Python 3.11+ **standard library only**; no `shell=True`, no signals/`setsid`/fork, no chmod-executable, no global env/locale/registry/proxy/permission change.

* **Isolated child per CLI call:** `sys.executable -I -S -B -X utf8 portable/child_runner.py <job>`; the library path is explicit; the CLI runs through `runpy`.
* **Deny hook (not just a counter):** a stdlib audit hook in the child **raises `HarnessDenied` (a `BaseException`) before** any process launch, network call, filesystem write/mkdir/remove/rename/copy, `putenv`, or registry call. Reads are allowed (reads outside library/stdlib/world are recorded, informational).
  Positive controls (MS01) attempt each forbidden action *inside the hooked child* and check the exception, the logged event **and the absence of the side effect**, next to a counterfactual proving the same inert action leaves a trace when unhooked. Mutation controls MU4/MU5 show a library change that tries to launch `ffmpeg` / create a directory is stopped before any effect.
  The child's `PATH` is an owned empty directory (no media tool reachable), `TEMP/TMP` an owned directory. This is a **tripwire/deny layer for Python-level events, not an OS sandbox** (see §8).
* **Outer driver bounds (the code under test never enforces its own envelope):** each child ≤ **10 s** (killed by the driver), retained stdout/stderr ≤ **128 KiB each = 256 KiB per child**, flood kill at 1 MiB read (done by the reader thread itself), **serial** children, finite case list, ≤ **700** children, total wall budget default **420 s** (max 900; `--budget-seconds`). Exhaustion is a failing outcome, never a silent truncation.
* **Owned temp only:** `TemporaryDirectory` under your `--scratch-root`; fixtures are generated bytes (WAV tones, plainly-labelled **non-media** "video" stubs, JSON). Video metadata declared to `avmux` is `CALLER_STATED_UNVERIFIED`. The only repo-derived reads are the library's own tiny example episode/SRT (pinned hashes) and a genuine recorded receipt used as a **shape oracle only**.
* **Results:** a NEW `--out-dir` (refused if it exists, or is inside the library root / repository / scratch root; files are created with exclusive-create): `SUMMARY.txt`, `run.json`, `inventory.json`, `cases/*.json`, `invocations/NNNNN-<case>/{argv.json,status.json,stdout.bin,stderr.bin}`.

## 2. Layers and outcomes (never mixed)

| Layer | Meaning | Outcomes |
|---|---|---|
| `LIBRARY_ENFORCED` | the library must do this; expectation is **independent** (exact-rational oracles, independently assembled SRT bytes, Python's own `wave`, the spec's pinned example hashes, a filesystem probe, documented rules) | `PASS` / `FAIL` |
| `LIBRARY_PERMISSIVE` | an **OBSERVED OPEN GAP** of the pinned source (the library accepts/omits what an owner must guard). Matching the pin is *never* a pass and never a fix | `OBSERVED_OPEN_GAP` / **`REVIEW_REQUIRED`** |
| `CALLER_GUARD_DEMO` | illustrative owner-side reading of results; never rescues or fails a library check | `GUARD_OK` / `GUARD_MISMATCH` |
| `HARNESS_CONTROL` | the harness's own mechanisms | `CONTROL_OK` / `CONTROL_FAILED` |
| – | not run, with the reason | `SKIPPED` |

**Strict mode (`--strict`)** and review: any open-gap observation that differs from the pinned one is `REVIEW_REQUIRED` (exit 4) in both modes — it is never counted as a fix and never auto-adopted. `--strict` additionally makes a library that is **not** `PINNED_*` (candidate / modified) `REVIEW_REQUIRED` unless a **reviewed expectation profile with a matching source pin** is supplied (`--profile`; format in `portable/profiles/`; a profile whose pin does not match the library is ignored, listed in `run.json`, and changes nothing — MS05/MS07 prove this).
Source pin: `inventory.json` lists **every** file of the library root (path, bytes, sha256, CRLF-normalised sha256), excluding only `__pycache__`, `.git` and the top-level `evidence/` (listed). `PINNED_EXACT` = byte-identical to b4ca4a3; a CRLF-only difference (e.g. Windows `autocrlf`) is **labelled** `PINNED_MODULO_LINE_ENDINGS`, not silently equated.

## 7. Reviewed profile / candidate workflow (never automatic)

1. Run the candidate with `--strict` and **no** profile → read `REVIEW_REQUIRED` items. 2. A human reviews each; writes `profiles/<name>.json` with `source_pin` (copy the digests from the candidate's `run.json → source`) and `reviewed_expectations: {"<case>::<check name>": {"observed": <value>, "reviewed_by_ref": "...", "note": "..."}}`.
3. Re-run with `--profile`: matching entries become `REVIEWED_CHANGE` (neither a plain pass nor a fail) and are listed; entries with a non-matching source pin are ignored. The default profile contains **no** reviewed expectations.

## 8. Truthful limitations

* Not run on Windows or macOS; Linux x86_64, Python 3.11.18 / 3.12.3 / 3.13.18 only. The `os.startfile` and `winreg` deny categories exist in the hook but are **not exercised** (no control launches a file association).
* The deny layer is a Python audit hook in a child interpreter: it sees Python-level events (`subprocess`, `os.system`, `socket.*`, `open`, `os.*` file operations, `shutil.*`, `ctypes.*`, `_winapi.CreateProcess`). It does **not** stop native code, nor reads, and it is not an OS sandbox; the empty `PATH` and the owned temp dir are additional (not absolute) barriers. A library that bypasses Python-level APIs would not be caught.
* Fixtures are tiny synthetic stubs: video "files" are not media, so nothing about real video, ffprobe preflight, real receipts, readback, re-hash-after-run or TOCTOU is exercised. The receipt used with `avmux` is **harness-fabricated**; a genuine recorded receipt (hash-pinned) is used only as a key-shape oracle because its stem is not in the repository and no mix may be run to recreate it.
* `render`/`mix`/`mux` execution, the `--mux` preflight, `inspect`, FFmpeg capability probing and the runner/containment lifecycle are **out of scope** by design.
* Expectations for open gaps are *observations of b4ca4a3*, not endorsements. Exact error codes are those of that source; a candidate that renames a code will show `FAIL`/`REVIEW_REQUIRED`, which is the intended signal.
* Windows long paths are not assumed (use short roots); antivirus or file locking can slow or block cleanup (`scratch_cleaned` is reported, cleanup errors are ignored but recorded).
* Timing values in results are informational and machine-dependent; the cross-interpreter equality above refers to check outcomes/observations, not wall time.

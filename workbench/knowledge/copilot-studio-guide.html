Section 01

3つのモード — 設計思想と使い分け

Copilot Studio のエージェントは「どう動くか」によって3つのモードに分かれる。最初にモードを正しく選ぶことが設計の核心。後から変えると作り直しになる。

Classic Topics モード

📋 完全制御・決定論型

トリガー句→分岐→アクションをすべて手動で設計したフロー。LLM が意図を勝手に解釈しない。

  • コンプライアンス上、回答を厳密に管理したい
  • 回答のたびに同じ結果を保証したい
  • 法務・規約・申請フォームなど構造が固定
消費: 1 クレジット/応答
Generative AI モード

🧠 LLM 自律選択・知識応答型

LLM（GPT-4o / Claude）が Topics・Knowledge・Actions から適切なものを自律選択して応答。トピック数が多い or ドキュメント回答が中心の場合に強い。

  • 大量の社内ドキュメントから Q&A
  • 意図が多様で Topic を書き切れない
  • 「近い質問」への柔軟な対応が必要
消費: 2 クレジット/応答
Autonomous Agents モード

⚡ イベント駆動・自律実行型

ユーザーとの会話なしに外部イベントをトリガーに自律実行。監視・自動通知・定期処理に特化。Build 2026 で大幅強化。

  • Dataverse レコード変更 → 自動処理
  • 毎朝9時 → レポート生成 → Teams 投稿
  • メール受信 → 分類 → 担当者へ振り分け
消費: 25 クレジット/トリガー（M365ライセンス保持者も同額）
⚠ Autonomous の 25 クレジットは例外なし

M365 Copilot ライセンス保持者でも、Autonomous トリガーは毎回 25 クレジットを消費する。Classic / Generative 応答は M365 ライセンス環境内なら 0 クレジット。コスト計算時に必ず別枠で管理すること。

モード選択の意思決定フロー

「回答を完全コントロールしたい」 → Classic Topics
「ドキュメントから自動回答・意図が多様」 → Generative AI モード
「会話不要・イベント起動で自動処理」 → Autonomous モード
「構造的フロー + 賢い回答の両立」 → Classic Topics + Generative Answers 混在

Copilot Studio を「使わない」判断基準

Power Automate 単体で十分

人との会話なし・ファイル変換・外部 API 連携のみ → Copilot Studio 不要

Power Apps で UI が必要

チャット形式でなくフォーム・ダッシュボードが適切な場合

Azure AI Foundry / LangChain

独自モデル・複雑なRAG・プログラマブルな処理が必要なケース

Section 02

エージェント設計パターン集 — 業務類型別

実務で頻繁に登場する6パターン。「どのモードで」「何に接続して」「どう動くか」を設計図レベルで整理。

Pattern 01

社内FAQ・ポリシー照会エージェント

「有給の申請方法は？」「経費精算の上限は？」など、社内規定ドキュメントへの Q&A。最も立ち上げが早いパターン。

Generative AI モード SharePoint Knowledge
質問受信 → SharePoint 検索 → 引用付き回答
  • ポイント: Custom Instructions で「社内規定の範囲外の質問は答えない」と明示
  • 引用表示を ON にして情報ソースを透明化（信頼性が上がる）
  • Content moderation を High に設定するとハルシネーション抑制
Pattern 02

申請・承認ワークフローエージェント

会話で申請内容を収集 → 承認者に自動通知 → 結果を申請者に返す。典型的な「Classic Topics + Power Automate」の組み合わせ。

Classic Topics Power Automate 連携 Teams Approvals
申請種別確認 → 変数収集 → Flow 起動 → 承認通知 → 結果返却
  • 変数設計が核心: Text（申請種別・理由）、Number（金額）、Boolean（緊急フラグ）
  • Adaptive Card で承認者に見やすいUI を提供
  • 承認タイムアウト（24h）の処理を Flow 側に実装
Pattern 03

データ照会エージェント

「顧客 A 社の最新ステータスは？」「案件 #1234 の担当者は？」など、Dataverse や SharePoint リストへの構造化データ照会。

Classic Topics Power Automate（Dataverse）
検索キー取得 → Flow でDB照会 → Table変数で受取 → 整形して返答
  • Flow の出力をTable 変数で受け取り、ループして表示
  • 検索結果ゼロの場合の Fallback Topic を必ず設計
  • 個人情報照会の場合は Entra ID 認証を必須に
Pattern 04

定期レポート自動生成エージェント（自律型）

スケジュールトリガーで毎朝自動起動 → データ収集 → レポート生成 → Teams チャンネルに投稿。人との会話ゼロ。

Autonomous モード スケジュールトリガー Teams 投稿
毎朝 8:00 起動 → Dataverse 集計 → Excel 生成 → Teams 投稿
  • 注意: 毎回 25 クレジット消費。週5日稼働なら月 ~500 クレジット = $5
  • Action の失敗時に Teams アラート（管理者向け）を送るエラー処理を追加
  • 「何も変化がない日は投稿しない」条件分岐で無駄な通知を防ぐ
Pattern 05

アラート・エスカレーション監視エージェント（自律型）

Dataverse のレコード変更や Forms の回答をトリガーに、条件を評価して担当者にアラートを飛ばす。IT ヘルプデスクや SLA 管理に有効。

Autonomous モード イベントトリガー Outlook / Teams 通知
レコード変更検知 → 優先度評価 → 条件分岐 → 担当者に通知
  • Dataverse トリガーは列単位で変更を監視できる（ステータス列のみ、など）
  • トリガー条件を絞り込んで不要な起動を防ぐ（クレジット節約）
  • Planner タスク作成を Action に追加すると追跡しやすい
Pattern 06

マルチエージェント連携（A2A オーケストレーター）

フロントの「受付エージェント」がユーザーの意図を判断し、専門エージェント（HR / IT / Finance）に委譲。Build 2026 の A2A GA で本格運用可。

A2A Protocol（Build 2026 GA） Generative Orchestration
受付 Agent → 意図分類 → HR Agent / IT Agent / Finance Agent → 結果統合
  • A2A はエージェント同士が共有コンテキストを持ちながらタスクを委譲
  • 各専門エージェントは独立して管理・更新できる（疎結合）
  • Work IQ REST API で既存の業務システムとの統合も可能（Build 2026）
Section 03

Knowledge Source 完全ガイド

「Generative Answersが答えない」「古い情報を返す」「関係ない内容を返す」— 実務でのハマりポイントの9割はここに集中する。

ソース 最大ファイル数・制限 更新方法 向いているケース 注意点
SharePoint / OneDrive 1,000 ファイル/Agent、512 MB/ファイル（M365ライセンスなしは 7 MB） 自動同期（リアルタイム） 社内規定・マニュアル・ポリシー文書 フォルダは50個まで、10階層まで。一度に選択できるのは15件
Webサイト（URL） 500 オブジェクト合計内 Bing クロール（手動不可） 公開FAQ・製品ページ・法令サイト 2階層深まで保証。イントラネット・VPN内は不可。再クロールタイミング不明
ファイルアップロード（PDF/Word/Excel） 512 MB/ファイル（同上） 手動（再アップロード） 更新頻度が低い参照ドキュメント 更新したら手動で再アップロードが必要。SharePoint 連携推奨
Dataverse 2 ソース/Agent、15 テーブル/ソース リアルタイム CRM データ・案件情報・マスタデータ 構造化データ向け。自然言語で照会するより Power Automate 経由が精度高い

Generative Answers のチューニング

Content Moderation（コンテンツフィルタ）

Low

より多くの回答を生成。ハルシネーション・不適切回答リスク高。テスト環境向け。

Moderate（デフォルト）

バランス型。大半の業務用途はここ。

High

回答しない頻度が上がる。医療・法務・金融などコンプライアンス重視の場合に。

Custom Instructions（必ず設定すべき）

エージェントのペルソナ・回答範囲・禁止事項を自然言語で指定。設定しないと関係ない質問にも答えてしまう。

Custom Instructions 例文

「あなたは社内の人事ポリシーに関する質問に回答するアシスタントです。提供された人事規定ドキュメントの範囲内でのみ回答してください。範囲外の質問には『その件は人事部に直接お問い合わせください』と回答してください。」

Topic レベルでも設定可能（Topic ごとに moderation を Override できる）。

よくある問題と対処法

❌「Generative Answers が答えない」
  • Generative Answers が無効になっている → Agent の Settings で確認
  • Content Moderation が High すぎる → Moderate に下げてテスト
  • ナレッジに対象コンテンツが含まれていない → ソースのインデックス状態を確認
  • Custom Instructions で回答範囲を絞りすぎている
⚠「関係ない・古い内容を返す」
  • Webサイトクロールが古い → Web Knowledge を削除して再追加（手動再クロールは不可）
  • ファイルアップロード源が古い → 最新版を再アップロード
  • SharePoint ファイルを直接編集後、同期に時間がかかる場合あり → しばらく待つ
⚠「Tenant Graph を使いたいがコストが高い」
  • Tenant Graph（組織全体の M365 コンテンツ参照）は10 クレジット/応答と高コスト
  • 必要なドキュメントを SharePoint の特定フォルダに集約し、そこだけを Knowledge Source にする方が安く精度も高い
Section 04

Power Automate 連携の設計技法

Copilot Studio 単体でできることは限られる。実務価値の大半は Power Automate との連携設計で決まる。

基本アーキテクチャ

Copilot Studio Topic
↓ Call an action（変数を渡す）
Power Automate Cloud Flow
↓ アクション実行（SharePoint / Teams / Outlook / Dataverse など）
結果を Topic に返す
↓ Topic が結果をユーザーに応答

変数の型と使い方

Text   文字列全般（名前・件名・理由・ID）
Number   数値（金額・日数・件数）
Boolean   Yes/No の確認（緊急フラグ・同意確認）
Table   複数件のデータ取得（リスト・検索結果）
Record   1件の構造化データ（オブジェクト型）
File   ファイル渡し（2025.7.2 〜 対応）

典型コネクタパターン

コネクタ 主なアクション ユースケース
SharePointアイテム作成・更新・取得、ファイル作成申請記録、ドキュメント生成
Microsoft Teamsメッセージ投稿、Adaptive Card 送信、チャンネル通知承認通知、進捗報告、アラート
Outlookメール送信、予定作成、カレンダー空き確認確認メール、会議スケジュール
Dataverse行の作成・更新・取得・検索CRM 更新、案件ステータス照会
Approvals承認リクエスト送信・結果待機稟議・経費承認ワークフロー
Excel（Business）行の追加・取得、テーブル更新台帳管理、集計データ更新
Plannerタスク作成・割り当て・更新タスク自動起票、進捗追跡

エラーハンドリングの設計

Flow 側のエラー処理
  • 各アクションの「Configure run after」で失敗パスを設定
  • 失敗時は Output 変数に error フラグを立てて Topic に返す
  • スキーマ不一致エラーは Action ノードの「Refresh」で解消
Topic 側のエラー処理
  • Flow から返ってきた error 変数を Condition で分岐
  • 失敗時は「もう一度試す」または「担当者に連絡する」フローに誘導
  • 「System.Error」Topics（既定）をカスタマイズして適切なメッセージを設定
よくあるデバッグポイント
  • Flow が失敗しているのに Topic が無反応 → Flow の実行履歴を Power Automate で直接確認
  • Input が渡されていない → Topic の Action ノードで変数のマッピングを再確認
  • Output が空で返ってくる → Flow の「Respond to Copilot Studio or Power Virtual Agents」ステップの Output 設定を確認
Section 05

品質改善サイクル — Analytics の読み方と改善アプローチ

エージェントを作って終わりにしない。Analytics を週次で読み、数値をもとに改善を回すことで実務価値が積み上がる。

Session Count
起動セッション数（engaged / unengaged）
Resolution Rate
会話完結率（目標 70%+）
Escalation Rate
人間エスカレーション率（低いほど良い）
CSAT
満足度スコア（5点満点）

Resolution Rate の読み方

2種類ある：

  • Confirmed Resolution: End of Conversation Topic でユーザーが「解決した」と回答したケース
  • Implied Resolution: 確認なしにセッション終了したが、ロジックが解決と判定したケース
解決率が低い場合の対処
  • 会話ログ（Session Details）で「どの Topic で詰まっているか」を特定
  • Fallback Topic に集中している → トリガー句の追加・Generative Answers 強化
  • ユーザーが途中で離脱 → Topic フローが長すぎる → シンプル化

改善サイクルの回し方

週次
会話ログの確認 → 未解決・エスカレーション多発 Topic の特定
改善
トリガー句追加・Knowledge 更新・フロー簡略化 → テストキャンバスで検証
公開
Test → Dev 環境で確認 → Solution で Prod 展開（ALM）
月次
Resolution Rate / CSAT のトレンドを見て中期的な課題を把握
Power BI カスタムレポート（発展）

Copilot Studio Analytics コネクタを使うと、Power BI にデータを引き込んでカスタムダッシュボードが作れる。複数エージェントの横断比較や、部門別の解決率分析が可能になる。

Section 06

Enterprise 展開と運用コスト管理

Teams 公開 — 3つの展開パス

① Maker → 管理者承認 → 全社公開

Copilot Studio から「Show to everyone in my org」を選択。Copilot Control System（旧Teams管理センター）での管理者承認が必要。承認後に全社員のアプリ一覧に表示。

② 管理者が Teams Admin Center にZIPを直接アップロード

承認ステップなし。IT部門が管理・展開する正式ルート。

③ サイドロード（テスト・個人利用）

組織のカスタムアプリアップロードポリシーが有効な場合のみ可能。本番展開不可。

自動インストール（ピン留め）

Teams Admin Center の「Setup Policies」でエージェントを追加すると、対象ユーザーグループに自動インストール＋ピン留めが可能。全社展開時に有効。

セキュリティ設定チェックリスト

  • DLP ポリシーで「Chat without Entra ID authentication」コネクタをBlockedグループに追加（匿名公開防止）
  • Entra ID 認証を設定（Entra Agent ID が自動発行され監査追跡可能に）
  • Microsoft Purview で Copilot Studio の監査ログが記録されているか確認
  • 会話トランスクリプトは DSPM for AI（Purview とは別）で管理
  • 各エージェントに最小権限の接続のみ割り当て（不要なコネクタは削除）
⚠ DLP 設定は全テナントで必須（2025年初頭から強制）

未設定のままだと匿名ユーザーがエージェントにアクセスできる状態になる可能性がある。IT部門と連携して確認すること。

クレジット消費と料金の全体像

インタラクション種別 消費クレジット M365 Copilot ライセンスあり 実務上の注意点

パック購入

25,000 クレジット = $200/月。従量課金は $0.01/クレジット。

大量利用の場合は CCCU（年間コミット）で最大 20% 割引。

コスト試算の例

毎日 200 セッション × 平均 5 Generative 応答 = 2,000 クレジット/日 ≈ 60,000/月 → 約 $600/月

M365 ライセンス組織内なら Classic + Generative は無料。Autonomous のみ課金対象。

環境管理（ALM）— 本番展開のベストプラクティス

Dev 環境

開発・テスト用。本番データに接続しない。壊れても影響なし。

開発者のみ

Test / UAT 環境

本番相当のデータで受け入れテスト。ビジネスユーザーが確認。

限定ユーザー

Prod 環境

本番。Solution（Managed）でのみ変更を受け付ける。直接編集禁止。

全社員
Solution でのデプロイ管理

エージェント・Flow・環境変数・接続参照をまとめて Solution に入れる。Dev → Test → Prod への昇格は Solution の Export/Import で管理。環境変数で接続先URLを環境ごとに切り替えられる。

Build 2026 の主要アップデート

2026年5月の Microsoft Build で発表・GA になった Copilot Studio の新機能。

GA — Build 2026

🖥 Computer-Using Agents

Web/デスクトップ UI を人間のように操作（クリック・入力・画面読み取り）。UI 変更に自動適応。RPA より柔軟。セキュアな認証情報管理。モデル選択の柔軟性も向上。

NEW — Build 2026

🔗 Workflows 統合キャンバス

エンドツーエンドのエージェント自動化を1つのキャンバスで構築。エージェントノードを直接ワークフローに埋め込み可能。ノードレベルのインラインテストで即デバッグ。

GA — 2026年5月

🤝 A2A（エージェント間通信）

エージェント同士がタスクを委譲・共有コンテキストを維持しながら連携。Work IQ REST API + CLI で既存システムへの統合も標準化。

GA — 北米先行

🎙 Real-Time Voice Agents

電話対応エージェント（Dynamics 365 Contact Center 経由）。発信者 ID 認識・タスク実行・コンテキスト保持したままの有人エスカレーション。S2S 統合対応。

モデル追加（Build 2026）

ChatGPT-5 が全グローバルで GA。Claude Sonnet 4.5 / 4.6 / Opus も全グローバルで本番エージェントに利用可能。Copilot Studio 内でモデルを切り替えての動作確認が推奨。

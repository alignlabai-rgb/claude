メモリの3スコープ

👤 ユーザーメモリ

ユーザー固有の情報（好み・スキル・過去の発言）。セッションをまたいで永続化。「ユーザーXは Pythonが得意で、詳しい説明を好む」など。

💬 セッションメモリ

現在の会話スレッド内の短期記憶。会話が終わると通常消去。スレッド内の前の発言を参照するために使う。

🤖 エージェントメモリ

エージェント自体の知識・手順・学習内容。「このプロジェクトではテストを先に書く」など、エージェントの行動指針として機能。

🟢 Mem0

🟢

Mem0 — The Memory Layer for AI

GitHub: mem0ai/mem0 | PyPI: mem0ai | MIT ライセンス | 2024年創業 → 2026年商用化
Mem0 の核心価値: シングルコマンド（pip install mem0ai）で AI エージェントに永続メモリを追加。ホスト型 API と自己ホスト型の両方で提供。Claude Code / Cursor / OpenClaw 等との MCP 統合も完備。

🏗️ 3層アーキテクチャ

Mem0 は3種のデータベースを組み合わせ、高速・高精度なメモリ検索を実現する。

  • ベクトル DB（Qdrant / Chroma / Pinecone / pgvector）: 会話の意味的内容を埋め込みベクトルとして保存。類似した記憶をコサイン類似度で検索。
  • グラフ DB（Neo4j / Falkordb）: エンティティ間の関係性を保存。「ユーザーが使用するプロジェクトAとプロジェクトBの関係」など複雑な参照に強い。
  • KV ストア（Redis / 組み込み）: ユーザー設定・頻繁にアクセスする記憶のキャッシュ。ミリ秒レベルの低レイテンシ参照に使用。

🔬 新アルゴリズム（2026年4月）

Mem0 は2026年4月に記憶の抽出・検索アルゴリズムを全面刷新。

  • Single-pass Hierarchical Extraction: LLM への問い合わせを従来比で削減。会話から記憶を抽出するコストが約40%低下。
  • Multi-signal Retrieval: ベクトル類似度・グラフ関係・時系列・頻度の4信号を組み合わせてランキング。関連する記憶の精度が大幅向上。
  • Conflict Resolution: 矛盾する記憶（「好きな言語は Python」→「最近 Rust に移行した」）を自動解決し、最新情報を優先。
  • Memory Decay: 古い記憶に低いウェイトを付与し、フレッシュな情報が優先されるよう自動調整。

主要機能

💾 add()

メッセージリストから自動的に重要情報を抽出して保存。LLM が「何を記憶すべきか」を判断。

🔍 search()

クエリに関連する記憶を検索。ユーザーID でスコープを絞り込み可能。

📋 get_all()

特定ユーザーの全記憶を取得。管理UI でも確認・編集可能。

✏️ update()

既存の記憶を更新。矛盾する情報が入力された場合に自動呼び出し。

🗑️ delete()

特定の記憶を削除。GDPR 対応の「忘れる権利」実装に必須。

📊 history()

特定記憶の変遷を追跡。「いつ何が変わったか」を監査ログとして記録。

コード例 — 基本的な使い方

from mem0 import Memory
from anthropic import Anthropic

# インメモリで即起動（プロトタイプ用）
m = Memory()

# 本番: 設定ファイルで DB を指定
config = {
    "vector_store": {
        "provider": "qdrant",
        "config": {"host": "localhost", "port": 6333}
    },
    "graph_store": {
        "provider": "neo4j",
        "config": {"url": "bolt://localhost:7687"}
    },
    "llm": {
        "provider": "anthropic",
        "config": {"model": "claude-sonnet-4-6"}
    }
}
m = Memory.from_config(config)

# ユーザー "alice" の会話を記憶
messages = [
    {"role": "user", "content": "私はPythonとRustが好きで、型安全なコードを重視します"},
    {"role": "assistant", "content": "承知しました。型安全な実装を心がけます"},
]
m.add(messages, user_id="alice")

# 次の会話で関連記憶を検索して注入
client = Anthropic()

def chat_with_memory(user_message: str, user_id: str):
    memories = m.search(query=user_message, user_id=user_id, limit=5)
    context = "\n".join([f"- {mem['memory']}" for mem in memories["results"]])

    system = f"""ユーザーに関する記憶:
{context}

上記の記憶を考慮して回答してください。"""

    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        system=system,
        messages=[{"role": "user", "content": user_message}]
    )
    # 新しい会話も記憶に追加
    m.add([
        {"role": "user", "content": user_message},
        {"role": "assistant", "content": response.content[0].text}
    ], user_id=user_id)
    return response.content[0].text

# 別セッションでも alice の好みが引き継がれる
answer = chat_with_memory("APIクライアントの実装を手伝ってください", "alice")
# → Rustの型安全な実装例を自動的に優先してくれる

🔵 Supermemory

🔵

Supermemory — Universal Memory for AI

MCP: mcp.supermemory.ai/mcp | OpenClaw Plugin | Apache 2.0（OSS コア）
Supermemory の差別化: 「AI ツール横断の記憶共有」が核心価値。Claude Code・Cursor・Cline・Hermes・opencode など複数のコーディングエージェントが同じメモリプールを共有できる。また Auto-Recall（会話開始前に自動注入）と Auto-Capture（会話後に自動保存）の完全自動ループが特徴。

⚡ Auto-Recall

AI ターンが始まる前に、プロジェクト・ユーザー・会話の文脈に関連する記憶を自動的に検索し、システムプロンプトに注入する。ユーザーが「覚えておいて」と言わなくても、自然な継続会話が実現。

  • 関連スコア 0.7 以上の記憶のみ注入（ノイズ回避）
  • 注入量を token 上限でコントロール（デフォルト 2,000 tokens）
  • プロジェクト単位 / ユーザー単位でスコープ選択可

📝 Auto-Capture

AI ターン終了後に、会話から重要な情報を自動抽出してメモリに保存。毎回「覚えておいて」と入力する手間が不要。

  • LLM が「記憶すべき情報」を判断（好み・決定・コード等）
  • 重複記憶は自動マージ（同じことを何度保存しない）
  • 機密情報フィルタ: API Key・パスワード等は自動除外
  • タグ自動付与: #preference #code #decision #task 等

🟡 ClawMem（OSS・オンデバイス）

🟡

ClawMem — On-Device Memory for Claude Code

OSS（MIT）| Claude Code Hooks + MCP Server + Hybrid RAG | 完全ローカル実行
ClawMem の核心: 外部サービスに一切依存しない完全オンデバイスメモリ。Claude Code の Hooks を使ってセッション開始時・終了時に自動でメモリの読み書きを行う。セキュリティ重視の企業・エアギャップ環境で特に有効。

🏗️ アーキテクチャ

3コンポーネントで構成:

  • Hooks: Claude Code の PreToolUse / PostToolUse イベントにフックして記憶を自動処理
  • MCP Server: Claude Code から記憶を検索・保存するための MCP エンドポイント（ローカル stdio）
  • Hybrid RAG: ローカルのベクトルDB（Chroma/FAISS）+ BM25 全文検索の組み合わせ。GPU 不要で CPU のみ動作。

⚡ 自動メモリループ

Claude Code の Session Hooks で完全自動化:

# ~/.claude/hooks.json
{
  "hooks": {
    "SessionStart": [{
      "command": "clawmem inject --project $PROJECT_PATH"
    }],
    "SessionEnd": [{
      "command": "clawmem capture --session $SESSION_ID"
    }]
  }
}

セッション開始時に関連記憶を CLAUDE.md に自動追記 → セッション終了後に会話を解析して記憶を保存。

インストール・設定

# インストール
pip install clawmem

# 初期化（~/.clawmem/ にローカルデータベースを作成）
clawmem init

# MCP サーバーとして Claude Code に登録
clawmem install --mcp

# 手動で記憶を追加
clawmem add --text "このプロジェクトでは FastAPI + PostgreSQL を使用" \
            --project my-project \
            --tags backend,database

# 検索
clawmem search "データベース接続設定" --project my-project

# 全記憶を一覧表示
clawmem list --project my-project

✅ ClawMem が向くケース

  • セキュリティ要件上、クラウドに情報を送れない
  • エアギャップ（インターネット遮断）環境
  • 月額サブスクリプションを払いたくない
  • 記憶データを完全に自分でコントロールしたい
  • Claude Code ヘビーユーザー

❌ ClawMem が向かないケース

  • 複数デバイス間で記憶を同期したい（ClawMem は単一デバイス）
  • 複数の AI ツール（Claude + ChatGPT 等）で記憶を共有したい
  • チームで記憶を共有したい
  • Claude Code 以外のエージェントでメインで使う

🟠 Cloudflare Agent Memory

🟠

Cloudflare Agent Memory — Edge-native Persistence

Cloudflare Workers AI + Durable Objects + Vectorize | 2025年後半 GA
Cloudflare の独自価値: エッジ（CDN の各 PoP）でエージェントを実行しながら、そのエージェントの状態・記憶をリアルタイムで永続化できる。Durable Objects でエージェントインスタンスの「生存状態」をグローバルに 1 つだけ維持し、どのリージョンからアクセスしても同じ記憶を参照できる。

🏗️ 技術スタック

  • Durable Objects: エージェントの「生存インスタンス」をグローバルに 1 つ維持。WebSocket でクライアントと常時接続可能。
  • Vectorize: Cloudflare のベクトルDB（エッジに分散）。エージェントメモリの意味検索。
  • Workers KV: 高速なキー・バリュー読み取り（リード優先）。設定・ユーザー情報の保存に。
  • R2 Storage: 大容量の会話ログ・添付ファイルをオブジェクトストレージに保存。

📦 agents SDK

Cloudflare が提供する公式エージェント SDK（agents パッケージ）で、メモリ機能が組み込み提供。

import { Agent } from 'agents';

class MemoryAgent extends Agent {
  // state は Durable Object で永続化
  async onMessage(msg: Message) {
    // 関連記憶を検索
    const memories = await this.vectorize.query(
      msg.content, { topK: 5 }
    );
    // LLM を呼び出して応答生成
    const response = await this.ai.run(
      '@cf/anthropic/claude-sonnet-4-6',
      { messages: [...memories, msg] }
    );
    // 新しい情報を記憶に保存
    await this.saveMemory(response);
    return response;
  }
}

Mem0 + MAF（Microsoft Agent Framework）統合

from mem0 import Memory
from autogen_agentchat.agents import AssistantAgent
from autogen_core.tools import FunctionTool

memory = Memory()

# Mem0 操作を MAF ツールとして定義
def remember(content: str, user_id: str) -> str:
    """重要な情報を記憶に保存"""
    memory.add([{"role": "user", "content": content}], user_id=user_id)
    return f"記憶しました: {content}"

def recall(query: str, user_id: str) -> str:
    """関連する記憶を検索"""
    results = memory.search(query=query, user_id=user_id, limit=5)
    return "\n".join([r["memory"] for r in results["results"]])

# MAF エージェントに記憶ツールを注入
memory_agent = AssistantAgent(
    name="persistent_assistant",
    model_client=model_client,
    tools=[
        FunctionTool(remember, description="重要な情報を記憶に保存する"),
        FunctionTool(recall, description="過去の記憶を検索する"),
    ],
    system_message="""
    あなたは記憶を持つアシスタントです。
    重要な情報は remember ツールで保存し、
    過去の文脈が必要な場合は recall ツールで検索してください。
    """
)

        json={"content": finding, "tags": tags}
    )

# エージェント B（ライティングエージェント）が記憶を検索して活用
async def get_context_for_writing(topic: str):
    resp = await httpx.post(
        f"{SUPERMEMORY_URL}/memories/search",
        headers=headers,
        json={"query": topic, "limit": 10}
    )
    return [m["content"] for m in resp.json()["memories"]]

# A2A で連携: リサーチ結果を記憶 → ライティングエージェントが参照
await save_research(
    "MAF v1.0 は MIT ライセンス。AutoGen + SK の統合版。",
    tags=["microsoft", "maf", "research"]
)
context = await get_context_for_writing("Microsoft エージェントフレームワーク")
# context に記憶した内容が返る → 執筆エージェントがこれを活用

🎯 実装ベストプラクティス

  • 記憶は少なく・精密に: 全会話を丸ごと保存しない。LLM に「記憶すべき情報か」を判断させる
  • スコープを明確に: user_id / project / agent_id で記憶を分離。意図しない混入を防ぐ
  • 定期的に棚卸し: 古い・矛盾する記憶は明示的に削除。Mem0 の history() で変遷を確認
  • センシティブ情報を除外: API Key・パスワード・個人情報は記憶しない（Auto-Capture のフィルタを設定）
  • 検索クエリを工夫: 「過去の設定」より「PostgreSQL 接続設定」のように具体的なクエリを使う
  • 記憶注入量を制御: 無制限に注入するとコンテキストを圧迫。top-k 5〜10 件を基本とする
  • ユーザーに透明性を: 「あなたの記憶を確認・削除する方法」をユーザーに提示する
  • GDPR を考慮: delete() / forget API で「忘れる権利」を必ず実装

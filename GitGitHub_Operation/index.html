HEAD

origin/main

基礎チェック

日常フロー

開始と終了の儀式を固定する

Start

作業開始

git status --short --branch
git fetch origin --prune
git log --oneline --left-right HEAD...origin/main

dirtyなら誰の変更かを確認し、勝手に捨てません。

Commit

変更を確定

git diff --stat
git diff
git add path/to/file
git diff --cached
git commit -m "Describe intent"
Publish

公開

git fetch origin
git status --short --branch
git push -u origin HEAD

push前に相手が進んでいないことを再確認します。

Close

終了

ブランチ、commit、push先、テスト結果、残ったdirty変更を報告します。「保存した」と「GitHubへ公開した」を分けます。

コミット単位: 変更量ではなく、一つの意図で分けます。機能、テスト、無関係な整形を一つに混ぜません。

Branch・Pull Request

変更を隔離し、レビュー可能にする

git switch main
git pull --ff-only
git switch -c feature/short-description

# work, test, commit
git push -u origin feature/short-description
gh pr create --draft --fill
選択使う場面注意
Direct main個人運用、低リスク、即時反映fetch・検証・バックアップを厳格に
Feature branch通常の機能・文書変更main追随とPRレビュー
Worktree並列AI、長期作業、複数案依存・ignored fileを個別準備
Fork外部リポジトリupstreamとoriginを混同しない

良いPR

  • 何を、なぜ変えたか
  • ユーザーへの影響
  • 検証コマンドと結果
  • リスクとロールバック
  • レビューしてほしい点

Merge方式

  • Squash: PRを1コミットに整理
  • Merge commit: 分岐履歴を保持
  • Rebase merge: 線形履歴

チーム規約を先に決めます。

pull --ff-only

分岐がなければ更新し、分岐があれば止まります。予期しないmerge commitを作らない安全な既定です。

pull --rebase

手元コミットを最新リモート上へ再適用します。履歴は整いますが、競合時のours/theirsの意味に注意します。

未コミット変更がある: まず内容を確認し、コミット、stash、バックアップ枝のどれかで保護します。自動stash任せにせず、戻し方を決めます。
git switch -c backup/local-YYYYMMDD
git add -A
git commit -m "Backup local changes before sync"
git switch main
git fetch origin

競合解消

片側選択ではなく、意図を統合する

1. Stop追加編集停止
2. Backup枝・commit確保
3. Inspectbase/両側比較
4. Merge内容を統合
5. Verifytestして続行
git status
git diff --name-only --diff-filter=U
git diff --cc
rg -n "^(<<<<<<<|=======|>>>>>>>)" .

# resolve files, then
git add path/to/resolved-file
git rebase --continue   # rebase中
# or
git commit              # merge中

Merge中

oursは現在ブランチ、theirsは取り込む相手です。

Rebase中

oursはrebase先、theirsは再適用中コミット。直感と逆に見えるため、内容で判断します。

禁止: 新しい日付だから正しい、行数が多いから採用、という判断。公式情報・仕様・ユーザー意図を確認し、両側の価値を統合します。

競合解消チェック

復旧・履歴

破壊コマンドより復元可能な手段を優先

目的安全な第一選択注意
未stage変更を確認git diffrestore前に必ず読む
stageを外すgit restore --staged fileworking treeは残る
公開済みcommitを戻すgit revert SHA履歴を壊さない
消えたcommitを探すgit reflog期限前に枝を作る
特定ファイルを過去から復元git restore --source SHA -- file現在変更を退避
git reflog --date=iso
git branch recovery/my-work SHA
git show SHA
git cherry-pick SHA
reset --hard: 明示的に捨てる対象を確認し、バックアップを作った場合だけ使用します。AIへ曖昧に「元に戻して」と依頼しません。

誤ってmainで作業

git switch -c feature/rescue-work
git switch main

変更を新枝へ保持してからmainへ戻ります。

push rejected

git fetch origin
git log --left-right HEAD...origin/main

分岐内容を確認し、rebaseまたはmergeを選びます。

Authentication

HTTPS credential、SSH key、GitHub CLIを混在させず、どの経路で認証しているか把握します。秘密鍵やPATをリポジトリへ保存しません。

Issue

問題、背景、完了条件、非対象を記録。実装前の合意単位として使います。

PR Review

変更概要より、バグ、セキュリティ、回帰、テスト不足を先に確認。指摘はファイルと理由を明示します。

Actions

失敗job、最初の原因、再現性を確認。ログ全体を貼らず、必要な行だけ共有します。

Protected branch: mainへ直接pushできない場合は、ルールを迂回せず、ブランチ・PR・必須check・reviewを通します。

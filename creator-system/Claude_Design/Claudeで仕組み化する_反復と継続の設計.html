実例集：仕組みになる4つの典型

どれも「1回やったあと、毎回ちょっとずつ楽になっていく」種類の作業だ。

CASE A · WEEKLY DIGEST

毎週金曜の
1週間ダイジェスト

場面毎週金曜の終業前、自分用に1週間を振り返るダイジェストが欲しい。 毎週ゼロから頼まず、同じ箱に放り込めば同じ形で返る 仕組みに畳む。
# --- 毎週このまま貼って投げるテンプレ --- あなたは私の専属エディタです。 下の1週間メモから、金曜ダイジェストを作って。 # 入力（私が貼る） WEEK: 2026-W22 NOTES: - 月曜: ... - 火曜: ... - 水曜: ... - 木曜: ... - 金曜: ... # 出力フォーマット（必ずこの順で） 1. ハイライト3つ（150字以内 / それぞれに記号 ◆） 2. 次週への申し送り（チェックリスト3つ） 3. 気持ちの一言（私から私へ、20字以内） 4. やめてもいいと思ったこと（1つ） # ルール - 全体で 500字以内 - お世辞・励まし不要 - 「来週がんばろう」みたいな締めは禁止 - 「やめてもいい」だけは 必ず1つ 出す
振り返り仕組みの肝は 「同じ箱に同じ形で入れる」こと。 入力フォーマット（NOTES:）と出力フォーマット（1〜4）を固定すると、 毎週の振り返りが 5分で完了するようになる。 そして「やめてもいい」のような 反対指針 を1つ入れておくと、習慣として腐らない。

CASE B · BRAND GUARDIAN

ブランドの守人を
1人常駐させる

場面自分のサービスのトーンを、誰が書いても揺らがないようにしたい。 ブランドの守人ロール を 役カード として作り、Projectsに常駐させる。
# --- Projectsの最初に貼る役カード --- あなたは "Inkbird" のブランド守人 「冬野」 です。 これから私が原稿を貼るたびに、ブランドの観点だけで講評してください。 # 性格 - 落ち着いた40代女性編集者 - 寡黙だが、芯のある言葉を返す - 励まさない。媚びない。 - 一度に 3点まで しか指摘しない # 採点軸 1. 静けさ: 余白がある言葉か 2. 主役: 「書く人」が主語になっているか 3. 禁則: 「未来 / 新しい / 挑戦」が入っていないか # 出力フォーマット | 観点 | 評価(◯/△/✗) | 直すなら | 最後に1行、冬野からのコメント。 「素晴らしい」「いいですね」は禁句。 # 確認 このカードでよければ「冬野、了解」とだけ返して。
振り返り役カードを 常駐 させると、Claudeは毎回同じ判定基準で動く。 「冬野」のような名前を与えるのは、Claudeのためではなく 自分のため。 「冬野ならどう言うか」と思えるようになると、書く前から自分でチェックがかかる。

CASE C · MEETING NOTES

打ち合わせメモを
自動で構造化

場面打ち合わせ後の生メモ（言いっぱなしの箇条書き）を、 毎回 同じ形式の議事録 に整える。書記の役を、Claudeに常設する。
# --- 議事録整形テンプレ --- あなたは経験豊富な書記です。 下の生メモを、決まった形式の議事録に整えてください。 # 入力（私が貼る） MEETING: [件名] DATE: [YYYY-MM-DD] ATTENDEES: [名前カンマ区切り] RAW: （生メモを貼る。順不同でいい） # 出力フォーマット 1. 決まったこと （箇条書き・各行に【決定】タグ） 2. 宿題 （箇条書き・各行に owner と期限） 3. 論点として残ったこと 4. 次回MTGの議題候補 # ルール - 私語・脱線は 削除 - 「〜したい」など願望は 宿題 に格上げ - 推測で owner を当てない。不明は「未定」と書く - 出力は Markdown表 形式 # おまけ 最後に "FOLLOWUP_SLACK" として、 社内Slack用の3行要約も。
振り返り議事録は 形式が9割。 「決定 / 宿題 / 論点 / 次回」の4つに分けるルールを最初に決めれば、 会議中はメモ取りに集中でき、整形はClaudeに任せられる。 Slack要約まで 同じ素材から 派生させると、後工程の手間が消える。

CASE D · FAILURE LOG

しくじりを
仕組みに変える

場面CH.05で書いた「しくじりノート」を、ばらばらの紙ではなく 1つの表 として育てる。 Claudeに、毎月の集計と 再発防止の傾向 まで出させる。
# --- 失敗ログ管理テンプレ --- あなたは私の専属の 「学習担当」 です。 失敗ログを管理し、月末に傾向を読み解いてください。 # ストック形式（私が貯めていく） | 日付 | カテゴリ | 何が起きたか | 次にやること | カテゴリは： - VAGUE（漠然依頼） - LIE（嘘・ハルシネ） - RUSH（一発完成狙い） - FLOOD（情報詰め込み） - NOCLOSE（畳まなかった） # 月末に頼むこと 1. カテゴリ別の件数 を集計 2. 多い順に トップ3 を抽出 3. それぞれに 再発防止ルール を1つ 4. 来月「これだけはやらない」を1つ # 注意 - 私のせいにしない言い方で - 「成長」「進化」みたいな言葉は使わない - 数字と 処方箋 だけでいい
振り返り失敗を 個別の出来事 ではなく 傾向 として見ると、対策が変わる。 「VAGUE が5件」と分かれば、対策は「毎回の最初に役カードを貼る」のような 仕組み に落ちる。 ノートは続けるだけでは弱い。集計して処方箋まで持ってきて、はじめて効く。

03

仕組み化テンプレ 6つ

そのままProjectsに貼ればよい土台。1つでも仕込めば、毎週の負荷が軽くなる。

PROJECT-SETUP

① プロジェクト開設宣言

Projectsを新規で立てるとき、最初に貼る「土台メッセージ」。

# --- このプロジェクトの宣言 ---
NAME: [プロジェクト名]
PURPOSE: [一行で目的]
HORIZON: [期間 / 終わりの形]

# 常駐資料
- brand_guide.md
- past_works.zip
- style_rules.pdf

# あなたの基本ふるまい
- 私が役を指定しない限り、相棒モード
- お世辞・励まし・無駄な締めは禁止
- 質問は 1つずつ
- 出力は Markdown 既定

# 終わるとき
セッション末に「3行サマリ＋宿題3＋一言」を残す。

準備OKなら「準備OK」とだけ返して。
ROLE-CARD

② 役カード

名前のついた役を呼び出せるようにする。複数の役を「名簿」として常備しよう。

あなたは 「[呼称]」 です。

# 性格・役割
- [年代 / 職業 / 経験]
- [1行で性格]

# 評価軸（3つまで）
1. [観点A]
2. [観点B]
3. [観点C]

# 禁則・口調
- 一度に 3点まで しか言わない
- 「素晴らしい」「いいですね」は禁句
- 励まさない・媚びない

# 出力形式
| 観点 | 評価(◯/△/✗) | 直すなら |

最後に、本人からの一言を1行。
このカードでよければ「[呼称]、了解」とだけ返して。
RECURRING

③ 定例タスクのマクロ

毎週・毎月の決まりごとを「同じ入口・同じ出口」に固定する。

# --- 定例タスク: [名前] ---
頻度: [毎週X曜 / 毎月N日]

# 入力（私が貼る）
WHEN: [周期番号 例: 2026-W22]
NOTES:
[フリーフォーマットのメモ]

# 出力フォーマット（厳守）
1. [項目A]
2. [項目B]
3. [項目C]

# ルール
- 全体 [N] 字以内
- お世辞・励まし禁止
- 「[必ず1つは出す項目]」を毎回入れる
- 出力の最後に「次の[周期]へ」と1行
FORMAT

④ 入出力の規約

回答の形を最初に固定する。後工程（コピペ・印刷・転記）が圧倒的に楽になる。

# --- 入出力規約 ---

# 入力ルール
- 私からの入力は YAML or Markdown
- 必須キー: [title, body, ...]
- 空欄は "TBD" と書く

# 出力ルール
- 既定は Markdown
- 表が必要なら | 区切り |
- コードブロックには言語タグ
- 出力の最初の行は必ず "# [タイトル]"

# 禁止
- 絵文字
- HTMLタグ（コード例を除く）
- 「以下のような」など曖昧な前置き

この規約でよければ「規約了解」とだけ。
HANDOFF

⑤ 引き継ぎ書

セッションの終わりに、未来の自分のための申し送りを残す儀式。

今日のセッションを畳んでください。

# 残してほしいもの
1. 決まったこと（3つ）
2. 未決の宿題（3つ） — owner / 期限つき
3. 来週の私への一言（20字以内）
4. 今日のしくじりログ（あれば1件）

# 体裁
- 箇条書き
- 来週の私が 3分で 読み返せる粒度
- 励ましや「がんばろう」は不要

最後に、HANDOFF_DATE: [YYYY-MM-DD HH:MM] と
NEXT_SESSION: [予定] を付けて。

これをそのままProjectのトップにピン留めします。
METRICS

⑥ 月次の観測

月末に貯めたものを集計させる。観測しないと、仕組みは育たない。

今月のログを集計してください。

# 集計対象
- 失敗ログ（カテゴリ別）
- 完了タスク（種類別）
- 過ごした時間（推定でいい）

# 出力
1. 数字の表（カテゴリ別件数・時間）
2. 気づき3つ（1行ずつ）
3. 来月の処方箋1つ（仕組みレベルで）
4. これだけはやらない ルール1つ

# 禁止
- 「成長しています」のような評価
- 抽象的な激励
- 「次もがんばりましょう」の締め

数字と 処方箋 だけでいい。
04

仕組み化の得意・不得意

仕組みに向く仕事と、無理に仕組みにしない方がいい仕事がある。線引きが上手いと、Claudeが楽になる。

◯仕組みに向くもの

SYSTEMIZE — 型にすると質が安定する
  • 定期的に発生する出力週次レポ・月次サマリ・議事録・告知文。毎回同じ形が要求される
  • 判定基準が明文化できる仕事ブランドガイド・トーン規範・チェックリスト。「これでOK」が言葉になる
  • 素材→形の変換生メモ→議事録、原稿→SNS投稿、文字起こし→字幕。フォーマット変換
  • 複数の役の使い分け編集者・批評家・調査担当。役カードを切り替えるだけで人格が動く
  • 失敗・学びの蓄積同じ穴に二度落ちないために、Claudeに記録と集計を任せる
  • 引き継ぎ・再開長期プロジェクトでの「前回からの続き」を、テンプレで取り戻す

△仕組みにしないほうがいいもの

KEEP HUMAN — 型にすると死ぬもの
  • 初動の発想・コンセプトはじまりは型から出ない。最初の1案だけは、毎回ゼロから話す
  • 感情・関係の話誰かを傷つけたとき、悩んでいるとき。テンプレで処理しない
  • 本当に大事な意思決定方向の岐路は人が選ぶ。仕組みは選択肢を出すまで、決めるのは自分
  • 偶然の発見仕組みは「いつもの形」を強化する。たまの脱線・寄り道を殺さない
  • 創作のピーク本気で良いものを書くときは、テンプレを 捨てる 勇気を持つ
  • 機密性の高い相談個人情報・社内秘・関係者の名前は、貼る前に必ず置き換える
05 / CYCLE

週・月・年の3つのリズム。

毎週
WEEKLY · 5min

軽い見直し

  • 金曜ダイジェスト1週間の出来事を、決まった型で短く。
  • 来週の宿題3つ増やしすぎない。本当に動かしたい3つだけ。
  • 「やめてもいい」1つ習慣を腐らせない、反対指針。
毎月
MONTHLY · 20min

傾向を読む

  • 失敗ログ集計カテゴリ別の件数・トップ3に処方箋。
  • 時間の使い方書く・つくる・整える、どこに何時間。
  • 「これだけはやらない」1つ増やすより、減らす。
毎年
YEARLY · 1h

仕組みを刷新

  • 使ってない型を捨てる古い役カード・テンプレを掃除。
  • 新しい役を1人増やす来年の自分のための、新しい相棒を1人だけ追加。
  • 長い手紙を1通来年の自分に、PCを閉じて手書きで。

📐 コツ ・3つの周期を別々の場所に置く。週は手帳、月はProjects、年は紙のノート、のように。 ・どれも 「やめる枠」 を必ず1つ残す。仕組みは増やすより削るのが難しい。 ・年の見直しだけは、Claudeを使わずに自分で。仕組みを 外から 見直す時間。

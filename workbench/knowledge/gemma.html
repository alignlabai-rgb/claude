2. Gemini API vs Gemma 4 ローカル — 使い分けマトリクス

判断基準Gemma 4（ローカル）Gemini API（クラウド）
データプライバシー ◎ 完全オフライン、データ漏洩なし △ Google サーバーへ送信
大量トークン処理コスト ◎ 自前 GPU コスト = 固定費 △ トークン量に比例して増加
オフライン環境 ◎ インターネット不要 ✗ 必須
ファインチューニング ◎ LoRA / QLoRA で自由に △ 制限あり（Vertex AI Fine-tuning）
最高性能 △ 31B Dense でも Gemini 3.1 Pro に及ばない ◎ Gemini 3.1 Pro / 3.5 Flash
セットアップ難易度 △ GPU 環境・Ollama / llama.cpp の構築が必要 ◎ API キーだけで即利用
レイテンシ ◎ ネットワーク遅延なし △ ネットワーク往復あり
規制・エアギャップ環境 ◎ 完全分離デプロイ可 ✗ 不可

🎯 判断の公式: プライバシー要件 / 大量トークン / オフライン / カスタム Fine-tuning → Gemma 4。最高性能 / マルチモーダル最前線 / セットアップ最小化 → Gemini API。

3. Apache 2.0 ライセンスと商用利用

できること ✅

  • 商用プロダクトへの組み込み
  • 改変・派生モデルの作成
  • 再配布（ライセンス表記必要）
  • 有償サービスでの利用
  • LoRA アダプタの販売・配布
  • SaaS・API サービス化

できないこと ❌

  • Google の商標・ロゴの無断使用
  • 有害コンテンツ生成（使用ポリシー違反）
  • Gemma 使用ポリシーに反する用途
  • Apache 2.0 表記の削除

Llama との違い

  • Llama 4: MAU 7億超はメタ承認が必要
  • Gemma 4: Apache 2.0 のみ、ユーザー数制限なし
  • 企業の法務レビューが通りやすい

② Hugging Face + Transformers（Python）

# pip install transformers torch accelerate
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_id = "google/gemma-4-27b-it"    # instruction-tuned 版
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    device_map="auto",                 # 複数 GPU 自動分割
)

chat = [{"role": "user", "content": "日本の量子コンピュータ研究の現状は？"}]
input_ids = tokenizer.apply_chat_template(
    chat, return_tensors="pt", add_generation_prompt=True
).to(model.device)

output = model.generate(input_ids, max_new_tokens=512, do_sample=True)
decoded = tokenizer.decode(output[0][input_ids.shape[-1]:], skip_special_tokens=True)
print(decoded)

5. Fine-tuning ガイド — Unsloth + LoRA

Gemma 4 31B を Unsloth + QLoRA で 16 GB VRAM の単一 GPU で1時間以内に Fine-tuning できる。

いつ Fine-tuning するか

  • 特定ドメインの専門用語・口調の統一
  • 社内ガイドライン準拠の応答パターン
  • プロンプト設計で解決しない場合
  • ターゲットタスクの精度を最大化したい

必要スペック目安

  • QLoRA 31B: 16 GB VRAM（RTX 4080 / A100 40G）
  • LoRA 26B MoE: 12 GB VRAM（RTX 4070 Ti）
  • LoRA E4B: 6 GB VRAM（RTX 3060）
  • フルファインチューニング 31B: ~80 GB VRAM
# pip install unsloth
from unsloth import FastLanguageModel
import torch

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="google/gemma-4-27b-it",
    max_seq_length=8192,
    dtype=torch.bfloat16,
    load_in_4bit=True,             # QLoRA: 4bit 量子化
)

# LoRA アダプタを追加
model = FastLanguageModel.get_peft_model(
    model,
    r=16,                          # LoRA ランク
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    use_gradient_checkpointing=True,
)

# 学習データは Alpaca / ShareGPT 形式の JSONL
from trl import SFTTrainer
from transformers import TrainingArguments

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=your_dataset,    # HuggingFace Dataset
    dataset_text_field="text",
    max_seq_length=8192,
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        num_train_epochs=3,
        learning_rate=2e-4,
        output_dir="./gemma4-ft",
        fp16=False, bf16=True,
    ),
)
trainer.train()

9. 実践ワークフロー

① ローカル RAG システム（プライバシー重視）

# pip install langchain langchain-community chromadb ollama
from langchain_community.llms import Ollama
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import OllamaEmbeddings
from langchain.chains import RetrievalQA
from langchain.document_loaders import PyPDFLoader

# ローカル PDF を読み込んでベクトル化
loader = PyPDFLoader("confidential_report.pdf")
docs = loader.load_and_split()

embeddings = OllamaEmbeddings(model="gemma4:27b")
vectorstore = Chroma.from_documents(docs, embeddings)

# Gemma 4 でローカル RAG
llm = Ollama(model="gemma4:27b")
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3}),
)

answer = qa_chain.invoke("四半期の主なリスク要因は何か？")
print(answer["result"])

② バッチ文書処理（オフライン・大量）

import ollama, json
from pathlib import Path

def summarize_doc(text: str) -> dict:
    res = ollama.chat(
        model="gemma4:27b",
        messages=[{
            "role": "user",
            "content": f"以下の文書を日本語で3行に要約してください:\n\n{text[:4000]}"
        }],
    )
    return {"summary": res.message.content}

# docs/ フォルダ内の全 txt ファイルを処理
results = []
for path in Path("docs").glob("*.txt"):
    text = path.read_text(encoding="utf-8")
    result = summarize_doc(text)
    result["file"] = path.name
    results.append(result)

with open("summaries.json", "w", encoding="utf-8") as f:
    json.dump(results, f, ensure_ascii=False, indent=2)
print(f"{len(results)} 件を処理しました")

11. Google エコシステムとの連携

🌐 ローカル〜クラウドのスペクトラム: Gemma 4（完全ローカル）→ Gemini Flash（低コスト API）→ Gemini Pro（最高性能 API）という連続体として使い分ける。プロトタイプは AI Studio、本番は用途に応じて Gemma か Gemini API を選択。

🤖 Antigravity との連携: Antigravity CLI / SDK はデフォルトで Gemini 3.5 Flash を使うが、ローカルの Gemma 4 を Ollama 経由で接続することで完全オフラインのエージェントシステムを構築できる。詳細は anti-gravity.html。

🛠 AI Studio でのテスト: Google AI Studio でも Gemma モデルを試せる。プロンプトを確定させたあと、同じプロンプトをローカル Ollama の Gemma 4 で実行するのが最も効率的な移行フロー。

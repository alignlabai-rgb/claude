Zhipu/Z.ai系（zai-org）が公開したキャラクター動作転写モデル。参照画像1枚 + 駆動動画から、そのキャラのポーズ違い画像・動画を大量生成できる。WanSCAILToVideo・SCAIL2ColoredMask・SAM3トラッキングの組み合わせで、追加のカスタムノード不要（標準モデルDLのみ）。

Krea社のオープンウェイト画像モデル。RAW（52ステップ・LoRA学習用）とTurbo（8ステップ推論用）のペア構成。「RAWで学習しTurboで量産」という運用がキャラクターLoRA制作の新しい定番になりつつある。

Nano Banana 2 Lite（v0.27.0, 2026-06-30）

ComfyUIから直接呼べるパートナーノードとして追加。参照画像・ラフ出し用途（1K画像 約$0.034・約4秒）で、ローカル生成の前段プレビューに使える。Imagen 4は2026年8月17日廃止予定のため、今から乗り換えておくのが安全。

int8モデル対応（v0.27.0, 2026-06-30）

Turing世代（RTX 20xx）以降のGPUでint8量子化モデルが高速化。旧GPUでもVRAM消費を抑えつつfp16に近い速度が出るようになり、低スペック環境でのキャラクターLoRA運用のハードルが下がった。

キャラクター一貫性 2026年7月版

「LoRA + IP-Adapter + ControlNet」に
SCAIL-2を足すとどう変わるか

manga-pipeline.htmlの3重構成（LoRA / IP-Adapter / ControlNet）は今も土台として有効。 そこに2026年6月以降実用段階に入ったSCAIL-2を足すと、 「基準ポーズ1枚から大量の一貫ポーズ違いを機械的に生成する」工程が追加できる。

従来: 1コマずつプロンプトでポーズ生成

# 旧来フロー（コマごとに再生成） for panel in panels: generate_panel( character, panel.pose_prompt, lora="hiro_v3.safetensors", controlnet_openpose=panel.pose_map ) # → コマごとにCLIP類似度チェックが必要 # 崩れたら再生成、を繰り返す

2026年7月: SCAIL-2で駆動動画からポーズ量産

# SCAIL-2 Animation Mode # 参照画像1枚 + 駆動動画（自作 or ストック）から # 同一キャラの一貫したポーズ違いを連続生成 WanSCAILToVideo( reference_image="ref/hiro_face_body.png", driving_video="motion/run_upstairs.mp4", mode="animation" ) # SCAIL2ColoredMask で複数キャラの # identity↔colorを固定（複数キャラシーンでも安定）

使い分けの考え方

静止画1コマだけ欲しい → 従来のLoRA+IP-Adapter+ControlNet
単発のコマ生成はセットアップが軽い従来手法の方が速い。SCAIL-2は駆動動画の用意が前提になる分、初期コストがかかる。
同じキャラで動作違いを大量に欲しい → SCAIL-2
「階段を駆け上がる」を6コマに分解したい時など、1本の駆動動画から一貫したポーズ列を切り出せる。連載モノでバトルシーン等の大量ポーズが必要な場面で特に効く。
複数キャラの絡みシーン → SCAIL-2 Replacement Mode
既存の実写/3Dモーション動画に写っている人物を、自キャラの参照画像で置き換える「Replacement Mode」。群像シーンのクロスコンタミネーション対策として、manga-pipeline.htmlのControlNet Openpose手法の代替・補完になる。
⚠️ SCAIL-2は2026年6月にComfyUI本体へ組み込まれたばかり（v0.25.0）。自パイプラインでの本格採用前には、まず少数シーンでA/Bテストを推奨。

具体的手順

Krea2でキャラクターLoRAを学習する

manga-pipeline.htmlのLoRA学習手順（Kohya SS / SDXL）に加えて、Krea2ベースでの学習手順を実データで追記する。

1
データ準備
1024×1024の高精細画像を約20枚用意（表情・角度バリエーション）。Krea2 RAWで学習し、量産はTurboで行う設計
2
学習ツール選択
AI Toolkit（手軽・初心者向け）または musubi-tuner（VRAM最適化に強い専門ツール）。Krea2はQwen3-VLエンコーダ等を同時ロードするため12GB環境では標準構成でのLoRA学習が困難 — musubi-tunerのVRAM最適化オプションが実質必須
3
学習実行
2,000ステップで十分な学習が確認されている（コミュニティ報告ベース）。SDXL系のKohya SS運用（2000〜3000ステップ・学習率1e-4）と近いレンジ
4
推論はTurboに切替
学習したLoRAをKrea2 Turbo（8ステップ推論）にロードして量産。RAWで学習・Turboで生成、という分業がKrea2の標準ワークフロー
# ComfyUI公式サンプル: docs.comfy.org/tutorials/image/krea/krea-2 # 既存Krea2ワークフローにLoRAノードを追加するだけで良い CheckpointLoader("krea2_turbo.safetensors") → LoraLoader( lora_name="hiro_krea2.safetensors", strength_model=0.85 ) → CLIPTextEncode(prompt) → KSampler(steps=8, cfg=1.5) # Turboは低steps/低cfgが基本 → VAEDecode → SaveImage # 学習側（musubi-tuner CLI例） python train_network.py \ --pretrained_model_name_or_path krea2_raw.safetensors \ --train_data_dir ./hiro_dataset \ --resolution 1024,1024 \ --max_train_steps 2000 \ --output_name hiro_krea2

実例 — 実際の制作スタジオ事例

Series Entertainment社の
ComfyUI本番導入事例

ComfyUI公式ブログが2026年2月に公開したケーススタディ。ゲーム・動画スタジオのSeries Entertainment社が、 ComfyUIのノードベースワークフローを本番制作の基盤に据え、Netflixタイトルを含む複数プロジェクトを出荷した実例。 漫画制作にも応用できる「キャラクター表情の量産」「一貫性を保った反復生成」の考え方が具体的な数値つきで示されている。

  • 生成資産数: 10万点以上（ゲーム・動画横断）
  • 制作速度: 従来手法比 180倍高速化（従来は1資産あたり6時間以上）
  • 表情生成: 6種の感情バリエーション（喜・哀・真剣・皮肉・思考・驚き）を数秒で生成
  • パイプライン数: 512×512の低解像度テストから高解像度バッチ生成まで、4本の再利用可能パイプライン
  • 成果: Netflixタイトル複数を出荷、クリエイター1人あたり週15分の完成動画を継続生産

manga-pipelineへの示唆

Series社の要点は「生成を単発の作業ではなく再利用可能な資産として扱う」こと。 具体的には：

① 感情×キャラのマトリクスを事前生成しておき、コマ生成時は都度re-promptせずマトリクスから選ぶ
② テスト用（低解像度）と本番用（高解像度）で同一ワークフローを流用し、ツール切替コストをゼロにする
③ バッチ実行・自動化を前提にワークフローを設計する（人間の都度操作を前提にしない）

これはmanga-pipeline.htmlの「ジャンルプリセット」「キャラ設定YAML」の設計思想とも一致する。

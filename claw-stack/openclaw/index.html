OpenClaw とは

OpenClaw は Claude API をフルに利用するクラウド常駐エージェント。NanoClaw が「スマホから起動するワンショット処理」であるのに対し、OpenClaw は複数ツール・長いワークフロー・HITL（人間介入）を組み合わせた複合タスクを自律実行する。

2026 年 5 月 24 日に再解禁。creator-system の漫画/動画パイプラインと直接統合されている。

いつ OpenClaw を使うか

◎ 最適

漫画 / 動画バッチ生成

ComfyUI + LoRA + ControlNet のパイプラインを 1 話分（30〜80 コマ）自動実行。HITL が必要なコマのみ Signal で確認を取る。

◎ 最適

マルチステップ配信タスク

note 投稿 → YouTube アップロード → KDP 登録 を順序通り実行。各ステップで API 認証エラーがあれば自動リトライ + Signal 通知。

適合

HITL が必要な判断タスク

品質評価で CLIP スコアが閾値を下回ったコマや、LoRA フォールバックが全段失敗したケースをユーザーへ Signal で転送。

非推奨

ワンショット質問

「○○を調べて」のような単発クエリは PicoClaw / NanoClaw で十分。OpenClaw はオーバースペック。

非推奨

24h 常駐タスク

電源断リスクのある長期監視タスクは Hermes Agent（VPS 常駐）の領域。OpenClaw はセッション起動型。

適合

週次定期処理

LLM トラッカー更新・hub-health チェック・API 認証メンテナンスを OpenClaw に依頼してバッチ実行させる。

YAML 設定例

# openclaw_config.yaml llm: provider: "anthropic" model: "claude-sonnet-4-6" max_tokens: 8192 hitl: channel: "signal" timeout_minutes: 30 fallback: "auto_approve" # タイムアウト後の動作 comfyui: host: "127.0.0.1" port: 8188 workflow_dir: "workflows/" quality: clip_threshold: 0.72 face_quality_threshold: 0.55 max_retries: 3

Signal Bot の設定手順

1

Signal CLI のインストール

signal-cli をサーバーにインストールし、専用電話番号でアカウント登録する。

2

OpenClaw との接続

config に Signal 番号と受信先番号を設定。HITL リクエストが発生すると OpenClaw が Signal メッセージを送信する。

3

返答パースの確認

y/n/e（edit）と日本語エイリアスが使える。詳細は creator-system/openclaw.html の Signal 返答パース実装を参照。

4

タイムアウト設定

デフォルト 30 分。タイムアウト後の動作（自動承認 / 自動拒否 / スキップ）を config で指定する。

フォールバック構造

エラートリガー型（即時）

  • HTTP 429 / 402 / 503 → 即フォールバック
  • 連続失敗 3 回 → 次ツールへ
if error.status_code in (429, 402, 503): return fallback_immediately()

品質トリガー型（遅延）

  • CLIP スコア < 閾値 かつ 2 回リトライ後 → HITL
  • LoRA 4 段階失敗 → Signal 転送
if clip_score < threshold and retry_count >= 2: request_human_review()

完全な実装コードは creator-system/openclaw.html のフォールバック発動条件セクションを参照。

Skill Workshop — エージェント自己改善ループ

v2026.6.1 で導入。エージェントが SKILL.md を直接書き換える代わりに提案→レビュー→適用の governed フローを経由する。

フロー概要

1

提案（Propose）

エージェントが繰り返し作業を検出 → SKILL.proposal.md に草案を自動生成。status: draft でバージョン管理される。

2

レビュー（Inspect）

openclaw skills workshop inspect <id> で差分確認。何が追加・変更されるかを人間がチェック。

3

適用（Apply）

openclaw skills workshop apply <id> で SKILL.md に書き込み。proposal-only フィールド（status/proposal date）は自動削除。

4

拒否・隔離

reject でゴミ箱へ。quarantine でリスク案件を隔離。ロールバックも標準装備。

CLI コマンド

openclaw skills workshop list openclaw skills workshop inspect <id> openclaw skills workshop apply <id> openclaw skills workshop reject <id> openclaw skills workshop quarantine <id>
どんな時に使うか： 漫画パイプラインで毎回同じ「LoRA 選定→CLIP 評価→HITL」の流れを繰り返しているとき、エージェントが自分で「これスキル化すべきでは？」と提案を出す。ユーザーは apply を叩くだけで次回から自動実行される。

Workboard マルチエージェント実例

# 複数エージェントをまたぐタスク計画 openclaw workboard create \ --title "Ep.03 フル制作" \ --agents "artist,writer,uploader" \ --steps "storyboard,render,caption,upload" # 進捗確認（横断ダッシュボード） openclaw workboard status --board ep03

Pi SDK 統合 — OpenClaw の内部エンジン

OpenClaw は Earendil 社の Pi SDK（@earendil-works/pi-agent-core）をコアエンジンとして使用。Creator System の漫画/動画ワークフローもこの上に構築されている。

主要依存パッケージ

パッケージ役割
@earendil-works/pi-agent-coreコアエージェントループ・ツール管理
pi-coding-agentコーディング特化エージェント
pi-aiマルチ LLM プロバイダー抽象層
pi-tuiターミナル UI コンポーネント

Gateway での createAgentSession() 呼び出し例

import { createAgent } from "@earendil-works/pi-coding-agent"; const session = await createAgent({ provider: "anthropic", model: "claude-sonnet-4-6", extensions: [comfyuiPlugin, signalPlugin], }); // OpenClaw が WhatsApp/Signal/Discord 等 // 全チャネルをこの1セッションに接続 await session.start();
Pi の RPC モードを使うと、外部プロセスから JSONL で OpenClaw エージェントを制御できる。CI/CD パイプラインとの連携に有効。

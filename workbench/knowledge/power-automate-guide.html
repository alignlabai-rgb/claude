フロー種別の完全解説

Instant Flow

即時フロー（手動起動）

モバイルアプリのボタン・Power Apps からのボタン・Teams のアダプティブカードで起動。入力パラメータを受け取れる。

モバイルボタンPower Apps 呼出Teams ボタン
Scheduled Flow

スケジュールフロー

指定した間隔・時刻に自動実行。「繰り返し」トリガー。分・時間・日・週・月単位で設定。タイムゾーン指定が重要。

日次バッチ週次レポート月末処理
Automated Flow

自動フロー（イベント駆動）

外部イベント（ファイル追加・メール受信・行変更等）をトリガーに自動起動。最も多用されるタイプ。

ファイル追加メール受信レコード変更
Desktop Flow

デスクトップフロー（RPA）

Power Automate Desktop で録画したUI操作を自動化。有人（アテンデッド）・無人（アンアテンデッド）を選択。

Windows UIWeb操作Excel/SAP
BPF

ビジネスプロセスフロー

Dataverse レコードに紐づくステージ進行管理。営業商談・審査フロー等の「状態遷移」を視覚化。Model-driven App と連携。

ステージ管理SLA制御Dataverse
Child Flow

子フロー（モジュール化）

「ソリューション」内で定義した別フローを呼び出す。共通ロジック（通知送信・ログ書込等）をライブラリ化して再利用。

式言語（Expression）マスターガイド

Power Automate の式は Azure Logic Apps と同じ Workflow Expression Language。 動的コンテンツだけでは対応できない処理（文字列整形・日付計算・配列操作・条件評価）はすべて式で解決する。GUI の「式」タブに入力する。

文字列操作

// 結合 concat('申請ID-', string(triggerOutputs()?['body/ID'])) // 部分取得 substring(variables('email'), 0, indexOf(variables('email'), '@')) // @ より前 last(split(variables('email'), '@')) // @ より後（ドメイン部） // 置換・トリム replace(variables('text'), '　', ' ') // 全角スペース→半角 trim(variables('text')) // 大文字小文字 toUpper(variables('status')) toLower(variables('email')) // 含む判定（条件式で使用） contains(variables('subject'), '緊急') startsWith(variables('filename'), 'INV-') endsWith(variables('filename'), '.pdf') // 長さ length(variables('text')) // 改行コードの除去（Teamsメッセージ等に有用） replace(replace(variables('text'), '\r\n', ' '), '\n', ' ')

日時操作

// 現在時刻（UTC） utcNow() // → 2026-05-31T10:00:00.0000000Z // フォーマット変換 formatDateTime(utcNow(), 'yyyy-MM-dd') // → 2026-05-31 formatDateTime(utcNow(), 'yyyy年M月d日') // → 2026年5月31日 formatDateTime(utcNow(), 'HH:mm') // → 19:00 (UTCなので注意) // タイムゾーン変換（日本時間） convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time') // 日本時間でフォーマット formatDateTime(convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time'), 'yyyy-MM-dd HH:mm') // 加算・減算 addDays(utcNow(), 7) // 7日後 addDays(utcNow(), -1) // 昨日 addHours(utcNow(), 9) // 9時間後 addMinutes(utcNow(), 30) // 30分後 // 差分（日数） div(sub(ticks(variables('deadline')), ticks(utcNow())), 864000000000) // ticks差を100ナノ秒単位から日数に変換

配列・JSON操作

// 配列の要素数 length(variables('items')) // 最初・最後の要素 first(variables('items')) last(variables('items')) // 特定プロパティだけ取り出す（配列→配列） // ※ Select アクション（データ操作）を使うと GUI で設定可能 // 配列に値が含まれるか contains(variables('approvers'), 'user@example.com') // JSONの特定キー取得 body('Parse_JSON')?['results']?[0]?['name'] // union（配列のマージ） union(variables('list1'), variables('list2')) // intersection（共通要素） intersection(variables('list1'), variables('list2'))

条件・型変換

// 三項演算子的な使い方 if(equals(variables('status'), 'Approved'), '承認済み', '未承認') // null チェック if(empty(triggerOutputs()?['body/comment']), 'コメントなし', triggerOutputs()?['body/comment']) coalesce(triggerOutputs()?['body/manager'], 'manager@example.com') // null なら代替値 // 型変換 string(12345) // 数値→文字列 int('42') // 文字列→整数 float('3.14') // 文字列→小数 bool('true') // 文字列→真偽値 json('{"key":"val"}') // 文字列→JSONオブジェクト base64(variables('text')) // Base64エンコード base64ToString(variables('enc')) // Base64デコード // 数値演算 add(100, 200) // 加算 sub(500, 150) // 減算 mul(3, 1.08) // 乗算（税込） div(1000, 3) // 除算 mod(10, 3) // 余り → 1

03

高度な制御フロー

並列分岐（Parallel Branch）

並列分岐は「同時に実行できるアクション群を分ける」もので、それぞれの結果を待って次に進む。 例：PDF生成・Teams通知・DB記録を同時実行して全完了後に完了メールを送る。
// 設計例：申請受付後の並列処理 [申請フォーム受信] ↓ 並列分岐 ─────────────────────────────────────┐ │ 分岐A: SharePoint にレコード作成 │ │ 分岐B: 申請者に受付メール送信 │ │ 分岐C: 承認者に Teams 通知 │ └─────────────────────────────────────────────────┘ ↓ （全分岐完了後） [承認フロー開始]

Do Until ループ（条件を満たすまで繰り返す）

// 例：外部APIのステータスが "completed" になるまでポーリング 変数初期化: status = "" 変数初期化: count = 0 Do Until: 条件: equals(variables('status'), 'completed') 上限: 回数 10 / タイムアウト PT1H ───────────────────────────── HTTP GET: /api/job/{jobId}/status JSON解析: レスポンス 変数設定: status = body('Parse_JSON')?['status'] 条件: status が 'failed' → Teams エラー通知 → 終了 遅延: 30秒 [完了後の処理]

Apply to each — 並列度の設定

「Apply to each」はデフォルトで直列実行（1件ずつ）。設定の「同時実行の制御」をオンにすると並列度1〜50で動かせる。 ただし順序が重要な処理（DB書込み順序が決まっている等）には使わない。

並列化が有効なケース

  • 独立したメール送信（1000人への一斉送信）
  • 独立したファイル変換処理
  • 各行のAPI呼び出し（順序不問）
  • 外部サービスへの書き込み（べき等な処理）

並列化してはいけないケース

  • 採番・連番の払い出し
  • 後続が前の結果に依存する処理
  • API のレートリミットがある処理
  • 同一レコードへの書き込み（競合する）

スコープ（Scope）— エラー境界の設計

// ベストプラクティス構造 スコープ: "Try" ← メイン処理をまとめる → アクション1 → アクション2 → アクション3 スコープ: "Catch" ← 実行条件: 「失敗した場合に実行」 → Teams にエラー通知 本文: concat('エラー: ', actions('Scope_Try')?['error']?['message']) → Dataverse エラーログ書込 フロー名: workflow()?['name'] 実行ID: workflow()?['run']?['name'] エラー詳細: string(actions('Scope_Try')?['error']) → 終了（失敗として） スコープ: "Finally" ← 実行条件: 「スキップされた場合に実行」を含む → 常に実行したい後処理（ロック解除など）

子フロー設計パターン

子フロー名入力出力呼び出し元

SharePoint 連携パターン集

SharePoint は Power Automate で最多利用のコネクタ。 リスト（構造化データ）とドキュメントライブラリ（ファイル）の2軸で考える。大量アイテムの操作は「フィルタークエリ」と「上位の取得件数」を必ず設定してパフォーマンスを守る。

リスト操作の頻出パターン

// ① 複数アイテム取得（フィルター付き） アクション: 「複数の項目の取得」 サイト: https://contoso.sharepoint.com/sites/HR リスト: 申請リスト フィルタークエリ: Status eq 'Pending' and Created ge '2026-05-01' 上位の取得件数: 500 列の絞り込み: ID,Title,ApplicantEmail,Status,Created // ② アイテム更新 アクション: 「項目の更新」 ID: triggerOutputs()?['body/ID'] Status: 'Approved' ApprovedAt: utcNow() ApproverComment: outputs('承認の開始と待機')?['body/responses'][0]['comments'] // ③ ファイルをメタデータ付きでアップロード アクション: 「ファイルの作成」 フォルダーパス: /Shared Documents/Reports/2026 ファイル名: concat(formatDateTime(utcNow(), 'yyyyMM'), '_売上レポート.xlsx') ファイルコンテンツ: outputs('Excel作成')?['body'] アクション: 「ファイルプロパティの更新」（メタデータ列を更新） 報告月: formatDateTime(utcNow(), 'yyyy-MM') 作成者部署: variables('dept')

大量データ処理のパターン（ページング）

// SharePoint リストが5000件超の場合のページング 変数初期化: skipToken = "" 変数初期化: allItems = [] Do Until: empty(variables('skipToken')) AND count > 0 複数の項目の取得: フィルター: Active eq true 上位の取得件数: 5000 ページトークン: variables('skipToken') ↓ 変数追加: allItems += body の value 変数設定: skipToken = body の @odata.nextLink (空なら終了) // ※「設定」で「ページ分割」をオンにすると自動ページングも可能 // 閾値: 100000 件まで対応（推奨値）

SharePoint 電子署名・承認ドキュメント管理フロー

// ドキュメント承認の完全フロー トリガー: [ドキュメントライブラリ] ファイルが作成された フォルダー: /申請中 ↓ 条件: ファイル名が '.pdf' で終わる ↓ Yes 承認の開始と待機: 承認者: split(triggerOutputs()?['body/{Author}/Email'], ';') タイトル: concat('【承認依頼】', triggerOutputs()?['body/{Name}']) 詳細: ファイルリンクを含む説明文 タイムアウト: PT72H // 3日 ↓ Switch (outcome): 'Approve' → ファイルを /承認済み フォルダへ移動 メタデータ: 承認日・承認者を更新 申請者にメール送信 'Reject' → ファイルを /差戻し フォルダへ移動 申請者にコメント付き差戻しメール タイムアウト → 上長にエスカレーションメール

Teams 連携 & Adaptive Cards 実践

Adaptive Card で操作UIを埋め込む

Adaptive Cards を Teams チャットに送ることで、フローの途中にインタラクティブなUIを挟める。 承認ボタン・フォーム入力・選択肢を Teams 上で完結させられるため、メールより圧倒的に回収率が高い。
// Adaptive Card の基本構造（JSON） { "type": "AdaptiveCard", "version": "1.4", "body": [ { "type": "TextBlock", "text": "【承認依頼】申請ID: ${申請ID}", "size": "Large", "weight": "Bolder" }, { "type": "FactSet", "facts": [ { "title": "申請者", "value": "${申請者名}" }, { "title": "金額", "value": "${金額}円" }, { "title": "理由", "value": "${理由}" } ] }, { "type": "Input.Text", "id": "comment", "placeholder": "コメント（任意）", "isMultiline": true } ], "actions": [ { "type": "Action.Submit", "title": "✅ 承認", "data": { "action": "approve" } }, { "type": "Action.Submit", "title": "❌ 差戻し", "data": { "action": "reject" } } ] }
// Power Automate での送信＆応答待ちアクション アクション: 「アダプティブカードを Teams ユーザーに投稿して応答を待機」 受信者: 承認者のメールアドレス メッセージ: 上記 Adaptive Card JSON（動的コンテンツで変数を埋め込む） 応答を待機: オン（最大72時間） ↓ 応答の取得: action: outputs?['body/data/action'] // 'approve' or 'reject' comment: outputs?['body/data/comment'] // テキスト入力の内容

デバッグ & トラブルシューティング

実行履歴の確認

make.powerautomate.com → フロー → 「28日間の実行履歴」。失敗したアクションをクリックすると入力・出力・エラーメッセージを確認できる。JSONをコピーして外部エディタで整形すると読みやすい。

テストモード

フロー編集画面の「テスト」→「自動（最近の実行を使用）」で前回の実行データを入力として再実行できる。実際にコネクタを動かさずに式だけテストしたい場合は「手動」を選ぶ。

実行の再送信

失敗した実行を「再送信」すると同じ入力データでフローを再実行できる。修正後の動作確認に最適。ただし冪等でない処理（二重書込み等）に注意。

よくあるエラーと対処法

エラー原因対処

The response did not match the expected schema「JSONの解析」のスキーマと実データが不一致実際のレスポンスJSON で「スキーマの生成」ボタンを再実行

Monitor（監視）ツールの活用

Power Automate の Monitor（make.powerautomate.com → モニター）では、全フローの実行状況をリアルタイムで一覧表示できる。 失敗率が高いフローを素早く特定し、アラートを設定することでSLA管理が可能。管理者は環境全体の実行状況を確認できる。

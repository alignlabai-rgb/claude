システム内での役割

評価通過コンテンツを
収益に変換する最終層

マネタイズシステムはパイプラインの最終ステップです。 評価システムを通過したコンテンツを受け取り、 各プラットフォームのAPIを介して自動投稿・販売を行います。 収益データはループの起点となり、ネタ生成AIと評価システムの最適化に活用されます。

  • 入力元: 評価システム（スコア85以上のコンテンツ）
  • 出力先: YouTube / note / Kindle / Booth / ファンクラブ
  • フィードバック先: 評価システム・ネタ生成AI（収益パターン）
  • 投稿自動化: 最適時間帯を学習し完全無人実行
  • 収益集計: 全プラットフォームを統合ダッシュボードで一元管理

セットアップガイド

各プラットフォームの
初期設定手順

▶️

YouTube — API連携セットアップ

要: チャンネル収益化
  1. Google Cloud Console でプロジェクト作成
  2. YouTube Data API v3 を有効化
  3. OAuth 2.0 クライアントIDを作成（デスクトップアプリ）
  4. YOUTUBE_CLIENT_ID / YOUTUBE_CLIENT_SECRET を .env に設定
  5. 初回認証フローを実行してリフレッシュトークンを取得
  6. チャンネル収益化: 1,000登録者 + 4,000時間達成後にYPP申請
# YouTube OAuth 初回認証 from google_auth_oauthlib.flow import InstalledAppFlow SCOPES = ["https://www.googleapis.com/auth/youtube.upload"] flow = InstalledAppFlow.from_client_secrets_file( "client_secrets.json", SCOPES ) credentials = flow.run_local_server(port=0) # → refresh_token を .env に保存
💡 APIの1日あたりアップロード上限: 6本（quotaユニット上限による）。月30本投稿なら複数チャンネルorクォータ申請が必要。
📝

note — セッションToken 取得手順

最も簡単

note は公式APIが非公開のため、セッショントークンを使った擬似API方式で自動投稿します。

  1. note.com にログイン（ブラウザ）
  2. DevTools → Application → Cookies を開く
  3. note_gql_auth_token の値をコピー
  4. NOTE_SESSION_TOKEN として .env に設定
  5. トークンは30日で失効するため月次更新が必要
⚠️ note 利用規約の自動化条項に注意。過度な連続投稿はアカウント停止リスクあり。1日最大5本までを推奨。
# note 投稿 API 呼び出し例 import requests headers = { "Cookie": f"note_gql_auth_token={TOKEN}", "Content-Type": "application/json" } payload = { "title": article_title, "body": article_body, "price": 300, "status": "published" } res = requests.post( "https://note.com/api/v2/notes", json=payload, headers=headers )
📚

Kindle KDP — 自動出版フロー

審査 3〜5日
  1. kdp.amazon.co.jp にアカウント作成（税務情報の入力が必要）
  2. 漫画PDFをEPUB3形式に自動変換（Calibre CLI 使用）
  3. カバー画像を自動生成（1600×2560px / JPEG）
  4. Selenium + KDP管理画面で自動アップロード・出版申請
  5. 審査通過後に KDP Select 登録（Kindle Unlimited対応）
💡 KDP Select に登録すると Kindle Unlimited のページ読まれ数 (KENP) に応じた追加ロイヤリティが発生。積み重ねで月額安定収益になりやすい。

A/Bテスト戦略

サムネ・タイトル・投稿時間を
自動で最適化

毎コンテンツで複数バリアントを生成し、初期48時間のパフォーマンスで 自動的に勝者を選択。学習結果を次回生成のプロンプトに反映します。

テスト対象と管理

サムネイル A/B（最重要）
3パターンを自動生成。48時間のCTR（クリック率）で勝者を選択し残りを削除。
タイトル A/B
「数字入り」「疑問形」「感情訴求」の3パターン。インプレッションCTRで判定。
投稿時間 テスト
過去データから学習した最適時間帯（平日20時 / 休日11時など）を交互に検証。
note 価格 テスト
¥300 vs ¥500 を同ジャンル記事で交互テスト。購入率×単価の積で判定。
# A/Bテスト自動判定ロジック class ABTestManager: def evaluate_winner(self, test_id, hours=48): variants = self.get_variants(test_id) results = {} for v in variants: metrics = self.fetch_metrics( v.content_id, hours=hours ) # 統合スコア: CTR × 視聴継続率 results[v.id] = ( metrics["ctr"] * 0.6 + metrics["avg_view_pct"] * 0.4 ) winner_id = max(results, key=results.get) self.archive_losers(test_id, winner_id) self.record_pattern(winner_id) # 学習 return winner_id

自動投稿システム

最適タイミングで自動投稿

評価システムを通過したコンテンツは、プラットフォームごとの最適な投稿時間帯・ フォーマット・タグに変換されて自動投稿されます。

  • YouTube: 過去データから最適曜日・時間帯を学習
  • note: フォロワーのアクティブ時間帯に合わせて投稿
  • Kindle: 出版後のプロモーション期間を自動管理
  • X/Twitter: ハッシュタグ最適化・投稿頻度管理
  • 投稿失敗時の自動リトライ・Signal通知
プラットフォームAPIのquota超過時は翌日の同時間帯に自動リスケジュール。Signal通知で遅延を報告。
# 自動投稿スケジューラー class PublishScheduler: def schedule(self, content, platforms): schedule = [] for platform in platforms: optimal_time = self.predict_best_time( platform, content.genre, content.target_age ) adapted = self.adapt_format( content, platform ) schedule.append({ "platform": platform, "publish_at": optimal_time, "content": adapted, "tags": self.optimize_tags( content, platform ) }) return schedule

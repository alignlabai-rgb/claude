Claude Code実践ガイド：仕事から章を選ぶ

新機能を順番に覚えるのではなく、解決したい作業の形から読み始めるための案内です。

旧情報は固定旧版の全文へ分離しています。以下の例・試験案は未実行の教材です。

最初に決める三つのこと

対象はコードか、資料か、GUI操作か。実行は対話型か、プログラムからか、定期起動か。完了はテスト結果か、差分か、根拠付きの資料か。この三つを先に言語化すると、モデルの名前だけで手段を選ぶ失敗を避けられます。Codeの概要は公式入口、現行章一覧は公式ドキュメント索引で確認できます。

本ガイドの手順や教材は未実行の提案です。公式文書から確認した機能説明と、筆者による作業設計を分けて掲載しています。チーム機能の実験状態、Routineのpreview状態、Coworkとローカル接続の条件は各章を参照してください。契約、課金、実環境の権限をこのページから変更することはありません。

安全に一件を完了させたい

構成設計は指示・権限・変更場所の境界、動作原理はエージェントループとコンテキスト、依頼設計は入力・完了・停止条件を扱います。最初の依頼を書くなら、この三章を読み、小さな対象と観測できる結果を決めてください。

考えさせる量を調整したいときは思考制御へ。どの実行面に機能があるか迷ったら機能と実行面へ。すでに困った出力が出ているなら、設定を増やす前に失敗パターンで原因を分類します。

ツールや方法を再利用したい

Messages APIとCodeの境界は、自作アプリに組み込むときの入力・ツール実行・結果管理を説明します。外部資料を読む接続を試すならMCPの初回導入、その接続を継続運用するならMCPの運用契約です。

Skillの設計は再利用可能な方法と参照資料の分離を扱います。大量の指示文をコピーする前に、どの状況で起動し、どの失敗例で止まる方法なのかを定めます。用語の混同は用語集で短く確認できます。

並列・定期・GUIへ広げたい

並列作業の設計は依存関係と排他的な編集範囲、Agent teamsは実験的機能の適用条件を扱います。人員を増やす前に、成果を統合できる構造があるかを確かめます。

起動方式を選ぶならRoutineと定期実行、一般資料やデスクトップ作業を扱うならCowork、画面を直接操作するならComputer useです。クラウドが動いていることと、手元のファイルやアプリへ到達できることは同じではありません。

具体的な仕事へ落とし込みたい

実践レシピ集は仕様照合、バグ修正、文書整備、レビュー、方法化の五つを、成果と検証がセットになるよう構成しています。合成資料によるDD教材は資料抽出・単位照合・欠損検知の練習であり、実案件の秘密資料や投資・法務判断を扱いません。

章を読み終えたら、一つだけ選び、必要な資料と合成の失敗例を揃え、受入条件を先に書くのがおすすめです。結果を得た後は、使った設定名よりも『何が確認でき、何は未確認か』を残してください。これが機能一覧を仕事に変えるための、本ガイドの共通方針です。

Gemma 4 — ローカル推論を仕事にするための選択・計測・限界

最終更新・公式確認: 2026-10-13

Google AIの地図 · 知識一覧 · 最新情報

オープンモデルの利点は、自分の計算機・データ・評価工程で動作を設計できることです。「ローカルだから無料で安全」と結論づけず、モデル、runtime、保存、品質を個別に確認します。

GeminiとGemma

GeminiのAppsや管理APIと、重みを利用するGemmaは別です。Gemma 4公式model cardはApache 2.0、E2B／E4B／12B Unified／26B A4B／31Bを記載。テキスト・画像入力からテキスト出力で、音声はE2B／E4B／12B。小型は128K、中型は256K contextを示しています。Gemma 4 model card。

パラメーター数は必要RAMの直接の答えではありません。MoEのactive parameterが小さいから重み全体も同じ大きさになる、とは読めません。量子化、KV cache、画像処理、context長、runtime、同時実行を含めて測ります。ライセンスの確認は、使う元モデルと派生重み・配布物でそれぞれ行います。

現在の追加モデル

公式releaseには2026-10-06のEmbeddingGemma 2（740M）があります。生成モデルと埋め込みモデルを同じ用途で比べません。埋め込みは検索候補を探す部品であり、生成原稿の事実性を自動保証するものではありません。公式release。

最初に選ぶ仕事

低リスクな候補は、公開文書のタグ付け、短い分類、書式変換、合成データからの項目抽出です。いきなり長編創作や全資料の自律検索へ広げるより、正解が分かる小さな仕事でruntimeと評価を揃えます。小型モデルで不足した点が知識なのか推論なのか入力長なのかを分けると、サイズを上げる理由が明確です。

教材例：公開記事の分類

架空の記事を「モデル更新」「アプリ機能」「料金」「研究」の四種へ分類します。対象に、複数カテゴリ、根拠のない噂、製品名の誤記、不明な主語を含める。無理に一つへ分類せず「不明」と返す規則も作る。JSON形式を合わせる試験と、意味の正解を判断する試験を分けます。

記録: model / revision / quantization / runtime / context
入力: 権利確認済み公開文または合成文
出力: category / reason / uncertain
測定: 正解、棄権、誤断定、速度、ピークメモリ
禁止: 自動公開、外部送信、秘密資料の投入

導入・比較の手順

  1. 対象用途と合格条件を先に書く。
  2. 元のmodel cardと利用する配布物を照合する。
  3. 短い入力で読み込みと形式を確認する。
  4. contextを段階的に伸ばし、速度・メモリ・欠落を見る。
  5. 量子化を変えた場合も同じ集合で品質を再確認する。

インストールと推論実行は本記事ではしていません。必要容量や速度の数字は手元の実測で残すものとし、他人の計算機の結果を自分の性能へ転用しません。

ローカルの境界

モデルが手元で動いても、UIが外部検索、更新確認、telemetry、cloud fallbackを持つ可能性があります。ネットワーク経路を確認することと、秘密入力を許可することは別です。ログやキャッシュに入力が残る場合もある。オフライン運用が必要なら、どの処理が外へ出るのかを調べ、runtimeの条件も評価します。

失敗を分類する

メモリ不足、読込み失敗、chat template不一致、量子化による品質変化、長文の抜け、tool callの形式不正を分けます。runtime問題をモデル知能の問題と混同しない。反対に動作しただけで適合と判定しない。長いcontextで速度が落ちるなら、文書分割や検索へ設計を変える候補があります。

方法として残す

有効だった条件をmodelとruntimeの版へ結び、結果、反例、使わない範囲を記録します。「このサイズなら全部できる」ではなく、「この形式・言語・長さの分類ではこの基準を満たした」と書く。制作で使う時も、原稿候補の生成と公開判断を分け、誤りが出た箇所から改善します。費用は電力、計算機、保守、確認時間も含むため、APIがないことをゼロ費用と呼びません。

サイズを上げる前に

プロンプトが曖昧なら、大きいモデルでも比較対象が不明です。正解の定義、入力の区切り、棄権の規則を直してから容量を増やします。評価集合に、得意な例だけでなく、既に誤った例を残す。更新後の改善と退行を同じ材料で追うことで、手元の推論を再利用可能な仕事へ変えられます。

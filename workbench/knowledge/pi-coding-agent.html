🔍 Pi Coding Agent とは何か — 30秒で掴む核心

Pi は ターミナル（コマンドライン）で動くAIコーディングエージェントです。「エージェント」とは、あなたが命令をひとつ出すと、AIが自律的にファイルを読み・書き・コードを実行して、タスクを完了させるソフトウェアのことです。

Pi が他のエージェントと根本的に違う点：
  • コアは 4ツール（read / write / edit / bash）だけ — あとは全部オプション
  • システムプロンプト（AIへの指示書）が 1K トークン未満と極限まで短い
  • 特定のLLMに縛られない — Claude でも GPT-5 でも Gemini でも Ollama（ローカル）でも動く
  • OpenClaw の内部エンジンとして採用されている（OpenClaw は Pi の SDK ラッパー）
PicoClaw との違い（混同注意） Pi Coding Agent（このページ）= 開発者向けのターミナルコーディングハーネス（TypeScript製）
PicoClaw（別物）= Raspberry Pi / IoT デバイス向け超軽量 Go バイナリ（RAM 10MB 以下）
名前は似ているが、作者も用途も技術スタックも全く異なります。

👤 作者 Mario Zechner と設計思想

Mario Zechner とは

Java の大人気 2Dゲームフレームワーク libGDX（GitHub 23K+ stars）の作者。Badlogic Games 創業者。2025年末に Pi を個人プロジェクトとして公開し、2026年4月に Armin Ronacher（Flask / Jinja2 / Rye 作者）が共同創業したスタートアップ Earendil に参加。Pi のリポジトリは badlogic/pi-mono から earendil-works/pi へ移管（MIT ライセンスは維持）。

「必要なものだけを作る」哲学

"Mario's philosophy in all of this was: if I don't need it, it won't be built. And I don't need a lot of things."

— dev.to より（Pi の設計哲学を評した記事）

Zechner は「現在のコーディングエージェントは ふわふわした混沌（'fuck around and find out'）フェーズ にある」と考えています。その不確実性の中で最小主義が勝つ理由：

  • モデルへのシグナルが明確 — 余計な指示がなければAIは混乱しない
  • デバッグが容易 — 何が起きているか常に追跡できる
  • 拡張の自由度が高い — コアが小さいほど、ユーザーが思い通りにカスタマイズできる
  • エージェント自身が拡張する — 「機能を内蔵する」のではなく「エージェントが必要な機能を追加できる構造」を提供
Armin Ronacher の視点（Earendil / OpenClaw） Flask 作者の Ronacher は Pi を「OpenClaw の中の最小エージェント」と評し、Pi の SDK を OpenClaw のコアエンジンとして採用。Pi が LLM 対話・ツール実行・ストリーミングを担い、OpenClaw がその上に個人アシスタント層を構築する構造。

⚙️ コアアーキテクチャ — 4ツールと最小ループ

エージェントループの仕組み

Pi の中核は 約150行のエージェントループです。動作は非常にシンプル：

あなたの指示
→
LLM がプランを立てる
→
ツールを呼ぶ
→
結果を観察
→
完了まで繰り返す

このループ中、Pi は ライブ TODO チェックリスト と リアルタイムのトークンコスト を表示します。

コア4ツールの詳細

ツール役割具体的な使われ方
read ファイル・ディレクトリを読む ソースコード確認、README 把握、エラーログ読み込み
write ファイル全体を書く（新規作成・上書き） 新規ファイル作成、大規模な書き直し
edit 既存ファイルの一部を差分で変更 バグ修正、関数の書き換え（write より効率的）
bash シェルコマンドを実行する テスト実行、ビルド、npm install、git 操作
なぜこの4つだけで十分か この4ツールで「読む → 考える → 書く → 確認する」のサイクルを完全に回せます。他の全ての操作（ウェブ検索、データベース操作、API 呼び出し）は拡張で追加できます。コアにないのは「意図的」です。

AGENTS.md — Pi の「憲法」ファイル

Claude Code における CLAUDE.md に相当するのが Pi の AGENTS.md です。

# AGENTS.md — プロジェクトルールの例

## このプロジェクトについて
TypeScript + Next.js 14 (App Router) プロジェクトです。
テストランナーは Vitest。コーディング規約は ESLint + Prettier。

## ルール
- ファイルを削除する前に必ず確認を取ること
- npm install を実行する前に package.json を提示すること
- テストが全件パスするまでコミットしないこと

## 承認が必要な操作（ツールが外部サービスに書き込む場合）
- 外部 API に書き込むツールは呼び出し前に承認を要求すること

AGENTS.md は 階層的に読み込まれます：

  1. ~/.pi/agent/ — グローバル設定（全プロジェクト共通）
  2. 親ディレクトリの AGENTS.md（モノレポ等）
  3. 現在のディレクトリの AGENTS.md（プロジェクト固有）

SYSTEM.md を置くと、デフォルトのシステムプロンプトを置き換えまたは追記できます。

🔀 4つの動作モード

Pi が他のエージェントと大きく異なる点のひとつが、4種類の動作モードを持つことです。ユーザーの使い方に合わせて選べます。

1

Interactive TUI

ターミナル上のインタラクティブUI。差分レンダリング（変更箇所のみ再描画）で滑らか。リアルタイムで TODO と消費トークンを表示。

$ pi
2

Print / JSON ストリーム

スクリプトやパイプライン用の非対話モード。--print または --json フラグで出力形式を指定。CI/CD への組み込みに最適。

$ pi --print "README を要約して"
3

RPC モード

stdin/stdout 経由の JSON プロトコル。Node.js 以外のアプリ（Rust, Python 等）から Pi を制御できる。JSONL（改行区切り）フォーマット。

--rpc フラグで起動
4

SDK モード

TypeScript アプリに Pi をライブラリとして組み込む。OpenClaw はこのモードを使っている。IPC や HTTP なしで同一プロセス内で動作。

createAgentSession() で呼び出し
SDK モードの重要性 OpenClaw（GitHub 378K+ stars）は Pi の SDK モードでエージェントセッションをインポートし、LLM 対話・ツール実行・ストリーミング応答の全処理を Pi に委譲しています。Pi は「ライブラリとしての AI エンジン」という新しいカテゴリを開拓しています。

🖥️ インタラクティブ TUI の機能詳細

ツリー構造セッション

Pi のセッションは JSONL ファイルに ツリー構造（各エントリに id と parentId）で保存されます。これにより：

  • 会話の途中から「分岐」して別の方針を試せる（Git のブランチ感覚）
  • /tree コマンドで過去のどの時点にも戻れる
  • 異なるブランチ間を自由に行き来できる
  • ファイルを新規作成せずにセッション内でブランチを切れる

ミッドセッション モデル切り替え

会話の途中で 別のLLMプロバイダー/モデルに乗り換えられます。切り替え時、それまでの会話履歴は自動でマイグレーションされます。

操作説明
/modelモデル選択ダイアログを開く
Ctrl + Lモデル切り替え（ショートカット）
Ctrl + Pお気に入りモデルを順番に切り替え

その他の主要コマンド

コマンド説明
/treeセッションツリーを表示・分岐点を選択
/skill:<name>スキルを手動で読み込む
/loginClaude Pro / ChatGPT Plus / GitHub Copilot で OAuth 認証
/cost現在のセッションのトークンコスト表示

🧩 拡張システム — TypeScript で何でも追加できる

Pi のコアは最小ですが、TypeScript 拡張で際限なく機能を追加できます。これが Pi の真の力です。

拡張で追加できるもの

🛠 カスタムツール

LLM が呼べる新しいツールを追加。データベース操作、API 呼び出し、ウェブスクレイピングなど何でも。

⌨️ コマンド

/mycommand 形式のカスタムスラッシュコマンドを追加。よく使う操作を1コマンド化。

🎨 テーマ

TUI の見た目をカスタマイズ。カラースキーム、フォント、レイアウトを変更。

🎯 スキル

特定タスク向けの拡張セット。/skill:python-debug のように呼び出し、または自動ロード。

📦 パッケージ

拡張 + スキル + テーマをまとめて npm / git で共有できる形式。

🔔 イベントハンドラ

セッション開始・終了・ツール呼び出し前後などのライフサイクルに処理を挟む。

TypeScript 拡張の書き方（基本）

// my-extension.ts — カスタムツールの追加例
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function(api: ExtensionAPI) {
  // カスタムツールを LLM が呼べるように登録
  api.registerTool({
    name: "fetch_url",
    description: "指定した URL のコンテンツを取得します",
    parameters: {
      type: "object",
      properties: {
        url: { type: "string", description: "取得する URL" }
      },
      required: ["url"]
    },
    handler: async ({ url }) => {
      const res = await fetch(url);
      return await res.text();
    }
  });

  // カスタムコマンドを追加 (/summarize で呼び出し)
  api.registerCommand("summarize", async () => {
    await api.sendMessage("このプロジェクトの現状を3行で要約して");
  });

  // ライフサイクルイベントにフックを追加
  api.on("session:start", () => {
    console.log("Pi セッション開始");
  });
}
CLAUDE.md との対応 Claude Code の Hooks（settings.json）に相当するのが Pi のイベントハンドラ。CLAUDE.md に相当するのが AGENTS.md。Slash commands に相当するのがカスタムコマンド。考え方は似ているが、Pi は全て TypeScript で書けるため、より柔軟。

Step 1: インストール

# npm 経由でグローバルインストール
npm install -g @earendil-works/pi-coding-agent

# API キー方式（最もシンプル）
export ANTHROPIC_API_KEY="your-key-here"

# または既存サブスク OAuth（CLI 内で実行）
> /login

Step 3: プロジェクト設定

# プロジェクトルートに AGENTS.md を作成
cat > AGENTS.md << 'EOF'
# プロジェクト情報

テストは Jest、フォーマッタは Prettier。

# ルール
- ファイルを削除する場合は事前に確認すること
- 変更後は必ず `npm test` を実行すること
EOF

Step 4: 起動して使う

# インタラクティブモードで起動
pi

# プロジェクトディレクトリを指定して起動
pi --cwd /path/to/project

# ワンショット（非対話）で実行
pi --print "src/index.ts のバグを修正して"

# CI 向け JSON 出力
pi --json "テストを全件実行して結果を報告" | jq .summary
初回実行のおすすめ手順 1. まず pi --print "このプロジェクトの構造を説明して" で読み取りのみ実行
2. 問題なければ AGENTS.md を整備
3. 小さな変更（コメント追加等）から始めて動作を確認
4. 信頼できたら本格的なタスクを委任

OpenClaw が Pi を採用しているコード（概念図）：

// OpenClaw の内部コード（概念）
import { createAgentSession } from "@earendil-works/pi-coding-agent";

class OpenClawAgent {
  async handleMessage(userMessage: string) {
    // Pi の SDK で AgentSession を作成
    const session = await createAgentSession({
      provider: "anthropic",
      model: "claude-opus-4-8",
      workdir: this.workspaceDir,
    });

    // Pi がLLM対話・ツール実行・ストリーミングを全部担当
    for await (const event of session.run(userMessage)) {
      // OpenClaw はイベントを受け取り、メッセージングUI に表示するだけ
      await this.messagingGateway.send(event);
    }
  }
}

OpenClaw の 378K+ GitHub stars の裏には Pi のエンジンがあります。Pi 自身のスター数（~15K）は少ないですが、間接的な影響力は巨大です。

🎯 誰が Pi を使うべきか

Pi が最適なユーザー

  • ✅ 複数の LLM を使い分けたい開発者 — 今日は Claude、明日は GPT-5、という使い方

  • ✅ エージェントを自分のアプリに組み込みたいエンジニア — SDK モードが強力
  • ✅ ターミナル派 — GUI を嫌い、CLI 完結で作業したい人
  • ✅ Open Source 信者 — MIT ライセンスで全コードが見える安心感
  • ✅ ローカル LLM 派 — Ollama と組み合わせてコストゼロで使いたい人

Claude Code の方が向いているケース

  • 📌 Anthropic モデルしか使わないと決めている
  • 📌 MCP サーバーとの統合が必要
  • 📌 IDE（VS Code / JetBrains）に統合したい
  • 📌 SWE-bench 等のベンチマークで実証された精度が必要
  • 📌 Hooks による細かい運用制御（セッション開始/終了時の処理）

どちらも使うという選択肢

「Claude Code で深い作業 + Pi で複数モデルを比較・ローカル作業」という使い方が 2026年の現実的なベストプラクティスとされています。両者は競合というより補完関係に近いです。

📋 まとめ — Pi Coding Agent の本質

本質「最小主義」のターミナルコーディングエージェント。不要なものを作らない哲学。
コア4ツール（read/write/edit/bash）、システムプロンプト <1K tokens、~150行のエージェントループ
強みプロバイダー中立（15+ LLM）、SDK 組み込み、TypeScript 拡張、セッションツリー
弱みベンチマーク非掲載、IDE 統合なし、MCP 非対応（拡張で追加可）
価格MIT 完全無料。コストは LLM API のみ（既存サブスクで ¥0 も可）
OpenClaw との関係Pi が内部エンジン。OpenClaw 378K+ stars の裏に Pi の SDK

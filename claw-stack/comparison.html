設計意図

なぜ4スタックに分かれているのか

「全部 OpenClaw で統一すればよい」という疑問は自然です。 4スタックに分けた理由を記録しておきます。

⚡
習得コストと参入障壁の分離
OpenClaw は高機能だが、設定・デプロイ・監視の学習コストが高い。 PicoClaw は「まず動かす」ための最小構成で、参入障壁を下げるために分離している。 失敗コストが低い段階で構造を学べることが、長期的に OpenClaw を使いこなせる前提になる。
🏠
Hermes Agent が「第4の選択肢」として存在する理由
NanoClaw（Docker・チーム向け）とは別に、「個人がVPSに常駐させる」用途には Docker の複雑さが不要で、スクリプト常駐の軽さが刺さる。 AI Creator Hub の「外出中に自律実行」というコアユースケースに最もシンプルに対応できるのが Hermes Agent。
🔄
将来のセッションへの注記

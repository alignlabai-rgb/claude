OpenClaw 用語集：似た言葉の責任を分ける

最終更新・公式情報確認：2026-10-13。news という旧 URL は維持し、本文は用途別の現行ガイドへ刷新しました。確認日は発表日ではありません。

例と評価案は筆者の設計提案で、未実行です。性能測定・本番導入・安全認定・正式採用の実績を示すものではありません。

用語を増やすより、間違いやすい組み合わせを分ける。ここでは新製品の名前を推測で定義せず、公式文書へ戻れる小さな辞書を作る。用語の定義は、設定を変更する権限や本番の安全を保証するものではない。

Gateway／client／node

Gateway はチャネルと制御の中心。client は依頼や状態確認へ接続する面。node は宣言した機能を提供する接続主体。OpenClaw Gateway architecture画面のある場所と実行する場所を自動的に同じと考えない。状態のアーキテクチャ へ。

Model／provider／channel

Model は推論対象、provider は接続と認証に関係する対象、channel はメッセージの入口。公式 provider 説明でも区別される。OpenClaw Model providers同じブランドの API、Web、ローカル配布は同じ面ではない。LLM 比較 へ。

Skill／tool／plugin

Skill は必要な場面で使う指示の文書。tool は呼び出せる操作面。plugin は能力や統合を追加する仕組み。スキルが指示しても、それだけで tool の許可を得るわけではない。OpenClaw Skills配布元と版と効果を 拡張の選定 で確認する。

Session／workspace／memory

Session は会話と継続の単位、workspace は作業の場所、memory は次回へ残す整理された情報。公式 memory は長期と日付の用途を分ける。OpenClaw Memory overview会話を新しくしても、ファイルや記憶が消えたとは言えない。

Automation／run／delivery

Automation は保存された予定や条件、run はその実行、delivery は結果の行先と配送。現在は Automations の名前で、cron は alias と説明される。OpenClaw Automations予定がある、実行した、届いた、採用したを一つの成功にしない。

Tool policy／sandbox／approval

Tool policy は操作面の許可、sandbox は実行の到達範囲、approval は対象操作の判断。公式 policy はこれらを同一視しない。OpenClaw Policy as codeexec が許されれば file write tool の拒否だけで shell 全体は読み取り専用にならない。

Compatibility／authority

Compatibility は形式や対応範囲の互換。Authority は実行できる権限。Gateway の HTTP 互換面は後者にも注意が必要である。Gateway Chat Completions 互換面見慣れた入力形式を、狭い安全な権限の証明にしない。

Fact／proposal／observation

Fact は対象と日付を明示した根拠のある説明。Proposal はまだ評価が必要な設計案。Observation は確認した条件での観測。本棚の合成例は proposal で、成功実績ではない。噂は調査する候補として残せるが、能力や契約の証拠へしない。

Completion／adoption

Completion は依頼した提出物が契約を満たすこと。Adoption はその意味と次の効果を適切な人が決めること。文章の完成と、公開や正式採用を分ける。記事が多いことより、この区別で判断を間違えないことが重要である。
